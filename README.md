# SSEA — Survival-based Self-Evolving Agent Architecture

**生存式自演化代理架构** · v0.3.1 · 第一阶段进行中（2026-09-28）

> 不是「更小的 Transformer」，而是把**语言生成架构**换成**生存控制架构** ——
> 感知 → 决策 → 行动 → 反馈 → 学习 → 遗传。
> **自然语言只作观察员接口，不进控制闭环。**

目标是设计一种新的模型架构，在**减少算力与内存带宽消耗的同时，保留语言之下那个
完整的认知基底**——多步规划、因果知觉、情景记忆、技能累积、非语言元认知、内在驱动；
并**明确放弃语言作为认知工具所提供的那部分能力**（精确离散符号运算、递归组合生成、
抽象概念的公共约定、显式自我叙述）：
低算力低带宽 · 精准回忆历史（记忆放外部，不压进权重）· 可自主修改自身代码与参数 ·
可保存 / 恢复 / 变异 / 继承 · 可在近乎真实的生态中生存、竞争、合作、演化。

> **2026-09-28 修订**：旧表述「不缩减智力」被替换。理由是「智力」不是标量、
> 该表述不可检验，且是一个必输的辩论位置——举出「精确算术」一个反例就能宣称
> 目标未达成，**而那个反例是真的**。更准确的定位：**SSEA 与 LLM 不是同一件事的
> 两种实现，而是两个不同的能力剖面**。权威条款见
> [docs/03](docs/03-architecture-spec.md) §8.2，论证见
> [docs/02](docs/02-nonverbal-cognition.md) §4.2–4.3。

第一阶段**不构建生态系统**，只构建「能够进入生态系统的最小生命体」。
**23** 项明确不做的事及各自的失败模式见 [docs/04](docs/04-boundaries.md)
（2026-09-28 由 20 项扩为 23 项：新增精确离散符号运算、递归组合生成、
二阶自我解释——即裁决一「明列放弃项」的落地）。

## 十条裁判标准（C1–C10）

全部模糊地带一律按这十条推导。**任何结论若无法回溯到其中至少一条，即视为偏离
SSEA 立场，不予采纳**（[docs/03](docs/03-architecture-spec.md) §1）。
完整出处见 [docs/06](docs/06-status-roadmap.md) §1.3。

| | | | |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | **C2** 自然语言只作观察员接口 | **C3** 权重/记忆/技能三分离 | **C4** 低算力低带宽 |
| **C5** 精准回忆历史 | **C6** 可自主修改自身 | **C7** 可保存/恢复/变异/继承 | **C8** 给基因先验，不给知识语料 |
| **C9** **不设外部评分函数，只有淘汰函数** | **C10** 创新在 L2/L3/L4，不在 L1 算子 | | |

两条最吃重的：**C8** 是「为什么不能接人类知识库」的答案，也是 `damage_urgency` /
`fatigue` 置 0 预留的理由——给结构先验，不给满能力。**C9** 是验证门**只判合法性、
不打分**的共同来源：一个提案让存活翻倍、另一个让它减半，只要都合法，Gate 一视同仁。

> **C9 于 2026-09-28 修订**（原文「不设评分函数」）：加「**外部**」二字，并正式
> 与自由能原理 / 主动推理结盟。**承重点是「淘汰归环境、模型物理上碰不到它」，
> 不是「模型内部没有任何驱动信号」**——`prediction_error` 与 `internal_drive_vector`
> 早已落地并直接改变行为，旧表述与设计不符且无红灯，是项目自己定义的「措辞债」。
> 三层信号区分与全部连带修订见 [docs/03](docs/03-architecture-spec.md) §8.1。
> ⚠️ 奖励塑形、观察员评分系统、Gate 打分、编译器排序**仍然全部禁止**。

## 证据现状 —— **这一节比上一节重要**

**910 项测试通过只说明工程质量，不说明架构有效。** 它证明的是：协议自洽、
序列化保真、约束不被违反、注入面四条性质成立、记忆与技能的机制按设计工作。
它**不**证明：这个架构比别的更省算力、记忆真的提升了生存率、技能固化真的
降低了能量消耗、基因继承真的传递了能力。

后者需要 [docs/03](docs/03-architecture-spec.md) §12 的七条验收实验：

| 2 | 记忆召回 | ✅ 已跑 | 写入成功率 **1.0000** · 检索命中率 **0.5164** · 危险回避率 **两臂均 0.9814**（**饱和**，不能作证据）；**粗粒度签名（5 个整数）在 7/8 seed 上相同**——但那是整数阈值化后的投影，两臂**动作在 5/8 个 seed 上不同**（变化 seed 内 56–99% 的帧不同，中位幅度 3.5e-4 ~ 1.8e-3） |

**跑通的五条里，三条是「机制通了」的数字，两条是仅有的对照组数字——
而它们说的是增益跨不过判据的分辨率。** 六号与七号那四个 `1.0000` 里，
有四个的分母来自**注入样本**（6 条与 5 条），**自然运行下这两个指标的分母是 0**
——看数字先看分母。

二号的 458 条落库、844 次检索、475 次命中说明记忆**确实在转**；
两臂（记忆开 / 记忆关）的**粗粒度签名**（帧数 / RUN 帧 / 可编译段 /
`ENERGY_GAINED` / 危险接触帧，共 5 个整数）在 **7/8 个 seed 上相同**，
但**动作在 5/8 个 seed 上不同**（变化 seed 内 56–99% 的帧不同，中位幅度 3.5e-4 ~ 1.8e-3）——**整数指标相同 ≠ 行为相同**。
三号固化出 2 条技能，**调用 33 次全部 `SKILL_FAILURE`**。
**它排除了「机制没接上」，也排除了「扰动传不到行为」，把问题逼到判据本身：
量不出差的时候，先怀疑尺子。** 读法与三种坏数字见
[docs/06](docs/06-status-roadmap.md) §5.2 与 §6.3.8。

**目前全项目唯一一组「行为真的变了」的实测数字**，是 Milestone 4 增量 3 的阈值自修正
（8 seed × 25 帧，强制睡眠一次）：记忆门开启率均值 **0.375 → 1.000**，
其中 **5/8** seed 恰好提案一步（`memory_gate_threshold` 0.5 → 0.4），**3/8** seed 保持沉默（这 3 个本就门全开，无事可修）。

> **「3/8 沉默」比「0.375 → 1.000」更重要**——一个每次都提的规则不配叫修正。
> 而且提升幅度大是因为随机初始化的门控值几乎恒定在 0.5 附近，阈值 0.5 恰好切在正中间。
> **一个全局阈值是钝器**：它只能把门全开，做不到「惊奇帧开、平淡帧关」的选择性，
> 而那需要被整个推迟的参数侧 Δθ。所以正确说法是
> **「门控不开」这个故障修好了，「门开得准不准」是下一步的事。**

## 架构一览

```
快环 FSL（实时控制，不输出自然语言、不做长文本推理、不频繁改权重）
  o_t ──► PerceptionEncoder ──► ┐
                                ├─► StateCore ──► ActionDecoder ──► Action
  MemorySystem.retrieve(p_t) ───┘                      │
  MetabolicMonitor.drive(...) ──────────────────────┘  ▼
                                                   SkillRunner ──► Environment
                                                        │
                                              o_{t+1}, f_t（含 prediction_error）

慢环 SEL（离线、可验证、可回滚）
  Action Trace + Feedback + Memory
      ──► ExperienceCompiler ──► 提案 ──► VerificationGate ──► StructureStore
                                                  │ pass            │ 原子切换版本号
                                                  │ reject          ▼
                                                  │        FastLoopContext（不可变快照）
                                                  └─► 版本号不切换 ──► 快环继续用旧版
```

**慢环不调用快环。** 慢环只**发布结构的新版本**，快环只**读取当前版本**。
这条注入面是双环之间**唯一**的接口，它的四条性质**由结构事实保证，而非调用方自觉**：

| 性质 | 由什么保证 |
|---|---|
| **快环零改动** | 快照与 Store 脱钩，快环只读快照；换版本 = 换句柄 |
| **失败天然回滚** | Gate 不通过则版本号不切换。**不存在「回滚」这个操作，因为从未应用** |
| **可遗传** | 快照内容就是 GenePackage 的直接来源 |
| **可审计** | 每次版本切换记 `(proposal_id, from_v, to_v, gate_result, timestamp)` |

`StructureStore` 上**没有** `rollback` / `revert` / `undo` / `restore` 方法——
这不是遗漏，是设计。有测试守着（`test_no_rollback_api_exists`）。

**四权分立**——「提什么」「在不在边界内」「能不能应用」「应用不应用」是四个不同的问题：

| 权 | 归谁 | 它**刻意不做**什么 |
|---|---|---|
| 提什么（ΔS / Δθ） | `ExperienceCompiler` / `LocalPlasticity` | 不提交、不评估好坏、不发明切分规则 |
| 在不在边界内 | `PlasticityController.allowed_scope` | **白名单**，且不可更新清单**先于**白名单匹配 |
| 能不能安全应用 | `VerificationGate` | **不打分**（C9）、不碰权重、不执行代码、不做回滚 |
| 应用不应用 | `StructureStore.commit` | 拒绝时记审计项、**不抛异常、不改版本号** |

## 动手改代码前必须知道的六件事

前五条是**踩过的坑**，不是理论风险。

1. **量不要从环形缓冲取。** `Environment.event_log()` / `event_notes()` 是
   `max_events=16` 的环形缓冲，「跑完再遍历事件流做统计」会**静默漏掉早期事件**，
   而且错的方向偏向零——正好把有效果的实验读成没效果。**实测咬过**：
   「跑完统计 `ENERGY_GAINED`」得到 0 次，而第 10 帧确实 `grasp: +0.356 energy`。
   用 `Environment.event_counts()`（只增不减、不截断）、逐帧 `Feedback` 增量、
   或 `StructureStore.audit_log()`（append-only）。
   三条能量口径写在 [experiments/_harness.py](experiments/_harness.py) 的模块 docstring 里，
   **别在各脚本里各定一套**。

2. **累计与窗口是两件事，两个仪器不可互换。** 全轮累计答得了「这轮 grasp 成功了几次」，
   答不了「按 `source_id` 接触了几次危险源」（按类型的 dict 没有这个维度），
   也答不了「固化前 vs 固化后」（那要按 `context_fingerprint` 切窗口）。
   反过来，`ENERGY_GAINED` 记的是**意图值**，而同一帧的 `Feedback.energy_change`
   可能是负的；`push` / `pull` / 基础代谢耗能**根本不发事件**——**只数事件一定漏**。

3. **测试对顺序敏感。** 若干测试用 `torch.randn` 从全局 RNG 取数，而夹具是随机初始化的
   ——顺序一变结论就翻。凡依赖随机门的断言（通道是否开启、是否写入）一律
   **按死门控或固定 seed，不断言抽奖结果**。`pytest-randomly` 已装好，15 seed 是纪律。

4. **记忆门控默认约一半概率关着。** 门控值由随机权重决定，几乎恒在 0.5 附近，
   而阈值恰是 0.5。**任何未固定 seed 的记忆实验结论都是抽奖。**

5. **07 被 08 修订过。** 动手前必须先读 [docs/03](docs/03-architecture-spec.md)
   第 5 节的 19 条修订条款汇总表。**凡 08 修订过的协议，以 08 为准，不以 07 原文为准。**

6. **不要在这里长出外部评分函数。** C9 是硬约束：只有淘汰函数，没有**外部**奖励。
   验证门不打分、经验编译器不排序、环境不生产 `prediction_error`（那是模型侧
   `SurpriseEstimator` 的产物）——都是同一条纪律的不同表述。
   **淘汰函数在模型之外，模型物理上碰不到它**，这是「模型不可修改淘汰函数」的
   结构保证。
   ⚠️ **2026-09-28 起本条的对象限定为「外部」**：模型内部的**内在驱动**
   （`prediction_error`、`internal_drive_vector`）是合法的第三层信号，
   **不在本条禁止范围内**——但它们的**定义**不可被模型修改、不可被提案触碰、
   不进入淘汰判定。三层信号区分见 [docs/03](docs/03-architecture-spec.md) §8.1。
   **本条仍然禁止**：奖励塑形（如「接近资源给分」）、观察员评分系统、
   Gate 打分、编译器排序。
