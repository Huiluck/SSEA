「一个都还没有」，理由是同一条：没有数字比假数字好。

**实验 2 / 3 的结论（2026-09-28）：机制在转，而脚本原判据量不出它的增益。**

| 读数 | 实验 2 | 实验 3 |
|---|---|---|
| 机制确实在运转 | 落库 **458** 条 / 检索 **844** 次 / 命中 **475** 次 | 固化出 **2** 条技能 |
| **脚本原判据（粗）** | **两臂的 5 个整数签名 7/8 seed 相同**；门决策只在 2/8 seed 上被改变 | 调用 **33** 帧，**33 次全部 `SKILL_FAILURE`**，成功率 **0.0000** |
| **逐帧细量（灵敏）** | **动作在 5/8 个 seed 上不同**（变化 seed 内 56–99% 的帧不同，中位幅度 3.5e-4 ~ 1.8e-3）；隐状态第 0 帧即分叉 | `编译它的成功段` 41 帧，**重放它 0 次成功** |

这两条是七实验里唯一带对照组的，所以它们给出的是**第一组对照数字**——
而对照数字的用处在这里兑现了：它把**三种**解释的输出分开了。前两种
（「机制没接上」/「接上了但推不动」）在旧写法里**输出一模一样**
（都是某个指标为 0）；最终落在**第三种**上，而它恰恰是前两种都没有
形状的那一种——**推得动，是尺子太粗**。

> **但第一版读法读错了第二句。** 「两臂逐位相同」当年写在这里，
> 说的是**粗粒度签名**（5 个整数：帧数 / RUN 帧 / 可编译段 / `ENERGY_GAINED` /
> 危险接触帧），不是整条轨迹——而整数是阈值化之后的投影，~1e-3 的扰动
> 投不过去。逐帧重量之后，两臂动作在 **5/8 个 seed 上不同**。
> 所以真正排掉的是**两个**解释：「机制没接上」与「接上了但扰动传不到行为」。
> 剩下的问题在**尺子**上。这条槽点对应 12 §6 债务 21（措辞债）——
> 下面「三之三」那一条本来就写对了方向，是正文没跟上它。

**两个算式早已定死**（2026-09-27），脚本本体是本次补上的。
原先它们**只有指标名**——没有公式、没有分母、没有窗口（14 §6.3.4），
于是「脚本该算什么」本身是个未决问题。算式现状：

| 指标 | 算式定在哪 | 它曾经缺什么 |
|---|---|---|
| `危险回避率` | `EpisodeResult.hazard_avoidance_rate` | 分母（哪些帧算暴露）与分子（什么算一次接触） |
| `能量消耗变化` | `energy_change_between_windows(trace)` | 窗口（按 `context_fingerprint` 切版本，不是全轮累计） |

两条都**不再需要 `source_id`**：危险暴露逐帧从 `observation.objects` 的
`threat_level > 0` 判定，接触从同一帧的 `Feedback.damage_change > 0` 判定——
`environment.py` 里 `self.damage` 只在 `_apply_hazard_contact` 一处增加，
所以这个等价是准的。（按类型的 dict 确实没有 `source_id` 维度，
`OBJECT_FOUND` 对资源与危险源一视同仁；**绕开它，而不是去修它**——
累计计数器是观察员面的仪器，不是这个指标的必经之路。）

**算式定了不等于数字有了，但两条前置现在都有了**（2026-09-27）：

- ~~行为层「走不动」~~——`loco_dir` 是未训练线性头、agent 不会转向。
  **已解除**：趋近本能装上后实测最近资源距离 3.251 → 0.268，8/8 seed 进入
  `reach = 1.0` 的可抓取范围（`measure_instinct.py`）。
- ~~世界层「没有可学的成功」~~——**已解除**：给操纵链补上先验后，
  默认世界里**第一次出现可编译的成功段**（0 → 2，`ENERGY_GAINED` 0 → 9）。
  快环能产出可固化段，慢环就有东西可编译——实验 3 因此**不再缺前提**。

详见 14 §6.3.2 / §6.3.4 / §6.3.5 / §6.3.6。`_harness.py` 模块 docstring 的
**一之四** 是这两个算式的规格出处，本文件不重抄公式。

**前置通了不等于结论有了——这一轮把这句话兑现了。**
`grasp` 臂那 2 段只落在 8 个 seed 里的 2 个上；对照组跑完之后，
实验 3 的读数正是「2 条技能、0 次成功调用」。前置解除的是**能不能测**，
不是**测出来是什么**。

### 一个静默陷阱：`SKILL_SUCCESS` 没有生产者

`SKILL_SUCCESS` / `SKILL_FAILURE` 在 `EVENT_TYPES` 里登记着，
但**没有任何代码发出它们**——`tests/test_environment.py` 里有一条测试
（`test_event_counts_name_the_producerless_types`）钉着这份无生产者清单。
于是 `Environment.event_counts()["SKILL_SUCCESS"]` **恒为 0**。

危险在于这个 0 读起来完全正常：脚本从计数器读调用成功率，得到 0，
写进报告就是**「技能从未被调用」**——而真相可能是**调用了几十次、每次都失败**。
这两句话指向完全不同的下一步（去修技能调用 vs 去修技能发现），
而输出里的区别只有一个 0。

正确来源是 `StepRecord.skill_event`——`SkillRunner.report()` 返回的正是
这两个字符串，**运行器那一侧是有生产者的**。`EpisodeResult.skill_successes` /
`skill_failures` 因此取自 trace 而非计数器，`exp3` 还会把两个来源**并排打**
出来做当场交叉验证。

推广：**「从计数器读到 0」与「没发生过」不是一回事**，
除非那个计数器有生产者。这一条适用于 `EVENT_TYPES` 里的每一个类型，
`ENERGY_LOST` / `SELF_MOD_APPLIED` / `SELF_MOD_ROLLBACK` 至今也是无生产者的。

### 第三种坏数字：饱和

项目的报告纪律一直在防两种坏数字：**`None` 被写成 `1.0`**
（0/0 当成 100%）与 **`1.0000` 的分母来自注入样本**。实验 2 给出了第三种：

> `危险回避率` 两臂都是 **0.9814**，差值为零。

这个数字**算对了**，但它**量不出东西**——8 个 seed 合计只有 336 个暴露帧、
6 次接触，一次接触就够让一个 seed 的率跳几个百分点。天花板效应下，
两臂的差别被压进噪声里。

**它比前两种难发现，因为数字本身完全正常。** 前两种是「算错」，
看分母就能抓；这一种要看的是**分母够不够大**——336 个暴露帧看着不小，
但它上面只挂了 6 次事件，有效信息量是 6 不是 336。
所以 `exp2` 把原始计数（暴露帧 / 接触帧 / 存活帧）与率**一起**打出来，
并且不用这个率下结论。

### 判据的体检（`measure_judgement_health.py`）

`measure_instinct.py` 回答「世界打通了没有」，这一支回答**「尺子还能不能量」**。
它把现有验收判据的实测样本喂给 `SSEA/sse_protocols/judgement_health.py`
（八条子句，协议见 `../docs/03-architecture-spec.md` §11），只体检、不改行为。

**2026-09-29 首次读数（8 seed × 200 帧）：八条判据 8/8 判红。**
最重的两条是**声明性**的，与数据无关：

| 子句 | 结果 | 含义 |
|---|---|---|
| H5 预算匹配基线 | **8/8 红** | 两臂是「机制开 / 关」消融，**不是**同等预算的简单基线臂 ⇒ 增益无法归因 |
| H6 搜索/评测分离 | **8/8 红** | 技能在 seed i 上编译、又在**同一个** seed i 上测调用 |
| H4 分辨率 | 4 条警告 | 8 条判据里有 4 条的取值数 < 样本数的 1/4（整数量化） |
| H8 可证红 | 3 条红 | 危险回避率 / 技能调用成功率 / 技能生成数量**当前拉不红** |

`V_τ`（逐情境跨臂方差）在**几乎所有情境上为 0**：危险回避率 7/7、记忆写入成功率 5/5、
记忆检索命中率 8/8、可编译段数 8/8、危险接触帧 8/8；唯一例外是技能生成数量
（6/8 为 0，最大 0.25）。把它与上文的「两臂动作在 5/8 个 seed 上不同」并列，
得到一句强结论：**差在动作层，丢在判据层。**

分母侧同样要紧：技能调用成功率 **1/16** 个样本有定义、能量消耗变化 **2/16**、
记忆写入成功率 **5/16**。分母这么小的时候，「率」的任何变化都在噪声量级。

### 本能的测量（`measure_instinct.py`）

这不是 §12 七实验里的任何一条，所以它不叫 `expN_`、也不进 `run_all.py`
的 `EXPERIMENTS`。它是**一次仪器读数**：回答「可学的世界打通了没有」。

**三臂**，不是两臂：`grasp` 臂是**累积**的（趋近 + 操纵），所以
**`approach` → `grasp` 这一跳就是操纵链那一层的增量**，不含趋近的影响。
写成"只装操纵"的臂是错的——没有趋近，agent 走不到 `reach = 1.0` 以内，
那一臂量出来的 0 是「够不着」，不是「操纵没通」。

| 量 | `off` | `approach` | `grasp` |
|---|---|---|---|
| **可编译段数（合计）** | 0 | 0 | **2**（seed 0 / 5） |
| **`ENERGY_GAINED`（合计）** | 0 | 0 | **9** |
| 最近资源距离（均值） | 3.251 | **0.268** | 2.152 |
| 存活帧数（均值） | 81.1 | 66.8 | 107.4 |

三臂共用同一个起点（`StructureStore()`），差异只可能来自播种；而「关本能」
那一臂**不是一个特制的开关，就是默认世界本身**——开关会漂移，空结构不会。

**判据是可编译段数，不是存活帧数。** `compile_skills` 要「连续 ≥3 帧直接成功
且整段净收益为正」，所以一段都没有 = 慢环没有任何东西可以固化。历史教训是
8 seed 3 次抓取把均寿命从 67 抬到 72 帧，而可编译段仍是 0——**活得久不等于
学到了东西**。

**`grasp` 臂的资源距离回升（0.268 → 2.152）是成效的副产品，不是退步**：
抓取成功会把那份资源从世界里移除（`environment._apply_manipulation` 按身份
删对象），于是近处的被吃掉之后「最近资源」自然变远。**一旦出现可编译段，
资源距离就不再是这一格的判据**——它是「两臂都没抓到」时的诊断工具。
脚本里显式打了这句话，因为 2.152 单独看会被读成「装了本能反而离得更远」。

同理，**`approach` 臂的存活帧数下降（81.1 → 66.8）不是反例**：定向移动比
随机游走更耗能，而能量没换成食物——C9 的淘汰函数如实反映了「趋近本身不是收益」。

**这一轮抓出了两个静默缺陷**，都不报错，详见 14 §6.3.5 的两个 blockquote：
`run_episode(store=...)` 的初始上下文曾忽略 store（本能进不了快环，
两臂数字会完全一样而被读成「本能没效果」，真相是**从未装上**）；
`UPDATE_ADAPTER` 曾被格式级要求 target 已存在，于是 `adapters` 类别
**永远无法被初始化**。两条都留了会红的回归钉子。

**补操纵链那一轮抓出的不是缺陷，是两个"假守卫"**（详见 14 §6.3.6）——
测试全绿，而它们其实守不住自己声称守住的东西：

- 门偏置的加注位置：挪到 sigmoid **之后**，68 项测试全绿。原因是原测试用的
  ±5.0 偏置在两种语义下都能跨过 0.5 阈值——**测的是「能翻转」，不是
  「在哪翻转」**。补了边界测试再跑同一个变异 → 红。
- 屏蔽与偏置的先后：变异"先屏蔽后加偏置"也全绿，因为 `-inf + 有限数 = -inf`，
  两种顺序**本来等价**。查下去才发现它在偏置为 `inf` 时分道扬镳
  （`-inf + inf = nan`，而 `nan` 胜过 `-inf`）——**那是个真洞：一份先验
  可以顶掉约束**。已在解码侧堵死（fail-closed），顺序侧留作第二道防线，
  并明说它**不是唯一那道**。

**这段的方法论比结论重要**：两个假守卫都是**变异测试**找出来的，
不是读代码读出来的。项目的纪律「它今天绿不算证明，能红才算」这次兑现了两次，
而且两次红都不是「代码写错了」，是「测试以为自己守住了、其实没守住」。

## 四个共用的设计选择

**一、量从 trace、累计计数器与审计日志取，不从环形缓冲取。**
`Environment.event_log()` / `event_notes()` 是 16 槽环形缓冲（12 §6 债务 10），
"跑完再遍历事件流"会**静默漏掉早期事件**。核对时它真的咬过一次：「跑完统计
`ENERGY_GAINED`」得到 0 次，而逐帧追踪显示第 10 帧确实 `grasp: +0.356 energy`。
所以有三个不丢的来源，**按问题选，互相顶替不了**：

| 来源 | 回答什么 | 不回答什么 |
|---|---|---|
| 逐帧 `Feedback` 增量 | 能量 / 伤害收支 | 事件类型分解 |
| `Environment.event_counts()` | 「这轮 grasp 成功了几次」 | 能量（`ENERGY_GAINED` 是**意图值**）；`source_id` 维度 |
| `StructureStore.audit_log()` | 提案与版本切换的明细 | 运行期的任何量 |

`event_counts()` 是 2026-09-27 加入的（只增不减、不截断），正是为补这个洞。
**但它与逐帧求和不是一回事**：它数的是**事件**，而 `push` / `pull` /
基础代谢的耗能**根本不发事件**（`ENERGY_LOST` 至今没有生产者），
所以"总能量支出"只数事件**一定漏**。要能量收支就用 trace 上的 `Feedback`。

**二、每个数字都必须能被人复跑。**
`run_episode` 的种子与帧数是显式参数，且 `torch.manual_seed` 在**构造任何对象
之前**调用——门控开不开由随机初始化决定（12 §4.3），种子的位置换一下就是
另一场抽奖。

**三、分母为 0 的指标必须主动造分母。**
自然运行下驳回率是 0，于是「失败回滚率」「被驳回提案对应的行为未改变率」
两个指标的分母是 0。0/0 最容易被写成 100% 然后当成机制有效的证据。
[`_injection.py`](_injection.py) 就是为这两列存在的。

同一件事在指标侧的落法：**算不出来时返回 `None`，不返回 1.0 也不返回 0.0。**
`hazard_avoidance_rate` / `mean_nearest_hazard_distance` /
`energy_change_between_windows` 都是这样——"没有危险源可见"不是"躲得极好"，
"没发生过版本切换"不是"固化没有效果"。跨 seed 聚合用
`mean_defined()`，它把 `None` 跳过并**把分母一并返回**，
逼调用方把分母打进输出。`print_table` 遇 `None` 就打 `None`——
那不是缺陷，那就是结论。

**三之二、「没有仪器」与「读数为 0」必须分开。** 实验 2 的对照组
（`ZeroMemoryRetriever`）没有 `stats` 属性，而实验臂有。若在采集时写
`getattr(retriever, "stats", MemoryStats())`，对照组就会长出一份**全 0 的统计**，
于是「记忆关着」与「记忆开着但一次都没触发」在输出里**长得一模一样**——
而这两个结论相反。所以 `_memory_stats()` 对没有仪器的检索器返回**空字典**，
`EpisodeResult.memory_instrumented` 用「字典非空」判有没有仪器，
`exp2` 的明细表把对照组的格子打成 `-` 而不是 `0`。

**三之三、机制读数与行为读数要分两档比。** 实验 2 里，记忆检索出来的条目
喂进隐状态，所以它**一定**扰动轨迹；问题是扰动走不走到粗粒度行为上去。
脚本因此比两档：**记忆门决策改变了几成 seed**（灵敏）与
**帧数 / RUN / 可编译段改变了几成 seed**（迟钝）。实测是 2/8 与 1/8。
只看粗粒度那一档会把「机制接上了但推不动」读成「机制没接上」——
**这两句话的输出是一样的**，而它们指向完全不同的下一步。

**本节的判断已被 2026-09-28 的逐帧实测确认，而且比这里写的更极端**：
两臂动作在 **5/8 个 seed 上不同**（变化 seed 内 56–99% 的帧不同，中位幅度 3.5e-4 ~ 1.8e-3）——不只是门决策那一档，
连动作本身都在变，**只有 5 个整数组成的粗粒度签名看不出来**。
所以「粗粒度那一档」不只是迟钝，它**在增益为 1e-3 量级时等于失明**。
教训落到判据选择上：**先量一遍机制的作用幅度，再挑判据的分辨率**；
反过来（先挑判据再看结果）会把「量不出」读成「没有」。

**四、全轮累计归 `Environment`，窗口内的统计归 harness。**
两处都做会得到两个会漂移的真相，所以分工划死：

- **`Environment.event_counts()`**——自构造或上次 `reset()` 以来的**全轮累计**，
  O(1)，免疫截断。注意它对 `reset()` **是归零的**（`FastLoop.__init__` 就会调
  `reset()`），所以 8-seed 循环里各轮总计**不同**才是对的；看到单调递增，
  就说明计数器活过了 `reset()`。
- **`count_events(trace, event_type)`**——**给定窗口内**的计数，按 `event_id`
  去重。去重治的是**重复计数**（观测里带的 `events` 是滚动窗口，同一个事件会
  连续出现在十几帧里），治不了**窗口外**——这正是它和上面那条的分界。
- **`energy_by_version_window(trace)`**——按 `StepRecord.context_fingerprint`
  切开的能量收支，**实验 3 的「能量消耗变化」必须用它，不能用全轮累计**：
  不切版本，固化**前**的消耗会永远留在分子里。切法照
  `plasticity._current_window`，那里记着不切窗口的实测代价（三轮睡眠把
  `memory_gate_threshold` 从 0.5 一路推到下界 0.15——「不是『收敛到合适的阈值』，
  是『撞到夹子』」）。**同一个错法在能量指标上会重演一遍。**
  差分由 `energy_change_between_windows(trace)` 给（末窗口 − 首窗口），
  **窗口不足两个时返回 `None`**。
- **`hazard_frames(trace)`**——`(危险源可见的 RUN 帧数, 其中受损伤的帧数,
  最近危险源距离之和)`。危险回避率的**唯一实现**（`run_episode` 与测试都调它），
  读的是逐帧 `observation`，不经事件流，所以没有环形缓冲那个洞。

派生量挂在 `EpisodeResult` 上：`energy_gained` / `energy_spent` / `damage_taken`
（逐帧现加）、`hazard_visible_frames` / `hazard_contact_frames` /
`nearest_hazard_distance_sum`（同样逐帧现加）、`event_totals`（尾部取一次）、
`net_energy_change` / `energy_spent_per_run_frame` / `hazard_avoidance_rate` /
`mean_nearest_hazard_distance`（属性）。三条能量口径写在
[`_harness.py`](_harness.py) 的模块 docstring 一之二里，**别在各脚本里各定一套**：

1. 分母是 **RUN 帧数**，不是 `len(trace)`——睡眠帧每帧**涨** 0.01 能量，
   用总帧数归一化会让"睡得多的回合"显得**更省**。
2. `energy_spent` 是**毛支出**，睡眠期的恢复不抵消它；净额另给。
3. 取的是**夹取后的「实现增量」**，不是「请求增量」。由此有一条**已知偏低、
   不是 bug**：6 处 `max(0.0, ...)` 与 damage 的 `min(max_damage, ...)` 都在
   丢弃超调，而死亡帧恰是消耗峰值帧。报告里注明，别当测量误差去"修"。

## 本次实验发现的守卫缺口

这些不是违规，是**没人检查过**。「没人检查过」与「检查过没问题」是两件事，
所以记在这里。

### 一、`Action` 通道内部的 str 字段从未被静态检查

`tests/test_protocol_consistency.py::TestNoNaturalLanguageInLoop` 的白名单是
在 `Observation, Feedback, EventVector, MemoryItem` 上算的；
`test_action_has_no_string_command_field` 只查 `Action` 的**顶层**字段名
（六个通道名）。

于是 `Action` 六个通道**内部**的 str 字段从来没被检查过：

| 字段 | 所在通道 | 实际装的是 |
|---|---|---|
| `Manipulation.target_id` | manipulation | 对象 id——**名字** |
| `Manipulation.operation` | manipulation | 操作码——**名字，须取自闭集** |
| `Communication.target_id` | communication | 对象 id——**名字** |
| `SkillCall.skill_id` | skill_call | 技能 id——**名字** |
| `SelfModification.proposal_type` | self_modification | 提案类型——**名字，须取自闭集** |

实测它们确实都是名字，所以**不是违规**。`experiments/_harness.py` 的
`IDENTIFIER_FIELDS` 把这四个补进了白名单。

### 二、光有字段名白名单不够，操作码必须查闭词表

补完字段名之后仍然有一个口子：只按字段名放行的话，`operation` 就成了一个
**"可以往里写任何字符串"**的字段——而"可以往里面写任何字符串"正是正文的入口。

所以 `_harness.py` 的 `count_strs_deep` 加了一层：标识符允许出现，但取自
闭词表的那些（`operation` / `proposal_type`）**必须命中** `OPERATIONS` /
`ALLOWED_PROPOSAL_TYPES` 才算名字。

名字与正文的分界就在这里：**名字取自闭集，正文不是。**

第一次跑实验 1 时这条检查报了 670 次越界，全部来自上面五个字段。
补完字段名白名单 + 闭词表之后是 **0**。

### 三、Verification Gate 后三级的注入样本还是空的

`_injection.py` 的六条攻击打中的层是：

```text
plasticity.scope  ×3      gate.format  ×1
plasticity.clip   ×1      store.commit ×1
```

**`gate.sandbox` / `gate.regression` / `gate.env_test` 三级没有注入样本。**
实验 6 里 18 条自然提案全部四级通过，所以那三级在"自然 + 注入"两个来源上
都没有拒绝记录。它们的拒绝能力目前**只有测试覆盖，没有实验覆盖**——
补法见 12 §6 债务 6b 之后的待办。
