# 05 · 名词表

**用途**：统一 SSEA 文档与代码里反复出现的术语。它只回答两件事——
**这个词在本项目里是什么意思**、**第一次/权威地出现在哪里**。

本表**不复述设计、不重抄公式**。设计在 [03-architecture-spec.md](03-architecture-spec.md) 里，
公式在代码里。「出处」一栏指的是**权威处**：有分歧时以那里为准，不要以本表为准。

**怎么用**：读文档撞见一个拿不准的词 → 查这里 → 跳到出处那一节读全。
反过来，写文档时想造新词 → 先查这里有没有现成的。

**维护纪律**：术语的含义若在某次增量里变了，**改的是出处那一份**，然后回来改这一行。
本表不产生新含义，也不做裁决。本表里没有的词，不代表不能用，只代表它还没被反复用到值得登记。

## 一、架构骨架

| 术语 | 意义 | 出处 |
|---|---|---|
| 双环 / 双环架构 | SSEA v0.3.1 的整体形状：慢环负责经验编译与演化，快环负责实时控制，两者不共享控制权 | 07 §5.3「双环关系」 |
| 快环 / FSL | Fast Survival Loop。逐帧跑感知 → 决策 → 行动 → 反馈的那一环，是**控制闭环**。低算力低带宽（C4）主要约束在这里 | 07 §5.1、08 §4.1 |
| 慢环 / SEL | Slow Survival Evolution Loop。整理经验、提结构提案、过验证门的那一环。睡眠期是它的一等公民状态（RUN → SLEEP → WAKE → RUN） | 07 §5.2、08 §4.2 / §4.3 |
| 结构注入面 | 双环之间**唯一**的交换通道：慢环发布结构新版本，快环读取不可变快照。**快环不反向写** | 08 §2.1「双环注入接口 —— Structure Injection Surface」 |
| 结构快照 | 快环每帧看到的那一份只读结构，实现为 `FastLoopContext`。字段注解是 `Mapping[...]`，且 store 侧按槽深拷贝 | 08 §2.1、`SSEA/sse_protocols/fast_loop_context.py` |
| 结构类别 | 快照里可被慢环替换的五类内容：`skills` / `rules` / `adapters` / `thresholds` / `retrieval` | `SSEA/sse_protocols/structure_store.py` 的 `STRUCTURE_KINDS` |
| 结构管理面 | `SSEA/sse_protocols/` 整个包。它**知道全部五个类别**（建档、校验、提交都要遍历它们），因此**不能**用来判定某个类别有没有消费者 | 14 §6.3.7 设计点二 |
| 遗传面 | 基因包 `GenePackage` 那一条线：权重 / 记忆 / 技能三分离里可保存、可恢复、可变异、可继承的那一面 | 07 §9 |
| 四权分立 | 「提什么」`ExperienceCompiler` / `LocalPlasticity` → 「在不在边界内」`PlasticityController.allowed_scope` → 「能不能安全应用」`VerificationGate`（不打分）→ 「应用不应用」`StructureStore.commit`。四件事四个部件，任何一个都不许兼第二职 | 14 §2.4 |
| 观察员面 | 自然语言所处的位置：**只能观察，不进入控制闭环**。语言模块不可被模型自己修改 | 07 §7.2、07 §17 |
| 承重 | 某个读者 / 某条断言**撑着另一件事**，动它会连带压塌别处，因此不能按字面处理。例：`verification_gate.py` 是 `rules` 唯一的静态命中，但它读的是「在不在边界内」，**不是消费** | 14 §6.3.7 设计点二 |

## 二、守卫词汇（2026-09-28 新增）

| 术语 | 意义 | 出处 |
|---|---|---|
| 消费者 | **读结构、并因此改变自己行为的代码**。四个「不是」：不是名字被提及、不是管理面的遍历、不是有调用方、不是「读过一次」。判定要问「读了之后哪一行行为变了」 | 08 §2.4（修订依据）、`SSEA/sse_protocols/action.py` 模块 docstring（约束原文）、14 §6.3.7 |
| 调用方 | 谁调用了这个方法。**调用方 ≠ 消费者**：`get_threshold()` 曾有调用方，但读出来的值不影响任何行为 | 14 §6.4 线 D 第 13 项 |
| 死类别 | 五类结构里**没有任何控制环路代码读它**的那一类。当前 `rules` 是唯一一个 | `tests/test_consumer_surface.py` 的 `NO_CONSUMER_YET` |
| 空转 | 机制在跑、测试全绿、提案 → 门 → Store 一路通过，但**对行为毫无影响**。本项目反复咬到的坑的统称 | 14 §6.3.7、12 §6 债务 17 |
| 假守卫 | 名字像守卫、实际**为它名字所指的缺陷红不了**的断言。三例：`test_channels_all_have_consumers` 只断言 `Action.CHANNELS` 元组，一个消费者都不查（已改名 `test_channel_names_are_the_documented_six`）；`test_precondition_records_starting_energy` **名字是对的**，但夹具三条记录 `body_energy` 恒为同一个数、`energy_change` 恒为 0，于是「起始能量」与「首帧动作后能量」**是同一个数**；`test_compiled_skill_is_invocable_by_the_runner` 只走到 `submit()`，**三道闸全在 `report()` 里**，所以它**在结构上不可能为可重放性变红**——它没问过那个问题（注意：这不是说它绿得假，是说它**没问**） | 12 §6 债务 17、**债务 26**、14 §6.3.7 |
| 名不副实 | 断言 / 文档的名字与它实际做的事不符。本项目认定这是**病**，不是措辞问题 | 12 §6 债务 17 |
| 盲区 | 静态扫不到的读者。当前唯一一处：`plasticity._current_value()` 用 `getattr(structure, kind, None)` 的**计算名**取值，AST 看不见。守卫的做法是**把它显式登记**（`DYNAMIC_READERS`），而不是假装它不存在 | `tests/test_consumer_surface.py` 的 `TestTheBlindSpotStaysDeclared` |
| 登记表 | 声明式清单，形状照抄项目的 `DEFERRED_DELTAS` / `DEFERRED_SCOPES`。**双向断言**：没消费者的必须登记，登记了的若长出消费者也要失败——逼人移出登记，不让清单烂掉 | `SSEA/experience_compiler.py` 的 `DEFERRED_DELTAS`、`SSEA/plasticity.py` 的 `DEFERRED_SCOPES`、`tests/test_consumer_surface.py` |
| 「今天绿不算证明，能红才算」 | 验证纪律：一个守卫只有在**人为造出它要防的那个缺陷时确实变红**之后，才算被验证过。绿的守卫可能什么都没查 | 14 §6.3.6（记录处） |
| 「名字是标签，作用点是内容」 | 判断「某个东西有没有被用上」时，看的是**作用点**（值流到哪里去了），不是名字出现在哪里。文本扫描会把 docstring 里的提及和裸字符串 `"rules"` 当成读者，所以守卫用 AST | 14 §6.3.7 设计点一 |
| 缺陷的五种来路 | 本项目迄今的缺陷按**怎么被发现的**分五种：**读出来的**（读代码时看见）、**变异出来的**（人为造缺陷看守卫红不红）、**改别处撞出来的**（改 A 时 B 抛异常，兜底分支顶替它干活）、**工具失效反向撞出来的**（探针什么都没收到，第一反应是探针写错，真相是被测对象根本没被用上）、**两条通路对不出来**的（把两条各自都说得通的通路并排放在同一份 trace 上对）。**前四种都在一条通路上找问题**，第五种要求**有第二条通路可比**，所以它躲得过测试、变异与逐层实读 | `README.md`「已修」段、12 §6 债务 20 与 26 前的引语 |
| 第四种来路 | 见「缺陷的五种来路」。**工具不工作时，先怀疑被测对象，再怀疑工具** | 12 §6 债务 20、`README.md` |
| 第五种来路 | 见「缺陷的五种来路」。**一处单看没错的代码，只有在「这两者是不是在量同一件事」被问出来之后才现形**。首例是 `precondition` 记录状态（说得通）× `SkillRunner` 拿它当闸（也说得通） | 12 §6 **债务 26**、16 §3.3 |
| 约定只读 vs 结构事实 | **约定只读**＝文档说别写，写下去照样成功；**结构事实**＝写下去抛异常。`frozen=True` 只挡重新绑定，**不挡改字段内部**——所以 `ctx.thresholds["x"]=1` 曾是静默成功的。改法是 `MappingProxyType` | `SSEA/sse_protocols/fast_loop_context.py` 模块 docstring |
| 顶层只读 vs 深度不可变 | **顶层只读**＝那一层 mapping 本身不可写；**深度不可变**＝里面嵌套的每一层都不可写。`MappingProxyType` **是浅的**，所以本项目只声称前者。声称后者会是假话——而 `retrieval` 恰好是**扁平策略**，顶层只读对它就是全覆盖，这正是删掉 `get_retrieval_policy` 那个深拷贝的理由 | `SSEA/sse_protocols/fast_loop_context.py` 模块 docstring（边界声明） |
| 死分支 | 因为判断条件**永不成立**而从未执行过的代码路径。危险处在于它**不报错**——真正干活的是兜底分支，而死分支上挂着的类型标注被静默丢弃，测试照样全绿 | 14 §5.3（第三例）、12 §6 债务 19 |
| 无生产者的事件类型 | 登记在 `EVENT_TYPES` 里、**却没有任何代码发出它**的类型。`event_counts()[T]` 因此**恒为 0**，而这个 0 读起来完全正常——会把「调用了几十次、每次都失败」报成「一次都没调用过」。当前有五个：`ENERGY_LOST` / `SKILL_SUCCESS` / `SKILL_FAILURE` / `SELF_MOD_APPLIED` / `SELF_MOD_ROLLBACK`。**「从计数器读到 0」与「没发生过」不是一回事，除非那个计数器有生产者** | `tests/test_environment.py::test_event_counts_name_the_producerless_types`、`experiments/README.md` |
| 假值判空 | 用 `x or default` 判「传了没有」。**定义了 `__len__` 的实例长度为 0 时是假值**，于是传进来的对象被静默换成 `default`，调用方的引用从此指向一个不在环里的对象。行为恰好相同，所以测不出来——**必须断言身份，不能断言行为** | 12 §6 债务 20、`SSEA/fast_loop.py` |

## 三、裁判标准（C 系列）

| 术语 | 意义 | 出处 |
|---|---|---|
| C1–C10 | 十项裁判标准，用来在模糊地带做裁决。**裁决从 SSEA 立场推导，不套业界默认做法** | 07 §8（逐条） |
| C4 | 低算力、低带宽。控制环路上的缓冲不无界增长——所以观测问题不靠调大 `max_events` 来修 | 根 README 项目目标、07 §5.1 |
| C8 | 给基因先验，不给知识语料。**先验**指「怎么学」的偏置，不是「学什么」的内容 | 03 第九节 |
| C9 | 只有淘汰函数，没有评分函数。环境**不给行为打分**，只决定活不活。所以「接近资源给分」这类奖励塑形直接违规；验证门也一视同仁，不比较两个提案谁更好 | 01 原始构想、07 §8.9 |
| 基因先验 | 见 C8。形式上可以是一段权重（`adapters` 里的 4×2 矩阵）、一个阈值、一条初始规则 | 03 第九节、08 §3.4 |
| 本能 | **被反复验证后压缩成权重形式的行为先验**。它住 `adapters`（可遗传、可变异、过验证门），**不住权重初始化**——后者不可继承、不受 C8 保护 | 08 §3.4、03 第九节 |
| 知识语料 | 外部喂进来的「学什么」的内容。C8 明确不给 | 03 第九节 |

## 四、测量纪律

| 术语 | 意义 | 出处 |
|---|---|---|
| 分母为 0 | 指标无定义时的正确返回值是 `None`，**不是 1.0**。0/0 写成 100% 是本项目反复出现的失败形状（实验 6 / 7） | 14 §5.2、`experiments/README.md`「三」 |
| `mean_defined` | 跨 seed 求均值时跳过 `None`，并把**分母**（有几个 seed 真的有定义）一并返回。分母必须打进实验输出 | `experiments/_harness.py` |
| 毛支出 vs 净额 | `energy_spent` 是**毛支出**：负增量取绝对值求和，睡眠期的恢复**不抵消**它 | `experiments/_harness.py` 模块 docstring |
| 实现增量 vs 请求增量 | 取的是夹取后的**实现增量**（`Feedback.energy_change` 实际生效的那部分），不是 agent 请求的增量。它已知偏低，**不是 bug，不得当测量误差去"修"** | `experiments/_harness.py` 模块 docstring |
| 直接成功 | 单帧层面的成功判据，定义在 `SSEA/skill_library._is_direct_success`。判据**只有一份**——抄第二份必然漂移，漂移的表现是「脚本说能编译、编译器说不能」 | `experiments/_harness.py` 的 `success_run_lengths` |
| 可编译段 / 连续正收益段 | 连续 ≥ `min_frames`(3) 帧的「直接成功」段。它是本能作用的**验收判据**，不是存活帧数——**活得久不等于学到了东西**（实测寿命 67 → 72 帧而可编译段仍是 0） | `experiments/_harness.py` 的 `success_run_lengths`、`SSEA/experience_compiler.py` |
| 逐位相同 | 对照组保真的判据：关掉机制时行为必须与改动前**逐位（bit-for-bit）相同**。对照组不是「另一个实现」，是同一段代码的机制项为 0 | 14 §6.3.6 |
| 顺序不变性 | 全套件在 `pytest-randomly` 的多个 seed 下结果必须一致。**不是形式主义**：门控约一半 seed 恒闭正是随机初始化造成的，「任何未固定 seed 的门控实验结论都是抽奖」 | `requirements.txt`、`tests/conftest.py` |
| 机制数字 vs 对照组数字 | 机制数字 = 「这条路径能走通」；对照组数字 = 「开与关的差别有多大」。**只有机制数字的项目，等于证明了「代码是任务书的忠实实现」，没证明「架构有效」**。实验 2 / 3 是仅有的两条带对照的，它们给出了第一组对照数字（2026-09-28），而**它暴露的是判据的分辨率不够**（见下条「尺子」） | 12 §4.2、14 §5.2 |
| 尺子 | **量不出差的时候，先怀疑尺子。** 尺子有两种坏法，**修法完全不同，不要合并成一句「判据不行」**（2026-09-28 拆开） | 12 §4.2、14 §5.2、16 §3.1 |
| 尺子坏法一：**太粗** | **分辨率低于效应幅度**。此时「没有差别」与「量不出差别」的输出**完全一样**。实例：exp2 的 `coarse_signature` 是 5 个整数，而记忆对动作的扰动中位只有 ~1e-3——投影到整数上就没了（12 §6 债务 21）。修法是**换更细的尺** | 12 §6 债务 21、14 §6.3.8、`experiments/exp2_memory_recall.py` 的 `coarse_signature` |
| 尺子坏法二：**量错了东西** | 尺子本身有分辨率，但**量的不是要判的那件事**，于是两条通路**互不蕴含**——A 通不过不能推出 B 通不过，反之亦然。实例：exp3 编译判据是窗口内 `energy_change` 的**积分** > 0（从不看水平），重放闸 1 是某一帧的**绝对水平**对比一个冻结的数（从不看窗口总量）。**换更细的尺没有用，得换判据**（12 §6 债务 26） | 12 §6 债务 26、16 §3.3 |
| 描述被当判据 | **尺子坏法二**的具体形状：一个**记录观测情境**的字段（`precondition`），被读成了**准入门槛**。「这条技能当时站在哪里」与「这条技能需要什么」**被当成了同一句话**。危险处在于**单看每一处都说得通**——只有把两条通路并排放在同一份 trace 上对，它才现形 | 12 §6 债务 26、`SSEA/skill_runner.py` 的 `_precondition_holds` |
| 措辞债 | 代码写对了、**正文名不副实**的那一类缺陷。与「假守卫」同源但落在文档上：`coarse_signature` 的 docstring 写着「粗粒度行为」，而四份文档把它读成了「两臂逐位相同」。**它比代码 bug 难发现，因为没有红灯** | 12 §6 债务 21、14 §6.3.8 |
| 饱和（指标饱和） | **第三种坏数字**：率算对了、分母也不是 0，但**分母上的机会太少**，于是率被顶到接近 1 或 0 并卡在那里——看起来漂亮，实际量不出任何差别。判据是**看底下的原始计数**：默认世界 336 个危险暴露帧上只挂了 6 次接触，一次接触就够让一个 seed 的率跳几个百分点。**一个饱和的率不能当证据，哪怕是两臂一样的 0.9814** | 14 §6.3.8（「第三种坏数字」的定义处）、§5.2、`experiments/README.md` |
| 通路通电 / 通路断电 | 单个 seed 层面「机制到底有没有被调用过」的读数：**通电** = 那个 seed 上机制确实开过（如记忆门的写请求 > 0），**断电** = 一次都没开。**断电的 seed 是双峰现象的证据，不是缺陷，也不得剔除**——剔掉就等于把「约一半 seed 恒闭」这个事实从分母里洗掉 | `experiments/exp2_memory_recall.py` 的输出与判读须知 |

## 六、本表自身的边界

- 本表**只登记反复出现的词**。一次性用词（某次增量里的临时叫法）不进表——进来会让表变成词典。
- 本表**不含代码标识符的完整清单**。要看五类结构、六通道、访问器有哪些，读
  `STRUCTURE_KINDS`、`Action.CHANNELS`、`FastLoopContext` 本身；那些是**可执行的真话**，
  抄进文档就会漂移。本表只在术语需要时才指向它们。
- 本表**不裁决模糊地带**。裁决在 07 §8 的 C 系列与 14 §2.4 的四权分立里。
