## 1. 一句话定位

- **论文主张**：把「多步信息检索」建模为 DAG 构建（code-as-planning），WebPlanner 分解子问题、多个 WebSearcher 并行分层检索，闭集/开集 QA 优于单轮 RAG 与 ReAct，3 分钟可读 300+ 网页。
- **对 SSEA 的意义**：**不适用**——它是「冻结 LLM + 搜索引擎」的生成式检索框架，控制环完全由自然语言 token 驱动，与 SSEA「非语言、以生存为组织原则」无回溯路径；仅作「搜索/深研族」对照臂。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
复杂意图无法一次检索完成；相关信息散落海量含噪网页；网页总长超出 LLM 上下文。既有方案把检索-整合当作 vanilla RAG，检索深度与问题分解不足。

### 2.2 核心思想
1. **planning as graph construction**：解题轨迹写成 DAG `G(Q)=⟨V,E⟩`，节点=可并行搜索的原子子问题，边=推理拓扑关系（§2.1）。
2. **code as planning + 角色分工**：用 Python 代码调用图 API 统一动作空间、借解释器报错自纠错；Planner 只看摘要、每个 Searcher 只处理自己子查询，天然做长上下文管理（§2.1–2.3、附录 E.1）。

### 2.3 关键机制 / 算法（可搬运零件清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| WebPlanner DAG 规划 | 用户问题 → 子问题节点图 + 响应节点 | 分解 + 编排 | §2.1, Fig.2 |
| 代码执行协议 + 异常回灌 | 错误代码 → 异常 → 重生成 | 运行时自纠错 | 附录 E.1, Fig.7 |
| WebSearcher 分层检索 | 子问题 → 摘要 | 4 步：query rewrite→聚合→选页→总结 | §2.2, Fig.3 |
| 多查询聚合 MQG / 前缀上下文 PPC | 子问题 → 多路查询去重；父/根响应 → 子代理输入 | 提召回 + 跨代理传上下文 | §2.2–2.3, Table 3 |
| 「未找到」/放弃节点 | 搜索失败 → not found / response | 避免死循环 | 附录 E.2, Fig.8/9 |

数据结构：`WebSearchGraph` = `nodes: Dict[str, Dict]` + 邻接表 `Dict[str, List[str]]`，节点含 content/type/thought/前驱列表，另有 START、END/response 特殊节点（附录 G）。

### 2.4 实验证据
| 任务 / 基准 | 对照基线 | 关键数字 | 统计口径 |
|---|---|---|---|
| 闭集 QA | w/o Search / ReAct | GPT-4o 59.8/55.1/53.5；InternLM2.5-7b 49.2/42.9/28.9（AVG） | Table 1，零样本 |
| 开集 QA | ChatGPT-Web、Perplexity Pro | 100 条人工查询、5 名专家投票；depth/breadth 领先，facticity 70% vs breadth 83% | §3.1, Fig.4 |
| 消融 | WebPlanner：—/ReAct/CodeAct/Ours；WebSearcher：w/o MQG/PPC/PS | 37.6/58.0/61.3/64.0；60.6/63.3/58.0 | Table 2/3，HotpotQA |
| 时间 / 泛化 | 人类标注者；换 3 模型 | 10 题 19h17min vs 23 min；300+ 页 < 3 min；DeepSeek-V2 69.6 / Qwen2.5-7b 57.6 / GLM4-9b 60.0 | 附录 B、D |

### 2.5 论文自陈局限与边界
假设依赖 LLM 强代码/规划能力、搜索引擎与网页文本可得；不足：引用质量未系统评估、不支持视觉输入、不能与网页交互、长上下文不足致幻觉（facticity 70% < breadth 83%）（§3.1.2、§5）。

## 3. SSEA 立场对齐

### 3.1 C1–C10 映射（短卡主要价值）
| 裁判标准 | 判定 | 依据 | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | ✗ | 控制环 = LLM 生成代码/文本 + 搜索引擎，无生存信号 | 不可改造；仅作「语言生成架构」反例 |
| **C2** 自然语言只作观察员接口 | ✗ | thoughts 直接驱动 DAG 构建与检索动作，语言在控制闭环内 | 若借用，须把图规划降为观察面 |
| **C3** 权重/记忆/技能三分离 | — | 无记忆/技能概念；图是单次会话内临时结构 | 不适用 |
| **C4** 低算力低带宽 | ✗ | 多次 LLM 调用 + 300+ 网页全文入 context；每问 3.2 次搜索（附录 C.2） | 与 SSEA 低带宽控制环相悖 |
| **C5** 精准回忆历史 | ◐ | 仅会话内「父/根前缀」传上下文，非可检索/可遗忘外置记忆 | 只可借局部上下文传递思想 |
| **C6** 可自主修改自身 | ◐ | 「代码执行→异常回灌→重生成」自纠错属运行时错误恢复，非改自身代码/权重 | 可借「解释器即校验器」形状，无四权拆分 |
| **C7** 保存/恢复/变异/继承 | — | 无 GenePackage、无跨代机制 | 不适用 |
| **C8** 给基因先验，不给知识语料 | — | 依赖冻结 LLM 参数 + 外部网页知识 | 不适用 |
| **C9** 不设评分函数，只有淘汰函数 | ✗ | 用 GPT-4o 主观打分、人工投票选最优，属外部评分 | 与 C9 直接冲突 |
| **C10** 创新在 L2/L3/L4 | — | 贡献是 L2 级代理编排的工程组合，未声明 L3/L4 | 不适用 |

### 3.2 L1–L4 定位、模块映射与实验对应（3.2–3.4）
L1 全部借用冻结 LLM；L2 提供 Planner/Searcher 分工 + DAG + 上下文前缀（唯一可对照处：外部检索的信息流编排）；L3 零样本无训练；L4 无。模块落点：DAG 子问题图无直接落点，仅作对照臂；解释器校验 + 异常回灌与四级验证门「格式/沙盒」形似，但只验代码合法性。已知债务：**无**一条被回应；可作实验 2「判据形状」的**反面参照**（LLM 投票选优 = C9 违规判据）。

## 5. 冲突、代价与风险

- **与硬约束的冲突 / 代价**：C1/C2/C4/C9 全 ✗（语言进闭环、算力高、外部评分）；每问多次 LLM 调用 + 300+ 页全文入 context，与低带宽控制环相反。若把「LLM 图规划」搬进控制环，立即违反 C1/C2/C4。
- **为何仍保留在论文池**：它是「搜索/深研族」代表实现，为「外部检索如何组织」与「LLM 投票式判据」提供对照与反例。

## 6. 组合分析

- **6.1 关系图谱**：对照—与 `ReAct`、`Self-RAG`、`Search-R1` 同族；互补—与 `Memento`/`FLEX` 记忆侧**无接口**（本篇无持久记忆）；替代—可替代「单轮 RAG」检索流程。不推荐与 SSEA 组件组合（无接口、立场冲突）。
- **6.2 本篇角色**：**外部检索族对照臂**——为「判据不该是 LLM 投票」提供反例（对照 `HarnessEval` 判据健康度）。
