## 1. 一句话定位

- **论文主张**：不存原始轨迹，而是用教师模型把成功轨迹蒸馏为**可复用策略原则**、把失败轨迹压缩为**简洁失败教训**，组织成两层技能库 SKILLBANK（常驻 general + Top-K 检索的 task-specific），再用 GRPO 训练「会用技能」的策略，并在每个验证轮次后按失败模式**增补/修订技能**，使技能库与策略共演化（p1–4）。
- **对 SSEA 的意义**：它是**「经验编译器 → 技能固化」这条链上最完整的一份工程形状说明书**——尤其给了 SSEA 目前完全缺失的**慢环回顾编译的触发条件与预算配额**（多久一次、每次看多少条失败、最多产几条技能）；但它把自然语言技能直接塞进控制闭环、并用外部奖励训练权重，触犯 C1/C2/C4/C9，只能拆零件不能整体搬。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- **问题设定**（§2 p2）：LLM agent 在交互环境 E 中按 POMDP 式采样，策略 π_θ(a_t | o_≤t, d, c)，目标 max_θ E[Σγ^t r_t]，且受**上下文长度约束 |c| ≤ L_max**。任务由自然语言描述 d 给出。
- **它指出的既有方案缺陷**（p1–2）：
  1. 基于记忆的方法把**原始轨迹**直接入库，冗长、冗余、噪声大，模型难以抽取关键信息；
  2. 这些方法「只是模仿过去的解」，**没有蒸馏出核心原则**，也没有让策略学会利用记忆；
  3. 如 Figure 1(a) 灰色虚线所示，**失败轨迹被丢弃**（"store raw trajectories and discard failures"），损失了只能从失败中学到的边界条件信息。

### 2.2 核心思想（关键 insight）
1. **有效经验迁移需要抽象，而非记忆**（p2）：人类专家不记每个动作，而是形成 compact、reusable 的 skill。
2. **成功与失败要差分处理**（§3.1 p3）：成功轨迹抽「导致完成的策略模式」；失败轨迹不能直接进上下文，要合成为**反事实式的失败教训**（失败点 / 错误推理 / 本应怎么做 / 通用预防原则）。
3. **技能库是动态部件而非静态知识源**（§3.3 p4）：策略变强 → 进入新状态区域 → 遭遇旧技能覆盖不到的情形 → 从验证失败中造新技能 → 进一步提升，形成 virtuous cycle。
4. **先教「怎么用技能」再进 RL**（cold-start SFT，p4）：直接把技能塞给未改动的模型收益有限，需要一段演示微调。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）

| 零件 | 输入 → 输出 | 作用 | 出处（节/式/图） |
|---|---|---|---|
| **成功轨迹蒸馏** s⁺ = M_T(τ⁺, d) | 成功轨迹 → 技能条目 | 抽关键决策点、正确动作理由、可迁移模式 | Eq.2 §3.1 p3 |
| **失败教训合成** s⁻ = M_T(τ⁻, d) | 失败轨迹 → 反事实教训（4 要素：失败点 / 错误推理 / 应有做法 / 通用原则） | 把冗长失败变成可进上下文的高密度信息 | Eq.3 §3.1 p3 |
| **两层 SKILLBANK** S = S_g ∪ (∪_k S_k) | 蒸馏产物 → general（跨任务：探索、状态管理、目标跟踪） + task-specific（按任务类别 k 组织） | 常驻通用层 + 按需检索专用层 | §3.2 p3 |
| **技能三元组** | — | `name`（3–5 词） + `principle`（1–2 句可执行模式） + **`when to apply`**（适用条件） | §3.2 p3；Prompt B.1 p13 |
| **分层检索** S_ret = TopK({s∈S_k : sim(e_d,e_s) > δ}, K) | 任务描述 d → Top-K 技能；**general 无条件常驻** | 降低 token 占用、提高推理效用 | Eq.4–5 p3；K=6、δ=0.4 p5/p14 |
| **Cold-start SFT** θ_sft = argmin L_CE(D_SFT; θ) | 教师生成 N 条「技能增强推理轨迹」 → 微调 base | 让 base 学会检索/解释/应用技能；同时作 π_ref | Eq.6 §3.3 p4；7,500（ALFWorld）/2,400（WebShop）条 p14 |
| **递归演化触发** | 每验证轮统计各类别成功率 Acc(C)，**仅当 Acc(C) < δ** 才触发该类别演化 | 定向增长，避免全局无差别膨胀 | §3.3 p4；δ=0.4 p14 |
| **多样性感知分层采样** | 失败验证轨迹 → 按类别分组 → 按失败严重度（负奖励）优先 → **round-robin 保类别熵** | 选哪些失败去分析 | §3.3 p4 |
| **教师增补/修订** S_new = M_T(T⁻_val, SKILLBANK) | 失败样本 + 现有库 → (1) 识别未覆盖失败模式 (2) 提议新技能 (3) 建议修订失效技能 | 库与策略共演化 | Eq.7 §3.3 p4 |
| **GRPO 策略优化** | 二元轨迹奖励 R_i = r(τ⁽ⁱ⁾) ∈ {0,1}，组内归一优势 A_i = (R_i − mean)/std | 用外部奖励更新权重 | Eq.8–9 §3.3 p4–5 |
| **完整流程** | 蒸馏 → 建库 → 冷启动 SFT → RL + 每验证轮演化 | 见 Algorithm 1 | p4 |

### 2.4 关键表示与数据结构
- **SKILLBANK**：两层集合 S_g ∪ (∪_{k=1}^{K} S_k)；每条技能为 JSON 结构 {skill id, title, principle, when to apply}，id 形如 `gen_001` / `hea_004` / `dyn_001`（动态新增以 `dyn` 前缀，p13）。
- **失败分类学**：与技能库并列的 error 表，每条 = {Failure Description, Root Cause, Mitigation}，形如 `err_001 Redundant Revisit`（Table 6 p15）、`err_004 Price Shift Oversight`（Table 8 p16）。**注意：这是结构化的失败-根因-缓解三元组，不是口头反思。**
- **蒸馏产物示例**（Table 5 p15）：`gen_001 Systematic Exploration`、`gen_014 Loop Escape Trigger`（连续 3–5 步状态无变化 → 切换搜索分支）、`gen_015 Pre-Action Sanity Check`（执行前确认前置条件：手空闲/容量/电源）等，每条都带明确 when-to-apply。
- **技能库容量轨迹**：初始 55 条（general 12 / task-specific 43）→ Step 150 时 100 条（12→20，43→80）（Fig.3 p7）。**论文未提及任何剪枝、合并、淘汰或遗忘机制。**

### 2.6 论文自陈局限与边界条件
- **论文未设专门的 Limitations 小节**（全文检索无 "Limitations"/"Future Work" 标题；结论节 §6 p9 只作正面总结）。以下为卡片从正文可确证的条件，非论文自陈：
- **假设依赖**：① 必须有一个**强教师模型** M_T（本文用 OpenAI o3）做蒸馏与 SFT 数据生成（p5、p13）；② 任务必须能给出**二元成功指示 r(τ)∈{0,1}**（GRPO 奖励的前提，§3.3 p4）；③ 任务需可按**类别 k 分组**以建 task-specific 层（§3.2 p3）；④ 环境为**文本交互**（ALFWorld / WebShop / 搜索 QA），观测与动作皆自然语言。
- **明确不适用的情形（推断，非论文声明）**：无类别结构的开放环境（task-specific 层无从建立）；无法给出二元成败判据的连续生存任务；算力受限场景（30h × 8×H100）。
- **结构缺口**：技能库**只增不减**（Fig.3 p7，55→100），无淘汰/合并/回滚；新增技能**入库前无验证**（Algorithm 1 line 29 直接 `SKILLBANK ← SKILLBANK ∪ S_new`）。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射

| 裁判标准 | 判定 | 依据（论文中的具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | **✗** | 优化目标是任务成功率与分数（ALFWorld 89.9%、WebShop 72.7%、QA 47.1%，Table 1–2）；环境中**无死亡/淘汰/能量约束**；策略输出是带 `<think>` 的自然语言推理再选动作（Fig.6 p9、Prompt A.1 p12） | 只搬「蒸馏-回顾-增补」的调度形状；**环境侧替换为 SSEA 生存域**，判据从成功率换成淘汰事件 |
| **C2** 自然语言只作观察员接口 | **✗** | 技能本身就是自然语言（`principle` + `when to apply`），并被**直接拼进策略上下文**参与动作选择：a_t ~ π_θ(a_t \| o_≤t, d, S_g, S_ret)（Eq.5 p3）；执行时推理链显式引用技能编号（"Per [hea_004] 'No Appliance Before Object'"，Fig.6 p9） | **语言只留在慢环编译面**：蒸馏输出必须再编译成结构化可执行物（动作序列 + 前置条件谓词），快环只读结构化快照；自然语言技能只能是编译中间产物，禁止入环 |
| **C3** 权重/记忆/技能三分离 | **◐** | 技能库确实外置于权重（SKILLBANK 独立于 π_θ）、原始轨迹与技能分层存放——符合分离；但**权重被大规模更新**（cold-start SFT + GRPO，Eq.6/9），且与技能库**耦合共演化**，三者生命周期不再独立（§3.3 p4） | 剥离 SFT/GRPO；Δθ 回归 SSEA 自身的内在驱动与结构提案通道；技能库维持独立生命周期与独立淘汰 |
| **C4** 低算力低带宽 | **✗**（训练侧）/ **◐**（推理带宽侧） | 训练侧：8×H100 80GB、RL 24h、合计 30h/实验（p14）；教师 o3 蒸馏（p5）。推理侧：检索把 prompt 从 ~1,450 降到 <1,300 tokens（−10.3%，Fig.4 p7）——这一侧**对 C4 友好** | 只搬推理侧与离线节律；训练侧完全不搬。蒸馏若需 LLM，限定在慢环睡眠期、按配额调用 |
| **C5** 精准回忆历史 | **◐**（有张力） | 论文立场**恰恰相反**：认为原始轨迹冗余有噪，主张用抽象**替代**记忆（p1–2）；失败教训保留的是反事实要点而非具体经历 | 蒸馏层只能作为**附加抽象层**，不得替代 episodic 精确记忆（Memento 侧）；原始经历仍需可精准写入/检索/回放 |
| **C6** 可自主修改自身 | **◐** | 技能库自主增补与修订（Eq.7 p4，教师提出 refine 建议）是自我修改；但**提案权在外部教师 o3**，且**无验证环节**——新技能 `S_new` 直接并入库（Algorithm 1 line 29），无边界权/验证权/应用权分离 | 新增/修订技能必须过 SSEA 四级门（格式→沙盒→回归→环境实测）才可进快照；提案权收归慢环编译器，应用权归 StructureStore |
| **C7** 可保存/恢复/变异/继承 | **—** | 仅涉及技能库**持久化**（代码开源、技能为 JSON 条目）；**未提及**变异、交叉、跨个体继承；库无淘汰机制，不构成达尔文闭环 | 无冲突亦无供给；若要用，需另接 HeritableFilter 判定哪些成熟技能可入 GenePackage |
| **C8** 给基因先验，不给知识语料 | **◐** | 技能**形式上**来自自身 rollout 蒸馏（Algorithm 1 line 2，π_base 自行采集），不检索外部语料——符合；但**实质上知识来自教师 o3 的预训练先验**（蒸馏与 SFT 数据生成皆由 o3 完成，p5、p13），是「模型即语料」的隐式注入 | 若保留蒸馏，教师只能做**形式操作**（抽象、压缩、结构化），不得补入环境知识；或改由「世界计价物（能量）」驱动的结构化切分替代 LLM 蒸馏 |
| **C9** 不设评分函数，只有淘汰函数 | **✗**（硬冲突） | ① GRPO 用**二元任务奖励** R_i = r(τ⁽ⁱ⁾)∈{0,1} 与组内归一优势 A_i=(R_i−mean)/std 更新权重（Eq.8–9 p4–5）；② 另有 **Invalid Action Penalty Coef 0.1** 作为塑形项（Table 4 p14）；③ 失败采样「按失败严重度（负奖励）优先」（§3.3 p4）——**排序即评分**；④ 演化触发条件为 **Acc(C) < δ=0.4**（p4、p14）——**阈值化评分**决定何时学习 | **必须剥离**：GRPO 奖励与优势归一化、invalid action penalty、按负奖励严重度排序、Acc(C)<δ 触发式评分。**可以保留**：① 「成功轨迹 / 失败轨迹差分处理」的经验编译器**输入形状**，但触发与分类依据改为**淘汰事件**（环境侧事实：死亡、能量跌破线），不是奖励；② 失败教训的四要素**结构**（失败点/错误推理/应有做法/通用原则）→ 映射为 SSEA 的 ΔR 规则提案与 Skill.precondition 收窄提案；③ 分层组织与 `when to apply` 三元组 → 对接 Skill 的 initiation set 谓词；④ **周期性回顾 + 增量增补 + 修订既有技能**的调度形状，触发改为「淘汰事件发生 / 固定睡眠窗到达」，与统计量无关 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | **✓** | 无新算子：GRPO/PPO 借用（Shao 2024、Schulman 2017），backbone 用现成 Qwen2.5-7B-Instruct（p5）；创新全在经验蒸馏管线（L2/L3）与技能-策略共演化调度（L3） | — |

### 3.2 L1–L4 层级定位

| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无；GRPO、Qwen2.5-7B、embedding 相似度检索均借用 | **无**（符合借用立场） |
| **L2 信息流层** | 技能库作为一条**注入面**：general 常驻 + task-specific Top-K 检索；蒸馏产物与执行上下文分离 | **中高**：给出「常驻本能层 + 按需检索层」的两层注入形状，可对照 SSEA 的注入面设计（但 SSEA 检索键是结构化的，非语义相似度） |
| **L3 学习层** | 差分蒸馏（成功→技能 / 失败→教训）、递归演化触发、失败的分层采样、技能修订提案 | **高**：直接对应 ExperienceCompiler 的输入处理与「何时编译」，是当前 0/33 之后最缺的形状 |
| **L4 演化层** | 无变异/继承；仅提供技能库**规模增长曲线**（55→100，Fig.3 p7）这一可观测指标 | **低（仅指标）**：库规模曲线可作技能库健康度/膨胀警报的仪器，不提供演化机制 |

### 3.3 模块映射

## 5. 冲突、代价与风险

- **与硬约束的冲突（逐条）**：
  - **C9（最硬）**：GRPO 的二元奖励 + 优势归一化 + invalid action penalty + 按负奖励严重度排序 + `Acc(C)<δ` 阈值触发，构成完整的外部评分体系。剥离清单见 3.1；剥离后剩下的「差分蒸馏 + 周期性回顾 + 配额 + 修订提案」**不含任何评分**，可安全搬运。
  - **C2**：自然语言技能直接进控制上下文（Eq.5、Fig.6）。必须降级为慢环编译中间产物，编译终点是结构化执行物。
  - **C1**：无生存压力、无淘汰，全部证据来自任务成功率。搬到生存域后，「失败」的定义须重写为淘汰事件。
  - **C4**：训练侧 30h × 8×H100 不可接受；**只搬非梯度的蒸馏与节律部分**后成本很低（蒸馏 0.5h 是在 o3 上做一次性的，SSEA 侧可换成本地小模型或结构化切分）。
  - **C3**：技能库与权重共演化——SSEA 必须切断「技能演化 ⇒ 权重更新」这条边。
- **隐含假设与失效条件**：① 需要二元成败指示（生存域里「成败」是死亡/存活，可用，但稀疏度更高）；② 需要任务类别划分（SSEA 生存域无显式类别，task-specific 层需重新定义切分依据，例如按生存子系统或按状态区域聚类）；③ 需要强教师（若 SSEA 低算力侧只有小模型，蒸馏质量下降——PSN 卡片已记录弱模型复用率 0.15 vs 0.4 的同类退化）。
- **算力 / 带宽 / 工程代价**：不搬训练侧则代价低；慢环每窗口回顾编译的 LLM 调用次数由配额（最多分析 10 条、最多产 3 条）硬性封顶，可纳入睡眠期预算。检索侧 token 收益（−10.3%）对 SSEA 意义有限——SSEA 控制环是结构化张量，不是 token。
- **搬运后的可能退化模式**：
  1. **库只增不减**（本篇自身缺陷，55→100 无剪枝）→ 违反 C4；表现为技能库膨胀、检索命中率下降、慢环编译耗时线性上升。**必须配 PSN 的重构/回滚或 SSEA 的遗忘机制**。
  2. **无验证直接入库**（Algorithm 1 line 29）→ 错误技能被固化；在生存域表现为「技能启动即致死」，且因判据形状问题可能**被计为成功**（正是债务 27/28）。
  3. **蒸馏幻觉**：教师从不完整轨迹里编出不成立的原则；SSEA 无奖励信号可纠偏，只能靠四级门与沙盒拦截。
  4. **抽象替代记忆**：若把蒸馏层当作记忆层用，会丢 C5 的精准回忆，表现为「同类情境的具体差异被抹平」。

### 6.2 推荐组合方案

1. **组合 A：技能生命周期闭环（SkillRL × PSN）**
   - **接口形态**：SkillRL 的蒸馏器作为 **PSN 的 CODEGEN 上游**——成功轨迹 → 候选技能（含 `when to apply` ⇒ PSN 的 E^pre/E^post 契约）；失败轨迹 → REFLECT 的**候选定责线索**（失败点 / 错误推理 ⇒ 沿调用轨迹定位到具体子技能）。
   - **组合后新增能力**：既有技能**产生**（本篇），又有技能**维护与压缩**（PSN 的重构/回滚）；库规模可收敛而非单调膨胀。
   - **新增风险**：两套 LLM 调用叠加，睡眠期预算被吃穿 → 必须用本篇的配额三元组硬性封顶。
2. **组合 B：睡眠期规格（SkillRL 节律 × LightMem 工序 × Dream-RSI 验证场）**
   - **接口形态**：固定睡眠窗到达 → LightMem 式摄入压缩 → 按类别分层采样失败经历（**按覆盖度而非严重度**）→ 蒸馏产出 ΔS/ΔR 提案（每窗 ≤3 条）→ 在 Dream-RSI 重放模拟器上跑近期窗验证 → 过四级门提交。
   - **组合后新增能力**：把「睡眠期计算预算未定义」变成有配额、有工序、有廉价验证场的完整规格。
   - **新增风险**：重放模拟器保真度不足会让验证变成假通过（债务 25 同类问题）。
3. **组合 C：实验 3 判据重设计（本篇分类学 × PSN 的 SRR/复用率）**
   - 判据分档：① 机制计数（失败侧提案数、precondition 收窄提案数、**先看分母**）→ ② 行为差（技能启动率 / SKILL_FAILURE 按失败分类学分列）→ ③ 淘汰结果（生存时长、能量，模型外）。

### 6.3 本篇在组合中的典型角色

- **技能供给侧的「原料加工厂」+ 慢环回顾的「节拍器」**：负责回答「从经历里提炼什么、多久提炼一次、一次提炼多少」；**不负责**技能的可执行化、验证与淘汰（交 PSN / 四级门 / 遗忘机制）。
- 次要角色：**MemRL 式冻结策略路线的反面对照**——为「C9 是否可放宽」提供一组实测证据（推断：不构成放宽理由）。

## 8. 裁决与下一步

- **应用等级：B 零件采用** —— 可搬的是**四件零件**：失败侧差分蒸馏的形状、慢环回顾编译的**预算配额三元组**、技能条目必须自带 `when to apply`（对接 `Skill.precondition`）、失败-根因-缓解分类学。不可搬的是 GRPO/SFT 训练管线、自然语言入环、技能库无验证入库与无淘汰。**不升 A 的理由**：C9 硬冲突 + C1/C2 冲突 + 无生存域证据；**不降 C 的理由**：它给了 SSEA 目前完全空白的「慢环回顾编译的调度形状」，这是硬缺口。
- **优先级：P1**（与 PSN 同期，作为其上游供给侧）。
- **建议动作**：
  1. 在 `experience_compiler.py` 增加**失败侧通道**：输入淘汰事件（死亡 / 能量跌破线）相关轨迹，产出 ΔR 规则提案 + `Skill.precondition` 收窄提案（**结构化，非文本教训**）；先核对现有 `compile_from_trace` 是否只吃成功侧。
  2. 定义**慢环回顾编译配额**：`review_interval`（睡眠窗数）、`max_episodes_per_review`、`max_proposals_per_review`、`max_skills_per_review`，初值直接照搬 Table 4 的 5 / 10或5 / 3 形状，随后按 SSEA 睡眠期预算标定——**这一步关闭「睡眠期计算预算未定义」缺口**。
  3. 为 `Skill.precondition` 定形状：明确为**状态集合谓词**（initiation set），并要求每条技能自带；把「when to apply」的可检查性做成 Gate 的格式门一项。
  4. 建立失败分类学表（Failure / Root Cause / Mitigation 三元组），用于实验 3 判据与慢环故障定位。
  5. **明令禁止**：不得引入任务成功率阈值作为学习触发条件（Acc(C)<δ 形式违反 C9）；不得引入奖励塑形项。
- **最小验证实验（实验 3 重设计的失败侧臂）**：
  - **双臂 / 消融**：慢环回顾编译配置为 A）**仅成功轨迹**（现状）；B）**成功 + 失败反事实蒸馏**（本篇形状，去 LLM 文本、改结构化提案）。两臂配额相同（每 5 个睡眠窗一次，最多分析 10 条，最多产 3 条提案）；≥8 seed。
  - **判据（分档，先看分母）**：① **机制计数**——失败侧产出的提案总数、其中 precondition 收窄类占比、ΔR 提案数（**若两臂均为 0，说明问题在编译器触发器而非蒸馏，先修触发器**）；② **行为差**——同源任务上技能启动率、SKILL_FAILURE 按失败分类学分列的计数；③ **淘汰结果**——生存时长 / 净能量（模型外，环境侧）。
  - **预期**：B 臂在后续同源任务上的 SKILL_FAILURE 计数下降，且 precondition 收窄提案 > 0（这是 0/33 所缺的那一类可观测）。
  - **证伪条件**：若 B 臂提案数显著 > 0 但行为差与淘汰结果均无变化 → 说明蒸馏产物未真正进入执行（注入面断链），应转向查 Gate/注入面而非继续调蒸馏；若 B 臂库规模单调膨胀且检索命中率下降 → 需立即接 PSN 的重构/回滚或遗忘机制（本篇自身无解）。
- **若 E 不采用**：不适用。
