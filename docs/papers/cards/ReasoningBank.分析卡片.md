## 1. 一句话定位

- **论文主张**：把智能体的**成功与失败轨迹**都蒸馏成结构化的「推理记忆项」（title / description / content），以嵌入相似度在测试时检索注入，形成「检索 → 行动 → 抽取 → 固化」的闭环；再配 MaTTS（记忆感知的测试时缩放，并行自对比 / 串行自精炼），用同一任务的多次探索产生对比信号来锻造更好的记忆，从而把「记忆驱动的经验缩放」确立为一条新的缩放维度（摘要、p1–3、§3）。
- **对 SSEA 的意义**：它是目前读到的对「**ΔM 该存什么**」给得最具体、且有量化依据的一篇——直接给出「存蒸馏后的策略/教训、不存原始轨迹」「**注入条数越少越好（k=1 最优）**」「**按 experience 召回、按 item 返回**」三条可搬运规则；同时它把「轨迹 → 技能」之间缺失的**中间表示层**摆到了台面上，正面回应技能固化 0/33 的表示问题。代价是它用 LLM-as-a-Judge 与 BoN 评分做标签源，与 C9 硬冲突。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- 问题本身：LLM 智能体被长期部署后会遭遇**连续任务流**，但它们「基本不从积累的交互历史中学习」，于是（i）重复过去的错误、（ii）丢弃有价值洞察、（iii）缺乏随时间变强的自演化能力（p1）。
- 它指出的既有方案缺陷：现有记忆机制要么存**原始轨迹**（Synapse 一类），要么只提炼**成功例程 / 工作流**（AWM 一类）。两类缺陷：① 无法蒸馏出更高层、可迁移的推理模式；② **过度强调成功经验，自身失败的教训基本未被利用**（p2）。结果是记忆停留在「被动记录」，给不出可行动、可泛化的指引。

### 2.2 核心思想（关键 insight）
1. **记忆的内容应该是「推理单元」而不是轨迹**：把经验蒸馏为「抽象掉底层执行细节、保留可迁移推理模式」的结构化知识单元（p5 Memory Schema）。
2. **失败是有用的、且与成功异构**：成功提供「已验证的策略」，失败提供「反事实信号与陷阱」，用于磨砺护栏（guardrails）；消融显示基线方法加上失败轨迹反而退化，只有 ReasoningBank 能把它转成建设性信号（p5、p10–11）。
3. **记忆与测试时缩放双向协同**：好记忆把缩放引导到更有希望的路径上；缩放产生的多样化轨迹又提供对比信号，锻造更好的记忆——论文称之为新缩放维度（p2、§4.4）。
4. **缩放的价值由记忆质量决定**：无记忆的缩放收益小且波动（39.0–42.2），弱记忆几乎不吃到缩放红利（Synapse Pass@1 40.6→41.2、AWM 44.4→45.5），强记忆才吃到（49.7→53.0）（p9–10）。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处（节/图/表/页） |
|---|---|---|---|
| **Memory Schema {title, description, content}** | 经验 → 三字段结构化记忆项 | 抽象掉执行细节、保留可迁移推理；既人可读又机器可用 | §3.2 p5 |
| **Memory Retrieval** | 当前 query 嵌入 → top-k 相似 *experience* → 其 memory items | 检索单元是「经验（任务级）」，返回单元是「记忆项」——**两级粒度分离** | §3.2 p5；A.2 p22（默认 k=1，gemini-embedding-001，余弦） |
| **Memory Extraction（成功路）** | 成功轨迹 → ≤3 条记忆项 | 「先想为什么成功，再总结洞察」 | Fig.9 左 p21 |
| **Memory Extraction（失败路）** | 失败轨迹 → ≤3 条记忆项 | 「先反思为什么失败，再总结教训/预防策略」 | Fig.9 右 p21 |
| **去语境化约束（三条硬规则）** | — | ≤3 条；不得重复/重叠；**不得提及具体网站、查询、字符串内容**，只写可泛化洞察 | Fig.9 p21 |
| **LLM-as-a-Judge** | query + 轨迹 + 终局页面 + 回答 → success/failure 二值 | 在无 ground-truth 的测试流中提供**代理正确性信号** | Fig.10 p22；A.2 p22（同 backbone，temp 0.0 求确定性） |
| **Memory Consolidation** | 新记忆项 → 追加入库 | 论文自陈为「minimal consolidation strategy」，**直接 add，不做剪枝** | A.2 p23 |
| **MaTTS 并行缩放（self-contrast）** | 同一 query 的 k 条轨迹 → ≤5 条记忆项 | 跨轨迹对比成败，识别一致模式、滤掉虚假解 | §3.3 p5–6；Fig.11 左 p23 |
| **MaTTS 串行缩放（self-refinement）** | 单轨迹反复复查 → 中间笔记也入记忆 | 捕获最终答案里不出现的推理尝试与修正 | §3.3 p6；Fig.11 右 p23 |
| **注入话术** | 记忆项拼进 system prompt（title + content） | 并要求模型「每步先显式讨论是否使用每条记忆，再行动」 | A.2 p23 |
| **存储格式** | JSON：{task query, 原始轨迹, memory items}；query 嵌入另存一个 JSON | 每个 run 独立持久化，支持测试时持续累积 | A.2 p23 |

### 2.4 关键表示与数据结构
- **记忆项**：`{title（核心策略的简洁标识）, description（一句话摘要）, content（蒸馏出的推理步骤 / 决策理由 / 操作洞察）}`，Markdown 强制格式（§3.2 p5、Fig.9 p21）。
- **一条经验 → 多条记忆项**：单轨迹最多 3 条，并行缩放时所有轨迹合计最多 5 条（Fig.9 p21、Fig.11 p23）。
- **记忆池**：JSON 列表，每条目含 query + 原始轨迹 + 记忆项；嵌入按 query 预计算，另文件存放（A.2 p23）。
- **检索粒度**：召回 top-k 个 *experience*，注入其全部关联 items（§3.2 p5）；默认 k=1，消融 k∈{0,1,2,3,4}（§C.1 p26）。
- 论文未定义记忆项之间的链接、版本、合并或删除结构（自陈局限，p29）。

### 2.6 论文自陈局限与边界条件
- **只做内容、不做架构**（§E p29）：未与情景式 / 层级式等其他记忆架构广泛比较，认为那是正交问题；本文只回答「存什么、复用什么」。
- **检索与固化故意做简单**（§E p29）：固定嵌入相似度检索 + 直接追加，不做自适应检索、层级固化；论文明说这是为了把增益归因到内容设计上。
- **依赖 LLM-as-a-Judge 提供正确性信号**（§E p29–30）：任务含糊或判定器自身出错时会引入噪声；论文称结果在噪声下仍鲁棒，建议未来引入更强 verifier、人在回路或集成判定。
- **未来方向**（§D p28）：模块化 / 可组合记忆（planning / tool-use / operational / user-centric 等分型）、分层记忆栈（情景轨迹 + 工作记忆 + 长期知识带衰减/刷新）、检索从嵌入相似度升级为「推理密集型控制器」（分解查询、多跳、按不确定性/新近度/成本选择）、学习型路由与固化策略。
- 边界条件：任务须有可判「成功 / 失败」的终局（判定器要能看终局页面状态与回答）；域为 web 与 SWE，观测是文本无障碍树 / 代码片段。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据（论文中的具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | ◐ | 域是 web 导航 / SWE 修 bug，非生存控制；但「检索→行动→蒸馏→固化」的闭环形状与 SSEA 慢环编译环同构（§3.2 p5） | 把「任务是否成功」换成**环境终局/淘汰事件**；控制环只吃结构化信号 |
| **C2** 自然语言只作观察员接口 | ◐（偏 ✗） | 记忆项三字段**全是自然语言**，且以 system prompt 形式注入策略输入（A.2 p23）→ 语言进入控制闭环 | 抽取放慢环，产物**张量化**后入快环（对齐 `ssea/tensorize.py`）；自然语言副本只留观察员面（日志/解释），不进 `m_t` |
| **C3** 权重/记忆/技能三分离 | ◐ | 只覆盖记忆一侧（ΔM）：无权重更新、无规则、无技能通道；且它把「策略」也装进记忆，与 SSEA 技能库的边界需要显式裁定 | **裁定归 ΔM**，并建立「ΔM 推理单元 → ΔS 技能」的单向晋升通道（理由见 3.3） |
| **C4** 低算力低带宽 | ◐ | 支持面：快环侧增量小，总 token 仅 +4.3% 换 +20.5% 性能（Table 5 p26）；k=1 默认，注入最省。冲突面：抽取 + 判定各需一次 LLM 调用（1562.1 / 2186.3 tokens）；MaTTS 需 k 倍 rollout；**固化只 add 不剪枝 → 记忆池无界增长**（A.2 p23），直接撞「缓冲不无界增长」 | 抽取 / 判定 / MaTTS **全部下沉到睡眠期（慢环）**，快环只做检索+注入；容量上限、合并、遗忘交给 `memory_system` 的 capacity + merge_threshold（与 MemRL FR、SEDM 准入配合） |
| **C5** 精准回忆历史 | ◐ | ✓：原始轨迹 + query 与记忆项一起持久化（JSON，A.2 p23），可精准写入与追溯。✗：检索是嵌入近似 top-k，非精确；**无 update / merge / delete，只有 add**（A.2 p23） | 保留「原始经验 + 蒸馏项」双存；检索走键 + 门控；合并与遗忘由外部组件补 |
| **C6** 可自主修改自身 | ◐ | 只改记忆库，不改代码 / 权重 / 规则；且写入**无验证门**（直接 append，A.2 p23）——四权里只有提案权，没有验证权 | ΔM 写入必须过四级验证门（至少 SEDM 式 A/B 准入），不得 append 了事 |
| **C7** 可保存/恢复/变异/继承 | ◐ | ✓：每个 run 持久化记忆池，可恢复继续累积（A.2 p23）。✗：无变异、无跨个体继承、无 GenePackage | JSON 持久化格式可借鉴；**跨代继承按 C8 明令禁止** |
| **C8** 给基因先验，不给知识语料 | ✓（在正确放置下） | 论文未涉及继承；推理单元是纯后天经验产物。若搬运时坚持「记忆不进结构快照」（`ssea/memory_system.py` 已有此纪律），则天然不跨代，与 C8 一致 | 必须写明：推理单元**不得进入 GenePackage**；否则后天知识跨代膨胀 |
| **C9** 不设外部评分函数，只有淘汰函数 | **✗** | 两处硬违规：① 成功/失败标签由 **LLM-as-a-Judge** 给出，且判定器 backbone **与智能体同一个**（A.2 p22）——典型的「观察员评分」；② MaTTS 的 BoN 用 LLM 按 **五维细则打分**择最优轨迹（Progress Toward Goal / Trajectory Efficiency / Loop Detection / Error Severity / Overall Trajectory Quality，Fig.12 p23） | 标签源换成**环境侧淘汰信号**：失败 = 淘汰事件（环境给，模型碰不到）；成功 = 未淘汰的连续存活段（环境可观测量，非评分）。BoN 整体删除。**保留**的是「成功/失败分两路抽取」这一**准入分类**思想——分类不是打分 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | ✓ | 无新算子；借用 gemini-embedding-001 + 现成 LLM。创新在记忆内容定义（L2）与抽取/缩放协议（L3） | — |

### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子（嵌入 + 现成 LLM） | 符合借用立场，无价值也无负担 |
| **L2 信息流层** | 记忆项 schema；「检索 → 行动 → 抽取 → 固化」四步数据流；**检索粒度（experience）与返回粒度（item）分离**；注入条数预算 | **高**：直接给出 ΔM 的内容规范与读取接口形态 |
| **L3 学习层** | 成功/失败双路抽取（含去语境化硬约束）；MaTTS 自对比 / 自精炼；策略随经验逐级涌现 | **高**：补上「轨迹 → 技能」之间的**中间表示层**，并给出慢环经验缩放的收益曲线形状 |
| **L4 演化层** | 无（无变异、无继承、无 GenePackage）；策略成熟度涌现可视为 L3→L4 的桥 | 中：成熟度阶梯可作为技能晋升门控的观测指标，需与 PSN 对接 |

### 3.3 模块映射（含 ΔS / ΔM 归属裁定）

**裁定：ReasoningBank 的「推理单元」在 SSEA 三分离（C3）中归 ΔM（记忆），不归 ΔS（技能）。**

三条理由：
1. **不可执行**——memory item 只有 `{title, description, content}` 三个自然语言字段，无动作序列、无前置条件，不能独立驱动行动。而 SSEA 的 `Skill`（`ssea/skill_library.py`）在结构上是 **option**：`precondition = initiation set`、`action_sequence = policy`，并带七项必备字段（前置条件 / 动作序列 / 预期结果 / 成功次数 / 失败次数 / 能量消耗 / 最后使用时间）。推理单元一项都不满足。
2. **无契约、不过门**——按 PSN 卡片的判据，技能须带契约并过成熟度门控与回滚验证；ReasoningBank 的单元是**直接 append 入库**（A.2 p23），无任何合法性验证。
3. **生命周期不同**——推理单元随 run 累积、可合并可遗忘、随个体生命周期存在，是记忆侧语义；技能须进 StructureStore 快照、过四级门、可打包进 GenePackage（ΔS 语义）。

**但它不是终点，而是 ΔS 的候选上游**：它是 ΔM 中的「策略型 / 教训型」子层。当某单元被反复检索命中、且能被编译成「带前置条件的开环动作程序」时，才走 ΔS 晋升通道。这一裁定把 SSEA 当前的失败点定位清楚了：`compile_from_trace()` 是「**轨迹 → 技能**」直连，中间缺的正是这一层表示——这是 0/33 的一种可能解释（**推断**，需实验验证）。

| 论文构件 | SSEA 落点（现有模块 / 缺失组件 / 新增建议） |
|---|---|
| Memory Schema {title, description, content} | `memory_system.py`：新增 `kind ∈ {STRATEGY, LESSON}` 的**策略型记忆记录**（张量为主体）；`description` 降级为慢环可读索引（观察员面） |

### 3.4 债务与验收实验对应
- **记忆门「开得准不准」的选择性缺失**（当前只修好「门不开」）：**正面回应**。给出可量化的「少而精」律——k=1（49.7）优于 k=2/3/4（46.0/45.5/44.4），说明**选择性不只是准入，还包括注入条数预算**（实测）。
- **`retrieve` 键收窄 → 召回精度上限低**：**部分回应**。不动键的宽度，改用「任务级键召回 + item 级返回」，把精度问题从「键够不够宽」转成「返回粒度够不够细」（推断，可实验）。
- **技能表示够不够（固化 0/33）**：**部分回应**。明确指出「原始轨迹」与「可执行工作流」之间还有一个可蒸馏的中间层——这正是当前「轨迹 → 技能」直连所缺的（推断）。
- **睡眠期计算预算未定义**：**形态参考**。MaTTS 给出 k=1→5 的收益曲线与「并行优于串行、串行早饱和、无记忆时缩放几乎无效」三条形状结论（实测于其域），可作为睡眠期预算曲线的形状先验，**数值不可直接搬运**。
- **债务 22（记忆二级门用常量阈值，慢环不可调）**：**间接**。论文的 k / top-k 是可调旋钮，且给出了调优依据（条数—性能曲线），可作为「阈值应由慢环按曲线调」的论据。
- **债务 25/26/27/28（判据形状错等）**：**不直接回应**，但「步数下降主要来自成功样本（↓2.1，26.9%）而非失败样本」这个拆解方法（Table 4 p11）值得借给逐帧动作差判据的设计——**看增益来自哪一侧**，避免把「提前砍掉失败尝试」误判为能力提升。
- 可服务的验收实验：**实验 2（记忆检索命中率 0.5164）**的粒度与条数改造；**技能固化实验 3（0/33）**的中间表示层改造。

## 5. 冲突、代价与风险

- **与硬约束的冲突（逐条）**
  - **C9 ✗（最硬）**：成功/失败标签来自与智能体**同 backbone** 的 LLM-as-a-Judge（A.2 p22）；MaTTS 的 BoN 更是显式五维评分细则（Fig.12 p23）。在 SSEA 里这是「奖励塑形 + 观察员评分」双重违规。改造不是调参，是**换信号源**：失败标签 = 环境淘汰事件；成功侧不打分，改用「未淘汰的连续存活段」作为可蒸馏片段。
  - **C2 ◐→✗**：记忆项以自然语言进 system prompt = 语言进控制闭环。改造：慢环抽取 → 张量化 → 快环只读张量；文本副本封在观察员面。
  - **C4 ◐**：固化只 add 不剪枝 → 缓冲无界增长；MaTTS 需 k 倍 rollout。改造：全部下沉慢环 + 容量/合并/遗忘外置。
  - **C3/C8 边界风险**：若把推理单元当技能塞进 GenePackage，就变成后天知识跨代，违反 C8。必须明令禁止。
- **隐含假设与失效条件**
  - 假设任务有**可判终局**（判定器能看终局页面 + 回答）。SSEA 的生存环**没有「任务成功」这种终局信号**——这是本篇搬运的最大失效条件：成功路抽取会失去标签源。失败路反而天然可用（淘汰即失败）。
  - 假设存在一个能产出「可泛化自然语言策略」的抽取器。SSEA 是非语言架构，没有这个抽取器，需要自建结构化等价物（这是搬运的主要工程量）。
  - 假设 query 可嵌入且相似任务共享策略。
- **算力 / 带宽 / 工程代价**
  - 快环侧几乎免费（注入 k=1 条张量）。抽取（≤3 条）+ 判定每任务各一次 LLM 调用，SSEA 侧对应慢环一次编译流水线的固定开销，需计入**睡眠期预算**（该预算目前未定义）。
  - 记忆池只增不减，长跑下检索成本线性增长，必须外接容量控制。
- **搬运后的可能退化模式**
  - 去语境化约束失效 → 记忆项退化为「具体坐标 / 具体网页 / 具体查询串」的过拟合噪声，检索反而带偏行动（对应论文观察到的「过多经验引入冲突或噪声」）。
  - 抽取器幻觉 → 伪造的教训被写入；又因**无准入门**，污染不可逆、且会被后续检索放大。
  - 未设注入条数上限 → 噪声压过策略，复现 k=2/3/4 的下降。
  - 标签源若改造不彻底（残留任何「模型自评好坏」）→ 直接违反 C9，且失败模式隐蔽（看起来在涨分，实为奖励塑形）。

## 6. 组合分析

### 6.1 关系图谱
| 关系 | 对象（点名） | 说明 |
|---|---|---|
| **前置依赖** | 轨迹/经验落库、环境侧终局或淘汰信号、慢环可离线批量跑 | 三者缺一则本篇的核心回路跑不起来；SSEA 已有前两项雏形（缺的是把标签源从模型换成环境） |

| **互补（最紧）** | **PSN** | 本篇提供 ΔS 的**上游素材**，PSN 提供下游的契约化 / 成熟度门控 / 回滚验证重构。**「推理单元 → 可执行技能」的晋升通道 = 本篇 × PSN 的接口**，是 0/33 最直接的候选解 |
| 互补 | **Memento** | 本篇用固定嵌入 top-k 检索，Memento 的可学习检索 μ 正好补「选哪条」；本篇的内容规范 + Memento 的选择策略 = 完整 ΔM 读取侧 |
| 互补 | **MemRL** | MemRL 的两阶段检索补本篇的单阶段嵌入；MemRL 的**遗忘率 FR** 补本篇完全缺失的遗忘；其「冻结库迁移验收」可复用于准入 |
| 互补（准入） | **SEDM** | 本篇「直接 append、无验证」是明确缺口，SEDM 的 SCEC 自包含打包 + A/B 准入验证是现成的**记忆准入官**；这也正是 SSEA 记忆门「开得准」的执行者 |
| 互补（槽位） | **LightMem** | 本篇的抽取 / 判定 / MaTTS rollout 都是**写入侧离线活**，应放进 LightMem 式的睡眠期巩固槽位；LightMem 的摄入压缩还能降低被蒸馏的原始轨迹体积 |

| 互补（诊断） | **RAGEN** | 本篇「弱记忆 + 缩放 → Pass@1 几乎不动（40.6→41.2、44.4→45.5）；强记忆 + 缩放 → 49.7→53.0」是一个**鉴别性现象**，可当记忆质量的诊断仪用，与 RAGEN 的 Echo Trap 诊断同类 |
| 替代 | **Reflexion** | 本篇是 Reflexion「试错—评估—反思外环」的**持久化 + 蒸馏版**：Reflexion 的反思留在当次 episode，本篇把它固化成跨任务的记忆项并加了失败路 |
| 替代 | **Voyager**（键/值技能库） | 同形（键=任务上下文、值=库条目），但 Voyager 的 value 是**可执行技能**，本篇的 value 是不可执行的推理项——差异点正是 ΔS/ΔM 的分界 |
| 同域对照 | **Synapse**（原始轨迹）、**AWM**（工作流） | 论文自己的基线：内容抽象度三级阶梯（原始 → 工作流 → 推理单元），结论是抽象到「推理单元」这一级最优 |
| 同域对照 | **SkillWeaver**、**WebRL** | SkillWeaver 的「提案—练习—合成—打磨」是本篇抽取器的**可执行化升级版**；WebRL 的「从失败造训练任务」与本篇的失败路抽取目的一致、路径不同 |

### 6.2 推荐组合方案
- **组合 A（ΔM 完整回路）**：**ReasoningBank（内容）× A-MEM（组织）× SEDM（准入）× MemRL（遗忘）**
  - 接口形态：`ExperienceUnit{key, kind ∈ {STRATEGY, LESSON}, tensor, observer_text}`；慢环按 A-MEM 建类型化链接，写入前过 SEDM 的 A/B 准入，容量与遗忘由 MemRL 的 FR 控制。
  - 组合后新增能力：有内容规范、有组织拓扑、有准入、有遗忘的完整 ΔM；且「少而精」预算律与链接闭包可共存（闭包只在返回的 item 级展开一步）。
  - 新增风险：四个组件串成一条链，任一环的门禁判据形状错都会被放大（对应债务 25–28 的老问题）。
- **组合 B（技能供给侧，直指 0/33）**：**ReasoningBank（抽取）× PSN（固化）**
  - 接口形态：轨迹 →（本篇）推理单元 →（成熟度门控：重复命中次数 + 涌现阶梯等级）→（PSN）带契约的可执行技能 + 回滚验证。
  - 组合后新增能力：把「轨迹 → 技能」的一步直连拆成两步，失败可定位到具体是哪一段（表示层还是契约层）。
  - 新增风险：推理单元本身不可执行，晋升为可执行程序这一步在 SSEA 的非语言架构下没有现成编译器，工程量最大。
- **组合 C（睡眠期缩放）**：**ReasoningBank（MaTTS 自对比）× LightMem（睡眠期槽位）× Dream-RSI（离线重放）**
  - 接口形态：慢环对同一情境做 k 次沙盒 rollout（k 由预算曲线定），自对比抽取，不做 BoN 择优（C9）。
  - 组合后新增能力：给「睡眠期计算预算未定义」提供一条**可测量的预算—收益曲线**。
  - 新增风险：k 倍算力与 C4 冲突；必须严格限定在慢环且受预算上限约束。

### 6.3 本篇在组合中的典型角色
- **记忆内容规范器 / 经验蒸馏器**：管「该往 ΔM 里存什么形态的东西、一次最多喂几条」。**不管**组织（A-MEM）、**不管**选择（Memento/MemRL）、**不管**准入（SEDM）、**不管**固化（PSN）——它只补内容这一格，但这一格目前是空的。

- **优先级：P1**。
- **建议动作**
  1. 在 `experience_compiler.py` 增加 `ExperienceUnit` 中间产物：`{key, kind ∈ {STRATEGY, LESSON}, tensor, observer_text}`，路径改为「trace → ExperienceUnit →（门控）→ 技能」，保留原 `compile_from_trace()` 作为对照臂。
  2. 标签源换血：**失败路**用环境淘汰事件（DeathHook 一旦接上即可用）；**成功路**不用评分，用「未淘汰的连续存活段」作为可蒸馏片段。任何形式的模型自评一律不进。
  3. `memory_system.retrieve()` 改为「任务/目标级键召回 experience → 返回 item 级」，并加**注入条数上限**参数（默认 1），由慢环按曲线调（回应债务 22）。
  4. 抽取/判定/MaTTS rollout 全部标为慢环作业，写入前过 SEDM 式 A/B 准入，`memory_system` 的 capacity + merge_threshold 兜底（回应无界增长）。
  5. 把「步数/增益来自成功侧还是失败侧」的拆解方法（Table 4）引入逐帧动作差判据的设计，避免把「提前砍掉失败尝试」误判为能力提升。
  6. 明确写入文档：推理单元**不得进 GenePackage**（C8）。
- **最小验证实验**
  - **双臂 / 消融设置**（两个正交实验，≥8 seed）：
    - 实验 ①（表示层）：**A 臂** 现有 `compile_from_trace()` 直出技能 vs **B 臂** 先抽 ExperienceUnit、再编译技能。
    - 实验 ②（预算律）：固定记忆门开率，`retrieve` 注入条数 k ∈ {0, 1, 2, 4}。
  - **判据（分档，先看分母）**：
    - 第一档 机制计数：抽出的 ExperienceUnit 条数（是否为 0）、去重率、去语境化通过率（是否残留具体坐标/网页/查询串）、写入准入通过率。
    - 第二档 行为差：逐帧动作差、`retrieve` 召回命中率（当前 0.5164）、平均步数；步数下降要区分来自存活样本还是被淘汰样本。
    - 第三档 淘汰结果：存活时长、危险回避率（**注意两臂均 0.9814 已饱和，不能作主判据**）。
  - **预期与证伪条件**：
    - 预期：B 臂 ExperienceUnit 数 > 0 且去重率 > 0；k=1 组召回精度 ≥ k=4 组。
    - **若 B 臂技能固化数仍为 0/33**，则结论是「瓶颈在单元 → 可执行契约这一段（PSN 侧），而非表示层」——这本身就是对 0/33 的定位结论。
    - **证伪（本篇不搬运）**：若抽出的单元在观察员面互相重复、或残留具体情境串、或 k 曲线不呈现「少而精」，则本篇的内容规范与预算律在其域外不成立。
