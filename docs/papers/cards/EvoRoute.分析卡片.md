## 1. 一句话定位

- **论文主张**：把「agent→LLM」的静态手工映射 ϕ 换成**按步（step-level）动态路由**——维护一个只增不减的步级经验库 K，新子任务到来时做**多面检索**（角色 / 语义 / 工具三面并集），再对候选模型做 **Pareto 前沿过滤**，最后用 **Thompson Sampling（NIG 共轭后验，闭式无训练）**在「性能 / 成本 / 时延」三目标效用下选一个 backbone，执行后把结果写回 K 形成闭环；在 GAIA、BrowseComp+ 等五个基准上，成本最高降约 80%、时延最高降逾 70%（Abstract, p1；§5.2 p7–8）。
- **对 SSEA 的意义**：它是 **L2 信息流层「结构注入面」的一个现成工程形态**——「按状态/经验把这一步路由到不同配置」。对 SSEA 可直接改写的问题是：慢环往不可变快照里**写什么**、快环**按什么键查**。同时它给出 C8 的一个干净切分点（先验超参可遗传、具体记录不可遗传）。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题

- **问题本身**： formalized as the **Agent System Trilemma**——性能（P，任务成功率）、成本（C，金钱/算力）、效率（D，挂钟时延）三者不可兼得（§2, p2；形式化见 Eq.4, p4）。例证：Gemini-2.5-Pro+ReAct 平均 74.27% 但 $521.61 / 123h（Table 2, p7）；Qwen3-14b+CK-Pro 仅 $4.16 但性能掉到 10.91%（Table 1, p6）；OWL-Workforce 平均每任务约 $3、简单查询可达 40 分钟（§1, p1）。
- **它指出的既有方案缺陷**：
  1. 既有 agentic 系统的 **agent→model 映射 ϕ 是静态、人工预定义的**（Eq.1, p3；p4 举 OWL-Workforce、Magentic-one、AgentOrchestra、AIME、CK-Pro 为例），不适应子任务难度差异；
  2. **single model routing**（整个任务一个模型）只适用于原子任务，处理不了浏览/编码/摘要等异质子任务（p2）；
  3. **multi-agent routing**（按角色分配模型）只在单步推理场景（数学、代码）验证过，且依赖大规模轨迹，不适合动态多轮 agentic 场景（p2）；
  4. 主流 routing 方法（LLM-Blender、ZOOTER、RouteLLM、GraphRouter、UniRoute、BEST-Route、Avengers）主要面向单轮回答、在 Chatbot Arena / MATH 等简单基准评测，未做到 deep research 场景的细粒度路由（§2, p3）。

### 2.2 核心思想（关键 insight）

1. **路由粒度下沉到「步」而非「任务」或「角色」**：在每一步执行前为当前激活 agent 选 backbone，而非给整个任务或整个角色固定一个模型（§1, p2；Eq.4, p4）。论文明确指出它改的是 ϕ（agent→model 映射），**不改角色集 I、不改拓扑、不改工具集**。
2. **「检索 → 过滤 → 选择」三段式，且过滤与选择分离**：先用三面并集保证召回，再用 Pareto 支配**剪掉被支配项**，最后在**非支配集上**做带不确定性的采样选择——剪枝与探索是两个独立动作（§4.2–4.3, p5–6）。
3. **策略演化 = 证据库演化，不是参数训练**：NIG 共轭后验可闭式更新（µ=x̄, ν=n, α=n/2, β=(n−1)s²/2），无需梯度、无需训练、无需微调任何模型（Eq.11 前段, p5）。
4. **探索与执行分相**：Optimization Phase 用树式探索采样多条轨迹主动丰富 K；Inference Phase 只走一条优化路径（§1, p2）——把「探索预算」与「单次执行成本」显式切开。
5. **结构复杂度要匹配任务内在复杂度**（副作用洞察）：观察到 **"architectural overfitting"**——Gemini-2.5-Pro+Smolagent 在 DS-1000 只得 31.7%，低于更简单的 Qwen3-14b+ReAct 的 38.2%（§5.3, p8）。

### 2.4 关键表示与数据结构

- **经验库 K**：扁平的步级记录集合，**只追加**（Eq.6 仅有 ∪），论文**未提及**遗忘、合并、压缩或容量上限。
- **记录元组 R_t**（Eq.5）：角色 id `i_t` / 被选模型 `l_t` / 自然语言子任务指令 `q_t` 及其嵌入 `e_t=Embed(q_t)` / 调用工具子集 `T_t` / 成本 `c_t` / 时延 `d_t` / **步级成功位 σ_t ∈ {0,1}**（如工具调用是否无错执行）/ 任务级成功率 `P(τ)`。
- **检索是三面析取并集**，不是 top-k：Eq.8/9/10 三个子集都是「全量匹配」（无 k 限制），并集规模随 |K| 增长。
- **模型池 L**：6 个现成 LLM（Qwen3-14B、GPT-4.1、GPT-4o、Claude-4-Sonnet、Gemini-2.5-Flash、Gemini-2.5-Pro），价格已知（Table 4, p13），**全程不微调任何权重**。
- **冷启动种子库**：~480 条步级记录（50 TaskCraft 任务 × Smolagent 与 CK-Pro 各跑一遍，逐步均匀随机选模型）（§A, p12）。

### 2.6 论文自陈局限与边界条件

- **自陈局限**（Limitation, p9）：只评测 CK-Pro 与 Smolagent 两个框架，**未**选 OWL、Agent-Orchestra、AIME；理由是这些 deep research 系统架构范式相近（中心协调器 + 多个专用子 agent），且 token 成本使穷尽式大规模基准评测不可行（引 Table 1 成本）。伦理方面自述无即时风险。
- **假设依赖**：① 任务级成功率 P(τ) 可获（benchmark 有标签）；② 模型池 L 固定且价格/能力已知（Table 4, p13）；③ θ_sim=0.85、NIG 无信息先验 (ν₀=0, α₀=0.5, β₀=0)、效用权重 (1.0, 0.1, 0.05) 均为**人工设定**（§5.1, p6–7）；④ 冷启动的 50 个 TaskCraft 任务分布可代表后续部署分布（论文未论证）。
- **明确不适用 / 未覆盖**：不适用于无任务级成败标签的场景；未评估 K 长期增长的检索时延与容量；未报告路由决策本身的 token / 时延开销（未提及）；优化相的「树式探索」在 §4 方法论中**未展开**（仅 §1 p2 一句话 + 图 2 的 Trajectory Database）。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射

| 裁判标准 | 判定 | 依据（论文中的具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | **✗/◐** | 域为 deep-research QA 与代码/医疗推理（GAIA、BrowseComp+、DS-1000、HotpotQA、DDXPlus）；优化目标是任务成功率与美元成本，非生存 | 只搬「按步选配置」的信息流形状，判据换成环境淘汰；域内数字不作 SSEA 证据 |
| **C2** 自然语言只作观察员接口 | **✗** | 路由键就是自然语言子任务指令的语义嵌入（`e_t = Embed(q_t)`，MiniLM + 余弦，Eq.5/Eq.9）；`q_t` 本身入库；PredictTools 兜底要**调用一次 LLM**（Qwen3-14b 零样本）分析指令语义（§B, p12）。语言**直接决定**路由，比 MaAS 更直接 | facet 键全部换成**结构化**量：角色 id / 工具集 id / 状态分档 / 惊奇或预测误差档位 / 资源压力档位；语义嵌入与 q_t 只留日志面（观察员），不进决策 |
| **C3** 权重/记忆/技能三分离 | **◐** | 权重侧 ✓：全程用现成 LLM，无任何微调；记忆侧 ✓：K 独立于权重、独立持久化；**技能侧 ✗**：无独立技能表示，路由策略 ≡ 库 + 统计量，不存在可组合/可复用/可契约化的技能单元 | 把「状态分档 → 配置」固化为 ΔS/ΔR 类技能条目进 GenePackage；K 只作记忆 M；配置池（对应 L）作为不可变快照的一部分 |
| **C4** 低算力低带宽 | **◐** | 支持面：决策本身廉价——NIG 闭式更新（µ=x̄, ν=n, α=n/2, β=(n−1)s²/2）+ 每模型每指标一次采样，|L|=6；PredictTools 多数情况零成本；实测总成本降 64–80%（Table 1）。**冲突面**：① 路由决策**在执行闭环内每步发生**（§1 p2「Before executing each step」）；② **K 只增不减**（Eq.6 仅 ∪，无遗忘/合并/上限），缓冲无界增长；③ 三面检索为**全量并集、无 top-k**，候选集随 \|K\| 线性增长；④ 环内需算 MiniLM 嵌入 | **把决策移出快环**：慢环产出「状态分档 → 配置」静态表，随不可变快照发布，快环只做 O(1) 查表；检索与后验更新全部放慢环/睡眠期；为 K 加容量上限 + 合并 + 遗忘（对接 MemRL 的 FR、LightMem 的摄入压缩、SEDM 的准入） |
| **C5** 精准回忆历史 | **◐** | 强面：步级精准写入（Eq.5 九元组，每步一条，含成本/时延/成功位）；三面检索（角色/语义/工具）比单键检索召回面宽——消融显示去掉多面检索掉 11.22%（Table 3）。弱面：**无遗忘、无合并、无容量治理**（未提及）；检索是析取全量并集，无 top-k 与精度控制 | 引入分面索引 + top-k + 容量上限；把「精准遗忘/合并」补上（MemRL / Mem0 的 DELETE-merge） |
| **C6** 可自主修改自身 | **◐** | 自修改仅限「向 K 追加记录」+「后验统计自动更新」；**不改**代码、权重、角色、拓扑、工具集；四权（提案/边界/验证/应用）拆分**未提及** | 若把「路由表本身」纳入自修改对象，须补四权拆分 + 验证门 + 回滚（Gödel Agent 卡片口径） |
| **C7** 可保存/恢复/变异/继承 | **◐** | 保存/恢复 ✓：K 是显式持久化结构（Eq.6）+ 冷启动库可重建（$28.8/3.6h/480 条，§A）。**变异 ✗**（无变异算子）；**继承 ✗**（无个体、无代际、无 GenePackage 概念，未提及跨个体传库） | 推断：可继承形态 = **facet 定义 + NIG 先验超参 + 冷启动配方**（结构性先验），**不含**具体记录；繁衍机会仍由环境淘汰给 |
| **C8** 给基因先验，不给知识语料 | **◐/✗** | 若 K 整体跨代 = **后天知识语料跨代**，直接违反防膨胀要求；冷启动的 ~480 条记录是「任务经验」而非本能 | **切分点**：facet 结构定义、NIG 超参 (ν₀, α₀, β₀)、双阶段协议 = 先验，可进 GenePackage；具体记录 R_t = 语料，不跨代。这是本篇对 C8 最有用的产出 |
| **C9** 不设评分函数，只有淘汰函数 | **✗/◐**（与 MaAS 卡片同一口径） | ① `U′(l) = w_p·x̃_P − w_c·x̃_C − w_d·x̃_D` + `l* = argmax`（Eq.11）＝**打分 + 排序**；② Pareto 支配＝**排序**；③ 权重 (1.0, 0.1, 0.05) 人工配置＝**奖励塑形**（§5.1 p7）；④ P̂ 用 P(τ)（benchmark 标签）加权＝外部评分进选择 | **效用只作仪器；选择过门**（与 MaAS 卡片一致）。具体：argmax → 合法性过滤 + 环境淘汰；人工权重 → 不可改的结构性约束；**可保留项**：σ_t（工具调用是否报错）是环境侧合法性信号，只作验证门输入、不作选择器输入；P(τ) 换成 SSEA 的环境淘汰函数（环境侧、模型碰不到）后可兼容 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | **✓** | L1 全部借用：MiniLM 句编码、现成 LLM 池、Thompson Sampling + NIG 共轭（Russo et al. 2020）；创新在 L2（步级路由信息流、三面分面索引）与 L3（经验驱动的策略更新） | — |

### 3.2 L1–L4 层级定位

| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子；借用 MiniLM、现成 LLM、Thompson/NIG | **低**（但符合 C10「借用且可替换」的立场，是正面信号） |
| **L2 信息流层** | **核心贡献**：① 步级（step-level）路由——执行前按状态/经验选配置，即「结构注入面」的运行时形态；② 三面析取检索——分面索引的信息流设计；③ 双阶段（优化相多轨迹 / 推理相单路径）——快慢环分离的显式工程形态 | **高**：直接对应「结构注入面 + 快环只读不可变快照」；三面检索直接回应 `retrieve` 键收窄 |
| **L3 学习层** | 经验驱动、闭式后验更新（无梯度、无训练、无微调）的策略自适应；自我改进只及于「证据库」 | **中-高**：给出一个「不改权重也能自我改进」的低成本范式，与 SSEA「慢环只发布结构新版本」同构 |
| **L4 演化层** | **无**：无种群、无变异、无代际、无继承。仅「冷启动种子库可导出」这一潜在形态（推断，论文未做） | **中**（间接）：提供 C8 的先验/语料切分点与「先验侧怎么填」的配方 |

## 5. 冲突、代价与风险

- **与硬约束的冲突**（对应 3.1 的 ✗/◐）：
  - **C2 ✗**：路由键 = 自然语言指令的语义嵌入，且 PredictTools 兜底调用 LLM。这是本篇**最硬**的冲突——不是「算子是 LLM 调用」这种外围冲突，而是**语言就是决策键本身**。改造后 facet 必须全部结构化，否则整个机制不能进 SSEA。
  - **C9 ✗/◐**：效用 U′ + argmax + Pareto 支配 + 人工权重 (1.0, 0.1, 0.05)。口径与 MaAS 卡片保持一致：**效用只作仪器；选择过门**。注意 σ_t 与（换成环境淘汰后的）P(τ) 本身不违规，**违规的是用它们做排序与选择**。
  - **C4 ◐**：路由决策在闭环内每步发生 + K 无界增长 + 全量并集检索。改造后决策必须**移出快环**。
  - **C8 ◐/✗**：K 若整体遗传即知识语料跨代。必须按 §4 #7 切分。
- **隐含假设与失效条件**：① 需要可比的 P(τ) 标签（生存域无标签，须换成环境淘汰函数）；② 模型/配置池固定且代价已知；③ θ_sim=0.85、先验超参、效用权重均为人工调参，换域即失效；④ 冷启动分布（TaskCraft 50 任务）≠ 部署分布时，后验会带着冷启动偏差收敛；⑤ 经验库可被污染或漂移 → 必须接 Misevolve 的红队路径。
- **算力 / 带宽 / 工程代价**：每步一次三面检索（成本随 |K| 增长）+ 一次 MiniLM 嵌入 + 可能的 LLM 兜底调用；Pareto 与 Thompson 只遍历 |L|=6，可忽略；冷启动一次性 $28.8 / 3.6h。主要工程代价在**索引结构与容量治理**（论文未做，需自建）。
- **搬运后的可能退化模式**：
  1. **路由塌缩**：权重偏斜导致永远选最便宜或最贵的配置（去掉 Thompson 掉 6.52%，说明纯贪心会早熟）；
  2. **冷启动依赖**：空库即掉 13.21%（Table 3），若种子分布不对齐，性能长期低于静态配置；
  3. **库膨胀**：候选集与决策时延随 |K| 线性上升，最终吃掉降本收益（这是本篇未评估的尾部风险）；
  4. **噪声并集**：析取并集引入无关 facet 记录，精度反而下降（需在最小实验中验证）；
  5. **投毒**：写入无准入门时，失败/恶意经验会持续影响后验。

### 6.2 推荐组合方案

1. **EvoRoute × Memento（记忆侧主干合成）**
   - 接口形态：案例库条目采用 R_t 式九元组（去语言化：q_t/e_t → 结构化状态向量）；检索为三面析取并集，**facet 定义固定进 GenePackage，facet 内相似度权重由 μ 学习**。
   - 新增能力：召回面变宽（本篇）且不牺牲可调性（Memento）；C8 的先验/语料边界同时落地。
   - 新增风险：μ 若学到「给出高分记录」即滑向 C9 —— μ 的优化信号只能来自环境淘汰，不能来自效用。
2. **EvoRoute × MaAS（L2 统一控制器）**
   - 接口形态：MaAS 出「深度/算子数/早退点」，EvoRoute 出「每步执行者」，两者产物写进**同一张注入表**，随不可变快照发布。
   - 新增能力：架构级与步骤级的资源分配合并，C4 的「按场景分配算力」完整化。
   - 新增风险：两级都在慢环，慢环预算压力上升；须先定睡眠期预算（否则反过来破坏 C4）。
3. **EvoRoute × Dream-RSI（优化相离线化）**
   - 接口形态：在线只跑**推理相**（单路径）；优化相的多轨迹树式探索由重放模拟完成，探索结果写入 K。
   - 新增能力：本篇最大的成本项（在线多轨迹采样）被消掉，同时给「睡眠期计算预算」一个可填的数字。
   - 新增风险：重放保真度不足 → 后验学到模拟器偏差（需 RAGEN 式诊断）。
4. **EvoRoute × SEDM + Misevolve（写入准入 + 红队）**
   - 接口形态：每条 R_t 追加前过 SCEC 自包含打包与 A/B 准入；整条写入路径过 Misevolve 四路径红队清单。
   - 新增能力：堵住「经验库投毒/漂移」这一本篇完全未覆盖的失效模式。
5. **EvoRoute × PSN（被选对象换成技能）**
   - 接口形态：模型池 L 换成「带契约的技能条目池」；Pareto 的三维改为（契约满足度 / 执行成本 / 时延），且**只用于合法性剪枝不用于打分**。
   - 新增能力：把「自路由」从选 backbone 升级为选技能，直接服务技能固化缺口。

### 6.3 本篇在组合中的典型角色

- **「注入面的选择机制」**：即回答「慢环往不可变快照里写什么、快环按什么键查」这一对接口的具体实现候选——**写**「状态分档 → 配置」表，**查** O(1) 表查找（检索/更新留在慢环）。
- 次级角色：**C4 三维记账的字段模板**（步级 c_t / d_t / σ_t，比 MaAS 的任务级记账更细）。

## 8. 裁决与下一步

- **应用等级：B 零件采用** —— 理由：三个零件（三面析取检索、步级记录与三维记账格式、双阶段预算协议）可直接落地并回应现存债务；但「检索 → Pareto → 效用 argmax」主干因 C2（语言即路由键）与 C9（打分排序 + 人工权重）**只能作思想参照**，不能整体搬。低于 Memento/PSN（A），高于 MaAS（C）——因为它的落点比 MaAS 具体（直接命中 retrieve 键债务）。
- **优先级：P1**。
- **建议动作**：
  1. **先做三面检索**：把 `retrieve` 键从单键扩为 (角色 / 工具集 / 状态分档) 三面析取并集；语义嵌入那一面替换为结构化状态相似度，量命中率变化；
  2. **落步级记录格式**：给记忆写入加 (配置 id, 工具集 id, 成本, 时延, 步级成功位 σ) 五个字段，**先只做记账与诊断**，不接任何选择器；
  3. **写入双阶段协议**：在线只跑推理相；多轨迹探索归入睡眠期预算，并在设计文档里给出预算数字（以冷启动 $28.8 / 3.6h 为量级参照）；
  4. **路由决策不进快环**：慢环产出「状态分档 → 配置」静态表，随不可变快照发布，快环 O(1) 查表；检索与后验更新只在慢环；
  5. **效用与 argmax 一律不进模型**：σ_t 只作验证门的合法性输入，不进选择器；P(τ) 换成环境淘汰函数；人工权重换成不可改的结构性约束；
  6. **GenePackage 只收** facet 定义 + NIG 先验超参 + 冷启动配方（结构性先验），**不收**具体记录；
  7. 补卡：`Multi-Agent Design`、`EvoConfig` 两篇在本库尚无卡片，建议补卡并与本篇一并裁决「候选生成 vs 候选选择」的分工。
- **最小验证实验（三面检索 vs 单键检索，服务记忆检索命中率）**：
  - **双臂 / 消融**：A 臂 = 当前单键 `retrieve`；B 臂 = 三面析取并集（角色 / 工具集 / 状态分档）。同一记忆库、同一查询集、**≥8 seed**；再加 B′ 臂（三面但每面加 top-k 上限）以隔离「并集引入噪声」效应。
  - **判据（分档，先看分母）**：① **机制计数**：候选集大小、命中条目数、单次检索时延、库容量增长曲线；② **行为差**：记忆检索命中率（当前 **0.5164**）、后续动作选择是否改变；③ **淘汰结果**：环境侧存活（**注意：危险回避率两臂均 0.9814 已饱和，不能作判据**）。
  - **预期与证伪**：预期 B 臂召回条目数与命中率上升，但候选集与时延同步上升，B′ 臂以 top-k 换回时延（即存在召回-时延权衡点）。**证伪条件**：若 B 臂命中率不升反降，说明析取并集引入噪声 > 召回增益，应改为 facet **加权**而非并集，或先加 SEDM 式写入准入。若命中率上升但行为差与淘汰结果无变化，说明瓶颈不在召回而在记忆条目本身的质量/表示，应转向技能表示问题（0/33 那条债务）而非继续调检索。
- **若 E 不采用**：不适用。
