## 1. 一句话定位
- **论文主张**：为「学术知识」（而非百科知识）构建 QA 基准 SciQA——在 ORKG 知识图上自底向上人工编写 100 个复杂问题（含 SPARQL 查询与答案），再用 8 个模板半自动生成 2465 个问题（合计 2565）；实测 JarvisQA（最优 12/100 正确）与 ChatGPT（14/63 正确）均表现很差，据此论证学术知识 QA 是下一代挑战任务（摘要 p1；p3；p11–12）。
- **对 SSEA 的意义**：**不适用**。这是外部知识语料上的问答评测集，不含控制环、生存信号、记忆/技能/权重三分离、自修改或演化机制，无法回溯到 C1–C10 任何一条（详见 §3.1）。

## 2. 问题 — 机制 — 证据
### 2.1 论文要解决的问题
- 问题本身：现有 QA 基准（WebQuestions/SimpleQuestions/LC-QuAD/QALD 等）几乎只面向 DBpedia、Wikidata、Freebase 等**百科式**知识图；学术知识图（ORKG）语义单元更复杂，缺少对应基准（p1；Table 1, p3）。
- 指出的缺陷：学术交流领域存在①表示异构 ②概念漂移与知识演化 ③粒度不一 ④超越简单实体描述的新结构（p1–2）；LLM 擅长复述多源常识，却不擅长只存在于单一来源的专门知识（p13）。
### 2.2 核心思想（关键 insight）
1. 学术贡献描述是**多个紧耦合实体描述的织体**（一个语义单元常含十余个互链实体），非单实体描述，问答难度结构性更高（p12）。
2. 以 ORKG 的 **comparison（比较表）**为聚合层，可在其上生成 superlative/比较/聚合类复杂问题（p4；p6–7）。
3. 人工小样本 + 模板半自动放量的混合基准构建法（100 手写 + 8 模板 × 占位符 = 2465）（p5–6）。
### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| 问题分类体系 | 自然语言问题 → 元数据标签 | 按 query shape/class/type 分类 | Table 3/4, p7–8 |
| 模板化自动生成 + SPARQL 预处理器 | 8 模板 + 占位符实体 → 2465 问句/SPARQL；人读标识符 → 字母数字 ID | 放量扩充基准、可执行化 | p5–6；Fig.3；p8 |
| 专家四档判定 | ChatGPT 答案 → Correct/Incorrect/Uncertain/No answer | LLM 答案评测口径 | p12；Table 6/7 |
### 2.4 关键表示与数据结构
- ORKG 资源计数（Table 2, p5）：Papers 14,538；Contributions 21,243；Research problems 5065；Research fields 709；Comparisons 1132；Triples 1,133,217；Classes 1621；Properties 6888；Resources 169,967；Literals 575,525（基于导出 RDF dump）。
- 每条问答三元组：自然语言问题 + 改写 + 人读/机读两版 SPARQL + 结果集 + 元数据（p5, p8）。
### 2.5 实验证据
| 任务 / 基准 | 对照基线 | 关键数字 | 统计口径 |
|---|---|---|---|
| JarvisQA 概念验证 | 7 种 JarvisQA 配置 | 可答 52/100（52%）；最优 JarvisXLS2 答 52 问仅 **12 正确**；Normal F1@10 0.339、Overall F1@10 0.235 | 仅手写 100 题；precision@k/recall@k/f1@k（Table 5, p11） |
| ChatGPT 评测 | 自身基线 | 生成 63 答案：**14 正确 / 40 错 / 9 不确定 / 37 无答案** | 100 手写题；4 名专家独立判定后合议（Table 6, p12） |
| 基准规模 | 5 个既有 QA 基准 | SciQA 2565 问（100 手写 + 2465 自动） | Table 1, p3；Table 3/4, p7–8 |
### 2.6 论文自陈局限与边界条件
- 自动生成仅限**计算机科学**一个领域（依赖 papers-with-code 2236 篇同构数据，约占 ORKG 论文 15%）（p5–6；结论 p14）。
- 面向学术数据的 NLP 组件（entity linker、query builder）缺失；LLM 缺乏知识图专属上下文理解；评测为**初步**：JarvisQA 只覆盖 52 题，ChatGPT 提示仅加 "short:"，未精细调优（p11–13）。

## 5. 冲突、代价与风险
- **与硬约束的冲突**：直接违反 C2（自然语言即任务本体）与 C9（外部评分函数 + 专家打分 + F1 排序）；与 C4 的低算力诉求方向相反（大 KG + LLM 评测）。
- **隐含假设与失效条件**：假设「问答正确率」可代表智能水平、知识从单一外部图精确检索即足够。SSEA 关心的是**生存闭环中的行为后果**，此假设在 SSEA 中不成立。搬运需接入 ORKG 全量 RDF（113 万三元组）与 SPARQL 端点，代价高、收益低。
- **搬运后的退化模式**：若强行把 SciQA 当训练信号，会把 SSEA 拖入「语言问答优化」轨道，即 C9 明令禁止的奖励塑形，直接破坏生存—淘汰闭环。
- **为什么仍保留在论文池**：作为**反面参照物**——它是「把 NL 问答正确率当作智能度量」的典型样本，可用来说明 SSEA 为何拒绝该类目标（与 C2/C9 的对照）。
