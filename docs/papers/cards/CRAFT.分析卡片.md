## 1. 一句话定位

- **论文主张**：把「给 LLM 挂现成通用 API」换成「**为任务专门造一套工具集、推理时再检索**」——用 GPT-4 从训练样本造代码解，
  经**抽象化（specific→general）+ 验证 + 去重**固化成可复用代码工具，推理时按「原问题/函数名/docstring」**多视图语义匹配**取回，
  免微调地把冻结 LLM 适配到 VQA/表格/数学三类域（p1 摘要、§2 p3–4）。
- **对 SSEA 的意义**：它是「**慢环制造技能 / 快环检索技能**」对位的**上游最简原型**（与 LATM 同族）——制造侧给「生成→抽象→
  验证→去重」四步流水线，检索侧给「多视图匹配 + 频次投票」；同时是 C9 的**干净反面**（检索器只用语义相似度、不含效用），
  正好对照 Memento 的可学习 μ、MemRL 两阶段（相似召回→效用重排）、EvoRoute 三面检索+效用选择。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- 问题本身：LLM 生成代码片段调用 API 可卸载计算/图像编码等子功能，但**通用 API 不够专用**，难以适配具体任务（p1）。
- 既有缺陷（§1 p1、§5.2 p9）：通用工具集（ToolLLM/Gorilla）对专用 API 覆盖不足；既有工具创建法或只造**单个**工具
  （CREATOR：每测试样例现造、无复用），或造**未验证、不可复用**的工具（LATM：仅 3 样本造一个，强依赖训练/测试同分布）。

### 2.2 核心思想（关键 insight）
1. **工具=可执行代码片段**，且要**为任务造一批**（大而多样），而非借通用 API 或只造一个（§2 p3）。
2. **具体解要抽象成通用工具**才有复用性：变量名泛化（cat→animal）、内部文本输入提为参数、起通用名并写 docstring（§2.1 p4）。
3. **造完即验证、去重后冻结**：抽象工具须能解回原问题才算通过；按「函数名+入参数」分组去冗（§2.1 p4）。
4. **检索要多视图**：需同时匹配原问题 q、函数名 f、docstring d，再按出现频次投票（§2.2 p4）。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **Generation（min-max 采样）** | 源数据 → 问题集 Q + GPT-4 生成的正确代码解 | 造多样工具：每轮补 k=100 个「与 Q 最不相似」的问题 | §2.1 p3 |
| **Abstraction** | 具体代码解 → 通用工具函数（泛化变量名/提参/命名+docstring） | 提升复用性（本文核心增益之一） | §2.1 p4、App.C.3 |
| **Validation / Deduplication** | 抽象工具 + 原问题 → 通过/丢弃；工具集 → 去冗集 | 回解原问题验正确性；按「名+入参数」分组选最通用者 | §2.1 p4 |
| **多视图检索 + 三视图 top-k** | 目标问题 q_t → 令 LLM 生成 f_t、d_t → T_qt/T_ft/T_dt（SimCSE 余弦，k=10/5/10） | 三列表按**出现频次**聚合取最频繁 3 个；单次者丢弃；空集退回直接生成 | Eq.1 §2.2 p4 |
| **执行闭环** | 检索工具 + 生成代码 → 实例化执行 → 预测 | 工具被当作 API 嵌入生成代码 | §2.2 p4 |

### 2.4 关键表示与数据结构
- **工具 t_i = (q_i, f_i, d_i) 三元组**：造它用的原问题、函数名、docstring——即检索的三个视图（§2.2 p4）。
- **工具集 T**：可执行 Python 代码片段集合；每个工具瞄准**原子小问题**（如识别物体颜色），便于分解与人工检查（§2.2 p4–5）。
- **无记忆/经历结构**：工具集是「技能缓存」，不含具体经历、无写入/遗忘/合并（未提及）。

### 2.5 实验证据（GPT-3.5-Turbo 骨干为主，Table 2 p6）
| 任务 / 基准 | 对照 | 关键数字 | 口径 |
|---|---|---|---|

### 2.6 论文自陈局限与边界条件
- 自陈局限（App.A p15）：① **基于代码生成**，只适用「能用写代码解决」的任务，拟用伪代码扩展；② 效果**极大依赖骨干模型的
  工具使用能力**，开源模型在工具操作设定下近乎随机（故主实验仅 GPT-3.5/4）。
- 假设依赖：源数据可采样到与目标分布相关的训练样本；工具正确性靠「解回原问题」单点验证（App.C.2）。不适用：非代码可解任务、弱工具操作能力骨干。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据（具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | **✗** | 域为 VQA/表格/数学 benchmark，无生存控制环；工具是「让 LLM 生成代码」的辅助件（p1、§3 p5） | 只搬「创建→检索」双阶段形状，判据与域须重造 |
| **C2** 自然语言只作观察员接口 | **✗** | 检索键就是自然语言（q_t 原文 + 令 LLM 生成的 f_t/d_t，§2.2 p4）；三视图全是语言派生 | 键须换为结构化量（状态分档/技能契约/工具 id）；语言只留日志面 |
| **C3** 权重/记忆/技能三分离 | **◐** | 权重侧 ✓（免微调、即插即用）；**技能侧 ✓**（工具集独立于权重、可执行代码）；**记忆侧 ✗**（无独立经历记忆） | 工具集归技能 ΔS；补记忆层（对照 Memento/MemRL） |
| **C4** 低算力低带宽 | ◐ | 支持面：工具一次造好、推理时复用代码，摊薄 LLM 调用（§1 p2）。冲突面：**制造与检索都在 LLM 闭环内**，构建一次性 ~$2,500（p3） | 制造全离线入慢环；检索若进快环须去语言化 + 廉价 |
| **C5** 精准回忆历史 | — | 工具集是技能缓存而非经历库；无写入/检索/遗忘/合并经历机制（未提及） | 不涉及 |
| **C6** 可自主修改自身 | ◐ | 「造工具」=扩展自身能力结构的雏形；但**无提案/边界/验证/应用四权分离**，验证仅单点回解（§2.1 p4） | 拆四权：生成=提案权、验证=沙盒门、应用须过四级门 |
| **C7** 保存/恢复/变异/继承 | ◐ | 工具集可持久化、跨任务复用（保存/恢复）；**无变异、无淘汰-繁衍、无代际继承**（未提及） | 工具文件作 GenePackage 材料；补淘汰与繁衍 |
| **C8** 给基因先验，不给知识语料 | ◐ | 抽象工具是**程序性结构**（可遗传），但造工具时**注入了源数据的任务知识**（具体物体/列名泛化前形态） | 只留抽象后结构；剥离源数据痕迹 |
| **C9** 不设评分函数，只有淘汰函数 | **◐/✗** | **无效用打分**（优于 MemRL/EvoRoute）：检索是纯相似度 top-k + 频次投票（Eq.1）。但验证门=「解回原问题」的**模型自判成功**，**无环境实测、无淘汰函数**（§2.1 p4） | 相似度检索可保留（本就不打分）；「回解成功」降为合法性门，成败交环境淘汰 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | **✓** | L1 全借用（SimCSE、GPT-4、ViperGPT）；创新在 L2（创建→检索信息流）与 L3（工具固化生命周期） | — |

### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子；借用 SimCSE 句编码、GPT-4、ViperGPT | 符合 C10 借用立场 |
| **L2 信息流层** | **核心**：离线造工具集 / 在线多视图检索 的信息流；工具以 (q,f,d) 三元组索引 | **高**：慢环造技能 / 快环查技能的最简对位 |
| **L3 学习层** | 生成→抽象→验证→去重 的工具固化流水线 | 中：技能库构造骨架（对照 PSN/SkillWeaver） |
| **L4 演化层** | **无**：无变异、无代际、无 GenePackage | 低：仅提供「先验/语料切分」参照 |

### 3.3 模块映射
| 论文构件 | SSEA 落点（现有/缺失/新增） |
|---|---|
| 四步工具创建流水线（生成/抽象/验证/去重） | 慢环**技能制造**骨架（对接 RuleCompiler、SkillLibrary） |
| Abstraction（specific→general） | 技能表示的**泛化算子**——直接回应「技能表示够不够」（0/33 后未答） |
| Validation（回解原问题） | 四级验证门的**沙盒门**形态（须补环境实测） |
| 多视图检索 (q,f,d) + 频次投票 | `retrieve` 键**扩面**参照（对照 EvoRoute 三面检索；但须去语言化） |
| 工具集 T（可执行代码片段） | 技能 ΔS（代码形态） |

### 3.4 债务与验收实验对应
- **技能表示够不够（0/33 之后仍未答）**：CRAFT 给一臂——「代码工具 + 抽象化」，可作技能表示对照。
- **判据形状（债务 25/26/27/28）**：其「回解成功」当唯一成功门，正是「无环境实测的伪成功」反面教材。
- **`retrieve` 键收窄 → 召回精度上限低**：多视图检索是「键扩面」的早期形态（但仍是语言键）。
- 不服务：Gene Manager/DeathHook（无代际与淘汰）、睡眠期预算（无离线预演定义）。

## 5. 冲突、代价与风险

- **与硬约束的冲突**（对应 3.1 的 ✗/◐）：**C2 ✗（最硬）** 检索键=自然语言（q_t/f_t/d_t 全语言派生），须结构化；
  **C1 ✗** 域为 NLP 基准无生存环；**C9 ◐/✗** 检索不打分（正面）但验证门=模型自判「回解成功」，无环境实测与淘汰；
  **C6/C7 ◐** 自修改无四权拆分、无变异/继承/淘汰闭环。
- **隐含假设与失效条件**：① 目标任务可由代码解决；② 骨干具工具操作能力（弱模型近随机，App.A p15）；③ 训练样本与目标分布相关。
- **算力/带宽/工程代价**：构建一次性 ~$2,500；检索需算 SimCSE 嵌入 + 令 LLM 生成 f_t/d_t（环内语言调用）。
- **搬运后的退化模式**：照搬「回解成功=成功」会重演债务 25/27（环境对无消费者通道报成功）；照搬语言检索键会违反 C2。

## 6. 组合分析

### 6.1 关系图谱
| 关系 | 对象（点名） | 说明 |
|---|---|---|
| **上游原型（最紧）** | **LLMToolMakers（LATM，C/P2）** | 同族最近：LATM 只造**一个**工具、无抽象/无去重；CRAFT 补上「批量+抽象+验证+去重+检索」。LATM 卡片已点名 CRAFT 为同批对照 |
| **同族扩展** | **SkillWeaver（B/P1）** | SkillWeaver 的「提案-练习-合成-打磨」是 CRAFT 创建流水线的**下游扩展**；CRAFT 是其中「创建+检索」环节的最简形态 |
| **技能侧主干** | **PSN（A/P1）** | CRAFT 造的是平铺代码工具、无契约/门控/回滚；PSN 补上**契约、成熟度门控、故障定位、回滚**——即 CRAFT 缺的治理层 |
| **同谱系前身** | **Voyager（B/P2）** | Voyager 键/值技能库 + 自动课程；CRAFT 的 (q,f,d) 三元组索引与 Voyager 键/值技能库同源，均为「代码技能+索引」 |
| **记忆侧对照（检索器口径）** | **Memento（A/P1）** | 二者是**检索器两极端**：Memento 用**可学习 μ**（效用方向）；CRAFT 用**纯语义多视图**（无学习）。CRAFT 是「不学检索」的基线臂 |
| **两阶段 / 多面检索对照** | **MemRL（B/P2）**、**EvoRoute（B/P1）** | MemRL=相似召回→**效用重排**、EvoRoute 三面（角色/语义/工具）**并集+Pareto+Thompson 效用**；CRAFT 三视图（问题/名/docstring）**频次投票、无效用**——同一「多面召回」形状的**去效用版**，可作消融对照臂 |
| 治理/离线 | Misevolve / Dream-RSI | 工具集投毒/漂移红队；制造阶段可先在重放中验证（CRAFT 缺） |

### 6.2 推荐组合方案
- **组合**：**CRAFT（创建→检索骨架）× PSN（契约/门控/回滚）× SkillWeaver（练习/打磨）**。CRAFT 提供「批量造工具 + 抽象化 +
  多视图检索」骨架；SkillWeaver 补练习与合成；PSN 把平铺工具契约化并加成熟度门控与回滚。组合后从「造得出」升级到
  「造得出、管得住、可回滚」的技能演化链；**新增风险**：仍须把检索键与使用侧**去语言化**（C2）。

### 6.3 本篇在组合中的典型角色
- **「创建→检索」双阶段的最简原型 / 检索器「无效用」对照臂**：说明慢环造技能、快环查技能的最早形态，并为「检索用语义还是效用」提供一条纯语义基线。

## 8. 裁决与下一步

- **应用等级：C 思想启发** —— 理由：「创建→检索」双阶段是 SSEA 慢环造技能/快环查技能的**上游最简原型**，抽象化算子与
  多视图检索可回溯到 C3/C10；但控制环内全是 LLM（✗C2）、域非生存（✗C1）、验证靠「回解自判」（◐C9），机制**不可直接移植**，故与同族 LATM 一致取 C。
- **优先级：P2**（上游原型 + 检索器对照臂；不阻塞当前债务）。
- **建议动作**：① 技能表示对照实验（实验 3）把「代码工具 + 抽象化」作为一臂，检验能否改善 0/33；② 用其「回解成功=成功」作
  **反例基线**，对照 SSEA 四级门，验证债务 25/27 判据形状修正；③ 在 `retrieve` 键扩面设计中引用其「多视图 (q,f,d)」形态，但**键去语言化**。
- **最小验证实验**：A 臂「单键 retrieve」（现状）vs B 臂「多视图检索」，键再分「语言视图 vs 结构化视图」两档；判据分档（先看分母）：
  ① 机制计数（候选集大小、命中条目数）→ ② 行为差（记忆检索命中率，当前 **0.5164**）→ ③ 环境淘汰结果（**危险回避率两臂均 0.9814 已饱和，不作判据**）。
  预期多视图提升召回但候选集与时延上升；**证伪条件**——若命中率不升反降，说明多视图引入噪声>召回增益，应改加权而非并集，或先加写入准入（SEDM）。
- 若 E 不采用：不适用（本卡为 C）。
