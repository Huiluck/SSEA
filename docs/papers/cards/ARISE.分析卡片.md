## 1. 一句话定位

- **论文主张**：把技能库从「外部静态检索资源」变成**智能体状态的内生分量**（Evolving-Skill MDP，状态 s_t=(q_t, M_t)），由**同一个策略 π_θ** 同时充当 Skills Manager（执行前用条件对数概率选技能 Download、执行后用第 G+1 条 rollout 从成功轨迹蒸馏新技能 Upload）与 Worker（写解答），并配 R∈{0,1,2} 层次奖励让「用技能且做对」严格优于「不用技能做对」，使**策略改进与技能库富集共演化**（p1–5）。
- **对 SSEA 的意义**：**注意「Intrinsic」是伪友**——它指技能库是状态的内生分量，**不是**内在动机/内驱信号（核对见 §3.1.1）；因此本篇对 SSEA 的价值不在驱动信号（该部分与 C9 冲突），而在两块可拆出的**协议级零件**：① 两层 Cache(10)/Reservoir(100) + 五操作固定序的**技能库生命周期协议**（≈ 快环只读小快照 / 慢环管大档案，正对 L2 信息流与 C4 缓冲有界）；② **只判合法性、不打分的四阶段准入门 + 确定性回退 + 弃权分支**（正对 C9 第三层与债务 25/26/27/28）。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- **问题设定**：RLVR（GRPO 系）训练数学推理时，每题各解各的，rollout 结束后**成功的推理策略被丢弃而非沉淀复用**（p2）。
- **它指出的既有方案缺陷（两条，p2）**：
  1. 技能的选择（执行前）与总结（执行后）都被**外包给外部检索器**，策略梯度**无法直接塑造技能选择**；
  2. 技能库的更新**与 RL 目标脱钩**，策略改进与库富集之间的反馈环断裂。
  - 点名对照：Reflexion / ExpeL / SimpleMem（推理时检索，库一次建成即固定）；EvolveR（共演化但外部检索）、SkillRL（轨迹蒸馏建层次技能库）、SAGE（顺序 rollout 把技能增强并入 GRPO）（p3）。

### 2.2 核心思想（关键 insight）
1. **技能库应是智能体状态的内生分量**，与策略在同一目标下联合优化 → ES-MDP ⟨Q, M, A, T, R⟩，库状态 M_t 由智能体自身动作塑造，且「信息单调增长」提供隐式课程（p3、p12）。
2. **不要外部检索器**：选择用 π_θ 自己的条件对数概率 s_k = Σ_l log π_θ(m_k^(l) | q, m_k^(<l))（Eq.2），于是优势信号可**端到端**传回选择偏好（p2、p4）。
3. **层次奖励创造差分**：R = r_task + r_skill ∈ {0,1,2}，只要同组并存 R=2 与 R=1，群相对优势就给「带技能的正确解」严格更高优势；当 µ_G>1 时连「不靠技能的正确解」都被压成负优势（p5、p13）。
4. **后期收益来自选择而非积累**：库规模在 ~step 1500 饱和而准确率继续升 → 「一旦曲目够用，库的**策展**比**规模**更重要」（p8、p19）。

### 2.4 关键表示与数据结构
- 库条目 **e_k = (m_k, u_k)**：技能文档 + 标量效用（EMA 维护，β=0.9）（p3、p14）。
- 技能文档 = **JSON，五字段、总长硬顶 220 字符**（Table 4 p14）；例：`exponential_base_matching`（Fig.4 p14）。
- 种子技能 **|M_seed|=5**，编码通用启发式：equation setup、modular arithmetic check、case enumeration、symmetry exploitation、extremal principle（Table 5 p15），**与生成技能同 schema**。
- 注入格式：`SKILL:{...JSON...}` 前缀 + 问题，走 chat template；评分时技能文本截断 128 token，注入时用全文（App.C.4 p15–16）。
- 层次：Manager/Worker 两级策略层级 + Cache/Reservoir 两级库 + 三元奖励层级。**未提及**技能—子技能—元技能的技能内容层级（单据层面五字段是平的，无子技能组合）。

### 2.6 论文自陈局限与边界条件
- **明确自陈**：「当前框架**仅在数学推理上评估**；扩展到多工具智能体任务与代码生成（可复用技能是可执行过程而非推理启发式）是有前景的未来方向」（§5 p8）。
- **隐含依赖（由机制推出）**：依赖**可验证奖励**（答案为精确数值匹配 / Omni-MATH 符号等价校验，A.3 p12）——无校验器的领域 r_task 不可得。
- **未提及**：多训练 seed 的方差；跨个体/跨代继承；技能变异算子；对账外的失败模式（如技能库被污染后的恢复）；在非英语/非数学域的行为。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据（论文中的具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | **✗** | 任务是数学题求解，控制环 = 「生成 4096 token 的 CoT → 答案校验」，无生存、无闭环控制、无死亡/资源约束（p1、p6） | 只搬**库生命周期外壳**，不搬其控制环；把「题对/题错」换成环境侧生存事实 |
| **C2** 自然语言只作观察员接口 | **✗** | 语言既是动作空间（CoT token）、又是技能载体（JSON 自然语言）、又是**评分依据**（Eq.2 对技能文本求 log-prob）（p4、p16） | 技能文档换为非语言结构（契约/参数向量）；Eq.2 换为固定定义的相似度，且定义权不交模型 |
| **C3** 权重/记忆/技能三分离 | **◐** | 存储上分离（技能是库内 JSON，独立於 θ；表 4 明确不微调之外）（p14）；但 Manager/Worker/Lib-generator **共用同一 θ**，且 θ 被梯度更新、技能内容又由该 θ 生成 → 三者**来源不分离**（Eq.1 p4） | 选择面与执行面分离；选择面不得被奖励反向传播塑形；技能库只由慢环写 |
| **C4** 低算力低带宽 | **◐** | ✓ 显式上限与记账：C_c=10、文档 220 字符、评分截断 128 token、+3.0% token、+16.6% 墙钟（Table 9/10）；✗ 绝对值：8×A100、4B 基座、4096 token 生成 | 只搬「有上限 + 有分项记账」的纪律，不搬实现；睡眠期预算表照抄 Table 10 的分项格式 |
| **C5** 精准回忆历史 | **✗** | 具体轨迹被**抽象成技能后即弃**；无单条经历的精准写入/检索/合并；DELETE 是无合并的永久删除（p15–16） | 作为**反例**保留：蒸馏会丢特异性，SSEA 需记忆（具体）与技能（抽象）双轨 |
| **C6** 可自主修改自身 | **◐** | 提案权 ✓（m_new 由 π_θ 自生成，Eq.9）；边界权 ✓（schema/δ/C_c/C_r/β 均为设计者常量，Table 3）；验证权 ✓（四阶段校验是**非模型**的确定性流水线，只判合法性，D.1）；应用权 ◐（ADD 后**立即生效，无 tentative、无回滚、无逆操作、无原子升版**） | 保留前三项；应用权补 PSN 式「提案→窗验→回滚」 |
| **C7** 可保存/恢复/变异/继承 | **◐** | 保存 ✓（JSON 持久化）、恢复 ✓（Reservoir 的 LOAD 可让被淘汰技能回捞，p15）；**变异 ✗**（无变异算子，新技能全部来自蒸馏，非对既有技能变异）；**继承 ✗**（无跨个体/跨代传递，技能是语言文档、绑定特定 θ） | 只取「保存/恢复」；变异与继承另找 L4 来源 |
| **C8** 给基因先验，不给知识语料 | **◐（偏 ✓）** | ✓ 5 条种子是**通用结构性启发式**（equation setup / case enumeration / symmetry exploitation / extremal principle / modular check），且与生成技能**同 schema**（Table 5 p15）——几乎就是「基因先验」的形状；✗ 后期库内容是领域知识文本（Vieta、inscribed angle，Table 8） | 只搬种子的**形状**（少、通用、schema 一致），内容换成结构性本能；不得搬知识型技能 |
| **C9** 不设评分函数，只有淘汰函数 | **✗** | ① 淘汰函数归环境 ✓（r_task 由答案校验器给出，模型碰不到）；② **无内在驱动**，取而代之的是设计者常量 r_skill=1.0 的**技能使用奖励**（Table 3/6）——属明令禁止的**奖励塑形**；③ 选择分 s_k 由模型自身 log-prob 给出且被奖励反向传播优化（**自评分回路**）；④ 库留存用 u_k **排序**（EVICT 最低效用、LOAD 交换、DELETE 按 10 分位） | 详见 §3.1.1：保留①与「零使用」硬淘汰，删除 r_skill 与 u_k 排序，选择用固定定义的非奖励相似度 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | **✓** | 无新算子：GRPO/clipped surrogate（Eq.5–6）、Qwen3-4B / Phi-4-mini 均为借用件；创新在库作为内生状态（L2）、策略驱动选择与蒸馏（L3）、库生命周期（L4 雏形） | — |

### 3.1.1 C9 三层信号的「定义权归属」核对（本篇判定要点）

| 信号层 | ARISE 构件 | **定义权 / 取值权归属** | 模型能否改 | 判定 |
|---|---|---|---|---|
| ① 淘汰函数 | r_task∈{0,1}（精确匹配 / 符号等价校验，A.3 p12） | **环境/校验器** | 否 | **✓** |
| ② 内在驱动 | — | **无**（论文无预测误差、无内驱、无好奇心项；「Intrinsic」指技能库是状态的**内生分量** M_t，不是内在动机） | — | **✗ 缺位** |
| ②′ 替代品 A | r_skill = 1.0 技能使用奖励（Table 3、Table 6 p17） | **设计者常量**，外部设定；作用是让 R=2 严格优于 R=1 | 否（但**性质**是奖励塑形） | **✗ 违规**（C9 明令：奖励塑形一律违规） |
| ②″ 替代品 B | 选择分 s_k = Σ_l log π_θ(m_k^(l)\|q, m_k^(<l))（Eq.2） | **定义**固定（条件对数概率，架构层不可改）；**取值**完全由 θ 决定，而 θ 又被外部奖励经 Eq.1 反向传播优化 | **间接可改**（模型通过改自己权重改自己的评分分布） | **✗ 自评分回路** |
| ③ 结构提案 | m_new ← π^lib_θ(·\|q, τ^+)（Eq.9） | **模型自身**生成 | — | **✓** |
| ③′ 验证门 | 四阶段校验：抽取→解析→截断→插入（D.1 p16） | **确定性流水线，非模型**；失败即丢弃或走确定性回退 | 否 | **✓ 只判合法性、不打分**（可直接搬） |
| ③″ 留存判据 | u_k EMA（β=0.9）+ EVICT 最低效用 / LOAD 交换 / DELETE（10 分位 **且** 零使用） | 规则与 β 由设计者定；**值由奖励导出** | 否（规则） | **◐**：「零累计使用」是环境侧可数事实 → ✓；「最低效用 / 10 分位」是**排序** → ✗ |

**裁决**：C9 = **✗**。（a）标题里的 **Intrinsic 是伪友**——ES-MDP 的「内生」指技能库进入智能体状态并与之共演化，**驱动信号仍是外部可验证奖励 + 设计者加的使用奖励**，与 SSEA C9 第二层「内在驱动（预测误差/内驱，定义不可改）」不是同一物；（b）不过它有**两个合规零件**：四阶段准入门（纯合法性）+ 零使用硬淘汰（可数事实），可拆出搬入 SSEA 验证门；（c）它自己就记录了 C9 想防的病：论文承认存在「高效用但低/负 IG」的技能——即**技能只是与简单题相关、并非因果贡献**（D.3 p18），而它的补救手段只是一个**只读诊断**，不是结构性修复。

### 3.4 债务与验收实验对应
- **债务 25/26/27/28（判据形状错 / 无消费者通道报成功 / 技能失效被判成成功）**：四阶段准入门给出「先看分母」的三层计数（**入库申请数 → 格式校验通过数 → 实际被选/被用次数**），替代 0/33 式的单一失败计数；IG 诊断直接对治「技能失效被判成成功」。
- **债务「技能表示够不够」（0/33 之后仍未回答）**：给出一个**极简可检验**的表示样本（五字段 + 硬顶长度 + 同 schema 种子），把「够不够」拆成「格式是否可校验 / 是否被选中 / 选中后是否有因果贡献」三个可分别判定的问题。
- **债务「记忆二级门用常量阈值，慢环不可调」（22）**：反例式启发——ARISE 的 δ/ε/C_c/N_w/β **全是设计者常量**，但每张常量都配了灵敏度表（Table 7）；说明常量本身不是原罪，**没有灵敏度记录与可调通路**才是问题（对 C9 的加分项：这些常量不改变「谁被淘汰」的定义权）。
- **债务「睡眠期计算预算未定义」**：Table 10 的分项墙钟（生成 4.8s / 评分 2.4s / 维护 0.1s / 总计 +16.6%）是可直接照抄的预算表格式。
- **债务「retrieve 键收窄 → 召回精度上限低」**：统一 schema + 长度归一 + 「长文档 log-prob 天然更负 → 偏置短文档」的显式警告（D.1 p17）。
- **缺失组件 Gene Manager**：本篇只覆盖技能库的**保存/恢复/淘汰**，**不提供**变异与跨代继承，故不能充当 Gene Manager，只能作为其「技能库侧」子模块原型。
- **服务验收实验**：主要是**实验 3（技能固化）判据重设计**；其次是实验 4/5 解锁后为 Gene Manager 的库维护部分提供协议草案。

## 5. 冲突、代价与风险

- **与硬约束的冲突（对应 3.1 的 ✗/◐）**
  - **C1/C2 ✗**：全语言、数学推理、RLVR 训练域——控制环就是语言生成环，技能载体是自然语言 JSON，评分依据是 token log-prob。这是**领域级**冲突，不可调和，只能「只搬外壳」。
  - **C9 ✗（核心）**：r_skill 是奖励塑形；u_k 驱动 EVICT/LOAD/DELETE 排序；选择分由模型自身给出并被奖励优化（自评分回路，属 RAGEN 所说 Echo Trap 的近亲）。论文自认的「高效用低 IG」病理（D.3 p18）正是 C9 所防之病，而它的补救只是诊断。
  - **C3 ◐**：同一 θ 兼任选择/执行/生成，来源不分离——与 SSEA「三者来源、生命周期、可遗传性不同」直接抵牾。
  - **C5 ✗ / C7 ◐**：无精确经历层；无变异算子、无跨代继承。
- **隐含假设与失效条件**
  1. **必须有可验证奖励**：生存域没有答案校验器，r_task 不可得 → 迁移时必须换成环境侧生存事实（死亡/资源耗尽），形状可类比、来源完全不同。
  2. **技能必须由同一策略生成且可文本化**：SSEA 非语言域无 token 概率，Eq.2 与 O_{G+1} 均失效。
  3. **训练期在线维护**：论文证明一次性离线重构无效（此结论出自 PSN 卡片；本篇未做该对比，**本篇未提及**离线/睡眠期变体）。
  4. **退化模式（论文实测）**：随机注入 → 利用率升到 82% 而准确率降到 55.1（p8）；C_c=50 → 活跃池被稀释且评分开销 ×5 而准确率降到 55.3；去掉 O_{G+1} → 库冻结、Omni 掉最多（26.0 vs 28.0）。
- **算力 / 带宽 / 工程代价**：绝对值不可承受（8×A100-80GB、2,000 步、4B 基座、每步 59.7s）。但**协议本身极廉价**：两层库 + 五操作 + 格式门 ≈ 纯簿记，无 GPU、无训练即可落地；IG 精确计算需每 (技能, 轨迹) 两次前向，只能用代理（Eq.15）或低频抽样。
- **搬运后的可能退化模式**
  1. 弃权门阈值定坏：δ 偏低 → 大量边缘技能注入（论文 δ=0.15 时准确率 −1.2）；δ 偏高 → 技能通道形同虚设（δ=0.55 时 −1.4）。SSEA 侧表现为「技能库存在但快环永远不用」——**与当前 0/33 无法区分**，必须先有分母计数。
  2. 用 u_k 排序 → 隐性引入打分，与 C9 冲突且难以事后察觉（退化形态：技能库逐步只留下「简单处境常客」）。
  3. 只搬格式门而不搬行为验证 → 结构合法但行为无用的技能大量入库，**正是当前债务 26/27 的形态**。

### 6.2 推荐组合方案
1. **技能库三级门（ARISE × PSN × SEDM）**
   - 形态：① ARISE 四阶段**格式门**（只判合法性、不打分）→ ② SEDM **A/B 行为准入**（打包自包含、A/B 验收）→ ③ PSN **回滚验证**（近期窗验证 + 劣化阈值 + 逆操作撤销）。
   - 纪律：三级门**均不得排序**；通过/不通过二值；淘汰判据用「零使用」「劣化超阈值」等可数事实。
   - 新增能力：把当前「0/33 单一判据」换成「申请→格式→行为→回滚」四段计数，**分母可见**。
2. **有界活跃池 + 快环只读（ARISE × SSEA 双环）**
   - 形态：活跃池（≈C_c=10）作为快环只读不可变快照；档案池仅慢环可见；慢环按固定序执行 UPDATE→ADD→EVICT→LOAD→DELETE，EVICT/LOAD 不用效用排序，改用「活跃池容量上限 + 最近使用时间」等无分事实。
   - 新增能力：直接兑现 C4「缓冲不无界增长」并给 L2 一个明确的分层形状。
3. **重放中做淘汰（ARISE × Dream-RSI）**
   - 形态：入库候选先在重放模拟器上跑近期受影响情境，无因果贡献即弃（用 IG 思路但**只作只读诊断**）。
   - 新增风险：重放保真度不足会把好技能误淘汰 → 需保留「被淘汰技能进 Reservoir 可回捞」的 LOAD 通路。
4. **自改进边界表（ARISE × Gödel Agent × Misevolve）**
   - 形态：把本篇的「可改/不可改清单」显式化：可改=技能库内容与权重；不可改=淘汰定义、schema、门阈值、训练器；再交 Misevolve 红队验收。

### 6.3 本篇在组合中的典型角色
- **技能库的「生命周期管理员」与「只判合法性的门卫」**：管「技能怎么进、放哪层、什么时候被请回、什么时候死」，不参与打分与排序（排序部分须切除）。

## 8. 裁决与下一步

- **应用等级：B 零件采用** —— 理由：两块零件（两层库生命周期协议、只判合法性不打分不排序的准入门 + 弃权分支）可直接进 `skill_library` 与验证门，且正对债务 25/26/27/28 与「库分层」；但控制环与驱动信号（C1/C2/C9）与 SSEA 立场硬冲突，**整体框架不采用**。
- **优先级：P1**（与 PSN 同批，作为其库维护侧的补丁件）。
- **建议动作**
  1. `skill_library` 分活跃池/档案池，定死容量；写五操作固定序与四条边界情形（含「门拒绝时仍执行 ADD→DELETE」「空档案时 LOAD/DELETE 为 no-op」）。
  2. 验证门第 1 级照抄四阶段校验（抽取→解析→截断→插入）+ **确定性回退**；明确写入「本门不打分、不排序、只判合法性」。
  3. `Gate` 增加 abstain 分支：无候选越过阈值 → 走无技能通道并**计数**该事件（对治无消费者通道报成功）。
  4. 淘汰/遗忘判据只用「零累计使用」等可数事实，**禁止**引入效用排序与分位数。
  5. 建睡眠期预算表，照抄 Table 10 的分项格式（生成 / 评分 / 维护 / 总计+%）。
  6. 把「r_skill 类奖励塑形」与「模型自评分回路」两条写入 Misevolve 红队清单。
  7. Gene Manager 的库维护子模块以本篇为原型草案，但**明确标注**：本篇不提供变异与继承，L4 部分另找来源。
- **最小验证实验（挂在实验 3 技能固化重设计下）**
  - **三臂**（同一技能演化流，≥8 seed）：
    - A 平铺技能库（无分层、容量无上限、无格式门）；
    - B 两层库 + 四阶段格式门（**无**弃权分支）；
    - C 两层库 + 四阶段格式门 + 弃权分支 + 零使用淘汰。
  - **判据分档（先看分母）**：
    1. 机制计数：入库申请数 / 格式校验通过数 / 弃权次数 / 被选中次数 / 被用次数 / EVICT·LOAD·DELETE 次数 / 活跃池与档案池规模曲线；
    2. 行为差：逐帧或逐任务动作分布差（**注意当前危险回避率两臂均 0.9814 已饱和**，须换更难场景或分层统计，否则读不出差异）；
    3. 淘汰结果：死亡/存活——判定权在环境，模型不可见。
  - **预期与证伪**：预期 C 的「无消费者通道报成功」计数显著下降、活跃池规模平台化、档案池可回捞；**证伪条件**：若弃权率过高而行为差为 0，说明门过保守或技能表示本身不足（回到「技能表示够不够」这一未决缺口）；若只看「技能失败计数」仍会得到 0/33 式误判，则该实验设计本身需重做。
- **若 E 不采用**：不适用（有明确可搬零件）。

## 9. 待确认问题

1. **数值不一致**：Table 1 报 AIME25 48.3 / Omni 宏均 26.8，Table 2（消融，同为 Qwen3-4B full）报 49.1 / 28.0 —— 哪一版为最终数字？Omni 的聚合口径（宏平均 vs 加权）是否不同？
2. **种子数不一致**：Table 3 与 Table 5 均称 |M_seed|=5，而消融 (c) 与 Fig.3a 称「库冻结在 24 条种子技能」——24 从何而来？
3. **统计口径**：Table 1 的 32 次 run 是**评测**重复；正文未报告训练 seed 数与跨 seed 方差 → +2.5/+2.3 等增益的稳定性未知。
4. **缺一个关键消融**：论文做了「去掉层次奖励（二元）」，但没做「保留三元分层但**仅作记录、不进优势差分**」的变体——后者才是 C9 合规形态，其利用率与准确率未知（论文**未提及**）。
5. **非语言域替换**：SSEA 无 token 概率，Eq.2 的条件对数概率评分应换成什么固定定义的相似度，才能既保持「端到端可塑」又不把定义权交给模型？
6. **补卡依赖**：SkillRL（2026-02-09）、AutoSkill（2026-03-01）在本项目内**尚无卡片**；本篇与它们在「策略内生 vs 外部蒸馏」「层次化指什么」上的分工，待补卡后再定，本文不作主张。
7. **淘汰阈值迁移**：DELETE 的「10 分位」在 SSEA 侧被禁用后，纯「零使用」判据的观察窗应取多长？过短会误杀季节性有用技能（论文用 Reservoir 的 LOAD 兜底，SSEA 是否照搬？）。
