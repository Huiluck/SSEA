## 1. 一句话定位

- **论文主张**：技能应当以**可执行程序**（Python 函数）而非自由文本表示，并且**只有同时通过「重放后任务仍成功 + 重放轨迹确曾调用新技能 + 所有技能调用都造成环境变化」三条判据的程序才允许进入智能体的动作空间**；在 WebArena 上，这一「程序表示 + 执行式验证」组合比静态基线高 23.5%、比文本技能对照（AWM）高 11.3% 成功率，并减少 10.7–15.3% 步数（摘要、Table 1 p1、p5）。
- **对 SSEA 的意义**：它回答的不是一个技能库，而是**「什么条件下的经验才值得被固化成可复用技能」**——正是技能固化实验 3 实测 0/33 之后仍未回答的那一问。它给的是**入库闸**（三判据 + 反伪成功的轨迹截断）与**三档分母仪器**（尝试归纳 / 通过验证 / 实际复用），直接改写 SSEA 实验 3 的判据形状，并正面回应债务 25/27（环境对无通道报成功、技能失效被判成成功）。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- **问题设定**（§2.1 p2–3）：在线自适应场景，只有一串 NL 查询 Q={q₁…q_N}，**没有标注轨迹、也没有 ground-truth reward**；智能体策略 π_L(·|M, A) 由 LM 骨干 L、记忆 M、技能库 A 组成，M 与 A 都以上下文形式喂给 LM。每个 episode e=(q, τ) 结束后可更新 M 与 A 并跨 episode 复用。
- **指出的既有方案缺陷**（p1、§2.2 p3）：
  1. 从人类标注 / LM 合成示范中**离线**学技能，存在示范与测试任务的分布错配，且采集成本高；
  2. 在线方案（AWM 等）把技能写成**自由文本**放进记忆，只是「供参考的软指南」，**没有质量与可验证性保证**，不能被执行、不能被检验；
  3. 文本技能的三类实测缺陷（§3.3 p5）：冗余步骤多、带有样例特有上下文（如把「找游戏配件」写死进通用搜索流程）、可分任务之间的边界模糊（把「搜索商品」和「加入心愿单」混在一条里）。

### 2.2 核心思想（关键 insight）
1. **程序的两个优势是「可验证」与「可组合」**（p3）：程序能被执行从而**验证**正确性；一个函数调用把多条 primitive action 折叠成一步，从而降低规划难度、减少步数。
2. **固化必须过闸，且闸要防「伪成功」**（p4）：把原轨迹重写成「调用新技能」的轨迹前缀 τ_D 在环境里执行，再让智能体续完；**并截掉技能调用之后的尾随动作**——否则诸如 `send_msg_to_user('2')` 的尾步无论技能是否有效都会返回正确答案，产生假阳性。
3. **入库判据是三条件合取，缺一不可**（p4）：Correctness（重放后任务被判成功）× Skill Usage（轨迹中至少调用了一个新技能）× Skill Validity（所有技能调用都**造成环境变化**，排除空转）。
4. **表示要与落点配套**（§3.3 p6）：同一份已验证的程序，放在记忆里只作参考，比放进动作空间**低 3.7 分**——因为智能体尝试调用却在动作空间里调不到。程序格式与「记忆」不兼容，与「动作空间」兼容。
5. **严格准入优于宽松入库**（p6）：ASI 的程序只有 **15.6%** 的 turn 通过验证，而 AWM 有 **31.4%** 的时间直接加入新技能；入库少，端到端成功率反而更高。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **episode 过滤 V_L(e)→0/1** | episode → 布尔 | 无 ground-truth reward 时，**只对被判正确的 episode 做归纳**（E_V） | §2.2 p3 |
| **episode 清洗** | 原始轨迹 → 干净轨迹 | 删除引发执行错误的步；把思维段压缩为一句（**87.9 → 13.4 tokens/步**） | §2.3 p3 |
| **归纳模块 I（LM）** | 单个 episode → 一组技能 D（Python 函数） | 非参数地扩展**动作空间** A，而非改权重、也非写记忆 | §2.2–2.3 p3 |
| **粒度约束（prompt 级）** | — | ≥3 个 primitive action、2–5 步、≤10 行；参数只用常见变量；docstring 必须含 Args/Returns/Examples；禁用 try-except、禁用未定义动作 | 附录 A.2 p15 |
| **轨迹重写 τ → τ_D** | 原轨迹 → 调用新技能的轨迹前缀 | 用技能调用替换子轨迹，定向地测新技能 | §2.3 Fig.2 p4 |
| **尾随动作截断** | τ_D → 截断后的 τ_D | **反伪成功**：删掉最后一个技能调用之后的 primitive 动作 | §2.3 p4 |
| **前缀执行 + 续写** | τ_D 在环境执行 → 续写 τ_A | 得到可检验的完整轨迹 τ_f = τ_D + τ_A | §2.3 p4 |
| **入库三判据** | τ_f → 0/1 | Correctness × Skill Usage × **Skill Validity（技能调用必须造成环境变化）**；全过才把被调用的 D 加入 A | §2.3 p4 |
| **技能更新（+update）** | 新网站经验 → 精炼旧技能 / 新建技能 | 跨站迁移时修复不兼容技能 | §5 Table 6 p8 |
| **三档复用统计** | episode 计数 | attempted induction / successful induction / reuse examples / total | Table 8 §B.1 p15–16 |

### 2.4 关键表示与数据结构
- **技能 = 一个可调用的 Python 函数**：`def search_product(box_id: str, query: str)`，体内只调用已定义的 primitive 动作（click / fill / keyboard_press / select_option / scroll / goto / send_msg_to_user / report_infeasible 等，见 Table 7 附录 p14），docstring 含自然语言 Args/Returns/Examples（Fig.1 p2、Fig.2 p4）。
- **两类技能形态**（§B.2 p16）：① 顺序串联高频共现的 primitive 动作（`search_product`）；② 含**高级编程原语**（if-else 分支、for 循环，如 `navigate_and_sort_category`、`browse_category_by_navigation`）。
- **三分离结构**：策略 π_L = LM 骨干 L（**冻结，不微调**）+ 记忆 M（文本工作流）+ 技能库 A（可执行程序，进动作空间）（§2.1 p2、§2.2 p3）。
- **未提及**：技能**没有前置条件**（未出现 initiation set / precondition / when-to-apply 谓词），也没有预期后置效果字段——「何时该调用」完全交给 LM 读 docstring 决定；**未提及**技能的删除、剪枝、遗忘或成熟度门控；**未提及**技能库规模上界。

### 2.6 论文自陈局限与边界条件
- **自陈三条开放问题**（§7 p9）：① 技能**粒度**在概念上/经验上怎样才合适；② **在线演化过程的稳定性**；③ 技能质量相对人类专家期望如何。
- **假设依赖**：在线阶段无 ground-truth reward，只能用 **LM 评判器 V_L** 代替（p3）；归纳按**逐个网站**进行，技能可能绑定具体页面常量（如 'Marketing'、'All Reviews' 链接）（§2.3 p4）；全部组件（策略 / 评判 / 归纳）都用同一个 claude-3.5-sonnet（p5）。
- **明确不适用的情形**：跨站实验**只取 10 条**信息查询，且**排除了 admin 与 software 域**（安全/不可恢复操作风险）（p8 脚注）；程序技能绑定 Python + Web 动作空间，换域需重写动作后端（推断）。
- **未提及**：技能库的删除/剪枝/遗忘机制、库规模长期曲线、跨智能体继承、失败侧的经验利用（只从被判**正确**的 episode 归纳）。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据（论文中的具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | ◐ | 域是 Web 导航（购物/论坛/GitLab/地图），**无生存压力、无淘汰函数**；但它是**控制环路上的动作空间扩展**，不是文本生成任务（§2.1–2.2 p2–3） | 只搬判据与协议，不搬域；死亡/存活语义仍归 SSEA 环境 |
| **C2** 自然语言只作观察员接口 | **◐（运行时 ✓ / 构造面 ◐）** | **代码不是自然语言**，必须分开判：① **运行时控制闭环 ✓**——技能以 Python 函数进**动作空间**被执行，闭环里流动的是函数调用与环境状态，不是句子（Fig.1 p2、§2.2 p3）；② **构造面 ◐**——归纳模块 I 是 NL prompt 驱动的 LM，docstring/Args/Examples 是 NL 元数据，episode 清洗也是 LM 做（p3、附录 p15）。**故不能笼统判 ✗** | 运行时零语言（保留）；把 LM 归纳严格关进慢环编译面（RuleCompiler 角色），编译产物只留可执行体 + 必要结构化契约，docstring 降级为观察员日志 |
| **C3** 权重/记忆/技能三分离 | **✓** | 明确三件：LM 骨干 L（**不微调**）/ 记忆 M（文本工作流）/ 技能库 A（可执行程序）；更新走非参数路径（§2.1–2.2 p2–3） | — |
| **C4** 低算力低带宽 | ◐ | 收益侧：步数 −10.7–15.3%、长程任务 −6.6–14.6%，复用替代重复推理（Table 1 p5、Table 4 p7）；成本侧：每条候选技能都要**在环境里重放 τ_D 前缀**再续写，归纳/清洗/评判都要 LM 调用（§2.3 p4） | 重放放进 Dream-RSI 模拟器而非真实环境；归纳只在慢环触发；候选用「复用频次达到阈值」才造 |
| **C5** 精准回忆历史 | ◐ | 有 M 与 episode 记录，且从 episode 中被过滤出 E_V 供归纳（p3）；但检索、写入、遗忘、合并机制均**未提及**，不是其贡献点 | 补 Memento/FLEX 的记忆侧；本篇只提供 episode→技能这一条写入通道 |
| **C6** 可自主修改自身 | **✓** | 智能体在推理期**自主扩展自己的动作空间**（A_t ∪ D_called → A_t+1），四权齐全：**提案权**=归纳模块 I；**边界权**=只改 A 不改 L、且 prompt 限定动作白名单与粒度；**验证权**=三判据；**应用权**=加入 A（§2.2–2.3 p3–4） | 映射为慢环「ΔS 技能提案 + 四级门」；四权拆分直接照搬 |
| **C7** 可保存/恢复/变异/继承 | ◐ | 保存 ✓（技能库跨 episode 持久化并复用 42.5% 案例，Table 8）；**变异** ◐（+update 可精炼/新建技能，Table 6 p8）；**恢复/回滚 未提及**（无逆操作、无回滚）；**继承 未提及**（无跨个体传递） | 回滚与逆操作由 PSN 补；可遗传判据由 HeritableFilter 另立（本篇给不出） |
| **C8** 给基因先验，不给知识语料 | ✓ | 技能全部在线自 episode 归纳，**无外部示范、无语料灌入**（p1、§2.2 p3）；「先验」只有动作空间白名单（结构性） | 注意：技能会写死页面常量（如链接名），属自生知识，**可跨代传递的部分须由 HeritableFilter 剔除** |
| **C9** 不设评分函数，只有淘汰函数 | **◐（形状 ✓ / 信号源 ✗）** | ✓ 的形状：入库判据是**三条件合取的布尔闸**，无分值、无排序、无奖励塑形；三条里两条是**环境侧事实**（任务是否完成、技能调用是否造成环境变化）（§2.3 p4）。✗ 的信号源：**无 ground-truth reward，用 LM 评判器 V_L 判成败**（p3），WebArena 的程序化 0/1 评估器只在**基准评测**时用、在线不用（p4–5）——即由模型充当评分者 | **V_L 必须替换为环境侧淘汰/终止函数**（SSEA 的 survival outcome）；三判据的布尔形状保留，分数一律不引入 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | ✓ | 无新算子、不训练；创新在**表示的落点**（动作空间 vs 记忆，L2）、**入库协议**（重写+截断+三判据，L3）、技能更新（L3） | — |

### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无；LM（claude-3.5-sonnet）为现成借用件 | 符合借用立场 |
| **L2 信息流层** | 技能从「记忆（只读参考）」改挂到「动作空间（可执行）」；τ_D 前缀重放的数据流 | **高**：直接回答「程序表示的落点」，并与 SSEA Skill Runner 的执行面结构对齐 |
| **L3 学习层** | **入库三判据 + 反伪成功截断 + 只从被判正确 episode 归纳** | **高**：这是 SSEA 实验 3 判据形状与债务 25/27 的直接答案 |
| **L4 演化层** | 仅 +update（精炼/新建）；**无回滚、无剪枝、无继承** | 低；本篇不是 L4 论文，需 PSN 补 |

### 3.3 模块映射
| 论文构件 | SSEA 落点（现有模块 / 缺失组件 / 新增建议） |
|---|---|
| 入库三判据（Correctness × Usage × Validity） | `verification_gate.py` 的沙盒门 + 环境实测门；**Validity（技能调用必须造成环境变化）直接补债务 25/27**：环境对无消费者通道报成功、技能失效被判成成功 |
| 轨迹重写 τ→τ_D + **尾随动作截断** | 慢环重放验证协议（可落 `environment.py` 重放 / Dream-RSI 模拟器）：**截掉技能调用之后的尾步**，否则「技能无效但后续动作碰巧完成」会被记成功 |
| episode 过滤（只从成功 episode 归纳） | `ExperienceCompiler` 的候选筛选；**过滤信号须来自环境淘汰结果，不得用 LM 评判** |
| episode 清洗（删错误步 + 思维压缩 87.9→13.4 tokens） | 慢环输入的降噪前置；对 SSEA 帧级轨迹同样适用（删无效帧、压缩冗余） |
| 粒度约束（≥3 动作 / 2–5 步 / ≤10 行 / 参数只用常见变量） | `skill_library.compile_from_trace` 的**切段约束**（当前无显式粒度约束）；注意 SSEA 是毫秒级帧，阈值需按帧重标定 |
| Python 函数技能体 | `sse_protocols/skill.py` 的 `Skill.action_sequence`（**option 的 policy**，由 Skill Runner 逐帧执行）；ASI 的「动作空间」落点 = SSEA 的 Skill Runner 执行面，**结构对齐** |
| **ASI 缺失的前置条件** | SSEA **已有更强的一侧**：`Skill.precondition` = option 的 **initiation set 谓词**（债务 26 修法：取首帧动作前能量，权威生产者 `skill_library._skill_for`）。这是 SSEA 强于 ASI 的地方，**不要被反向替换** |
| SSEA 缺失的**后置证据校验** | `Skill.expected_outcome` 目前无「是否造成环境变化」的强制校验 → 由 ASI 的 Validity 判据补上 |
| 三档计数（attempted / successful / reuse）+ 42.5% 复用率 | **实验 3 判据重设计的分母骨架**（见 §8）；当前 0/33 只有一个分子，没有分母 |
| 无剪枝/无淘汰（ASI 未提及） | SSEA 已有 `skill_library.prunable`（line 318）——**这块 ASI 提供不了，不要指望它** |
| 归纳模块 I（LM 离线造程序） | 缺失组件 **RuleCompiler** 的模板（与 PSN 的 CODEGEN 同角色） |

### 3.4 债务与验收实验对应
- **「技能表示够不够」（0/33 之后仍未回答）**：本篇给出**诊断分解**——把「0/33」拆成 attempted / successful / reuse 三档分母，三种零值对应三种完全不同的病因（无候选 / 拒收 / 入库但不被调用），**表示问题只是其中第二种的一种可能**（见 §8 判据分档）。
- **债务 25/27**（环境对无消费者通道报成功、技能失效被判成成功）：Validity 判据（所有技能调用必须造成环境变化）+ 尾随动作截断，是这两条债务的**直接修法原型**。
- **债务 26**（判据形状错）：从「数 SKILL_FAILURE」改为「数三档分母」，并加入成功率/复用率/库规模曲线（与 PSN 的 SRR 指标包并用）。
- **缺失组件 RuleCompiler**：归纳模块 I 的 prompt 契约（动作白名单 + 粒度 + docstring 三段 + 禁 try-except）是可直接抄的编译规格。
- **服务验收实验 3（技能固化）的重设计**；间接服务实验 6/7（结构演化需合法技能供给）。

## 5. 冲突、代价与风险

- **与硬约束的冲突**
  1. **C9（最硬）**：成败判定由 LM 评判器 V_L 给出（p3），属「观察员评分」性质的模型自评；**必须整体替换为环境侧淘汰函数**。三判据的布尔形状可留，信号源不可留。
  2. **C1**：域是 Web 导航，无生存/淘汰语义；本文所有成功率数字都依赖 WebArena 的程序化评估器，**搬到生存域后量级全部失效**，只能搬机制不能搬数。
  3. **C2（构造面）**：归纳、清洗、评判都由 NL prompt 的 LM 承担；若 SSEA 低算力侧用小模型，归纳质量会塌（本篇未做模型强弱消融，**未提及**弱模型表现，属推断）。
  4. **C7**：无回滚、无剪枝、无继承——**库会单向膨胀**（本篇无库规模曲线，未提及）。
- **隐含假设与失效条件**：假设技能一旦验证通过就长期有效；但跨站实验显示 `sort_listings` 类技能会因页面设计变化而失效（p8），而**失效检测靠智能体自己不调用**（软性、不可靠）。SSEA 生存域里环境漂移更剧烈，需要**显式的失效检测**（precondition 破坏 → SKILL_FAILURE），这块 ASI 给不了。
- **算力 / 带宽 / 工程代价**：每条候选技能都要一次「环境重放 τ_D + 续写到 Hmax」的完整验证（p4），**验证成本 ≈ 一次完整任务试错**；再加归纳/清洗/评判三次 LM 调用。对 SSEA 慢环而言，这是**睡眠期计算预算**的一笔明确开销（当前睡眠期预算未定义）。缓解：只在候选复用频次越阈值后才造；重放跑在 Dream-RSI 模拟器。
- **搬运后的可能退化模式**：① 若把「验证通过率 15.6%」误当成目标去优化，会退化成**放宽判据换入库数**（论文结论恰恰相反：少而精更好）；② 若沿用 LM 评判器，退化为**模型自评自证**，技能库被系统性高估；③ 技能写死环境常量（如页面 ID），在环境漂移后**静默失效**（ASI 只能靠智能体不去调用来规避）。

## 6. 组合分析

### 6.1 关系图谱
| 关系 | 对象（点名） | 说明 |
|---|---|---|
| **最紧互补** | **PSN**（Evolving Programmatic Skill Networks，A/P1，技能侧主干） | 分工是**入库闸 vs 库治理**：ASI 管「这一条技能凭什么进来」（重写+截断+三判据），PSN 管「进来之后何时改、怎么重组、改坏怎么退」（成熟度门控 Eq.6、规范化重构、20% 回滚）。ASI **未提及**成熟度/回滚/剪枝，PSN **未提及**反伪成功的轨迹截断。二者无重叠，应串联 |

| 互补（失败侧） | **SkillRL**（B/P1） | ASI **只从被判正确的 episode 归纳**（明确未提及失败侧利用），SkillRL 提供**失败侧差分蒸馏**与慢环回顾配额三元组；两者合起来才是完整的「成功侧固化 + 失败侧修正」。注意 SkillRL 的 GRPO/权重更新与 ASI 的 V_L 都要按 C9 剥离 |

| 对照 | **Reflexion**（B/P2） | ASI 的验证是**执行式、环境侧**的，不是语言自我批评；本篇可替代 Reflexion 在技能固化环节的角色 |

### 6.2 推荐组合方案
1. **晶化闸：Memento/FLEX（供候选）× ASI（准入闸）× PSN（库治理）**
   - 接口形态：案例/经验库统计复用频次 → 越阈则调 RuleCompiler 生成候选技能 → **ASI 三判据**（重放前缀 + 截断尾步 + 环境变化校验，判者全为环境侧）→ 通过者入库 → 之后交给 **PSN** 的成熟度门控/重构/回滚治理。
   - 组合后新增能力：技能固化从「成功就写」变为「**有候选、有拒收、有复用三档可观测**」，且入库后不会单向腐烂。
   - 新增风险：两级门叠加会把入库率压得极低（ASI 单级已只有 15.6% 通过），需要「attempted 计数」证明不是候选生成侧饿死。
2. **离线淘汰：ASI 验证 × Dream-RSI 重放**
   - 形态：τ_D 前缀与续写在模拟器内执行，通过后再进真实环境实测门。
   - 新增能力：验证成本从一次真实试错降为一次离线重放；风险：模拟器与真实环境漂移会让验证结论失真（需 OpenSkill 的验证器可信度仪器监测）。

### 6.3 本篇在组合中的典型角色
- **技能入库闸 / 固化判据的供给者**：不负责库的结构、不负责长期治理、不负责记忆，只负责回答「这一条经验凭什么变成技能、变成之后怎么证明它真的有用」。同时附带**实验 3 的三档分母仪器**。

## 8. 裁决与下一步

- **应用等级：B 零件采用（准 A）** —— 理由：可搬的是**四件硬零件**（入库三判据、尾随动作截断的反伪成功协议、attempted/successful/reuse 三档分母、粒度契约），且它们是 SSEA 实验 3 判据重设计与债务 25/27 的**直接答案**；但**C9 冲突（LM 评判器）必须整体替换**、域为 Web 无生存语义、无回滚/剪枝/继承，故不能作技能侧主干（主干已由 **PSN** 占据）。
- **优先级：P1**（与实验 3 重设计同一批次）。
- **建议动作**：
  1. 在 `verification_gate` 增加**技能调用有效性校验**：一次技能执行若未造成任何环境状态变化 → 判失败（对应债务 25/27）；
  2. 慢环重放验证加入**尾随动作截断**：只校验「技能调用段」是否把任务推到位，尾随的补偿动作不得计入成功；
  3. 实验 3 判据从「SKILL_FAILURE 计数」改为**三档分母**：attempted_induction / passed_verification / reused，并按 PSN 的成熟度分层；
  4. `compile_from_trace` 增加显式**粒度契约**（步数区间、动作白名单、参数只用可序列化标量），阈值按帧重标定；
  5. RuleCompiler 的编译规格抄 ASI 的 prompt 契约（Args/Returns/Examples + 动作白名单 + 禁异常吞咽）；
  6. **明确禁止**搬运 LM 评判器 V_L：判者一律换 SSEA 环境侧淘汰/终止信号。
- **最小验证实验（实验 3 重设计，ASI 臂）**：
  - **双臂**：A 臂 = 现状（`compile_from_trace` + precondition 门，0/33）；B 臂 = A + ASI 三判据（重放前缀 + 尾随截断 + 环境变化校验，判者全部环境侧）。≥8 seed。
  - **判据（先看分母）**：① 机制计数——attempted / passed / reused 三档；② 行为差——技能被调用的帧数占比、每帧动作差；③ 淘汰结果——死亡/存活（模型外，不打分）。
  - **预期与证伪（这是本实验的关键，三种零值对应三种病因）**：
    - 若 **attempted=0** → 病在**候选生成/切段**，不是判据也不是表示问题；
    - 若 attempted>0 而 **passed=0** → 病在**判据**（拒收），此时「技能表示够不够」仍未证成，需查切段与 precondition 取值（债务 26 的 `_skill_for` 首帧能量）；
    - 若 passed>0 而 **reused=0** → 病在**调用面**（precondition 的 initiation set 太窄、或规划面不检索技能），**也不是表示问题**；
    - 只有 passed>0 且 reused>0 且下游行为/淘汰结果改善，才算技能固化成立。
  - **参考量级（不可作硬目标）**：论文中 reused/total=42.5%、passed/total=7.6%、passed/attempted≈45.5%（Table 8）。
- 若 **E 不采用**：不适用——至少三判据与三档分母必须进实验 3。

## 9. 待确认问题

1. **C9 的替换方案**：SSEA 用哪个环境侧信号替代 V_L 的成败判定？生存域的「任务完成」如何定义（存活时长？目标达成谓词？），才能既不打分又能做布尔闸？
2. **表 1 步数百分比与正文不自洽**：表 1 为 ASI 5.0 / vanilla 5.6 / AWM 5.9，按此反算对 vanilla 减 10.7%、对 AWM 减 15.3%；但 §3.2 p5 写作「15.3% and 10.6% than vanilla and AWM」（顺序相反、且 10.6 与 10.7 不符）。引用时需以表 1 数值为准，**是否属笔误需人工核对**。
3. **粒度阈值如何按帧重标定**：「2–5 步 / ≥3 动作」在 Web 的粗动作粒度下成立；SSEA 快环是毫秒级帧、动作为移动/取食等，等价阈值是多少？
4. **Validity 判据在非 Web 环境的定义**：「技能调用造成环境变化」在 SSEA 里对应什么？能量变化？位置变化？**无消费者通道**（债务 25）如何判定才算「无变化」？
5. **技能写死环境常量**（如页面 ID）在 SSEA 里对应「技能绑定具体状态常量」，是否应禁止、还是允许但要求 precondition 收窄？与债务 26 的 precondition 修法如何共存？
6. **SkillNet 的关系需补卡核对**：本卡对 SkillNet 的判断仅基于其 PDF 摘要（五维评估含 Executability、60 万技能库、SkillNet-Gym/Fabric），未逐节精读；其「多维打分式评估」与 C9 的冲突程度需出卡后复核。
7. **弱模型退化未测**：论文未做归纳模块模型强弱的消融（**未提及**），SSEA 低算力侧用小模型做编译器时，三判据是否仍能挡住坏技能？
