## 1. 一句话定位

- **论文主张**：用 few-shot 提示教冻结 LLM 做 **rubber duck debugging**——执行自己的代码、逐行 NL 解释、据执行结果生成反馈并修订；Spider（无单测）+2–3%（最难档 +9%），TransCoder/MBPP（有单测）最多 +12%（摘要 p1、Table 1–2 p9、Fig.6 p10）。
- **对 SSEA 的意义**：它是 **C9 的干净正向参照**——**反馈信号 = 执行结果（确定性事实）而非评分**；并给出 **C9 反面证据**：**无执行事实时纯模型自评几乎不涨且过度自信**（Table 3 p10）。但其**修订产物是语言（token 序列）**，与 SSEA 的**结构化修订产物**不同——只借「形状」与「证据」，不借「载体」。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- **问题本身**：复杂编程任务一次生成正确代码很难；重采样+rerank 需几十个候选（§1 p1–2）。
- **既有缺陷**：代码修复模型需**额外训练**；LLM 在**缺外部反馈**（单测/人类指令）时**无法自我纠正代码**（§1 p2）。

### 2.2 核心思想（关键 insight）
1. **不教模型「预测错误信息」，而教它「解释自己的代码」**：逐行解释 + 对照问题描述，模型即可自行发现缺陷（§3 p3–4）。
2. **反馈分两类，强弱悬殊**：**执行结果**（UT / trace）是外部确定性信息；**模型自判**（simple feedback）是无信息的「对/错」句——前者才是性能跃升来源（§3 p3–4、Table 3 p10）。
3. **不丢弃错误预测，而是复用**：失败程序作修订起点，显著提升 sample efficiency（§1 p2、§5.2.1 p10）。

### 2.3 关键机制 / 算法（零件清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **三步循环** Generation→Explanation→Feedback | 问题 → 候选程序 → 解释 → 反馈 → 修订程序 | 一轮自调试；通过或达上限（10 轮）即停 | §3 p3 |
| **Simple feedback** | 程序 → 「对/错，请修」句 | 最弱反馈，无解释步 | §3 p3 |
| **Unit Test (UT) feedback** | 失败用例 + 实际输出 → 反馈文本 | **注入执行事实**（确定性） | §3 p3、Fig.5 p8 |
| **Code Explanation (Expl.)** | 程序 → 逐行 NL 解释 | 无单测时的主要信号（Spider） | §3 p4 |
| **Execution trace (Trace)** | 程序+样例输入 → 逐行轨迹（**模型生成，非真实执行**） | 有单测时的补充信号 | §3 p4 |
| **执行式候选选择 / 成功轮自检** | n 候选 → 执行结果多数票；过单测代码 → 自检且**仍过测试才采纳** | 选初始程序（**选择步**）；防伪成功 | §2 p2–3、App.G.5–G.7 p76–77 |

### 2.4 关键表示与数据结构
- **无持久结构**：全部状态在**单次推理的 prompt 上下文**里；few-shot 示例**人写死**（App.E–G p67–78），不演化、不落盘、跨 episode 无存储。**未提及**记忆库、技能库、版本化。

### 2.5 实验证据
| 任务 / 基准 | 对照基线 | 关键数字 | 统计口径 |
|---|---|---|---|
| Spider Dev（无单测） | Codex 81.3；MBR-Exec 75.2；LEVER 81.9 | Codex **81.3** / +Expl **84.1**；extra hard **63.9→72.9（+9%）** | Table 1a/2a p9、Fig.6b p10；未报 seed |

### 2.6 论文自陈局限与边界条件
- **无独立 Limitations 节**（v2 亦无）。§7 未来工作（p14）：假设「解释能力↑ → 调试能力↑」；**「模型生成的语义错误反馈并不比逐行解释更有用」**。
- **边界条件**（推断自设定）：① 产物须**可执行**；② 有单测以单测为准，**无单测只能靠模型自判**（Spider）；③ 停机=判据通过或固定 10 轮（§5 p7）。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据 | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构 | **✗** | 域为代码生成，无生存信号、无淘汰闭环（§4 p4–6） | 仅作反面/对照；不搬运 |
| **C2** 自然语言只作观察员 | **✗** | 语言（解释/反馈/代码）**就是**改进闭环唯一载体；模型既提案又判断（§3 p3–4） | 只取「执行事实作门」一条，语言回路整体不入 |
| **C3** 权重/记忆/技能三分离 | **◐** | 骨干**冻结、不微调**（✓ 权重不动，§5 p6）；但**无外置记忆、无技能库**，改进全在 in-context、随 episode 丢弃 | 保留「权重冻结」，记忆/技能另配（Memento/FLEX/PSN） |
| **C4** 低算力低带宽 | **◐** | 无训练无梯度（✓）；但迭代式长上下文、最多 10 轮、前沿 LLM，token 随轮数增长（§5 p7） | 只借「单轮内闭环」形状 |
| **C5** 精准回忆历史 | **✗** | **无任何外置可检索记忆**；失败预测仅在**同一题内**复用（§1 p2） | — |
| **C6** 可自主修改自身 | **◐** | 模型可改**自己的产物**（代码文本），但改的是**实例产物**非架构/参数；四权不分（提案+应用同一轮；验证=外部执行器；无边界权）（§3 p3） | 只借「执行器作独立验证」这一半 |
| **C7** 保存/恢复/变异/继承 | **✗** | 无版本化、无种群、无继承；few-shot 示例人写死 | — |
| **C8** 给基因先验，不给知识语料 | **—** | 无基因先验概念；演示携带任务知识但不跨代（无继承机制） | — |
| **C9** 不设评分，只有淘汰 | **◐（本篇核心）** | **正向**：UT 反馈 = **执行结果**（确定性事实、pass/fail、**不打分不排序**），与「验证门只判合法性」同形（§3 p3、Fig.5 p8）。**反面证据**：无执行事实时（Spider simple feedback）**几乎不涨**，纯模型自评**过度自信**（Table 3 p10）。**扣分**：① 无 UT 时以**模型自判**为反馈（观察员评分，违规）；② 初始程序用**执行式多数票**选择（非打分，但仍是**选择/排序**步，§2 p2–3） | 只取①层信号（执行事实）作门；**去掉**模型自判路径与多数票选择，改为合法性门 + 模型外淘汰 |
| **C10** 创新在 L2/L3/L4 | **◐** | 无新 L1 算子（✓ 借用 LLM）；但创新落在**推理期提示协议**（L2 边缘、语言内），非结构创新 | 仅作 L2 对照形状 |

### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子，用现成 LLM | 符合「L1 借用」 |
| **L2 信息流层** | 「生成→解释→反馈→修订」**推理期环路**（§3 p3） | 中：给出**语言内**版本的修订回路，作对照 |
| **L3 学习层** | **无学习**——不更新权重、不写记忆，改进随 episode 消失 | 低：反证「不进 L3 的测试时修订」上限 |
| **L4 演化层** | —（无） | — |

### 3.3 模块映射与「与三级门/慢环修订提案相近」是否成立
| 论文构件 | SSEA 落点 |
|---|---|
| UT 反馈（执行事实） | **验证门二/三级（沙盒/回归）的确定性判据形状**（同形，SSEA 已有） |
| 「解释 + 反馈 → 修订」回路 | **慢环修订提案的对照臂**：形状像，但**产物层级不同** |
| 成功轮自检（仍过单测才采纳） | **反伪成功**弱形态；对照 **ASI** 的三判据硬闸 |
| 执行式多数票选择 | **✗ 不进模型**（C9） |

**判定：形状成立，内容不成立。**
- **成立**：① 反馈是**确定性事实**（跑一遍、比对输出、pass/fail），与三级门判据同源；② **同一判据逐版本重跑**，与回归门「每版都过门」同形；③ 不丢弃失败产物而**修订重提案**，与慢环修订提案同形。
- **不成立（关键）**：① **产物层级**——Self-Debug 修订 **token 序列（语言）**，SSEA 的 ΔS/ΔM/ΔR/Δθ 是**结构**；前者门判「文本跑得对不对」，后者门判「结构版本是否合法、是否破坏既有能力」。② **门的内容**——UT 是**任务验收用例**（实例门），三级门是**累积回归集**（版本门）；故它更像 SSEA 的**二级沙盒门 + 验收**，而非三级回归门。③ **权限**——提案与应用同体、验证外置，四权不分。④ **位置**——推理期在线、语言在环；SSEA 慢环离线、产物结构化。

### 3.4 债务与验收实验对应
- **债务 25/26/27（判据形状 / 环境对无消费者通道报成功 / 技能失效被判成功）**：**正面参照**——「以确定性执行事实作 pass/fail」是可用的判据形状；**反伪成功**（成功轮自检）与 **ASI 的尾随动作截断**同题。
- **C9 决策**：正向证据（执行事实作门可行）+ 反面证据（模型自评不可靠），支撑 SSEA 只取①层信号。
- 其余债务（记忆门/技能表示/睡眠期预算）：**未回应**。

## 5. 冲突、代价与风险
- **与硬约束的冲突**：**C1 ✗**（非生存域）、**C2 ✗**（语言在控制/改进环内）、**C5 ✗ / C7 ✗**（无记忆、无继承）、**C9 ◐**（模型自判路径 + 多数票选择违规）。
- **隐含假设与失效条件**：产物**可执行**；有单测时判据可判定；**无单测时假设模型自判可靠——论文自己证否了这一假设**（Table 3 p10，GPT-3.5/4 几乎不涨）。
- **工程代价**：机制廉价（纯提示，无训练）；但**依赖前沿 LLM 且 token 消耗随轮数增长**。
- **搬运后的退化模式**：若照搬「解释→修订」而**把产物留在语言内**，则修订无结构、不可版本化、不可回滚——退化为 SSEA 明确拒绝的形态。
- **为何仍保留在池中**：它是 **C9 少数「执行事实作门」的正向实证**，且**自证了自评反馈的失效**——两条结论可直接引用；作为**对照臂**界定 SSEA 修订产物的层级。

## 6. 组合分析

### 6.1 关系图谱
| 关系 | 对象 | 说明 |
|---|---|---|
| **同题·载体对照（最紧）** | **LLMasCode**（A/P1） | 二者都用「执行/测试作接受判据」，但**产物层级相反**：Self-Debug 产物是**语言（代码文本）**、闸是任务用例；LLMasCode 产物是**可执行代码结构**、闸是**对外层函数的确定性断言 + commit as code**。**LLMasCode 是 Self-Debug 的「结构化升级版」** |
| **互补（C9 改造参照）** | **EvoTest**（B/P1） | EvoTest 的 **UCB 评分排序**是 C9 违规点；Self-Debug 恰是**不打分、只 pass/fail** 的对照；EvoTest 的 failure 循环检测 ≈ Self-Debug 的「失败预测复用」 |
| **互补（无评分门的另一形态）** | **SelfConsolidation**（B/P1） | EvoSC 的巩固损失是**重建式 CE、不打分**；Self-Debug 的执行门是**事实 pass/fail、不打分**——一个参数侧、一个推理期，共同证明「不用价值打分也能驱动改进」 |
| **互补（反伪成功硬闸）** | **InducingProgrammaticSkills（ASI）**（B/P1） | Self-Debug 在 MBPP 只可见 1/3 单测，「过可见测试 ≠ 正确」，其对策（自检轮 + 仍过测试才采纳）是**弱形态**；ASI 的**三判据合取 + 尾随动作截断**是硬闸，可补此缺 |
| **前置/同族 · 待补** | **Reflexion**（B/P2）；**ReVeal**（**本目录暂无卡片**） | Self-Debug 是 Reflexion 在代码域的实例（§6 p13 自陈同族）；ReVeal 同属执行反馈自修复族，需补卡后确认差异 |

### 6.2 推荐组合方案
- **组合（仅作对照臂，不建主链）**：**Self-Debug（语言内修订）+ LLMasCode（结构化修订）** 作 **A/B 对照**——同一执行门，载体一语言一结构，用来**量化「产物层级」对可版本化/可回滚/可回归的影响**。
- **接口形态**：仅共享「执行事实作 pass/fail 判据」这一条；Self-Debug 侧不落盘、不版本化。
- **新增风险**：若把其语言回路误当慢环提案骨架，会引入 C2/C5/C7 三处违规。

### 6.3 本篇在组合中的典型角色
- **C9 的正向参照 + 「语言内修订」的对照臂**：界定 SSEA 修订产物必须是**结构**而非语言；不承担任何主干功能。
