## 1. 一句话定位

- **论文主张**：给冻结 LLM 一个 **verify-then-correct 外环**——先用外部工具（搜索引擎/代码解释器/计算器/PERSPECTIVE API）对初稿生成**自然语言 critique**，再据 critique 改写；无需训练与标注。在自由式 QA、数学程序合成、毒性削减三类任务普遍提升，并**自证「无工具的自评」不可靠**（摘要 p1、§4 p6–9）。
- **对 SSEA 的意义**：它是 **C9 边界最干净的实测样本**——critic 分两类：①**工具验证**（执行结果、错误信息、检索证据=外部可验证事实）②**LLM 自评**（无外部依据，等价观察员评分）。`CRITIC w/o Tool` 消融用数字证明后者**不涨甚至倒退**。SSEA 验证门只应吃第 ①类，第 ②类一律违规——这是该抄的唯一零件。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- **问题本身**：LLM 会幻觉、写错代码、产生毒性内容；传统缓解靠行为克隆/RL/自训练，需大规模人工标注，昂贵且难获得（§1 p1）。**既有方案缺陷**：**纯自反馈不可靠**——测试过的 LLM 无法准确判断「自己知道什么」，无外部反馈时自纠仅微弱提升甚至倒退（§1 p2、§C.1 p22）。

### 2.2 核心思想
1. **把「批判」外置成工具交互**：critique = 模型生成查询 → 工具返回证据 → 模型据证据写批判（§3.3–3.4 p5）。
2. **二分法（本篇最关键）**：critic 信号源有两类——**工具验证（可验证外部事实）** 与 **LLM 自评（无外部依据）**；前者是增益来源，后者不可靠。`CRITIC w/o Tool` 即拿掉工具、只留 LLM 自评（§4.1 p6）。
3. **迭代 + 停机**：`Verify⇒Correct` 可重复，「连续两轮答案不变」或达最大迭代数 n 即停（Algorithm 1 p4；QA n=3、数学 n=4、毒性 n=4）。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| verify-then-correct 外环 | 初稿 ŷᵢ → critique cᵢ → 修订 ŷᵢ₊₁ | 外环形状（与慢环提案-验证同构） | Algorithm 1 p4 |
| **工具验证 critic** | 查询/程序 → 搜索证据/执行结果/错误信息 | **环境侧可验证事实**（C9 允许形状） | §3.3 p5、§4.2 p7 |
| **LLM 自评 critic** | 初稿 → 「对/错」判断 | **观察员评分**（C9 禁止形状） | §4.1 `w/o Tool` p6、§D.1 p24 |
| 停机判据 | 连续两轮答案不变 / 达 n | 迭代纪律（可搬为慢环停机判据） | §4.1 p6、§4.2 p7 |

### 2.4 关键表示与数据结构
- 全流程为**文本拼接**：`ŷᵢ₊₁ ∼ P_M(·|℘⊕x⊕ŷᵢ⊕cᵢ)`（⊕ 为拼接，§3.4 p5）；API 结果直接与模型 query 拼接成 critique。无结构化状态、无持久记忆、无技能库（全文未提及）。

### 2.5 实验证据
| 任务 / 基准 | 对照基线 | 关键数字 | 统计口径 |
|---|---|---|---|
| QA（ChatGPT / Text-Davinci-003，AmbigNQ） | CoT 51.8/64.3、44.2/58.6 EM/F1 | CRITIC 62.0/74.9、50.0/64.9；`w/o Tool` 55.2/67.3、42.0/58.3 | 每集随机 500 例（Table 1 p6） |
| 数学（ChatGPT, GSM8k） | PoT 72.5 | CRITIC 78.2(+5.7)；`w/o Tool` 77.0(+4.5) | 官方 test split（Table 2 p7） |
| 数学（Text-Davinci-003, GSM8k） | PoT 70.1 | CRITIC 72.2；**`w/o Tool` 68.3(-1.8) 倒退** | 同上 |
| 毒性（ChatGPT, RealToxicityPrompts） | ChatGPT 0.325 | +CRITIC 0.173；`w/o Tool` 0.339（**更差**） | 1k prompts×25 代（Table 3 p8） |
| 自评可靠性（ChatGPT） | Self-Eval ACC 0.540（HotpotQA） | CRITIC ACC 0.765、AUROC 0.831 | F1>0.6 判正确（Table 5 p24） |

### 2.6 论文自陈局限与边界条件（App A p21）
- **推理延迟**：时间开销随迭代数 n 线性增长（数学修正两次≈PoT 两倍耗时）。**提示工程依赖**：效果依赖 ReAct 式手工 demonstration，不同提示构造可能影响结果；仅文本模态。
- **不可靠边界**：CRITIC 后幻觉仍未清零（36%→7%，因搜不到/误解证据）；「拒答」占 CRITIC 错误 12%（§D.2.1 p25）。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据（论文中的具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | ✗ | critique 与修订均为自然语言 token 序列，控制回路即语言回路（§3.4 p5） | 不搬框架本体；只抽「信号源二分法」 |
| **C2** 自然语言只作观察员接口 | ✗ | critiques 直接进控制闭环、作为修订输入（Algorithm 1 line 7 p4） | 语言只在日志/解释面；进环的须是结构化事实 |
| **C3** 权重/记忆/技能三分离 | — | 无记忆模块、无技能库、无参数更新；历史仅存上下文窗口 | 不涉及 |
| **C4** 低算力低带宽 | ✗ | 自陈延迟随迭代线性增长（App A p21）；每轮含工具调用+长上下文 | 借其「2–3 轮足够、可只用 1 轮」的**停机纪律**（Fig 3–5）作慢环预算上限参考 |
| **C5** 精准回忆历史 | — | 无外置可检索记忆；每次 verify 只用当前上下文 ℘⊕x⊕ŷᵢ⊕cᵢ | 不涉及 |
| **C6** 可自主修改自身 | ✗ | 显式「frozen LLMs」（p1、§5 p9）；只改输出，不改权重/结构；四权未拆 | 只借「提案-验证-应用」外环形状 |
| **C7** 保存/恢复/变异/继承 | ✗ | 无 GenePackage、无跨代机制 | 不涉及 |
| **C8** 给基因先验不给知识语料 | — | few-shot demonstration 是任务示例（知识性），非基因先验 | 不涉及 |
| **C9** 不设评分函数，只有淘汰函数 | ◐ **（核心）** | **二分法**：工具验证（执行结果/错误信息/检索证据=可验证事实）≈环境侧事实，合规；**LLM 自评**（`w/o Tool`、Self-Eval）=观察员评分，违规。论文自证后者不可靠：`w/o Tool` GSM8k 倒退 -1.8（Table 2）、毒性更差 0.339（Table 3）；Self-Eval ACC 仅 0.540≈随机（Table 5） | **只留工具验证、剥离 LLM 自评**：①验证门只吃确定性事实（执行成败/错误信息/检索命中），**只判合法性、不打分、不排序**；②PERSPECTIVE API 连续毒性分**必须改造为确定性门**（「毒性>阈值即非法」）而非打分择优；③自评置信分（A–D 加权）不得进环 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | — | 创新在推理时 ICL 外环（prompt 层），不涉及 L1 算子替换 | 外环形状可归入 L2/L3 边缘，无 L1 主张 |

### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| L1 算子层 | 无（冻结黑箱 LLM） | 无 |
| L2 信息流层 | verify-then-correct 外环 + 工具文本接口 | 形状可映射慢环「提案→验证」，但载体是语言，须换载体 |
| L3 学习层 | 无参数更新，仅推理时修订输出 | 借「修订不落盘」的反面：SSEA 需 ΔS/ΔM 落盘 |
| L4 演化层 | 无 | 无 |

### 3.3 模块映射
| 论文构件 | SSEA 落点 |
|---|---|
| **工具验证 critic** | **四级验证门（沙盒/回归/环境实测）信号源**：只接受确定性事实 |
| LLM 自评 critic | **禁止**接入验证门；可留观察员日志面（C2） |
| 停机判据（两轮不变/n 上限） | 慢环 SEL 停机判据（回应「睡眠期计算预算未定义」） |
| `w/o Tool` 消融设计 | 验证门验收的**对照臂协议**（同提示、只去工具信号源） |

### 3.4 债务与验收实验对应
- 可回应债务：**25/26/27/28（判据形状错、环境对无消费者通道报成功、技能失效被判成功）**——二分法给出「什么才算合法成功信号」；「睡眠期计算预算未定义」——借其迭代上限/停机纪律。
- 可服务验收实验：技能固化实验 3（0/33 判据形状）——验证门信号源须是可验证事实而非自评。

## 5. 冲突、代价与风险

- **与硬约束的冲突**：C1/C2（语言在环）✗、C6（冻结不自改）✗、C9 的 LLM 自评分支 ✗。**唯一可留的是 C9 工具验证分支**。
- **隐含假设与失效条件**：假设存在可靠外部工具且结果可解析；工具失败（搜不到证据）时错误转为「拒答」12%（§D.2.1 p25）。**算力/带宽代价**：延迟随 n 线性增长（App A p21），但所用工具（搜索/本地解释器/PERSPECTIVE）均免费（§D.3 p26），零训练成本。
- **搬运后的退化模式**：若把「LLM 自评」误当「工具验证」接入验证门，会重演已证伪路径——**正确样本被改错**（-4.3%，Table 7）、自评准确率≈随机（0.540）；以「机制计数上升但行为变差」形式失败。

## 6. 组合分析

### 6.1 关系图谱
| 关系 | 对象（点名论文/方法族） | 说明 |
|---|---|---|
| 前置依赖 | 外部工具（搜索/解释器/计算器） | 无工具则退化为被证伪的自评 |
| 互补 | **Reflexion**（B/P2） | Reflexion 的 Evaluator 用奖励函数/自评打分，CRITIC 把 critic 源换成工具；二者共同暴露「无外部依据自评不可靠」（CRITIC Table 4 将 Reflexion 归为 LLM 反馈、Medium reliability，p22） |
| 互补 | **SelfDebug**（D/P3） | 同为「执行反馈驱动修订」；SelfDebug 用执行结果（确定性事实），CRITIC 在数学任务用代码解释器，二者同构，可互为对照臂 |
| 替代 | **GSM8KVerifiers**（D/P2） | GSM8KVerifiers 的 verifier 是「外部评分+排序择优」（C9 反面）；CRITIC 的「只判合法性不打分」（执行结果/错误信息）是其正向替代 |
| 方法学约束 | **HarnessEval**（A/P0） | 提供判据健康度检查表；CRITIC 的 `w/o Tool` 正是「预算匹配对照」范例，可作 SSEA 验证门验收的对照臂设计参考 |
| 协议对齐 | **SkillsBench**（D/P1） | SkillsBench 用确定性 verifier + 配对对照；CRITIC 的二分法与之一致——critic 信号须可验证、可复现 |

### 6.2 推荐组合方案
- **组合**：本篇（二分法）+ HarnessEval（判据健康度）+ GSM8KVerifiers（确定性 verifier 口径）。
- **接口形态**：验证门新增「信号源准入」字段——每条 critique 标注来源 ∈ {工具验证(事实), LLM 自评(观察员)}，前者可判合法性，后者仅入日志。
- **组合后新增能力**：把「什么算合法成功/失败信号」从隐式约定变为显式规则，直接修债务 25–28。
- **新增风险**：工具本身可能失败（搜不到证据→误判），须配「拒答/挂起」而非「默认成功」。

### 6.3 本篇在组合中的典型角色
- **C9 边界判据的对照臂** + **验证门信号源准入规则的供给方**（廉价、零大算力、规则级）。

## 8. 裁决与下一步

- **应用等级**：**B 零件采用** —— 理由：框架本体（语言在环、冻结不自改、LLM 自评）与 C1/C2/C6/C9 冲突，不采用；但「工具验证 vs LLM 自评」二分法 + `w/o Tool` 消融可直接改造为 SSEA 验证门信号源准入规则，对债务 25–28 有直接价值。
- **优先级**：**P1**
- **建议动作**：
  1. 验证门规范新增「critic 信号源准入」条款：只接受确定性外部事实，禁止 LLM 自评进环。
  2. 把 PERSPECTIVE 式连续评分改造为确定性门（阈值→非法），纳入债务 25 修复。
- **最小验证实验**：
  - **双臂/消融**：A 臂=验证门只接工具验证事实；B 臂=A 臂 + 追加 LLM 自评信号（复刻 `w/o Tool`）。
  - **判据（分档）**：机制计数（自评信号条数）→ 行为差（合法样本被改错率、误判率）→ 淘汰结果（存活/淘汰差）；先看分母（n 样本数）。
  - **预期与证伪**：预期 B 臂「合法样本被改错率」上升（对照论文 -4.3% 与 Self-Eval 0.540）；若 B 臂行为无退化，则二分法对 SSEA 不成立，降级为 C 思想启发。

## 9. 待确认问题

- 需作者/团队决策：SSEA 验证门是否引入「信号源类型」显式字段，或仅在规范层约束。
