## 1. 一句话定位

- **论文主张**：发布 GSM8K（8.5K 小学应用题），并证明训练独立 **verifier** 对 100 个候选解**打分并择优**，可带来约等于 30× 模型扩容的增益，且验证随数据扩展优于微调（摘要、p2、p12）。
- **对 SSEA 的意义**：本篇是 **C9 的典型反面**——「外部评分 + 排序择优」正是 SSEA 明令禁止的形状；同时 GSM8K 的「答案是否等于标准解」是**确定性 verifier**，可改造为验证门的合法性判据（只判合法、不打分）。

## 2. 问题 — 机制 — 证据

### 2.1 问题
SOTA 语言模型多步数学推理仍会灾难性出错，自回归生成**无自我纠错**，一步错则全解不可恢复（p1）。纯生成需指数级参数；既有数学数据集模板化、解质量差（MathQA ~30% 不一致、Ape210K 无自然语言解）（p4）。

### 2.2 核心思想
1. **验证比生成简单**：把「一次生成对」换成「生成多个 + 挑对的」（p2）。
2. **验证器可自动标注**：训练信号**仅**由「解是否到达正确最终答案」决定，无需人工偏好（p5、p7）。
3. **验证数据扩展律更优**：6B verification ≈ 175B finetuning（p2、Fig 5）。

### 2.3 关键机制 / 零件
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| Verifier 训练流水线 | 生成器(2 epoch)→每题 100 候选→按答案对错标注→verifier(1 epoch) | 打分器数据构造 | §4.2 p8、Fig 4 |
| Verifier 打分 | (题目, 候选解) → P(解正确) | **外部评分函数** | §4.2 p7 |
| 测试时搜索 | 100 候选 → verifier 排序 → 取最高分 | **打分+排序择优** | §4.2 p8 |
| token vs solution 级 | 逐 token / 仅末 token 预测正确性 | token 级更不易过拟合 | §4.3 p9 |
| 联合目标 | 验证损失 + 语言建模损失（不加权相加） | 语言目标为辅助增益 | §4.3 p9、App E p20 |
| 计算器标注 | `<<表达式=结果>>`，测试时覆盖采样 | 抑制算术错误 | §4 p6、App C p17 |

### 2.4 表示与数据结构
- Verifier = 语言模型 + 一个**标量头**（单 bias + 单 gain，作用于末层 unembedding 对应特殊 token 的 logit），可逐 token 输出预测值（App E p20）。
- 数据：8.5K 题（7.5K 训练 / 1K 测试），每题 2–8 步初等算术，含自然语言解与计算器标注（p3、App A）。

### 2.5 实验证据
| 任务 / 基准 | 对照 | 关键数字 | 口径 |
|---|---|---|---|
| GSM8K 全量 | 6B finetuning vs 6B verification | verification ≈ 175B finetuning，**≈30× 模型扩容** | p2、p12；6B 为 3 seed 均值，175B 单次（Fig 5） |
| 数据扩展 | finetuning 曲线 | verifier 随数据增益显著更大，175B verifier 更早「起飞」 | Fig 5 p8 |
| token vs solution | 两种 verifier | token-level 最终更优、后期仍在改进 | Fig 6a p9 |
| 生成器/验证器尺寸 | 4 组合 | **大生成器+小验证器 > 小生成器+大验证器** | Fig 6c p9–10 |
| 测试时算力 | 候选数 25→3200 | 6B 提升至 400 候选后**转降**（对抗解骗过 verifier） | Fig 7a p10 |
| dropout / 目标消融 | 0% vs 20%；联合 vs 纯验证 | 20% dropout 显著提升；加语言目标是严格改进 | §4.3 p9、§5.2 p11 |

### 2.6 自陈局限与边界条件
- **假阳性**：部分解用**错误推理**得正确最终答案，被标为正确，污染验证器（p7、App F）。
- **对抗解**：候选过多时 verifier 被「骗过」的对抗解利用，性能转降（p10）；小 verifier 仍有效，提示其可能只依赖粗启发式而非真正验证推理（§4.3 p10）。
- 未见独立 Limitations 章节；数据集估计 ~2% 含破坏性错误、1.7% 仍有分歧（p3、App A）。

### 3.2–3.4 层级、落点与债务（压缩）
- **层级**：L1 用 GPT-3 家族、无新算子（符合算子借用）；L2 为「生成器→候选→verifier 打分→排序」反例管线；L3 仅「用答案对错自动标注」思想可用；L4 无。
- **模块映射**：GSM8K 答案对错检查 → 验证门**合法性判据**（只判合法）；verifier 打分+排序 → **禁止**接入控制环，仅作研究者侧对照仪器。
- **债务/实验对应**：回应**判据形状债务（26/28）**——提供「答案是否等于标准解」的**确定性二值判据**样本，用于校准「机制计数→动作差→淘汰」分档，并服务技能固化实验（0/33）。

## 5. 冲突、代价与风险

- **C9 硬冲突（本篇核心）**：论文增益来源就是**训练一个外部评分函数（verifier 输出 P(正确)）并对候选解打分、排序、取最高分**（§4.2 p7–8）。SSEA 验证门**只判合法性、不打分、不排序**——形状正相反：verifier 给所有候选连续分并择优，验证门对单个提案做通过/不通过二值判定，选择权交**环境淘汰函数**。论文的「答案对错」虽为二值，却被用于**训练打分器**而非直接作淘汰函数，故仍违规。
- **改造方向（只保留合法性判定、剥离打分排序）**：
  1. **保留**：用「解的最终答案是否等于标准答案」这一确定性、可复算检查，作为验证门的**合法性/正确性二值判据**（不产生连续分）。
  2. **剥离**：删除标量头 P(正确) 连续分、删除「排序取最高分」与 top-k 投票、删除以对错信号训练打分器。
  3. **替换选择机制**：候选取舍由**环境淘汰函数**决定（归环境、模型碰不到），模型侧仅保留提案权；最终得到「确定性 verifier 只回答合法/不合法」，正对应 C9 三层信号中「淘汰函数归环境」的形状。
- **隐含假设/失效条件**：verifier 有效依赖候选集含正确解（coverage），且存在**对抗解骗过 verifier** 的失效点（p10）；GSM8K 判据本身有假阳性（错误推理得对答案，p7）。
- **算力/工程代价**：175B + 100 候选与 SSEA 低算力立场相反，仅作对照，不落地。

## 6. 组合分析

### 6.1 关系图谱
| 关系 | 对象 | 说明 |
|---|---|---|
| 对照（C9 反例） | **SkillsBench（确定性 verifier）** | 二者都涉 verifier；SkillsBench 走**确定性**验证（可复算、无学习打分器），本篇走**学习打分器+排序**。SSEA 取前者合法性判定形状，弃后者打分排序。 |
| 互补 | **RAGEN** | RAGEN 的**不确定性过滤**是「不靠打分器也能筛选」的另一条路径，可作对照。 |
| 互补 | **WebRL** | WebRL 从失败造训练任务，说明「失败驱动」可替代「打分排序」；本篇的假阳性/对抗解失效点正是 WebRL 类课程要覆盖的场景。 |
| 对照 | **HarnessEval** | 关注评测 harness 的确定性与可复现；本篇「答案相等」判据可作为其确定性 verifier 的一个实例。 |

### 6.2 推荐组合方案
- **组合**：本篇（GSM8K 确定性判据）× SkillsBench（确定性 verifier 协议）。
- **接口形态**：GSM8K「题目+标准答案」→ 确定性相等检查输出二值合法性；SkillsBench 提供可复算验证外壳；共同构成验证门的**合法性判定**测试床（不含任何打分）。
- **新增能力 / 风险**：得到确定性、可复算、无评分的合法性判据，回应技能固化实验（0/33）「判据形状错」债务；风险是把「答案对错」误当奖励/分数，需在协议层显式禁止连续分与排序。

### 6.3 本篇在组合中的典型角色
- **C9 反面基准（打分+排序的教科书形状）+ 确定性合法性判据的供给源**。

## 8. 裁决与下一步

- **应用等级：D 基准对照** —— 理由：GSM8K 的「答案对错确定性检查」可作验证门的合法性判据试验场；论文主体的 verifier 打分+排序机制是 **C9 反面教材**，不得接入控制环。**优先级：P2**。
- **建议动作**：① 抽取「题目+标准答案 → 二值合法性」检查，作验证门判据的确定性实例，校准债务 26/28；② 把「打分+排序」写进 C9 合规审查反例清单，禁止连续分与择优；③ 与 SkillsBench 配对形成「合法/不合法」判定测试床。
- **最小验证实验**：双臂 A = 打分+排序择优（论文形状，仅研究者侧仪器）；B = 只保留确定性合法性判定、选择交环境淘汰。判据分档：先看**机制计数**（连续分/排序调用应为 0）→ 再看**行为差** → 最后看**淘汰结果**，先看分母（候选数/判定次数）。预期 B 臂无评分仍能稳定判定且不违规；若 B 臂必须依赖连续分才能工作，则证伪「剥离打分排序仍可行」。
- 若 **E 不采用**：不适用（本篇为 D）。
