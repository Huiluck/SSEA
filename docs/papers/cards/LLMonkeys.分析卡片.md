## 1. 一句话定位

- **论文主张**：把推理算力花在**重复采样**上，**覆盖率**（任一采样解对的比例）随采样数在**四个数量级**上增长，且常可拟合为**指数幂律** `c≈exp(a·k^b)`（Eq.2–3 p8）；但覆盖率能否**兑现为性能**取决于**精度**——有自动验证器（单元测试/证明器）时覆盖率直接等于成功率，**无验证器时多数投票/奖励模型在 ~100 采样后饱和**（摘要 p1、§4 p9）。
- **对 SSEA 的意义**：它给出「多试」的**正单调上界**，同时证明**没有可靠的淘汰/验证函数，覆盖率再高也兑现不了**——这正是 SSEA 的 C9 命题（选择压力必须来自可靠的淘汰函数）在语言域的量化实证。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- **问题本身**：训练算力扩展已被研究，**推理算力扩展**（同一问题多次采样）缺乏系统刻画（§1 p1–2）。
- **既有方案缺陷**：用户/开发者通常只让模型**试一次**；重复采样只在个别域（AlphaCode 百万采样、ARC 谜题）有零散证据，**跨任务/模型/预算的扩展律未知**（§1 p2、§6 p13）。

### 2.2 核心思想（关键 insight）
1. **覆盖率与精度二分**：重复采样的有效性由两个独立属性决定——**coverage**（能否采到正确解）与 **precision**（能否从采样集里**识别**正确解）（§1 p2、Fig.1 p2）。
2. **覆盖率可被扩展律刻画**：`log(c)≈a·k^b`，即 `c≈exp(a·k^b)`，a、b 为拟合参数（Eq.2–3 p8、Fig.5 p8）。
3. **无验证器则覆盖率无用**：正确解常以极低概率出现（1% 或更低，Fig.8 p11）；验证器必须能"大海捞针"，而主流方法做不到（§4 p9–10）。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **重复采样流程 / 覆盖率-精度分解** | 问题 → 多候选解（正温度采样）→ 验证器择优；区分上界（oracle）与实现（验证器） | 推理算力扩展的最简形状；"能采到"≠"能选出" | Fig.1 p2、§2 p3、§4 p9 |
| **无偏 pass@k 估计** | N 采样、C_i 正确数 → pass@k | 降方差地估计覆盖率 | Eq.1 p4（引 Chen et al.） |
| **指数幂律拟合** | 采样数 k、覆盖率 c → 参数 (a,b) | 覆盖率扩展律 | Eq.2–3 p8；拟合口径 §C.1 p24 |
| **三类验证器对照** | 采样集 → 最终答案 | Majority Vote / Reward Model + Best-of-N / RM + Majority Vote | §4.1 p9 |

### 2.4 关键表示与数据结构
- **覆盖率**：任一采样解正确的题目比例；有自动验证器时**等于**成功率；对 CodeContests/SWE-bench 即 **pass@k**（§2 p3–4）。
- **任务集**：GSM8K 128 / MATH 128 / MiniF2F-MATH 130 / CodeContests 140 / SWE-bench Lite 300（去 flaky 后 266）题；采样 temperature 0.5–0.6，每题 **10,000 采样**，SWE-bench 每题 **250** 次独立轨迹（§2 p4、§A p19–22、§B.1 p23）。

### 2.5 实验证据
| 任务 / 基准 | 对照基线 | 关键数字 | 统计口径 |
|---|---|---|---|
| SWE-bench Lite（DeepSeek-Coder-V2-Instruct + Moatless） | 单次 SOTA 43% | **15.9%（1 采样）→ 56%（250 采样）** | pass@k，Fig.2 p5、摘要 p1 |
| CodeContests（Gemma-2B）/ MATH（Pythia-160M） | — | 0.02% → **7.1%**（>300×）/ 0.27% → **57%**（pass@10k） | Fig.3 p5–6、§2.2 p6 |

| GSM8K / MATH 三类验证器 | 覆盖率（oracle） | 均在 **~100 采样后饱和**，覆盖率却继续升过 95% | Fig.7 p9–10 |

### 2.6 论文自陈局限与边界条件
- **假设依赖**：只做**最简**重复采样——同一 prompt、同超参、**各次完全独立**（§5 p12）；未做多样性、多轮、**从先前尝试学习**三条改进方向（§5 p12 future work）。
- **验证器缺陷实证**：SWE-bench Lite **11.3%** 题目 flaky tests（§4.2.1 p11）；CodeContests **122 题中 35 题**存在"正确解却挂测试"的**假阴性**（§4.2.2 p11）——即"自动验证器"也非完美；**验证器不可靠**时覆盖率无法兑现（§4 p9）。

### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子 | 符合借用立场 |
| **L2 信息流层** | **覆盖率-采样数扩展律** + **覆盖率/精度二分**（采样→验证→择优的信息流） | **高**：为"预算匹配基线"提供上界形状与"上界≠实现"判读 |
| **L3 学习层** | 无（各次独立、无更新） | 低：仅"从先前尝试学习"列为未来工作 |
| **L4 演化层** | 无 | — |

### 3.3 模块映射
| 论文构件 | SSEA 落点 |
|---|---|
| 覆盖率/精度二分（pass@k vs 实现） | **验收实验判读**：区分"能采到"（上界）与"能选出"（实现）——对应 HarnessEval 的 pass@k/pass@1 |
| 覆盖率扩展律 `c≈exp(a·k^b)` | **预算匹配基线的曲线形状模板**（正单调，与 MoreLLMCalls 非单调并列） |
| 自动验证器 vs 无验证器对照 / flaky tests、false negatives | **验证门/淘汰函数必要性**论据 + **债务 26/27/28**（假阳性/假阴性）的实证样本 |

### 3.4 债务与验收实验对应
- **判据饱和（危险回避率两臂均 0.9814）**：本篇"覆盖率上界与可实现性能之差随预算扩大"提示饱和可能是**实现端（验证/淘汰）不可靠**而非能力见顶。
- **债务 26/27/28（判据形状错 / 无消费者通道报成功 / 技能失效被判成功）**：flaky tests（11.3%）与 CodeContests 假阴性（35/122）是"**验证器不可靠 → 假阳性/假阴性**"的直接实证。
- **睡眠期计算预算未定义**：覆盖率扩展律给出"**多采样边际收益递减**"的数学形状（本篇为正单调，不含转负点——转负见 MoreLLMCalls）；**七条验收通用**——任何"多试后涨点"都须先报**覆盖率上界**与**实际实现**之差（先看分母）。

## 5. 冲突、代价与风险

- **与硬约束的冲突**：**C9（最关键）**——全篇以 accuracy/coverage 为度量、验证器为**评分+排序择优**（§4.1 p9）；→ 只借"覆盖率上界 vs 实现"的**判读与形状**，不搬其评分式选择；SSEA 侧把"verifier 择优"换成"**环境侧淘汰存活**"。**C1/C2**——语言任务、语言进环（p1、§2 p3）；→ 只搬预算判据。**C4**——10,000 采样/题算力重（§A）；→ 仅作离线依据。
- **隐含假设与失效条件**：假定存在**可识别正确解**的验证器；论文自己证明该假定在无自动验证器域（MATH/GSM8K）**不成立**（§4 p9）。**算力/带宽/工程代价**：搬运为**协议级、零在线算力**，成本在"重跑匹配预算基线"。
- **搬运后的退化模式**：若照搬"多数投票/奖励模型择优"，会引入**新的外部评分系统**（C9 违规），且重演"~100 饱和"的失效。

## 6. 组合分析

### 6.1 关系图谱（三篇同主题：「增益来自更多尝试还是更好设计」）
| 关系 | 对象（点名） | 说明 |
|---|---|---|
| **同主题·正单调上界（本篇）** | **MoreLLMCalls**（D/P1） | 本篇证"覆盖率随采样数**正单调**增长（4 个数量级）"；MoreLLMCalls 证"**混合难度下调用数-性能可非单调**（inverse-U/U）"——**同一问题的正/反两面**，须并读方能定预算匹配基线口径 |
| **同主题·归因纪律** | **HarnessEval**（A/P0） | 本篇的 **coverage(=pass@k) vs precision** 二分，正是 HarnessEval "**增益只在 pass@k 出现就不是设计改进**"的语言域实证；HarnessEval 补上"预算匹配基线 + 搜索/评测分离"的方法论 |
| **点名连接·验证器可靠性** | **TTCS**（B/P1） | TTCS 用 **majority voting 一致率 s** 作无标签难度信号；本篇证 **majority vote 在 ~100 采样后饱和且不可靠**（尤其难题）——直接给 TTCS 的 s 一个**可靠性警告** |
| **点名连接·验证器家族** | **GSM8KVerifiers**（D/P2） | Cobbe 的 **trained verifier + best-of-N** 正是本篇测试的 "reward model + best-of-N" 家族源头；本篇给出其**随采样预算增大而饱和**（Fig.7 p9–10）的负面标定 |
| **点名连接·确定性验证** | **SkillsBench**（D/P1） | SkillsBench 的**确定性 verifier（reward∈{0,1}）** 正是本篇所称"自动验证器"（单元测试/证明器）形态；本篇论证**只有这类可靠验证器才能让覆盖率兑现**——支持 SkillsBench 走确定性 verifier 而非 LLM-judge |

**三篇横向对账（一句话）**：重复采样给出**正单调的覆盖率上界**（LLMonkeys）；该上界能否兑现取决于**验证器可靠性**（LLMonkeys：无验证器则 ~100 饱和）与**任务难度混合**（MoreLLMCalls：混合难度下加预算可有害）；而任何"设计增益"必须先在**同等预算**下证明不是 pass@k 的搜索增益（HarnessEval）。

### 6.2 推荐组合方案
- **组合 / 接口形态**：本篇 **× MoreLLMCalls × HarnessEval**（+ 验证侧 GSM8KVerifiers / SkillsBench、难度侧 TTCS）——**LLMonkeys** 提供"**覆盖率上界 + 验证器可靠性**"；**MoreLLMCalls** 提供"**预算曲线形状 + 最优预算**"；**HarnessEval** 提供"**怎么测得公平**"（预算匹配基线 + pass@1/pass@k + held-out）。
- **组合后新增能力 / 风险**：七条验收的"预算匹配基线"臂同时拥有**上界形状（本篇）+ 非单调警示（MoreLLMCalls）+ 归因纪律（HarnessEval）**；风险是三篇合流若不约束会退化成新的**外部评分系统**（C9），须硬性规定只输出**淘汰存活/拒绝**。

### 6.3 本篇在组合中的典型角色
- **覆盖率上界供给器 / 「多试≠有效」的验证器标尺**：管"多试能采到多少"与"采到了能不能选出来"。

## 8. 裁决与下一步

- **应用等级：D 基准对照** —— 理由：**不提供**可插拔算法零件（C3/C5/C6/C7/C8 全"未提及"），且以**外部评分**为核心（C9 ✗）；但其**覆盖率/精度二分 + 扩展律 + 验证器可靠性实证**是 SSEA"预算匹配基线 / 淘汰函数必要性"的**直接量化论据**，必须作为**对照参照**保留。
- **优先级：P1（近期）** —— 与 MoreLLMCalls 同主题、协议级、零在线算力，可在下一轮七条验收前挂上。
- **建议动作**：① 在判据健康度检查表中，为"预算匹配基线"条目补**覆盖率上界 vs 实际实现**的显式对照口径；② 为实验 2/3 报**覆盖率上界**（oracle）与**实际可实现**之差；③ 建立 issue：`覆盖率上界与验证器可靠性（LLMonkeys）`，挂实验 2（饱和）、实验 3（0/33）；④ 与 MoreLLMCalls / HarnessEval 并读，标定三篇同主题口径。
- **最小验证实验**（以**实验 3 技能固化 0/33** 为对象）：
  - **双臂设置**：**臂 A**＝多试 + **接入可靠淘汰/验证**（环境侧存活判定）；**臂 B**＝多试但**淘汰/验证不可靠**（随机选或多数票式弱聚合）。
  - **判据分档（机制计数 → 行为差 → 淘汰结果；先看分母）**：① 机制计数（分母：多少 seed / 多少尝试 / 多少候选）；② 行为差（覆盖率上界 vs 可实现性能之差，臂 A vs 臂 B）；③ 淘汰结果（技能在**未参与编译**条件下是否存活）。
  - **预期与证伪**：**预期**——臂 B 覆盖率上界虽升，但可实现性能不升（重演 ~100 饱和）⇒ 证明"**没有可靠淘汰函数，多试无效**"。**证伪**——若臂 B 在无可靠淘汰下仍随尝试数稳定提升 ⇒ 本篇结论不适用该场景，须另找 0/33 成因。
- 若 **E 不采用**：不适用（裁决为 D）。
