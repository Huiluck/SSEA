## 1. 一句话定位

- **论文主张**：以技能为中心的网页智能体自改进框架，三阶段——**技能提案**（系统探索网站，
  提出程序性/导航性/信息搜寻三类超出当前技能库的任务）、**技能合成**（反复练习、LLM 奖励
  模型判成败，静态分析动作序列后 LLM 把成功轨迹封装成带前置状态文档的可复用 Python API）、
  **技能打磨**（以默认页面独立单元测试 + 调试，必要参数自动生成测试用例）；合成的 API
  plug-and-play，且可由强模型合成、弱模型直接使用（p3–5）。
- **对 SSEA 的意义**：提供**技能构造生命周期的网页/工具环境版**（与 PSN 的契约化治理
  配套），其「强模型造、弱模型用」是 GenePackage 跨能力继承的直接形状；前置条件文档与
  API 选择门是 C9 友好的分类式检查。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- 网页动作空间高度复杂，现有跨网站训练方法依赖大规模轨迹数据集、过拟合特定网站结构，
  对未见网站泛化弱（p1）。
- 轨迹式技能（trajectory memory）有三大问题：抽象层次浅、泛化弱；持续更新对网站变化
  敏感；存储/共享轨迹（每条约 0.3 GB）难以在智能体间转移（p2）。

### 2.2 核心思想（关键 insight）
1. **技能应是抽象、可复用的 API，而非轨迹**：Python/Playwright 函数体积极小、可组合、
  可跨网站/跨智能体共享（p2、Fig.2）。
2. **无需外部监督**：环境探索 + LLM 奖励模型即可发现并验证技能（p2）。
3. **三类任务覆盖网站功能空间**：程序性（原子动作序列工作流）、导航性（构建概念地图）、
  信息搜寻（数据抽取/枚举）（p3）。
4. **组合 API 随迭代自发涌现**：一个 API 内部调用多个更简单 API（p8）。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **技能提案** | 网站观测（截图/URL/无障碍树）+ 课程提示（简单→复杂）→ 三类任务 | 系统探索、技能边界扩张 | §2.1 p3 |
| 程序性任务 | 原子动作序列 → 可泛化工作流（如识别药→填文本框→点提交） | 流程型技能 | p3 |
| 导航性任务 | 探索分区/页面 → 概念地图（如访问评论区、用户资料） | 空间型技能 | p3 |
| 信息搜寻任务 | 网页数据 → 抽取/枚举（如提交列表、仓库修订） | 数据型技能 | p3 |
| **技能练习** | 反复尝试 → 成功轨迹（奖励模型判定）；信息类同时合成抽取代码 | 素材收集 | §2.2 p4 |
| **奖励模型** | 任务描述 + 动作轨迹 + 截图/描述序列 + 执行结果 → 成败 | LLM 评估器 | p4 |
| **API 合成** | 静态分析每动作 → LLM 生成 Python 函数（签名/文档串含前置状态与使用日志/函数体） | 轨迹→可复用 API | Fig.2 p4 |
| **技能打磨** | 默认 Playwright 页面独立单元测试 → 失败调试；LLM 生额外参数与测试用例 | 入库前可靠性验证 | §2.3 p5 |
| API 选择模块 | 推理时选相关 API、移除前置不满足者 | 门控式选择 | p6 |
| 组合 API | 迭代后 API 调用多个简单 API | 层级技能 | p8 |

### 2.4 关键表示与数据结构
- 技能=Python 函数（Playwright）；文档串记录前置状态与既往使用日志；技能文件即外部
  记忆，体积小、可序列化共享（p4）。

### 2.5 实验证据
| 实验 | 对照 | 关键数字 | 出处 |
|---|---|---|---|
| WebArena（160 迭代 GPT-4o） | CodeAct 基线 | 相对提升 **39.8%（GPT-4o）/54.3%（GPT-4o-mini）** | Table 1 p7 |
| Table 1 分项 | — | GPT-4o 22.8→29.8（Δ32%）；GPT-4o-mini 9.2→14.1（**Δ45%**）；Gitlab/CMS 增益大 | Table 1 p7 |
| Online-Mind2Web（4 个真实在线网站，57 任务） | 基线 | 平均 **+39.8%**；Drug +151%、Flight +20%、Car +0% | Table 2 p7 |
| 弱智能体实验 | GPT-4o-mini + GPT-4o 合成的 API | 跨网站增益 **40%–133%**（无需改设计） | p7 |
| 人工官方 API 对比 | 低/中/高 API 支持度网站 | 低支持站点（Reddit）合成 API 可比；高支持（Gitlab/Map）不及官方 | Fig.3 p8 |
| 组合 API 案例 | — | 迭代后自发形成多 API 组合（关覆盖层等） | p8 |
| 失败案例 | Cookpad/S3 | 两类失败：找错 API（参数错）、关键词错（视觉/语言理解） | p8 |

### 2.6 论文自陈局限与边界条件
- LLM API 调用（如 cuisine_type）仍会出错，弱模型更甚；高 API 支持站点不及人工；
- 最后几步强环境理解/视觉推理仍是短板；探索 160 迭代成本不低。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据 | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | ◐ | 网页域；运行时执行 Python API | 机制迁移到生存行为 |
| **C2** 自然语言只作观察员接口 | ◐ | LLM 提案/练习/合成；产物运行时为非语言代码 | LLM 工作放慢环 |
| **C3** 权重/记忆/技能三分离 | ✓ | 无权重更新，技能为外部文件 | — |
| **C4** 低算力低带宽 | ◐ | 160 探索迭代 API 密集；API 复用摊销、弱模型借 API 大幅增益 | 探索离线、提高复用 |
| **C5** 精准回忆历史 | ◐ | 技能文件即外部记忆（非情景） | 技能/经验分层 |
| **C6** 可自主修改自身 | ◐ | 能力经技能持续增长 | 映射技能库增长 |
| **C7** 保存/恢复/变异/继承 | **✓/◐** | API 跨智能体 plug-and-play（可继承产物）；无恢复机制 | 技能文件作基因包材料 |
| **C8** 给基因先验，不给知识语料 | **✓** | 强模型合成 API、弱模型继承使用=能力先验；无语料 | — |
| **C9** 不设评分函数，只有淘汰函数 | **◐（偏 ✓）** | 无模型内分数；奖励模型只输出成败、API 选择以前置条件分类过滤 | 成败判定移出模型；保留前置门 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | ✓ | 创新在技能信息流(L2)与构造生命周期(L3) | — |

### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子 | 符合借用立场 |
| **L2 信息流层** | 提案-练习-合成-打磨-选择流 | **高** |
| **L3 学习层** | 技能构造与验证闭环、组合涌现 | 中-高 |
| **L4 演化层** | 强→弱 API 继承、跨网站泛化 | 中 |

### 3.3 模块映射
| 论文构件 | SSEA 落点 |

## 5. 冲突、代价与风险

- 探索期 API 调用密集（C4），应离线、与重放预筛配套。
- LLM 奖励模型判成败可能出错（与 Misevolve 工具路径风险同源）。
- 高 API 支持环境下合成件不及人工官方件（抽象有缺口）。
- 网页域非生存；弱模型最后一步视觉/语言理解短板在生存域可能对应关键动作失败。

## 6. 组合分析

### 6.1 关系图谱
| 关系 | 对象 | 说明 |
|---|---|---|
| 前置依赖 | 可执行 API 环境、静态分析、测试运行器 | SSEA 部分具备 |
| 治理升级 | **PSN** | SkillWeaver 流水线 + PSN 契约/门控/回滚 |
| 同域前身 | Voyager | Minecraft 版技能库；SkillWeaver 为网页版且 API 化 |
| 同日同伴 | Inducing Programmatic Skills | 程序化技能诱导对照 |
| 廉价验证 | Dream-RSI | 练习/打磨在重放中先行 |
| 通用化 | Alita | Alita 以技能文件承载通用能力 |
| 风险治理 | Misevolve | API 合成/复用须过工具路径红队 |
| 同域基线 | CodeAct、SWE-bench 类 | 对照 |

### 6.2 推荐组合方案
1. **技能构造治理全包（SkillWeaver × PSN × Dream-RSI）**
   - 提案/练习（SkillWeaver）→ 重放中验证（Dream-RSI）→ 契约化入库 + 门控/回滚（PSN）。
2. **强→弱基因继承（SkillWeaver × MemRL/SEDM）**
   - 强模型合成的 API 经迁移重验后进入 HeritableFilter，弱模型零探索继承。
3. **网页-具身迁移（SkillWeaver × Voyager）**
   - 统一技能文件格式（前置文档 + 使用日志），跨环境共享技能构造管线。

### 6.3 本篇在组合中的典型角色
- **技能流水线工头 / 强→弱蒸馏器**：管「网站上有什么可学、怎么把成功动作变成 API、API 能不能可靠复用」。

## 8. 裁决与下一步

- **应用等级：B 零件采用** —— 采用技能提案/练习/合成/打磨流水线、前置文档、单元测试与
  强→弱可移植协议。
- **优先级：P1**。
- **建议动作**：
  1. 为工具/可执行环境实现三阶段技能构造管线，全程慢环；
  2. 技能文档统一含前置状态与使用日志，入库前必须独立单元测试；
  3. 推理时技能选择走前置门，不满足条件不调用；
  4. HeritableFilter 支持「强模型造、弱模型用、迁移前重验」；
  5. 组合 API 的形成过程记录谱系，支持回滚。
- **最小验证实验（技能流水线，服务实验3）**：
  - 对比：无技能/轨迹记忆/合成 API；≥8 seed；
  - 判据：技能数与覆盖率（分母）→ 逐任务成功率差 → 模型外淘汰；
  - 预期：合成 API 臂在新网站/弱模型上显著少探索、高成功；轨迹臂转移成本高、泛化弱。
