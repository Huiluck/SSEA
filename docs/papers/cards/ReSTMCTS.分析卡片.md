## 1. 一句话定位
- **论文主张**：自训练瓶颈是「答案对≠推理对」（假阳性中间步）；把 **MCTS\* 树搜索**放在**过程奖励模型 V_θ** 引导下采集高质轨迹与逐步价值，并用**互自训练**（policy 与 value model 同时迭代）互相改进——无需逐步人工标注，靠「给定 oracle 终答案，估计该步通向正确答案的概率」自动造逐步标签（摘要 p1、§3）。
- **对 SSEA 的意义**：**其过程奖励模型是 C9 的教科书反面**（训练打分器 + 用它给搜索排序），须逐条判 ✗；但「**用搜索产生的轨迹做离线自训练**」的形状，与 SSEA 慢环「回顾编译（trace→Δ）＋前瞻预演（搜索）」双通路**结构同构**——可作**形状参照**（改权重须换为发布 ΔS/ΔM，评分须换为淘汰）。
## 2. 问题 — 机制 — 证据
### 2.1 论文要解决的问题
- 问题本身：现有 LLM 自训练（STaR/RFT/ReSTEM/V-STaR）**只按最终答案对错筛样本**，即使轨迹得对答案，中间步也可能错或无用（假阳性），微调集质量低（p1–2）。
- 既有缺陷：① 用可靠 PRM 逐步验证需**密集人工标注**，不可扩展（p2）；② 用 ORM 做树搜索剪枝/回传须**完整生成**每条轨迹，昂贵低效（p5）。
### 2.2 核心思想（关键 insight）
1. **逐步标签可自动造**：给定 oracle 终答案，用**足够次数的 rollout** 估计「此步通向正确答案的概率」即得过程奖励，免人工标注（摘要、§3.2）。
2. **质量值 = 过程奖励 × 距离权重**：v_k 由 PRM 打分 r_{s_k} 与「推理距离」m_k（还差几步到正确答案）合成，越接近终点权重越高（Eq.1–2、Observation 1–3 p4–5）。
3. **搜索即数据工厂**：MCTS\* 既是推理策略、又是**自训练数据采集器**——剪枝→验证→逐步推断 v，产 (Q,p,v) 供 PRM 与 policy 互训（图 1、图 4、Algorithm 1）。
### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **质量值 v_k** | 前值 v_{k−1} + 加权奖励 w_{s_k} | 部分解质量（搜索引导目标） | Eq.1 p4 |
| **加权奖励 w_{s_k}** | r_{s_k}(PRM 分)、m_k、v_{k−1} | 单步质量，含推理距离权重 | Eq.2 p4 |
| **推理距离 m_k** | 部分解 p_k → 到正确答案最少步数 | 难度/进度（隐藏量，rollout 估计） | §3.1 p3–4 |
| **过程奖励模型 V_θ** | (q,p) → v 标量（加线性层） | **打分器**，引导 MCTS\* | §3.1、Eq.37 p25 |
| **MCTS\*** | 搜索树 → 轨迹 + 逐步 v | 四阶段：选点/扩展/贪婪 rollout/回传；含 self-critic | §3.1、Algorithm 2 p5、C.1 p21 |
| **互自训练** | π_{S_{i−1}} + V_{i−1} → π_{S_i} + V_i | policy SFT + value MSE 交替迭代 | Algorithm 1 p6 |
| 数据生成四步 | 搜索→剪枝→验证→奖励推断 | 造 (Q,p,v) 与正确轨迹集 | 图 4 p24 |

### 2.4 关键表示与数据结构
- 搜索树节点 C=(p_C, n_C, v_C)：部分解、访问数、质量值；每问 q 一棵树 T_q（p5）。
- 超参（§E.2 p25）：结束阈值 **0.9**、rollout 步限 **m=2**、α=0.5、迭代 **T=50**、扩展分支 **b=3**。
- 初始 PRM 训练集 D_V0：SciInstruct 11,554 问 + ChatGLM2 生成错误步×3，共 **473.4k** 样本；初版 value model 准确率 **69.3%**（14k 测试样本，容差 0.1）（p7、Eq.38 p25）。

### 2.6 论文自陈局限与边界条件（§H p30）
- **依赖 oracle 标签**：首轮筛选靠监督集真答案；未证明可推广到无真值任务（编码、agent、对话、SWE-Bench）。
- **value model 规模/多样性**：初始集由 SciGLM 生成、偏数理，需更大 backbone 与更多域。
- **数据筛选技术**：轨迹质量决定自训练效果，仍需更强 top-k 过滤；自陈「更优做法可能是**在线 RL**」（§6 p10）。
## 3. SSEA 立场对齐（核心维度）
### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据（论文具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | ✗ | 域为数学/科学题；控制对象是语言 token 序列（p1、§3.1） | 仅借「搜索↔编译」信息流，控制信号换结构化生存量 |
| **C2** 自然语言只作观察员接口 | ✗ | 题、步、奖励、self-critic 全为自然语言，语言在闭环内（图 1、§F） | 预演在结构化状态上做，语言不入环 |
| **C3** 权重/记忆/技能三分离 | ✗ | π 与 V_θ **两个权重网络共训**；无独立记忆/技能（Algorithm 1 p6） | 预演产出走 ΔS/ΔM 分离；不接受权重共训 |
| **C4** 低算力低带宽 | ✗ | MCTS\* **108 s/题**；T=50、b=3；自陈 prompt token 随 b,T 快速上升（Table 6、§E.4 p26） | 预演必须有预算闸；先做零 rollout 结构检查（见 SkillNet） |
| **C5** 精准回忆历史 | ✗/— | 仅搜索树内 (p,n,v) 统计，无跨 episode 检索/写入/遗忘/合并 | 记忆侧交 Memento / FLEX |
| **C6** 可自主修改自身 | ◐ | 迭代改**权重**（policy SFT + value MSE，Eq.37），无四权分离 | 提案归慢环、验证归门、应用原子升版 |
| **C7** 保存/恢复/变异/继承 | ✗ | 无 GenePackage、无变异/继承（仅权重 checkpoint） | 不搬 |
| **C8** 给基因先验，不给知识语料 | ✗ | 预训练语料 + 自训练把任务知识写进权重（p7） | 基因只放结构先验 |
| **C9** 不设评分函数，只有淘汰函数 | **✗（本篇主战场，逐条见下）** | V_θ 输出连续 v 分；MCTS\* 据 v **选点/剪枝/回传**；验证器据分**排序择优**（Eq.1–2、§3.1、§4.3） | 剥离评分器与排序，只留「答案对错」二值淘汰（见 §5） |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | ✓ | 无新算子（ChatGLM3/Mistral、MCTS/UCT 全借用）；创新在搜索×自训练协议（L2/L3） | — |

**C9 逐条判定（本篇重点）——四问全 ✗**：
1. **设外部评分函数**：✗ —— V_θ 是**训练出来的外部评分器**，输出连续质量值 v∈[0,1]（Eq.1–2、Eq.37）。
2. **用评分排序/选路**：✗ —— MCTS\* 用 v 做**选点、剪枝、回传**（§3.1 p5）；验证器用 Πv_i 给候选**排序取最高**（§E.3 p25）。
3. **验证门只判合法性**：✗ —— 论文的「验证」= 打分（非合法/不合法二值）；答案对错仅用于**训练打分器**，未直接充当淘汰函数（p6 第 7 行 label_correctness）。
4. **奖励塑形**：✗ —— 加权奖励 w_{s_k} 含 1−2r_{s_k} 塑形项（Eq.2），典型奖励塑形。
   - **剥离方向**：① 保留「终答案=oracle」这一**确定性二值**判据（与 STaR 门同形、C9 友好）；② 删除 V_θ 连续分、v 选点/剪枝/回传、Πv_i 排序、w 的塑形项；③ 选择权交**环境淘汰函数**（模型碰不到），慢环只保留提案权。
### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子（ChatGLM3-6B / Mistral-7B、MCTS/UCT 借用） | 符合借用立场 |
| **L2 信息流层** | MCTS\* + PRM 引导的搜索↔数据管线（搜索产轨迹→筛选→编译训练信号） | **中高**：与慢环「前瞻预演＋回顾编译」双通路同构，可作形状参照 |
| **L3 学习层** | 互自训练（policy SFT + value MSE 交替），改权重 | 中：迭代形状可参照，**权重共训不可搬**（C3） |
| **L4 演化层** | 无 | — |

### 3.4 债务与验收实验对应
- **睡眠期计算预算未定义** → **间接回应**：把搜索的算力代价显式记账（#token、wall-time/题、T/b 超参），是「预演必须先定预算」的实证（Table 6、图 2、§E.4）。

- 服务**慢环双通路（回顾编译＋前瞻预演）**的形状论证（若建该实验）。

## 5. 冲突、代价与风险
- **与硬约束的冲突（逐条）**：**C9（最硬，四问全 ✗）**——外部评分器 + 评分排序 + 奖励塑形；**C1/C2**——语言即控制对象；**C3**——π 与 V_θ 权重共训；**C4**——108 s/题、高 token；**C8**——知识进权重。
- **改造方向（C9 剥离三步）**：① 保留「终答案=oracle」二值合法性检查；② 删除 V_θ 连续分、v 选点/剪枝/回传、Πv_i 排序、w 的塑形项；③ 选择交环境淘汰函数，慢环仅保留提案权。
- **隐含假设与失效条件**：全部增益依赖**有 oracle 真答案**可筛（§H p30）；无真值任务作者自陈未解决。剪枝依赖「有至少一条正确轨迹」——coverage 不足即失效。
- **算力 / 带宽 / 工程代价**：MCTS\* 单题 108 s（Table 6）；T=50、b=3；prompt token 随 b,T 快速上升（§E.4）——与低算力立场相反。
- **搬运后的可能退化模式**：若把预演做成「用评分器选路」，慢环会长出**模型内评分函数** → 架构变质（C9）；若只搬「搜索→自训练」形状而不改权重为 Δ，会把「发布结构新版本」退化为「共训权重」。

### 6.2 推荐组合方案
- **组合**：**本篇（搜索↔编译双通路形状 + 预算记账）× SkillNet（零 rollout 结构筛选）× Dream-RSI（重放场地）× STaR（二值筛选门）**
- **接口形态**：SSEA 慢环「前瞻预演」在结构化状态上做搜索（剥离 V_θ 评分，选择交环境淘汰）→ 产出轨迹进「回顾编译」→ 用 STaR 式**二值**合法性筛选（不打分）→ 编译为 ΔS/ΔM → 过四级验证门原子升版。先做 SkillNet 式零 rollout 结构筛选，再用 Dream-RSI 重放验证。
- **新增能力 / 风险**：把「预演有没有用、花多少算力」变成可记账、可证伪的实验；风险＝若预演引入任何模型内评分/排序即违反 C9——须硬性规定预演**只输出候选，不输出分数、不排序**。
### 6.3 本篇在组合中的典型角色
- **「搜索产轨迹 → 离线自训练」双通路形状的参照样本 + C9 反面标本（打分+排序+塑形三连）**——管「搜索与编译如何互为数据源」，同时标记「训练评分器引导搜索」这条 SSEA 禁区。

## 8. 裁决与下一步
- **应用等级：C 思想启发** —— 理由：PRM 打分 + 搜索排序 + 奖励塑形是 **C9 典型反面**，机制整体不采用；但其「**搜索产轨迹 → 自训练**」形状与 SSEA 慢环「回顾编译（trace→Δ）＋前瞻预演（搜索）」双通路有对位，且**搜索预算记账**直接服务「睡眠期计算预算未定义」缺口。**优先级：P2**。
- **建议动作**：① 把本篇写进 C9 合规审查**反例清单**（「连续分 + 排序选路 + 塑形项」三连禁止）；② 在 experiments「前瞻预演」实验照搬其**预算记账**（报 #token、wall-time、搜索步数 T·b 为协变量）；③ 建 issue：`预演产出须落为 ΔS/ΔM（Memento/PSN），不得共训权重`；④ 双通路对位论证：慢环「预演（搜索）」与「回顾编译（trace→Δ）」互为数据源，本篇为该形状的 LLM 域实例。
- **最小验证实验（预演双通路实验的判据参照）**：
  - **双臂 / 消融**：A＝预演开（结构化状态搜索，**无评分选路**，选择交环境淘汰）；B＝预演关（纯回顾编译）；另加 C＝「把同等算力花在多次采样」的**预算匹配**基线；≥8 seed。
  - **判据（分档，先看分母）**：① 机制计数（预演次数、#forward/#token、分母 episode 数，且**连续分/排序调用应为 0**）→ ② 行为差（pass@1 单次行为 vs best-of）→ ③ 淘汰结果（模型外存活/死亡）。
  - **预期与证伪**：预期 A 臂在 pass@1 上胜 B 且预算匹配；**证伪**＝若增益只在 best-of 出现、或与预算匹配采样臂无差 ⇒ 增益来自「多试」而非预演设计（与 TreeSearchDecoding 判读一致），应弃该机制；**若 A 臂必须依赖 V_θ 连续分才能工作 ⇒ 证伪「剥离评分仍可行」**。
## 9. 待确认问题
1. 「搜索↔编译」双通路中，SSEA 的结构化状态搜索如何定义**动作**（本篇动作为「一个推理步」）？是否需要等价的可离散化步？
2. 剥离 V_θ 评分后，预演如何**剪枝/回传**（MCTS\* 依赖 v 回传）——改用环境淘汰结果作回传信号，还是放弃树结构改束搜索？
3. 预算记账的**匹配口径**（同 #forward / 同 wall-time / 同 episode 数）如何定义？
4. 二值 oracle 筛选在生存域（无标准答案）是否有等价物，还是必须改为环境淘汰二值信号？
