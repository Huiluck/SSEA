## 1. 一句话定位

- **论文主张**：把工作记忆（即 LLM 的输入上下文）的管理从「外部启发式控制器」搬进**策略自身的动作空间**——`A = A_task ∪ A_mem`，`A_mem` 是一个 **Prune&Write** 算子 `a_mem = (I_target, c)`（要删的条目 id 集合 + 生成式记忆内容），动作记录**原地追加**、保持可寻址；用 SFT 冷启动 + 端到端 RL（配 DCPO 解决「上下文被原地改写」导致的训练/推理失配）联合优化任务表现与上下文效率，使 MemAct-RL-14B 达到 16× 大模型的精度而平均上下文长度降 51%（摘要 p1；§3 p3–4；§4 p6–8）。
- **对 SSEA 的意义**：它把「**整理自己的状态**」升格为一类一等动作——这与 SSEA Action 六通道里的 `memory` 通道正面对位，并**照出了 SSEA 该通道的真实缺口**：`MemoryWrite(store, content, importance)` 只能**写**、不能裁/删/合并，即 SSEA 有「记」的动作、没有「忘」的动作。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题

- **问题本身**：长视野 agentic 任务（深度研究、软件工程）里，agent 的工作记忆就是每步的输入上下文；不加管理它会**被无关信息填满**，引发 attention dilution 与 "lost-in-the-middle" 行为。因此瓶颈从「扩容」转为**主动策展（Context Curation）**：策略性地选择、整合与剪除信息，维持聚焦且与目标相关的推理轨迹（p1）。
- **它指出的既有方案缺陷**（§1 p1–2、§2 p2）：
  1. **扩容派**（长上下文模型、YaRN 一类）：扩大了容量但不保证推理更好，效果由 Context Engineering 决定；
  2. **外部启发式派**（MemGPT / A-MEM / Mem0 一类，用固定规则与外部控制器管理）：**与 agent 的核心推理策略解耦**，无法把「保留什么信息」与「任务表现」端到端联合优化；
  3. **早期 RL 派**（Memory-R1、MemAgent、MEM1 一类）：约束太死——要么**强制每步压缩**（MEM1），要么**粗粒度地把上下文当成整块缓冲**检索；
  4. **周期摘要派**（token 级压缩、选择性剪枝、周期摘要）：计算高效但**不知道 agent 的推理状态**在哪一步，会丢掉语义上关键的依赖。

### 2.2 核心思想（关键 insight）

1. **上下文管理是策略的内在能力，不是策略无关的外挂机制**。把它写进动作空间，就能在「任务表现」与「上下文效率」之间做**联合优化**，而不是先定一个压缩率再被动接受它的损失（p1–2）。
2. **编辑必须是细粒度、可寻址的原地操作**。为每一轮交互发一个唯一 `id`，删除按 id 集合执行，且**记忆动作自身的记录原地追加、保持可寻址**——这样被写下的摘要后续还能被再编辑（§3.1–3.2 p3）。
3. **「什么时候整理」本身是要学的东西，不能写死**。固定 5 轮一次的调度虽然更省上下文，却在复杂任务上掉点——因为它会删掉关键中间信息（§4.5 p7，Table 1 †行）。
4. **动态上下文与因果 LM 的训练假设根本冲突**：被删的 token 已经写进了后续 token 的 KV 表示，注意力掩码救不了，必须**物理重建轨迹**（§3.3 p4）。这是全篇唯一真正新的工程洞察。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）

| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **动作空间增广** `A = A_task ∪ A_mem` | 当前状态 → 任务动作 **或** 记忆动作 | 让「整理」与「执行」在同一策略里竞争/切换 | §3.1 p3；Fig.1 p1 |
| **ID 可寻址状态** `H_t = [z_1..z_k]`，`z_i = (a_i, o_i, id_i)` | 交互历史 → 唯一可寻址条目序列 | 使「删除第 1、3 轮」成为可执行动作 | §3.2 p3 |
| **Prune&Write 算子** `a_mem = (I_target, c)` | 状态 → (待删 id 集合, 生成式记忆内容) | 原地裁剪 + 写入摘要/反思/计划，维持推理连续性 | §3.1–3.2 p3；Fig.2 p3 |
| **记忆动作转移** `H_{t+1} = {z_i ∈ H_t \| id_i ∉ I_target} ⊕ (a_t, o_status, id_mem)` | 编辑后状态 | 保证写入的记忆**自身可寻址**、可被后续再编辑 | Eq.1 p3 |
| **DCPO 轨迹分段** `σ_i = (C_i, y_i)`，`C_i = H_{t_mem_i}` | 断裂轨迹 → K+1 个逻辑一致片段 | 绕过「非单调上下文」带来的训练/推理失配 | §3.3.1 p4；Eq.2 p4；Alg.1 p11 |
| **「为什么不能用注意力掩码」论证** | — | 已删 token 的影响驻留在后续 KV 里；推理引擎为单调扩张设计 | §3.3 p4 |
| **稀疏终端奖励** `R(τ) ∈ {+1.0, −0.1, 0}` | 轨迹终局 → 标量 | 成功 +1；违反约束（超 20K token 上下文 / 40 步）−0.1；否则 0 | §3.3.2 p4；§4.3.1 p6 |
| **组相对优势 + 裁剪代理目标** `A(τ) = (R − mean)/ (std + ε)`，`J_clip` | N_traj=5 条轨迹 → 优势 | GRPO 式信用分配；每个片段继承轨迹级优势 | Eq.4–6 p4；Alg.1 p11 |
| **分阶段提示冷启动（SFT）** | 教师模型 + 软/硬阈值 τ_soft(8K)/τ_hard(16K) → SFT 数据 | 前沿模型也不会自发调用记忆工具，需按上下文长度注入由弱到强的提示，再**抹掉提示**只留正确轨迹 | §4.1.2 p5；Alg.2 p11 |
| **记忆结构模板** `[OBJECTIVE] / [CONCLUSIONS/FACTS] / [STATUS] / [ASSUMPTIONS]` | 待写入内容 → 四段式结构化记忆 | 约束生成式 memory payload 的形状 | §A.5.2 p14 |
| **复杂度限训、泛化检验** | 训练只用 ≤3 目标，测试 4–8 目标 | 保证增益来自**策略**而非背题型 | §4.1.2 p5；Table 3 p12 |

### 2.4 关键表示与数据结构

- **状态 = 工作记忆 = 上下文**：`s_t ≡ H_t`，一串带唯一 id 的交互记录 `z_i = (a_i, o_i, id_i)`；`id` 的作用是**上下文被反复改写后仍能精确寻址**（§3.2 p3）。
- **记忆动作产物**：`a_mem = (I_target, c)`——离散的 id 集合 + 自由文本 `c`（"synthesizes summarization, reflection, and planning"，§3.2 p3）；落盘形态为四段式模板（p14）。
- **训练样本**：SFT 930 条 → 3,000 个片段；RL 10,240 条轨迹（Table 3, p11–12）；训练侧目标数被刻意限制为 ≤3（1-obj / 2-obj / 3-obj = 8,192 / 1,025 / 1,023）。

### 2.6 论文自陈局限与边界条件

- **假设依赖**（§6 p9）：
  1. 依赖**稀疏的终局奖励**，因此很难把信用准确归到某一个具体的记忆动作上；
  2. 长视野下**可能误删「要到后面才变得相关」的信息**——论文自陈这是当前的结构性风险，并用「记忆行为与推理内在耦合」来论证这条路终局上可解，但**未给出解法**；
  3. 片段采样是**随机且等权**的，没有用后验方法识别关键步，可能把算力分配到信息量低的片段上。
- **明确不适用 / 明确边界**：
  - 压缩是**有损的**，一旦摘要化就**无法恢复原始数据**；
  - 局部记忆**无法维持无限精度**，故论文自认与系统级基础设施是**互补而非替代**关系，其优先级是「在标准上下文窗口内验证核心机制，在决策层建立一个有原则的接口」；
  - 未来工作才考虑给动作空间加**外部存储的选择性检索、分层缓存**（§6 p9）。
- **实测失败模式**（Table 10, p16）：① **歧义被吞**——两条同名不同源的检索结果未加判别就被折叠成同一假设，错误假设写进记忆后**带着后续推理一路跑偏**；② **记忆幻觉**——检索反复无果时模型「填坑」编造关联，当成事实存进记忆，导向自信且完全错误的最终答案。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射

| 裁判标准 | 判定 | 依据（论文中的具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | ◐ | 目标函数是问答精度，域是深度检索；但**机制形状是控制形状**：状态是可寻址条目序列、动作是 ID 过滤算子、转移是集合差 + 追加（§3.2 p3） | 把 `H_t` 从 token 序列换成**固定宽度结构化工作集**；把 `A_task` 从 search/browse 换成 locomotion/manipulation |
| **C2** 自然语言只作观察员接口 | **✗** | 三重语言依赖：状态是 token；`a_mem` 的 payload `c` 是**生成的自然语言**（摘要+反思+计划，§3.2 p3），单次约 160–200 token（Table 5 p12）；任务成功由 **LLM-Judge 三遍一致性**判定（§4.2 p5）；冷启动数据由 DeepSeek-V3.1 蒸馏（§4.1.2 p5） | **`c` 必须换成结构化写入项**（向量 + 键 + 来源 id 集合 + 置信），`I_target` 保留为 id 集合；LLM-Judge 与教师模型整段搬到**仪器侧**，不进模型 |
| **C3** 权重/记忆/技能三分离 | **✗** | 「记忆策略」被**训进权重**：Qwen2.5-7B/14B 上 SFT 6 epoch（lr 5e-5）+ RL（DCPO, lr 1e-6, H100）（§4.3.1 p6）。记忆行为与 θ 绑死，不属于可独立版本化的记忆结构 | 把「何时/裁剪多少」的**参数从 θ 挪到结构快照**（新增可提案字段），走 提案→四级门→原子升版；θ 侧不留记忆策展能力 |
| **C4** 低算力低带宽 | ◐（**结论强对齐、手段不对齐**） | 对齐面：有界工作集（3,500 token/步，−50%~−60%）、稀疏触发（8-obj 上 3.7–3.9 次记忆动作 / 20.2–25.2 次任务动作，Table 2 p8）、**内联执行**不做整段重处理（论文明确以此对比 A-MEM，§4.4 p7）。冲突面：SFT 930 条 + RL 10,240 条轨迹、H100、每次动作还要生成百余 token | 只搬「有界 + 稀疏 + 内联」三条；payload 从自然语言换结构化；训练侧整体不搬。**SSEA 的对应物不是模型上下文，而是控制路径上的 append-only 缓冲**（见 §5） |
| **C5** 精准回忆历史 | ◐ | 正面：ID 可寻址 + 原地追加，是一种**可审计的精确编辑纪律**。负面：Prune&Write 本身是**有损重写**——论文自陈摘要后原始数据不可恢复（§6 p9），与「可精准写入/检索/遗忘/合并」中的**精准遗忘**相抵触 | 搬编辑纪律（按 id 精确删除、留痕可审计），**不搬有损重写**：SSEA 的裁剪必须是 id 级精确丢弃或结构化合并，不能是自然语言覆盖 |
| **C6** 可自主修改自身 | ◐ | 提供了「**动作空间里显式存在一个改自己状态的动作**」这一形态（`A_mem`），这正是 SSEA `memory`/`self_modification` 通道想要的形状。但四权全在**外部训练脚本**手里：没有提案权（动作由采样产生）、没有边界权、没有验证权、没有应用权（梯度由 RL 循环施加） | 记忆动作必须**过验证门**；边界权归环境（越界即拒，不是扣分——不设 `r_pen`） |
| **C7** 可保存/恢复/变异/继承 | —（**未提及**） | 论文未涉及跨个体继承、变异、GenePackage；学到的策展策略以模型 checkpoint 形式存在 | 若按 C3 改造把策展参数做成可提案结构，则可直接进 GenePackage（本篇本身不提供） |
| **C8** 给基因先验，不给知识语料 | **✗** | 冷启动数据由 **DeepSeek-V3.1**（前沿模型）蒸馏，语料来源是 **HotpotQA / Asearcher**（人类构造的 QA 数据集）；只保留答案正确的轨迹（§4.1.2 p5、Alg.2 p11） | 蒸馏与人类语料**不得进基因包**；仅可作为研究者侧一次性初始化技巧，且需与自生成经验在实验上分离 |
| **C9** 不设评分函数，只有淘汰函数 | **✗（硬冲突，本篇最重的一条）** | 显式外部奖励 `r_task = +1.0`、`r_pen = −0.1`（超 20K token / 40 步）（§4.3.1 p6）；组相对优势归一化 + GRPO 裁剪代理目标（Eq.4–6 p4）；任务成败由 **LLM-Judge 评估器**判定（§4.2 p5）；SFT 阶段按「答案对不对」筛轨迹（Alg.2 p11）。这是**奖励塑形 + 观察员评分**的完整配置 | 剥离方案见 §5.1（五步） |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | ✓ | 无任何新算子；贡献是 L2（记忆管理与策略统一进同一动作空间）+ L3（策展策略的学习）；底座 Qwen2.5 全是借用（§3–4） | — |

### 3.2 L1–L4 层级定位

| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无。Qwen2.5-7B/14B、SGLang、GRPO 全为借用 | 无（符合借用立场） |

### 3.4 债务与验收实验对应

**可回应的已知债务**

- **债务 27（环境把无消费者通道报成成功）**：本篇是它的**风险放大器**，不是解药。本篇主张「新增一类动作」，而 `Environment._apply` 只处理 5 个通道、`skill` 无分支，只带新通道的动作会得到 `action_success=True`、零事件、只扣基础代谢（docs/03 §9.5）。**在债务 27 修好之前给 memory 通道加子类型，等于再复制一次债务 27。**
- **「缓冲不得在控制路径上无界增长」（C4 派生）**：本篇给出判据（有界 / 稀疏 / 触发可审计）。SSEA 现状：`memory_system` 侧**已**有界（capacity=256 会淘汰），但 `environment.memory_requests` 是**全量 append、无上界**的列表（`experiments/_harness.py:343` 自陈「不是 16 槽环形缓冲」）——与 `_echoed` 的有界裁剪形成对照。**这是本篇能立刻兑现的 C4 收益。**
- **债务 22（记忆二级门用常量阈值，慢环不可调）**：本篇**不能**解（它的选择性来自奖励），但可把「裁剪预算/裁剪粒度」做成可提案结构字段，从侧面给慢环一个合法调节面。

**本篇明确回不了的债务**（写清楚以免误抱期望）

- **记忆门「开得准不准」的选择性缺失** → 本篇的选择性来自 `r_task`，搬不得（Memento 的 μ 才是这一缺口的对位件）。
- **`retrieve` 键收窄 → 召回精度上限低** → 本篇**不检索外部记忆**，只裁剪工作集；外部检索被明列为未来工作（§6 p9）。
- **技能表示够不够（0/33）** → 无关。
- **Gene Manager 缺失** → 无关（本篇无 L4）。

**可服务的验收实验**

- **实验 2（记忆召回）的增强**：把「只写不裁」改成「写 + 裁」双臂，可把该实验的判据从「命中率」扩到「工作集上界」。
- 不服务实验 3（技能固化）/ 实验 4、5（卡在 Gene Manager）。

## 5. 冲突、代价与风险

### 5.1 C9 硬冲突的剥离方案（五步）

本篇的学习信号**全部**来自外部奖励与观察员评分。剥离顺序：

1. **整条 RL 回路删除**：SFT 冷启动（DeepSeek-V3.1 蒸馏）、DCPO、稀疏奖励 `(+1.0 / −0.1 / 0)`、组相对优势、GRPO 裁剪目标——**一个都不进 SSEA**。
2. **保留三件无奖励依赖物**：① ID 可寻址的条目序列表示；② 动作空间里显式存在「改自己工作集」这一类动作；③ 稀疏性这一**观测事实**（~5:1），它只能当**结构预算的先验**，不能当奖励。
3. **触发信号换源**：`r_task`/`r_pen` → SSEA 已有的内部驱动（`prediction_error` / `surprise_estimator` / `metabolic.drive_vector`）——属 C9 的第 ② 层（定义不可改），不是第 ① 层的淘汰函数，也不是第 ③ 层的提案。
4. **判据不放回模型**：「整理得对不对」只由**环境侧淘汰函数**与**验证门判合法性**（不打分、不排序）。误删「后面才相关的信息」（论文自陈的主要风险，§6 p9）在 SSEA 里应表现为**淘汰率/生存时长的环境事实**，绝不能变成一个负分。
5. **评估器搬去仪器侧**：LLM-Judge 三遍一致性、规则 F1 全部只给研究者看，不进任何闭环。

### 5.2 与硬约束的其余冲突

- **C2（语言载体）**：`a_mem` 的 payload 是自然语言，且单次 160–200 token（Table 5 p12）——**快环付不起这个带宽**。必须整段换成结构化写入项。
- **C3/C6（策略进权重 + 四权外置）**：记忆策展能力若留在 θ 里，就绕过了「提案→门→升版」路径，且不可版本化、不可遗传、不可回滚。
- **C8（蒸馏 + 人类语料）**：冷启动数据是前沿模型蒸馏 + HotpotQA/Asearcher，属明确禁止的遗传内容。

### 5.3 「memory 动作」在 SSEA 里到底有没有真消费者（本次评估的核心结论）

**有，但只实现了「写」这一半，且它落在环境之外。**

- **真消费者存在**：`fast_loop.py:406` → `self.memory.write(a_t.memory, p_t, obs_next, feedback)` → Memory System。这是**与环境并列**的一条消费路径，源码注释亦明确声明「Action.memory 通道的消费者是 Memory System，不是 Environment」。
- **环境侧不消费**：`environment.py:757 _apply_memory` 只 append 进 `memory_requests` 并记一条 `MEMORY_STORED` 事件，不改变世界——它是**观察项，不是后果**。
- **与 `skill` 通道的关键差别**：`skill` 在**环境侧无分支**（债务 27），其唯一读者是 `skill_runner.py`（`fast_loop.py:380` 提交、`skill_runner.py:119` 断言 `action.skill is not None`），即「有读者、但环境不认」。`memory` 是「有读者、环境也记一笔、但记的不是后果」。**二者的共同形状是：环境都不为它产生后果。** 这正是债务 27 那条「主动报告成功」的温床。
- **风险判定（重要）**：照本篇新增一个「裁剪动作」子类型，**最大风险不是机制不work，而是再制造一次债务 27**——新通道被环境忽略、`action_success=True` 照发、测试全绿。`tests/test_consumer_surface.py` 现有**三个**扫描面（结构类别 / 访问器 / Action 六通道），按 `docs/03 §9.5` 的自陈，**这三个面都扫不到「环境有没有消费这个通道」**。

### 5.4 隐含假设与失效条件

- 假设**存在一个 token 序列形式的上下文**可供原地编辑；SSEA 快环没有，需先定义「工作集」这个对象，否则 Prune&Write 是空转。
- 假设**删除是按 id 的精确操作**；SSEA 目前未暴露按 id 删除的公共接口（`memory_system` 只有容量触发的 `_evict_one`）。
- 假设**整理频率可由策略自由决定**；SSEA 必须把它约束成结构预算（C4 + C6 边界权）。
- 论文的**证据域是网页问答**，且无 seed / 无方差报告；迁移到具身生存域后「裁剪提升精度」这一结论**没有任何外部证据**。

### 5.5 算力 / 带宽 / 工程代价

- **不搬训练侧**：无 H100 / 万级轨迹成本。**搬骨架**：新增 `WorkingSet`（有界、id 寻址）+ `MemoryCuration` 动作子类型 + 结构预算字段 + 环境侧消费分支 + 第四面守卫。
- **每帧成本**：必须做到 O(预算命中)，不能每帧扫描全库；裁剪只在触发帧发生（对齐论文实测的稀疏性）。
- **审计成本**：每次裁剪要留痕（删了哪些 id、写入了什么），否则慢环无法回放、验证门无法判合法性。

### 5.6 搬运后的可能退化模式

1. **静默空转（最可能）**：动作发出、环境不消费、`action_success=True`——**就是债务 27 的形状**，且现有守卫抓不到。
2. **裁剪掉关键项却无人察觉**：论文自陈的失效模式（§6 p9）；在 SSEA 里表现为淘汰率上升，但若判据已饱和（危险回避率两臂均 0.9814）则**看不出来**。
3. **记忆幻觉的结构化版本**：若裁剪动作的写入项允许「模型自己填内容」，会产生与 Table 10 p16 同形的污染，且因无语言痕迹更难发现。
4. **预算字段变成新的常量阈值**：若把裁剪预算写死在结构里而慢环不可提案，等于又造一个债务 22。

| **前置依赖** | 有界 id 寻址工作集、按 id 删除的消费者、环境侧通道消费断言（**债务 27 的第四面守卫**） | **没有这三者，本篇的任何零件都无处落** |

### 6.2 推荐组合方案

**组合：Memory-as-Action（骨架） × Memento（取） × LightMem（触发/巩固） × SEDM（准入）**

- **接口形态**：
  - `WorkingSet`（有界 N，条目带 id）作为快环的第四个输入，与 `p_t`/`m_t`/`body` 并列；
  - `Action.memory` 扩展为二选一子类型：`MemoryWrite`（现状）+ `MemoryCuration(drop_ids, write_item)`；
  - 触发信号：`surprise_estimator` / `metabolic.drive_vector`（C9 ②层），**外加** LightMem 式的「缓冲达阈值」硬触发（边界权归环境）；
  - 触发预算（每 N 帧至多一次、单次至多删 K 条）作为**结构字段**，慢环可提案（顺带回应债务 22）；
  - 写入项经 SEDM 准入后再入库。
- **组合后新增能力**：SSEA 记忆通道从「只写」升级为「写 + 精确裁 + 有界工作集 + 可审计的触发」；快环第一次拥有**遗忘记账**。
- **新增风险**：① 新通道被环境忽略 → 债务 27 复制品（**必修前置**）；② 裁剪掉后续需要的条目（论文自陈未解）→ 只能靠环境淘汰率观察；③ 组合了四篇各自的 C9 冲突面，剥离不彻底会把评分函数从后门带回来。

### 6.3 本篇在组合中的典型角色

- **「忘」这一半的动作定义者 / 工作集边界的守门人**：它不提供内容（ReasoningBank/FLEX 提供）、不提供取回策略（Memento 提供）、不提供训练信号（它自己的信号必须丢弃），**唯一独占的贡献是「按 id 精确裁剪自己状态」这个动作形状，以及「固定周期不如自适应」这条证据**。

## 8. 裁决与下一步

- **应用等级：B 零件采用**
  - 不是 A：它要解决的问题（token 上下文饱和）在 SSEA 快环**不存在同构形式**；它的学习信号整条违反 C9，剥完之后不再是一套「方法」，只剩两个零件。

- **优先级：P2**（前置未清，不能上 P1）
  - 前置 1：**债务 27 先修**——环境对无消费者通道报成功。在本篇主张「新增一类动作」的前提下，这条不清就动手等于复制它。
  - 前置 2：`tests/test_consumer_surface.py` 加**第四扫描面**：「环境 `_apply` 是否为该通道产生后果」。现有三面按 `docs/03 §9.5` 自陈扫不到这一面。
- **建议动作**：
  1. **（可立即做，与本篇等级无关）** 把 `environment.memory_requests` 从全量 append 改为**有界环形缓冲 + 计数**，与 `_echoed` 的 `MAX_ECHOED_SIGNALS` 处理对齐；分母语义在 `_harness.py:343` 已声明「不应静默漏」，改的时候保持这一性质。这是本篇能立刻兑现的 C4 收益。
  2. 补**第四面守卫**（环境是否消费该通道），并用人造死通道验证它会红（照抄 `TestTheGuardCanActuallyGoRed` 的形状）。
  3. 在纸上定义 `WorkingSet`（有界 N、条目带 id）与 `MemoryCuration(drop_ids, write_item)` 的协议形状；**先造消费者（按 id 删除/合并的公共接口）再造通道**——`memory_system` 目前只有容量触发的 `_evict_one`。
  4. 触发信号接 `surprise_estimator` / `metabolic.drive_vector`；预算字段（每 N 帧至多一次、单次至多删 K 条）做成**结构字段**，慢环可提案（顺带给债务 22 一个合法调节面）。
  5. 把 Table 10 p16 的两条失败模式写进 Misevolve 红队清单：写记忆项必须带**来源 id 集合 + 置信**，禁止把未消解的歧义折叠为事实。
  6. **与 AgentFold 成对读**（同题、同期、同域），先判「剥离奖励后谁剩得多」再决定用谁的骨架。
- **最小验证实验（增强实验 2）**：
  - **双臂**：A 臂 = 现状（仅 `MemoryWrite`）；B 臂 = 增加 `MemoryCuration`（按 id 裁剪 + 写入），触发用 `prediction_error`/惊奇，预算取论文实测稀疏比作上界（先给 5:1，即每 5 个任务动作至多 1 次整理）。≥8 个固定 seed。
  - **判据（分档，先看分母）**：
    1. **机制计数**：curation 动作发出数（**分母！一次都没发出就先查触发信号**）→ 实际裁剪条数 → `memory.stats.evicted` 变化 → 工作集大小分布（均值与上界）；
    2. **逐帧动作差**（第三档，对位债务 26 的教训）：两臂在同一 seed 上的逐帧动作序列差异；
    3. **淘汰结果放模型外**：生存时长 / 危险回避率——⚠️ 该判据两臂均 0.9814 **已饱和**，本实验不能拿它当主判据，需换未饱和量（如长视野下工作集上界、能量轨迹）。
  - **预期**：B 臂快环工作集上界显著低于 A 臂，且两臂逐帧动作序列出现非零差异。
  - **证伪条件**：若两臂逐帧动作**零差异** → 按项目纪律**先怀疑尺子**（判据饱和 / curation 从未触发），而不是先判机制无效；若差异存在但淘汰结果无变化 → 说明该尺度上记忆裁剪对生存无边际收益，应记入「固定环境下记忆增益的结构性上限」这一开放问题（与 Memento 案例库饱和互证）。
- **若 E 不采用**：不适用（本篇有真实可搬零件）。但若两个前置（债务 27 + 第四面守卫）在一个迭代内修不完，**应暂停本篇的任何代码落地**，只保留动作 1（缓冲有界化）。

## 9. 待确认问题

1. **正文与表不自洽（需人工核对）**：p7 §4.5 写「MemAct-RL improves multi-objective accuracy from **0.485** to **0.591** compared to its SFT version」，但 Table 1 的 14B MemAct-SFT 平均是 **0.553**、0.485 是 Table 4 的 **7B-RL** 平均。疑似跨型号混用，引用该数字前须核对。
2. **统计口径缺失**：全文**未提及** seed 数、重复次数、方差或置信区间；多目标每档 200 样本。所有「优于」结论的显著性无从判断。
3. **无奖励条件下「何时裁剪」如何学**：本篇的触发完全依赖 `r_task`。换成 `prediction_error`/惊奇驱动后，「整理」是否还学得出来、学出来的是不是同一形状的策略（7B 粗放 / 14B 双峰）——**本文没有任何证据**，属推断，需作者确认是否值得自测。
4. **SSEA 的「工作集」到底放什么**：快环目前没有 `H_t` 这一对象。放进 WorkingSet 的应该是感知帧、检索到的记忆项，还是自身的动作-后果对？各自的 id 由谁签发？**这是搬本篇之前必须裁决的设计问题**。
5. **裁剪的边界权归谁**：论文用 `r_pen = −0.1` 惩罚「超 20K token / 40 步」。SSEA 不能用扣分，只能**拒绝执行**（边界权归环境）。拒绝后动作的语义是什么（空动作 / `ACTION_FAILED` 事件）？需与债务 27/28 一并裁决——28 的 `action_success` 正是 27 报出来的假成功。
6. **裁剪掉的内容要不要留可恢复痕迹**：论文明确「有损、不可恢复」（§6 p9）。SSEA 若要 C5 的精准遗忘，是否需要 tiered 冷存储（论文的未来工作，p9）？还是就按 LightMem 的「软更新、合并不删除」？
7. **AgentFold 的相对位置**：与本篇同题同期同域，尚未立卡。需读全文后判定：它的「proactive context management」是否也是 RL 驱动？若不是，它对 SSEA 的可用性可能**高于**本篇。
8. **MemGen 的载体能否替代本篇的 payload**：本篇的 `c` 是自然语言（C2 ✗）。MemGen 的生成式潜在记忆若是向量载体，则本篇的「动作形状」+ MemGen 的「载体」可能是一个合规组合——**待 MemGen 立卡后判定**。
