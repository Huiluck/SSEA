## 1. 一句话定位

- **论文主张**：把 BIG-Bench 中「此前无任何模型超过平均人类评分」的 23 个任务（27 子任务）筛成 BIG-Bench Hard（BBH）；加 CoT 提示后 Codex 在 17/23 任务上超过平均人类评分，并证明 CoT 是「需足够模型规模才涌现」的提示策略。
- **对 SSEA 的意义 / 为什么不适用**：这是**纯语言推理基准 + 提示技术**论文，整条价值链建立在「大规模语言模型 + 自然语言输入输出 + 外部准确率评分」之上，与 SSEA 非语言、生存控制、无外部评分的立场**无回溯路径**（连反面教材都算不上），故用短卡排除。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- 问题本身：BIG-Bench 里哪些任务连最强模型都不如平均人类评分？是「本质不可解」还是「提示方式不对」？（p.13003）
- 既有方案缺陷：BIG-Bench 原评测用 standard「answer-only」few-shot prompting，对多步推理任务**系统性低估**模型能力（p.13006）。

### 2.2 核心思想
1. 用「是否超过平均人类评分」这一单一判据从 209 个任务层层筛出 23 个（Table 1, p.13005）。
2. 用人工撰写的 CoT 样例替换 answer-only 样例，把同一模型同一批任务拉高 10–20%（Table 2, p.13007）。
3. CoT 增益是**规模依赖的涌现现象**：小模型为负、大模型才转正（Figure 4, p.13008）。

### 2.3 关键机制 / 算法（零件清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| BBH 筛选流水线 | 209 任务 → 23 任务 | 7 条硬性判据层层过滤 | Table 1, p.13005；附录 D, p.13048 |
| CoT few-shot 提示 | 任务描述 + 3 个人工 CoT 样例 + 测试题 → 推理链 + 答案 | 把多步推理显式化 | §3, p.13005；附录 C, p.13038+ |
| 关键字抽答案 | 生成文本 → 最终答案 | 用「the answer is」定位，EM 计分 | §3, p.13006 |

### 2.4 关键表示与数据结构
- 每任务 = `{task description, few-shot exemplars（含 CoT 链）, test examples}`，答案用 exact match 比对；除 3 任务外随机抽 **250** 测试样本，Causal Judgement/Penguins in a Table/Snarks 用全量 187/146/178（§3 及脚注 6, p.13006/13011）。

### 2.5 实验证据
| 任务 / 基准 | 对照基线 | 关键数字 | 统计口径 |
|---|---|---|---|
| BBH 全部（23 任务均值） | avg human-rater 67.7 | Codex CoT 73.9（+16.7）；PaLM 540B CoT 65.2；InstructGPT CoT 68.4 | Table 2, p.13007；单次 greedy 解码 |
| 超过平均人类评分的任务数 | — | Codex CoT **17/23**（AO 仅 5/23）；PaLM CoT 10/23 | Table 2, p.13007 |
| 涌现任务 | 平坦 scaling 曲线 | Multi-Step Arithmetic / Tracking Shuffled Objects / Web of Lies 由随机转正 | Figure 5, p.13008 |
| CoT 反例 | answer-only | Causal Judgement / Ruin Names / Snarks 上 CoT 反而更差 | §5.5, p.13009 |

### 2.6 论文自陈局限与边界条件
- 人类评分基线不严谨（历时近一年、格式多次变更、允许上网、题面难懂），「超过平均人类」≠ 真理解/真推理（§8.1, p.13011）。
- 可能存在未检测到的标签偏置；CoT 样例由人工撰写、对格式/措辞敏感；几乎全为英文任务（§8.2–8.4, p.13011）。
- 承认 CoT 可能被滥用于生成有害/虚假文本（§8.5, p.13012）。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射（短卡主要价值：记录「为什么排除」）
| 裁判标准 | 判定 | 依据 / 为什么不适用 |
|---|---|---|
| **C1** 生存控制架构，非语言生成 | ✗ | 全篇是语言模型基准，无控制环/生存信号，输入输出均为自然语言（§2, p.13004） |
| **C2** 自然语言只作观察员接口 | ✗ | 语言是任务**全部载体**，CoT 链直接参与决策（§3, p.13005），恰是 C2 要排除的形态 |
| **C3** 权重/记忆/技能三分离 | — | 不涉及记忆/技能；few-shot 样例仅存于上下文，非持久结构 |
| **C4** 低算力低带宽 | ✗ | 依赖 540B PaLM / code-davinci-002 级大模型（§3, p.13005），与低算力路线相反 |
| **C5** 精准回忆历史 | — | 无外置记忆的写入/检索/遗忘机制，只有一次性 in-context exemplars |
| **C6** 可自主修改自身 | — | 权重冻结，不含自修改机制 |
| **C7** 可保存/恢复/变异/继承 | — | 无 GenePackage / 繁衍 / 淘汰概念 |
| **C8** 给基因先验，不给知识语料 | ✗ | 立场相反：任务大量依赖 Web 规模知识语料（Sports/Movie/Ruin Names，§5.3, p.13008） |
| **C9** 不设评分函数，只有淘汰函数 | ✗ | 论文核心就是**外部准确率评分与模型排序**（EM accuracy, §3, p.13006），直接违反 C9 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | — | CoT 是**提示技巧**非架构创新，未触及 SSEA 的 L2/L3/L4 |

## 5. 冲突、代价与风险

- **与硬约束的冲突**：C1/C2/C4/C8/C9 五条直接冲突（见 3.1）——它正是 SSEA 要**避免**的「语言生成架构 + 外部评分」范式。
- **隐含假设与失效条件**：假设「超过平均人类评分 = 能力」；论文 §8.1 自认此等式不成立；需 540B 级模型与大规模推理算力，与低算力控制环不相容。
- **为什么仍保留在论文池**：作为**评测口径与提示技术的参照样本**——当实验 2 需为「QA 式判据」找反例、或需说明「为何不能用外部准确率当慢环判据」时，BBH 是干净的对照锚点（对应债务 25/26 判据形状讨论）。

## 8. 裁决与下一步

- **应用等级**：**E 不采用**，优先级 **P3** —— 理由：纯 NLP 推理基准 + 提示技术，无法回溯到 C1–C10 任何一条，且直接违反 C9 外部评分与 C4 低算力约束。
- **建议动作**：1. 仅在需要「外部评分判据反例」时引用；2. 不建原型、不开 issue、不接模块；最小验证实验 —（不适用）。
- **若 E 不采用：原因**：立场无回溯路径（§7 判据），其核心机制（大模型 + 自然语言 + 外部准确率）与 SSEA 非语言、生存控制、无评分立场正面冲突。
