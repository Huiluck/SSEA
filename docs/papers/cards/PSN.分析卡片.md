## 1. 一句话定位

- **论文主张**：技能不是平铺脚本库，而是一张**可执行符号程序构成的有向网络**（节点=技能：
  控制流/参数/前后置条件/子技能调用；边=调用关系）；通过三个由 LLM 实例化、但由架构
  决定的机制——**REFLECT 故障定位、成熟度感知更新门控、回滚验证下的规范化结构重构**——
  让网络随经验持续生长、修复与压缩（p1–4）。
- **对 SSEA 的意义**：是**技能侧的主干参照**：技能表示直接喂给 Gate（前置条件=合法性键）、
  REFLECT 替代口头反思、成熟度门控对接可塑性、重构+回滚+逆操作是自修改安全的模板；
  其 Skill Retention Rate 等指标为实验 3「0/33 SKILL_FAILURE 判据形状错」提供修正形状。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- **问题设定**（p2）：POMDP 下开放任务流 T={τ_1,τ_2,…}（自然语言任务 + 目标谓词
  g_τ:S→{0,1}），顺序到达、视野与组合性各异；智能体须持续获取、精炼、重组可复用技能。
- 既有两缺陷（p1）：
  1. 技能以**平铺脚本库**呈现，缺乏层级组合的原则性机制；
  2. 智能体缺乏**为复用赋信用、修复符号程序、重组技能结构**的统一框架。

### 2.2 核心思想（关键 insight）
1. **技能是带契约的可执行程序**：显式控制流、参数、前置/后置条件、子技能，前置-效应
   结构类似程序化世界模型（p2）。
2. **学习动力学可类比神经网络训练**：故障定位≈沿激活路径反向传播；成熟度门控≈自适应
   学习率（稳定-可塑性权衡）；结构重构≈神经架构搜索（p1、p5）。
3. **自修改必须 tentative + 可回滚**：所有重构先提案、在近期任务滑动窗上验证、劣化超
   20% 即用记录的逆操作撤销（p4–5）。
4. **组合泛化靠复用而非新造**：成功的规划被蒸馏为新技能；网络经重构保持紧凑（p3、p8）。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **技能表示** s=(C_s,P_s,E_s,CHILDREN) | E_s=(E^pre,E^post) 契约、调用子技能 | 可执行、可检查、可组合的技能单元 | §2.1 p2 |
| **技能价值 V(s)=β_s−u_s** | 执行历史 → 拉普拉斯平滑成功率 − 不确定性 | 规划选择 + 更新频率调制（双重角色） | p2 |
| **混合规划器（后向链）** | 目标 g → S(g)={s:E^post⇒g}，递归展开前置 | 优先复用现有技能；Boltzmann 探索新技能 | Eq.2 p3 |
| **前向规划蒸馏 CODEGEN** | 无可复用技能时 LLM 规划 → 新技能 s_t | 成功规划入库并建立调用链接 | Eq.3–4 p3 |
| **REFLECT 两阶段信用分配** | 失败 (f_t,s,T_t) → 修复提案 ∇̃_s | 自顶向下沿调用轨迹定责 → 自底向上 PATCH | Eq.1、5 p2、4 |
| 修复滚动缓冲 | 最近 5 个修复提案 | 防止相互矛盾的修复叠加 | p4 |
| **成熟度门控** | V(s) → P(update s)=(1−ε)σ(γ(0.6−V(s)))+ε | 成熟技能趋稳（少更新、防遗忘）、未成熟保塑 | Eq.6 p4 |
| **规范化重构（5 类）** | 参数化覆盖/行为覆盖/兄弟特化/公共子技能提取/重复消除 | 网络级语义保持重组 | §2.5 p4 |
| 候选发现 + 确定性重写 | 父母/子女 + Top5 语义相关技能 → 包装/替换/合成/合并 | 限制重构搜索范围 | p4 |
| **回滚验证 + 逆操作** | 候选网络在 3 个近期受影响任务上验证；成功率降 >20% 即撤销 | 自修改安全闸 | p5 |
| 多时间尺度动力学 | 每次执行定责 / 10–50 次重构 / 5–10 次成功后重组 | 快/中/慢三层节律 | p5 |

### 2.4 关键表示与数据结构
- 技能网络 N_t=(S_t,L_t)：节点技能、边 L_t 调用关系；执行轨迹 T_t 记录每个被调技能的
  (s, E^pre, E^post, 状态) 与符号状态快照 σ，作为优化与重构的监督（p4）。
- 前后置条件从观察到的成功/失败状态与经验迁移中增量校准（p4）。

### 2.6 论文自陈局限与边界条件
- 全部操作算子（REFLECT/CODEGEN/PLAN）由提示式 LLM 承担，能力随模型强弱变化；
  不微调模型；实验限于沙盒游戏（Minecraft/Crafter）（p13–14）。
- 预印本，尚在审稿。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据 | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | ◐ | Crafter 即生存机制（怪物/饥饿/危险导致死亡）；运行时执行的是符号程序而非生成文本（p8） | 迁移到 SSEA 生存域；语言只在离线构造侧 |
| **C2** 自然语言只作观察员接口 | **◐（偏 ✓）** | 技能运行时完全非语言；LLM 仅在失败/重构时**离线造程序**（≈RuleCompiler 角色）（p3） | 把 LLM 严格限制在慢环编译面，运行时零语言 |
| **C3** 权重/记忆/技能三分离 | **✓** | 明确不微调；技能库=独立于权重的可执行代码；轨迹另存（p13） | — |
| **C4** 低算力低带宽 | ✓/◐ | 零梯度；LLM 调用仅在失败与稀疏重构时触发；程序复用替代重复推理 | 控制重构频率（中/慢节律） |
| **C5** 精准回忆历史 | ◐ | 执行轨迹与状态快照落库；契约从观察校准；非其核心 | — |
| **C6** 可自主修改自身 | **✓** | 在线修改自身技能网络（=自身能力结构），含修复与重组（p4） | 映射为技能库 Δ 的受控自修改 |
| **C7** 可保存/恢复/变异/继承 | ✓/◐ | 重构记录**逆操作**、可回滚（恢复）；技能持久化；无跨个体继承 | 成熟技能作基因包候选（见 HeritableFilter） |
| **C8** 给基因先验，不给知识语料 | ✓ | 技能全部自任务流自生成；后向链规划；无语料灌入 | — |
| **C9** 不设评分函数，只有淘汰函数 | ◐ | V(s) 经验成功率用于 Boltzmann 选择与更新调制（冲突）；但重构验证是**成败式淘汰**（降 >20% 即撤）（p5） | V 仅作环境侧经验事实记录；去掉 Boltzmann，选择交后向链+合法性门；保留成败式回滚 |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | ✓ | 创新在网络结构(L2)、信用/门控(L3)、架构搜索式重构(L4)；无新算子 | — |

### 3.2 L1–L4 层级定位
| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子；LLM 为现成件 | 符合借用立场 |
| **L2 信息流层** | 技能网络、调用轨迹、后向链数据流 | **高**：技能-门-规划的耦合模板 |
| **L3 学习层** | 两阶段信用分配、成熟度门控、契约校准 | **高**：替代口头反思、稳定技能演化 |
| **L4 演化层** | 结构重构 + 回滚验证（架构搜索式） | **高**：自修改安全与库紧凑度 |

### 3.3 模块映射

### 3.4 债务与验收实验对应
- **实验 3 判据形状错（0/33 SKILL_FAILURE）**：改用 SRR/复用率/契约校准状态计数，
  按成熟度分层统计失败；0/33 的形状问题被「保持率 + 成败回滚」替代。
- **缺失组件 RuleCompiler**：CODEGEN+REFLECT 的 LLM 离线编译即模板。
- **缺失组件 HeritableFilter**：成熟度（V(s)≥拐点、契约稳定）作可继承性判据。
- **债务 26**：结构性指标（fan-in/复用率/库规模）补充分辨率。
- 服务**实验 3（技能固化）的重设计**。

## 5. 冲突、代价与风险

- **C9 冲突点**：V(s) 聚合经验成功率并驱动 Boltzmann 选择——须降级为环境侧事实记录，
  选择交后向链与合法性门；成败式回滚保留（它本就是淘汰逻辑）。
- **强依赖 LLM 算子质量**：弱模型修复更浅（5.0 vs 2.7 技能/修复）、复用率更低
  （0.15 vs 0.4）；架构能吸收部分噪声但非全部；SSEA 低算力侧用小模型时收益打折。
- **维护必须在线、与执行耦合**：离线一次性重构被证明无效（0.6875 vs 0.8462），
  意味着持续的慢环 LLM 调用成本。
- 预印本未审稿；技能语言绑定 JavaScript/Python，迁移需重写后端。
- 重构搜索虽受限（Top5 + 确定性重写），仍可能在大库上变贵。

## 6. 组合分析

### 6.1 关系图谱
| 关系 | 对象 | 说明 |
|---|---|---|
| 前置依赖 | 技能执行轨迹、结果反馈、可序列化程序 | SSEA 已有 SkillLibrary 雏形 |
| 直接前身 | **Voyager**（同 Minecraft 谱系） | PSN = Voyager + 网络/门控/重构；技能提示可沿用，维护机制整体升级 |
| 互补（最紧） | **Memento** | 案例（情景、μ 检索）→ 高频复用、成熟后结晶为 PSN 技能； episodic 与 programmatic 两层 |
| 互补 | **Dream-RSI** | 重构的回滚验证放进重放模拟器离线跑，省真实环境交互 |
| 互补 | **RAGEN** | PSN 全程零梯度（Echo Trap 证据支持其选择）；若未来以训练组件替代 LLM 算子，RAGEN 接手稳定性 |
| 互补 | SkillWeaver / Inducing Programmatic Skills / SkillRL / AutoSkill | 技能族同伴：构造侧 vs PSN 维护侧 |
| 替代 | Reflexion 式口头反思、平铺技能库 | REFLECT 沿轨迹定责 + 网络重组 |

### 6.2 推荐组合方案
1. **案例→技能结晶管线（Memento × PSN）**
   - 形态：μ 检索复用案例；同类成功案例累积越过成熟阈值 → CODEGEN 蒸馏为带契约技能；
     成熟度门控决定冻结。
   - 纪律：V 只作事实；选择无评分；新技能必须带可验证契约。
2. **重放中验证重构（PSN × Dream-RSI）**
   - 形态：重构候选先在重放模拟器的近期任务窗上跑，>20% 劣化即弃；通过后再进真实环境。
   - 新增能力：自修改验证从「真实环境试错」变为「离线廉价淘汰」。
3. **实验 3 重设计**：以 SRR + 契约校准 + 成败回滚为判据，替代 SKILL_FAILURE 0/33 计数。

### 6.3 本篇在组合中的典型角色
- **技能库的结构化维护者 / 自修改安全框架**：管「技能何时改、怎么改、改坏了怎么退」。
