## 1. 一句话定位

- **论文主张**：提出 Agent-World——一个「真实世界环境规模化合成 + 持续自演化训练」的闭环竞技场：先用 deep-research agent 从数千个真实主题（MCP Servers ~2.8K / Tool Docs ~0.5K / 工业 PRD ~0.2K）自主挖出主题对齐的数据库与可执行工具集（**1978 个环境、19822 个工具**），再在其上用「工具图随机游走 + 程序化脚本」两条路径合成**可验证任务与可控难度**，最后用 GRPO 多环境 RL 训练，并由诊断 agent 从失败轨迹定位弱环境、定向扩环境再训，形成智能体与环境的共演化（p1、p3、p5、p9–12）。
- **对 SSEA 的意义**：它是目前看到的最完整的**「环境侧 = 数据库状态 D + 可执行工具集 F」可规模化工厂**。SSEA 第二阶段的选择压力若来自环境，就必须有「能批量造出、难度可标定、判定可执行、且**每个 Action 通道都有消费者**」的环境族——本篇恰好提供了这四件事的形状，直接指向债务 26/27（`skill` 通道无消费者、环境对无消费者通道报成功）与债务 25（判据形状错）；但它把难度标定与奖励交给「模型表现 / LLM 评委」，与 C9 第一层硬冲突，须剥离后才能用。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题
- 问题本身：LLM 作为通用智能体需要在**有状态的、可组合的**外部工具环境里交互（如订机票：查库存→下单→改日历，每步都改环境状态），但现实环境的构建与规模化是瓶颈（p2）。
- 它指出的既有方案缺陷（p2「两个未解瓶颈」）：
  1. **可扩展的真实感与复杂环境合成**：现有环境多为纯 LLM 生成或来自有限开源工具链，与真实交互逻辑不匹配；且复杂度有限，训不出长视野、状态密集任务。
  2. **持续自演化训练机制缺失**：已有工作偏重「造环境」，缺少用规模化环境**诊断智能体弱点并驱动持续改进**的原则性机制。
- 对 LLM-as-simulator 路线的具体批评：可扩展但易幻觉、偏离真实动态（p2）。

### 2.2 核心思想（关键 insight）
1. **环境 = (数据库 D, 工具集 F) 这一对可参数化对象**（`e=(D,F)`，p4）：把「状态」外置成可读写的结构化数据库，把「动作」具体化成读写该数据库的可执行函数。环境因此可被**自动生成、自动测试、自动版本化**——这是本篇最有搬运价值的抽象。
2. **拒绝 LLM 编造状态，改为从 Web 挖真实数据**：明确批评「LLM-synthesized databases」（p5），主张 Web 已含大量可实时更新的高价值结构化数据，用 deep-research agent 挖库 + 迭代复杂化 `φ`。
3. **任务可验证性靠「沙盒执行产物」而非参考答案字符串**：图任务产出执行轨迹 + rubric；程序化任务产出可执行解脚本 `π_code` + 可执行验证脚本 `V_code(a, a*)`，后者同时校验**答案与数据库状态** `s^E`（p8）。
4. **环境生态同时是训练场与诊断仪**：同一套 `E` 既供 RL 训练，又作为动态 arena 每轮重合成任务、定位弱环境、定向扩环境（p11–12, Algorithm 1）。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）
| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **环境参数化 `e=(D,F)`** | 主题 `m` → (数据库 D, 工具集 F) | 状态外置、动作可执行，环境可自动生成/测试/版本化 | §2 p4 |
| 主题收集（三源合并） | MCP Servers(Smithery ~2.8K) / 工具文档(~0.5K) / 工业 PRD(~0.2K) → 种子主题集 `M` | 环境多样性锚点 | §3.1 p4–5, Fig.2 p5 |
| **Agentic Database Mining** `D(m)=G(m;π_θ,T)` | 主题 + 搜索/浏览器/编译器/OS 工具 → 结构化数据库 | 用真实 Web 数据代替 LLM 编造状态 | p5 |
| **数据库复杂化算子 `φ`**（迭代 N 轮） | `D^(n)(m)` → `D^(n+1)(m)` | **环境侧的「变异算子」**：把小而简单的库扩成复杂库 | p5 |
| **工具生成与交叉验证** | coding agent `ψ` 生成 `(f̂, Ĉ_f̂)` → 三条件过滤 | 准入：能编译 **且** 单测通过率 `Acc(f̂;Ĉ_f̂)>0.5` **且** 该环境至少 1 个有效工具 + 1 个有效用例 | p5–6 |
| 环境分层分类法 | 层次聚类 → 50 类中心 → GPT-OSS-120B 归纳 → **3 名标注员**合并为 20 个一级类 | 20 一级 / 50 二级 / >2K 三级标签，支撑分层采样 | p6, Fig.3 |
| **工具图 + 随机游走** | 节点=工具，边权 strong=3 / weak=2 / independent=1 → 工具调用序列 `τ` → LLM 精修 `τ*` | 合成有依赖结构的长链任务 | p7 |
| 图任务 rubric 生成 | `τ*` 沙盒执行轨迹 → 任务描述 `q_final` + JSON 标准答案 `a*` + 结构化 rubric `R` | 多维自动判分（字段完整性/模式匹配/数值容差） | p7 |
| **任务质量一致性过滤** | ReAct agent 跑 5 次 → **至少 2 次**一致成功才保留 | 保「难而可解」，剔除不可解/不稳定任务 | p7（图）、p8（程序化） |
| **图任务难度标定**（三旋钮） | ① 提高随机游走最大步数（拉长工具链）② 提高 weak/independent 边采样概率（弱化显式顺序）③ 改写任务描述遮蔽工具名与执行逻辑 | 在不破坏可解性的前提下抬难度 | p7 |
| **程序化任务合成** | LLM 写 `q_prog` + 端到端可执行 Python 解 `π_code`（ReAct 调试循环）→ `a*` | 覆盖条件分支/循环/聚合等非线性推理 | p8 |
| **验证脚本生成 `V_code(a,a*)`** | `(q_prog, π_code, a*)` → 可执行验证脚本（多级断言 + 自定义逻辑） | 判定**答案与数据库状态**是否满足约束 | p8 |
| **程序化难度标定** | 增加唯一工具数与调用数、强制条件分支/跨库聚合排序过滤、遮蔽 API 与执行痕迹 | 同上 | p8 |
| **结构化可验证奖励** | 图任务：rubric-conditioned LLM-as-judge 逐条判分取通过率；程序化：`Execute(V_code(y,y*))` | RL 监督信号 | p10 |
| GRPO 策略更新 | 每组 G 条 rollout，token 级优势，clip + KL 到参考策略 | 稳定训练 | p10–11, 式(1) |
| **分层 Arena 构造** | 每个一级类随机抽 **K=5** 个环境 → `E_arena` | 覆盖广度 vs 评测成本可控 | p11 |
| **动态评测任务合成** | 每轮 r 对每个 arena 环境**重新**合成图任务+程序化任务及判据 | 防对静态评测集过拟合 | p11 |
| **Agentic Diagnosis `δ`** | 失败轨迹 + 按环境/类目的错误分布 + 工具 schema/库描述 → 弱环境排序 `W^(r)` + 定向任务生成指南 `G^(r)_guide` | 定位能力缺口 | p11, 附录 A p30–31 |
| **Agent-Environment Co-Evolution**（Algorithm 1） | `π^(r)` → 评测 → 诊断 → 复杂化 `D` + 定向生成 `X^(r)_target` → 继续 RL → `π^(r+1)` | 闭环自演化 | p12 |

### 2.4 关键表示与数据结构
- 环境 `e=(D,F)`：`D` 为环境状态 `s^E` 的载体（结构化记录/文件）；`F={f_k}` 为读写 `D` 的可调用算子（p4）。
- POMDP 元组 `(U,S,A,O,P)`，状态分解为 `S = S^E × S^H`（环境状态 × 对话状态），`s^E` **不可直接观测**，须由工具观测 `O^E` 推断（p3–4）。
- 动作空间 `A = A_tool ∪ A_resp`：结构化工具调用，或自然语言回复（p4）。
- 环境生态 `E = {(D^(N)(m), F(m)) | m ∈ M}`（p6）。
- 任务集：`X_graph`（含 rubric `R`）、`X_prog`（含验证脚本 `V_code`）（p7–8）。
- 诊断产物：弱环境集合 `W^(r) ⊆ E_arena`、生成指南 `G^(r)_guide(m)`（p11）。
- 数据库文件类型多样：json / csv / sql / html / tex / yaml（p9, Fig.4d）。

### 2.6 论文自陈局限与边界条件
- **论文未设独立 Limitations / Future Work 节**（检索全文 48 页，仅出现 "limitation" 作为行文用词，p2、p13，无局限清单）——这是本卡的观察，不是论文主张。
- 假设依赖（可回溯的隐含边界）：
  - 环境必须是「数据库 + 工具」形状；`s^E` 不可直视、只能由 `O^E` 推断（p4）——对非结构化/连续动力学环境不适用。
  - 任务保留门槛是「ReAct agent 跑 5 次至少 2 次成功」（p7–8）——**任务可解性以「某个 agent 能解」为定义**，因此难度上限被该 agent 能力封顶。
  - 难度以 **Doubao-Seed-2.0-pro 的 Pass@10** 作为探针（p9）——**难度标尺依赖另一个模型**。
  - 工具准入仅要求 `Acc>0.5`（p6）——工具可以「半数用例失败」仍被保留。
  - 人类介入仅在 taxonomy 环节：3 名标注员合并 50 个二级标签为 20 个一级标签（p6）；环境/工具/任务的生成与校验**全部自动化**。
- 明确不适用的情形（推断，论文未自陈）：无状态环境、连续控制/物理世界、无工具可用的封闭域；SSEA 的毫秒级快环（见 §5）。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射
| 裁判标准 | 判定 | 依据（论文具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | **◐** | 结构同向：状态外置 `s^E`、动作是读写状态的可执行算子、观测是结构化 `O^E`（p4），正是控制环友好的形状；但**域**是 MCP 工具调用/生产力场景（机票、邮箱、日历、酒店），不是生存域（p2、附录 B） | 只搬环境骨架，重定义状态量为生存相关量（能量/危险/资源）；不搬领域语义 |
| **C2** 自然语言只作观察员接口 | **◐（须分层判定，见下）** | **离线侧 ✓**：LLM 只出现在环境/任务/验证脚本的**建造期**（deep-research 挖库 p5、coding agent 写工具 p5–6、LLM 写 `q/π_code/V_code` p7–8、诊断 agent p11），产物是**可执行代码与数据**，运行时不加载语言。**在线侧 ✗**：被训练的策略每步输出「自然语言推理 + 工具/回答决策」（p10），`A_resp` 直接是自然语言动作（p4） | **只搬离线侧管线，不搬 LLM 策略**。判定锚点：**语言出现在编译期而非运行期**——故环境合成不构成 C2 违规，勿笼统判 ✗ |
| **C3** 权重/记忆/技能三分离 | **◐** | 环境 `(D,F)` 完全在模型之外、可独立版本化（p4、p6），与「环境不属于模型」同向；但论文不涉及记忆与技能，无三分离语义 | 环境侧可安全外置；记忆/技能分离仍按 PSN/Memento/FLEX 路线 |
| **C4** 低算力低带宽 | **◐（分层）** | **合成侧重**：1978 环境 / 19822 工具 / GPT-OSS-120B 挖库（p9、p13）；**交互侧重**：单任务平均 >20 轮、最长 >40 轮、轨迹上限 80K tokens（p9、p13） | 合成侧可接受（**离线一次性、可摊销**）；在线侧必须裁剪：工具数、轮数、观测字段数都要压到结构化小包（C4 的低带宽不是 token 而是结构化字段） |
| **C5** 精准回忆历史 | **—** | 论文不涉及记忆机制（未提及检索/写入/遗忘） | 可反向利用：`D` 是**可验证的外部事实源**，可作为记忆写入后的对照面（写入是否与 `s^E` 一致） |
| **C6** 可自主修改自身 | **◐** | 只覆盖四权中的**参数面应用权**：GRPO 更新 `π_θ`（p10–11）；提案权在外部合成管线、验证权在 `V_code`/rubric、边界权**无**（无禁止修改区） | 借「验证权外置」的形状；SSEA 仍需自己的提案/边界/验证/应用四权拆分 |
| **C7** 保存/恢复/变异/继承 | **◐** | 提供了**环境侧的变异算子** `φ`（迭代复杂化数据库 N 轮，p5）与环境包可快照性（附录 B 给出目录结构 + 工具实现）；但环境无代际/继承语义，智能体侧无 GenePackage | 把 `φ` 改造成 SSEA 的**环境变异算子**（与基因变异对偶）；保存/恢复/继承仍由 Gene Manager 承担（**当前缺失**） |
| **C8** 给基因先验，不给知识语料 | **✓** | 世界知识全部留在**环境数据库**里（从 Web 挖真实数据，p5），不进策略权重；策略侧只学到交互逻辑 | 与 C8 完全同向：**知识留在环境、结构进基因**。可把本篇作为「知识外置到环境」的工程样板 |
| **C9** 不设评分函数，只有淘汰函数 | **✗（硬冲突，须剥离）** | 三处违规：① **rubric-conditioned LLM-as-judge** 逐条打分并取通过率（p10）——典型的观察员评分；② 奖励直接进入 GRPO 优势做**排序与塑形**（p10–11）；③ **难度由被测智能体的失败痕迹驱动**（诊断 `δ` → `W^(r)` → 定向生成更难任务 + 复杂化 `D`，p11–12）——智能体的行为反过来决定了它要承受的淘汰压力 | 剥离方案见 §5.1（三条分别处理） |
| **C10** 创新在 L2/L3/L4，不在 L1 算子 | **✓** | L1 全部借用（GRPO [84]、ReAct、层次聚类 [101]、VQ 无）；创新在环境合成管线与共演化循环 | 无冲突 |

| 层次 | 论文在该层提供了什么 | 对 SSEA 的价值 |
|---|---|---|
| **L1 算子层** | 无新算子（GRPO / ReAct / 层次聚类均为借用） | 无（符合 C10，不加分也不扣分） |

## 5. 冲突、代价与风险

### 5.1 与硬约束的冲突（逐条）
1. **C9 ✗ ①：rubric-conditioned LLM-as-judge 是评分函数**（p10）。
   → **剥离**：判据只允许**可执行断言**（`V_code` 形状），输出二值「通过 / 淘汰」；删除 rubric 打分与通过率平均值；任何 LLM 评委一律不进判定路径（C9 明文：观察员评分违规）。
2. **C9 ✗ ②：奖励进 GRPO 做排序与塑形**（p10–11）。
   → **剥离**：SSEA 侧不接 RL reward；`V_code` 的二值结果只作为**环境实测门的合法性判据**（四级门的第四级），不参与打分、不排序（C9：验证门只判合法性）。
3. **C9 ✗ ③（最主要冲突）：难度由被测对象的失败痕迹驱动**——诊断 agent 读失败轨迹 → 排出弱环境 `W^(r)` → 定向生成更难任务 + 复杂化数据库（p11–12）。这意味着**智能体的行为可以改变它随后承受的淘汰压力**，模型可以「装弱」来降低难度，淘汰函数因此**不再与模型物理隔离**（违反 C9 第一层）。
   → **剥离方案（三层）**：
   - **输入层**：诊断的输入**不得包含个体轨迹**。只允许**群体级、跨世代的聚合统计**（某环境类目上整代的淘汰率分布），且统计窗口跨多个世代，使单个个体无法通过自身行为影响当期环境。
   - **标定层**：难度必须由**环境侧的离线结构指标**决定——工具图深度、状态维度、交互轮数、状态转移分支数、不可观测度（`s^E` 需要几步才能推断）——**不得**以「某模型 Pass@10 只解出 1 次」这类以模型为标尺的量定义难度（p9 的 Doubao-Seed-2.0-pro 探针即属此类，须替换）。
   - **冻结层**：环境一经发布即写入**环境版本号并冻结**，模型**读不到也改不了**（对应 C9「模型物理上碰不到」）；环境只在慢环的离线侧、按环境版本号升版，方式与 ΔS/ΔM/ΔR/Δθ 的原子升版对称。
   - 剥离后保留的价值：**环境与智能体共演化**这个方向本身不否定（达尔文闭环本就需要环境侧变异），否定的是「由被测个体的失败来定向定制」这一种实现。
4. **C2 ✗（仅在线侧）：策略输出自然语言推理与回答**（p4、p10）。→ 不搬策略本体，只搬离线合成管线。
5. **C1 ◐：域非生存**。→ 状态量重定义（能量/危险/资源），工具语义换成生存动作。

### 5.2 隐含假设与失效条件
- 任务可解性以「ReAct agent 5 次中 2 次成功」定义（p7–8）→ **难度上限被该 agent 的能力封顶**；若 SSEA 用它造题，会造出「永远可解」的环境，淘汰压力不足。
- 工具准入 `Acc>0.5`（p6）→ 允许「半数用例失败」的工具进入环境，会造成**环境本身的不确定性被误判为智能体失败**（与债务 25/28 同类）。SSEA 侧应抬高门槛。
- 难度探针依赖 Doubao-Seed-2.0-pro（p9）→ 换标尺则难度刻度全变，不可复现、不可跨项目比较。
- 环境是离散状态 + 确定性工具（附录 B 全为 json/csv 文件读写）→ 对连续动力学、噪声、部分可观测延迟等生存要素**未覆盖**。
- 论文未提供环境合成的单位成本（挖一个环境/一个工具消耗多少算力、多少 token）→ **未提及**，无法据此定 SSEA 的睡眠期计算预算。

### 5.3 算力 / 带宽 / 工程代价
- 合成侧：1978 环境 × 19822 工具，挖库/写工具/造题/诊断均用 GPT-OSS-120B（p13）→ 重资产，但**离线一次性可摊销**，且 SSEA 不需要复现 8B/14B 策略训练（省掉 RL 侧全部开销）。
- 交互侧：>20 轮、上限 80K tokens 的轨迹（p9、p13）与 SSEA 毫秒级快环（C4）不兼容 → 在线侧必须裁剪到「小工具集 + 短轮数 + 结构化字段观测」。
- 工程代价主要落在**通道契约改造**上：要先给 6 个 Action 通道各自配消费者与单测，才能谈环境规模化——这与债务 27 是同一件事，顺序不能颠倒。

### 5.4 搬运后的可能退化模式
- **环境塌缩**：自动合成的环境收敛到少数几种模板（论文 taxonomy 只有 20 个一级类；若抽样不放回则会退化）→ 淘汰压力多样性下降，指标重新饱和。
- **判据过严 / 过松**：`V_code` 若只判末端状态，会漏掉「过程正确但末态偶然正确」与「过程错误但末态恰好正确」两类；若判过细则会把噪声当失败（对应债务 25 的另一种形状错）。
- **难度通胀**：复杂化 `φ` 无上界控制时，环境会一路变难，淘汰率趋 1，所有基因一起死，失去选择性（与「记忆门选择性缺失」同类风险）。
- **幻觉污染**：尽管论文拒绝 LLM 编造状态（p5），但工具/任务/验证脚本仍由 LLM 生成；若 `V_code` 自身有 bug，会把**环境判据的 bug** 记到智能体账上。
- **装弱博弈**（若未做 §5.1-3 的剥离）：智能体学会表现得更差以换取更简单环境——这是本篇机制搬到 SSEA 后最危险的退化模式。

| 风险清单 | **Misevolve** | 误演化威胁模型与红队验收清单。**需新增一条威胁路径：环境侧污染/难度博弈**（本篇 §5.4 各项），此前清单只覆盖模型/记忆/工具/工作流四路径，环境侧是第五条 |
| 训练诊断 | **RAGEN** | Echo Trap 诊断 + 不确定性过滤。本篇共演化若未剥离，会与 Echo Trap 叠加（模型自我强化的同时还在改环境） |
| 间接 | **FLEX / Memento / MemRL / LightMem / Mem0 / A-MEM** | 记忆侧主干。本篇不直接相关，但环境包提供**可验证的外部事实源**，可作为记忆写入正确性的对照面（写入是否与 `s^E` 一致） |
| 形式化参照 | **Gödel Agent / ADAS / MaAS** | 自指递归自改进、自动设计智能体的形式化。本篇的 `π^(r)→W^(r)→X^(r)_target→π^(r+1)` 可作为**环境侧**的形式化实例补进北极星 |

### 6.2 推荐组合方案
- **组合 1（最优先）：本篇（通道消费者准入 + 状态判据）× SSEA 6 通道**
  - 接口形态：每个 Action 通道 = 一个 `F` 中的工具，必须满足「可编译 / 有单测 / 该环境至少 1 个有效用例」；`skill` 通道若无消费者 → **准入失败**（不是成功）。
  - 组合后新增能力：债务 26/27/28 一次性闭合；「技能失效被判成成功」失去生存空间。
  - 新增风险：准入过严导致当前环境大面积不合规 → 需先做一次通道盘点（分母：6 通道中合规数）。
- **组合 2：本篇（环境包 + `V_code`）× PSN（技能契约）**
  - 接口：PSN 的技能契约声明「调用后 `s^E` 应满足的断言」，本篇 `V_code` 执行该断言。
  - 新增能力：技能固化实验（当前 0/33）的判据从「形状匹配」换成「环境状态验证」。
  - 风险：断言写错会把环境 bug 记到技能账上 → 需 `V_code` 自身的元验证（`V_code` 对已知正确轨迹必须判通过）。
- **组合 3：本篇（难度三旋钮）× 淘汰率仪表**
  - 接口：三旋钮 → 淘汰率曲线；目标是把危险回避率从 0.9814 拉到可分档区间（避免饱和）。
  - 风险：难度通胀（见 §5.4）→ 需给旋钮设上界与「淘汰率分档」的停机判据（可借 FLEX 的 logistic 增长曲线作停机判据的形状）。
- **组合 4：本篇（环境版本化）× Gene Manager（缺失）**
  - 接口：环境版本号与 GenePackage 版本号配对，A/B 对照时两者同时固定。
  - 风险：Gene Manager 未实现前，环境版本化只能手工记账 → 建议环境版本号先做（无依赖），Gene Manager 后补。
- **组合 5：本篇（分层 arena + 每轮重合成）× SEDM（A/B 准入）**
  - 环境包也走「自包含打包 + A/B 准入」，防止环境侧引入回归。
- **组合 6：防污染 —— 本篇 × Misevolve**
  - 把「难度博弈 / 环境塌缩 / 判据 bug 误记」三条加入误演化红队清单（环境侧第五条路径）。
- **组合 7（与 GenEnv 的取舍）**：GenEnv 与本篇共演化同冲突，**合并判一次**，共用「难度由环境侧离线结构指标决定 + 个体轨迹不得作为生成条件」的剥离规则。
- **组合 8（与 Genie 的分工）**：Genie 管「没记录的未来长什么样」（离线想象），本篇管「动作把可验证状态推向哪」（在线淘汰），**不得互换**。

### 6.3 本篇在组合中的典型角色
- **环境包工厂 + 淘汰判据形状供应商 + 难度刻度盘**：管「淘汰压力从哪来、怎么批量造、难度怎么标定、判定怎么写」。
- 明确**不是**：不是记忆组织者、不是技能表示方案、不是策略训练方法（这三块分别归 Memento/FLEX、PSN、RAGEN）。

## 8. 裁决与下一步

- **应用等级：B 零件采用** —— 采用「环境包 `(D,F)` 契约 + 通道消费者准入 + `V_code` 状态判据 + 难度三旋钮 + 分层 arena + 环境侧变异算子 `φ`」；**不采用** LLM 策略本体、rubric LLM-as-judge 奖励、以及以个体失败痕迹驱动的难度共演化（须按 §5.1 剥离后方可谈）。未给 A 的原因：存在 C9 硬冲突需实质改造，且证据侧有数字不自洽与无消融（证据强度 3）。
- **优先级：P1** —— 不是 P0，因为当前卡点（Gene Manager 缺失、实验 4/5 未跑）不是环境数量问题；但环境契约是债务 26/27 的直接解，应在记忆/技能主干之后、环境规模化之前落。**若 §5.1 的剥离方案经实验验证可行，可升 A。**

- **建议动作**（按执行顺序）：
  1. **通道盘点（先做，零依赖）**：对 6 个 Action 通道逐个判定「是否有消费者 / 是否有单测 / 是否至少 1 个有效用例」，列出合规数（这是所有后续工作的分母）。
  2. **落地通道消费者契约**：无消费者的通道判定为**准入失败**而非成功（直接闭合债务 26/27）。
  3. **判据形状改造**：四级验证门的判据从「输出形状」改为「环境状态 + 可执行断言」（`V_code` 形状），并给 `V_code` 自身加元验证（对已知正确轨迹必须判通过）。
  4. **环境版本号**：先于 Gene Manager 实现，环境一经发布即冻结、模型不可读写（C9 第一层的工程保障）。
  5. **难度刻度盘原型**：三旋钮 + 淘汰率曲线，用于把回避率从 0.9814 拉离饱和；难度**只由环境侧结构指标**定义（工具图深度 / 状态维度 / 轮数 / 分支数），禁用任何「某模型 Pass@10」式标尺。
  6. **环境卡模板**：直接抄附录 B 的格式（目录结构 + 工具清单与意图 + 参考实现），用于 SSEA 环境包文档。
  7. **Misevolve 清单增补**：加入环境侧第五条误演化路径（难度博弈 / 环境塌缩 / 判据 bug 误记）。
  8. **与 GenEnv 合并评估**：同一冲突只判一次，共用剥离规则。

- **最小验证实验（通道契约 + 判据形状）**
  - **双臂 / 消融**：
    - Arm A（对照）：现有 6 通道手写环境 + 现有判据。
    - Arm B（处理）：6 通道全部加「可编译 / 有单测 / ≥1 有效用例」准入；判据改为 `V_code` 判定环境状态；`skill` 通道因无消费者应被判**准入失败**。
    - 消融 B1：只加通道准入、不改判据；B2：只改判据、不加准入（用于定位债务 26/27 与 25/28 各自的贡献）。
  - **判据（分档，先看分母）**：
    1. **机制计数**：无消费者通道数（分母 = 6）→ 期望 A 臂 ≥1（`skill`）、B 臂 0；准入拒绝事件数是否 >0（若 =0 说明契约未接入判定路径，实验无效）。
    2. **行为差**：注入已知失效技能后，被误判为「成功」的次数 → A 臂 >0（债务 28）、B 臂 0。
    3. **淘汰结果**：第四级环境实测门的淘汰率是否脱离饱和（当前危险回避率 0.9814）；B 臂应出现可分档的淘汰率分布而非全通过。
  - **预期与证伪**：预期 B 臂捕获 `skill` 通道准入失败且失效技能不再被判成功。**证伪条件**：若 B 臂仍把失效技能判成功 → 说明判据形状错在更上游（技能表示问题，本篇不解决，转 PSN / 技能表示议题）；若 B 臂淘汰率全 0 或全 1 → 难度标定失效（进入难度刻度盘实验）。

- **补充实验（难度刻度盘）**：固定环境包，只调三旋钮，测淘汰率随旋钮的单调性与可分档性；判据为「淘汰率能否落在 0.2–0.8 的可分档区间」；若无论如何调整都饱和于 0 或 1 → 说明本篇难度标定对 SSEA 域无效。

- 若 **E 不采用**：不适用（裁决为 B）。

## 9. 待确认问题

- **需作者 / 团队决策**：
  1. SSEA 的「环境」是否允许由 LLM 离线生成（本篇立场：可以是，只要产物是可执行代码与真实数据、运行时不加载语言）？需团队明确「编译期语言 / 运行期语言」的分界线，这会同时影响 Genie、GenEnv、AutoForge 等一批卡片的判定。
  2. 环境与智能体共演化，在剥离「个体失败驱动」之后，SSEA 是否接受**群体级、跨世代统计**驱动的环境难度调整？若不接受，则环境只能静态，多样性须靠数量而非反馈。
  3. 环境变异算子 `φ` 的**上界**由谁定（防止难度通胀）？是否纳入慢环的边界权？
- **需补查的文献或资料**：
  1. GenEnv（难度对齐共演化）与本篇的**具体差异**：两者是否都允许个体失败驱动难度？若是，剥离方案可合并。
  2. EnvScaler / ScaleEnv / AutoEnv / AutoForge / Endless Terminals 各自的**可验证性方案**是否与本篇 `V_code` 等价，还是各有更严的判据形状（决定债务 25 的解法选哪个）。
  3. 环境合成的单位成本（本篇未提及：挖 1 个环境 / 1 个工具的 token 与算力开销）——这是定义 SSEA 睡眠期计算预算的必要输入。
- **需人工核对的公式 / 数字 / 实现**：
  1. **Table 2 与正文不一致**：表 2 中 Agent-World-14B(base) τ²-Bench = **60.2**，正文 §4.3.4 另处写 base = **45.3**（终点同为 38.1 的 MCP-Mark 列一致，τ² 终点 65.4 vs 50.5）。需核对哪一个对应 Table 1 的 65.4。
  2. **MCP-Mark 列**：Table 2 的 "MCP-Mark (Post.)" base = 29.5，而 Table 1 中 Agent-World-14B 的 MCP-Mark(Postgres 子列) = 16.6、Avg = 13.3 —— 两个表的评测协议可能不同，需确认哪个是可比的。

  4. 工具准入阈值 `Acc>0.5`（p6）的来源与敏感性：论文未给消融，需自行确定 SSEA 侧的可接受门槛。
  5. 附录 A 的诊断提示词与 Table A 的输出 schema 未在本卡逐字段核对（仅确认其输入含失败轨迹、错误分布、工具 schema；输出含弱环境排序 + 定向生成指南）。
