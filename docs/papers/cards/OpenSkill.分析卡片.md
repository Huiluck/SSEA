## 1. 一句话定位

- **论文主张**：定义并求解 **open-world self-evolution**——只给一个任务 prompt 与开放世界资源（文档/仓库/网页/教程），不给技能、不给示范、不给奖励、不给 verifier，智能体必须**同时自建技能与自建验证信号**；OpenSkill 用「开放世界取知识（k_i）+ 取验证锚点（k^v_i）→ 用锚点生成虚拟 pytest 断言集（\tilde T）→ 以虚拟通过率 \tilde r 驱动最多 J=3 轮精炼 → 冻结技能 artifact 零样本部署」三阶段管线，在 SkillsBench 上达 43.6%（Opus 4.6）/ 42.1%（GPT 5.2），超过最强闭世界基线 +8.9 / +8.8 点（p1、p5–6）。
- **对 SSEA 的意义**：它把「**验证信号从哪里来**」这个 SSEA 一直回避的问题推到了台面上，并给出一个可测量、可审计的参考答案——**验证信号应由环境侧持有的、独立于模型的可核验事实锚点生成，且验证者与提案者必须物理隔离**；这正对 SSEA 的环境侧缺口（实验 4/5 卡在 Gene Manager、**环境对无消费者通道报成功**、技能失效被判成成功）与**验证门可信度**这一未测量的对象。但它把这件事做成了 LLM 控制器 + markdown 技能 + 自建评分，与 C1/C2/C8/C9 四处冲突，**只能拆零件，不能整搬**。

## 2. 问题 — 机制 — 证据

### 2.1 论文要解决的问题

- **问题设定**（§2.1 p3）：n 个目标任务 {(I_i, E_i)}，智能体 π_θ 产生终态 x_i；每任务配隐藏真值测试集 T^GT_i ∈ {0,1}。演化方式限定为**上下文增广**（不改权重 θ），即构造技能集 S_i 使 T^GT_i(π_θ(I_i, S_i, E_i)) = 1。
- **难点**（p1–3）：开放世界部署**只给一个 seed task prompt**，没有初始技能、没有成功轨迹、没有 verifier、没有奖励。「观察输入 (I_i, E_i) 不算监督；只有依赖隐藏信号 T^GT_i（金答案/奖励/verifier 输出）才算监督」（p3）。形式化要求 \hat S_i = f(I_i, E_i, K)（Eq.2），且 f **不观察也不反推** T^GT_i（supervision-free 定义，p3）。
- **它指出的既有方案两条缺陷**（p1–2）：
  1. **Limitation 1 技能构造侧**：依赖人工写技能、模型自造知识、或从成功轨迹蒸馏——代价高、受先验知识上限约束、或在首次成功之前根本不存在。
  2. **Limitation 2 验证构造侧**：既有自改进环依赖任务级反馈、自我反馈或 verifier 输出；开放世界部署期间**没有可靠反馈**，必须自建一个监督来自开放世界知识（而非隐藏答案）的练习环境。

### 2.2 核心思想（关键 insight）

1. **开放世界同时供给「学什么」与「拿什么验」**：同一批外部证据要同时产出技能内容（k_i）与**验证锚点**（k^v_i）——四类可独立核验的锚点：可手算的小输入参考值、数据集级统计不变量、用替代工具交叉验证的程序、带已知输入输出对的公开基准/参考实现（p4、Appendix B.2 p15）。
2. **虚拟验证器（Virtual Verifier）**：用一个**独立 LLM session**（与技能创造者共享容器与产物文件，但**不共享对话、推理与实现代码**）生成确定性 pytest 断言集 \tilde T_i = g(I_i, E_i, k^v_i)（Eq.3 p4），以 \tilde r = 通过断言数/总数（Eq.4 p4）作质量代理；隔离的目的是避免 confirmation bias（B.3 p16）。
3. **失败分诊驱动精炼，而非笼统反思**：\tilde r < 1 时产出结构化诊断 F^(j)（逐断言结果 + 根因分析 + 修改建议），并用一个分类器把失败分成 **SELF-FIXABLE（实现 bug，自己改）** vs **NEEDS-DR（知识缺口，触发定向检索）**（p5、B.5 p16）。
4. **技能是可移植 artifact 而非权重**：显式 artifact 可零样本部署到**任意**目标 agent，无需再训练、无需再生成；论文明确拒绝权重路线（"expensive, model-specific, and opaque"，p3）。

### 2.3 关键机制 / 算法（可独立搬运的「零件」清单）

| 零件 | 输入 → 输出 | 作用 | 出处 |
|---|---|---|---|
| **开放世界知识获取 D** | (I_i, E_i) → 背景文档 k_i + 来源 URL 列表 | 给技能构造提供当前/领域知识，突破参数化知识上限 | §2.2.1 p4、B.1 p15 |
| **Leakage filtering（sanitize_query）** | 查询串 → 去掉基准名及其变体的查询串 | 防止检索引擎命中基准自身页面泄漏答案 | B.1 p15 |
| **Skill Planner** | (I_i, E_i, k_i) → 技能计划 p_i（1–4 个技能：名/职责/关键函数/依赖章节） | **固定技能数量与职责边界**（架构先定，LLM 只填内容） | B.1 p15–16 |
| **验证知识检索 D^v（四类锚点）** | (I_i, E_i) → k^v_i（参考值 / 统计不变量 / 交叉验证程序 / 已知 IO 对的公开实现） | 为虚拟测试提供**独立于模型的"事实锚点"** | §2.2.1 p4、B.2 p16 |
| **"Already Known" 去重块** | k_i 前 4000 字符注入 D^v prompt | 保证 k^v_i 与 k_i 不相交（验证信息与内容信息解耦） | B.2 p16 |
| **虚拟测试生成器 g（Independent Verifier）** | (I_i, E_i, k^v_i) → pytest 断言集 \tilde T_i（≤60 条） | 产出**确定性、可复现**的逐条 0/1 检查 | Eq.3 p4、B.3 p16 |
| **非 LLM 解析器** | pytest 输出 → \tilde r^(j) = 通过/总数（跳过项不计） | 质量信号**不经语言模型判定**，避免 LLM-as-judge 校准问题 | B.3 p16 |
| **诊断式精炼（Eq.5）** | (\hat S^(j), F^(j)) → \hat S^(j+1) | 逐断言定位 + 根因 + 修改建议；禁止直接改输出文件 | Eq.5 p4、B.4 p16 |
| **gap-vs-bug 分类器** | 失败断言 + 诊断 + 领域知识 → SELF-FIXABLE / NEEDS-DR | **分诊**：实现错误自修 vs 知识缺口触发定向检索（≤3 次/任务）；分类器失败时保守默认 SELF-FIXABLE | B.5 p16 |
| **终止与早停** | \tilde r = 1.0 且结构检查通过 → surrogate_pass；否则最多 J=3 轮 | 精炼预算硬上限 | §2.2.2 p5、B.4 p16 |
| **多重早停护栏** | idle/stale episode 3/10、token 预算 warn 70% / stop 90%、verifier 20 / creator 60 episodes、host 干预 ≤1 | **计算预算治理** | Table 5 p15、B.4 p16 |
| **冻结部署（Stage 3）** | \hat S\*_i（**终止时的最后一个版本，就地编辑，非 best-of-N 择优**）→ 目标 agent | 技能与构造模型解耦，可跨模型迁移 | §2.2.3 p5、B.6 p17 |
| **五层信息隔离审计** | code / container / GT-oracle bypass / log / prompt 五层 | 证明构造期未接触 GT | Appendix F p18–19 |

### 2.4 关键表示与数据结构

- **技能集** \hat S_i = {\hat s_{i,1},...,\hat s_{i,m}}，规模 m ∈ [1,4] 由 Stage-1 计划 p_i 固定（p4）；落地形态是 **SKILL.md markdown 文档 + 内嵌脚本**（基线 Self-Gen 的提示词显示：YAML frontmatter + 约束 + 工作流 + 常见错误，可选 scripts/ 目录，p19–20）。**注意：无契约、无前置/后置条件、无版本、无成熟度、无回滚记录**——与 PSN 的技能表示形成尖锐对照。
- **验证知识 k^v_i**：四类锚点的文本块，作为生成虚拟测试的 "primary oracle"（B.2–B.3 p16）。
- **虚拟测试** \tilde t_{i,k} ∈ {0,1}：**确定性相等断言**（如 `assert x == y`），非评分、非 LLM 判定（B.3 p16）。
- **诊断 F^(j)**：逐断言通过/失败位 + 根因 + 修改建议的**结构化**报告（p4）。
- **未提及**：没有跨任务技能库、没有技能复用率/成熟度/淘汰机制、没有情景记忆库、没有权重更新。每个任务一套技能，**任务之间不共享、不淘汰**（推断：全文按 per-task 构造，Appendix B.6 明确"each task"）。

### 2.6 论文自陈局限与边界条件

- **自陈三条局限**（p10）：① 网页与仓库来源可能**噪声、过时、相互矛盾** → "requires provenance tracking and source validation"（论文自认未解决）；② 虚拟任务可能无法覆盖真实任务难度——**太易则高估技能质量**，若由隐藏答案/verifier 行为反推则**重新引入目标监督**；③ 开放世界检索相对闭世界技能生成**增加成本与延迟**。
- **隔离是"进程级 + prompt 级"，不是文件系统沙箱**（B.3 p16 原文自认）；且 Appendix F p19 承认存在**唯一一条 GT 派生信号：1 bit 的 pass/fail**，在"重新调用验证器写更深测试"时使用（无 GT 内容、断言细节与期望值外泄）。
- **假设依赖**：依赖商业 deep-research API（deep-research-pro-preview-12-2025）与搜索增强 LLM（gemini-3.1-flash-lite）；依赖 pytest 可执行的任务形态（非标准任务上验证器整体失效，见 Appendix C）。
- **明确不适用 / 未覆盖**：全部基准为文本—代码—科学类 agentic 任务，**无具身、无生存、无连续控制、无跨任务技能库与淘汰**；技能为 per-task artifact，**未提及**技能淘汰、复用率、库规模增长、灾难性遗忘；未做权重更新（主动放弃）；Manufacturing 域全域 0.0 未解释。

## 3. SSEA 立场对齐（核心维度）

### 3.1 C1–C10 映射

| 裁判标准 | 判定 | 依据（论文具体机制/数字） | 若冲突：改造方向 |
|---|---|---|---|
| **C1** 生存控制架构，非语言生成 | **✗** | 控制器全程是 LLM session：planner 出检索查询、creator 写技能并精炼、verifier 写测试、classifier 做分诊（B.1–B.5 p15–16）；任务域是 SkillsBench/SocialMaze/ScienceWorld，**无生存信号、无危险、无死亡**，Eq.6 的 PassRate 是任务通过率而非存活率（p5） | 只借**离线构造面的形状**（取证据→自建验证→精炼→冻结），把 LLM 全部放到慢环编译面；快环控制器仍只处理结构化生存信号，运行时零 LLM |
| **C2** 自然语言只作观察员接口 | **✗**（硬冲突） | 自然语言**既是控制器又是技能表示又是验证器**：技能是 SKILL.md markdown（G.2 p20），虚拟测试是 LLM 写的 pytest 脚本，精炼由 LLM 在同一长会话内自主完成（B.4 p16）。这与「会说≠会做」正面冲突 | 三重降级：① 技能表示改结构化 ΔS（契约 + 参数 + 前后置，走 PSN 路线）；② 验证测试改**环境侧**持有与生成，模型不得自持；③ LLM 只作 RuleCompiler，产物须过静态检查与环境再验证才交付 |
| **C3** 权重/记忆/技能三分离 | **◐** | **权重/技能分离明确成立**：显式拒绝权重修改（"expensive, model-specific, and opaque"，p3），技能是独立可移植 artifact（B.6 p17）；但**记忆侧缺失**——无情景记忆库，跨任务只有"技能 artifact 可跨模型复用"，经历不落库（**未提及**） | 保留其"artifact 优于权重"的论证（对 C3/C7 是有力外部证据）；记忆侧仍由 Memento/MemRL 承担 |
| **C4** 低算力低带宽 | **✗/◐** | 单任务创建 ≈749K tokens / 39 min，84 任务 31.4 API-小时 ≈$1,800（Table 7 p17）；依赖商业 deep-research API。**正面**：预算治理显式且严格——技能数固定 1–4、测试上限 60、J=3、host 干预 ≤1、idle/stale 3/10、token warn/stop 70%/90%（Table 5 p15） | 量级不可搬；**只搬预算治理的形状**：SSEA 慢环必须有等价的「预算门 + 早停 + 上限 + 护栏」，且预算由环境侧设定，非模型自定 |
| **C5** 精准回忆历史 | **—（未提及）** | 论文无经验记忆、无跨 episode 检索、无遗忘/合并；技能为 per-task 冻结产物 | 无直接供给。间接启发：k^v_i 的"四类锚点"是一种**可检索的外部事实槽**形态，SSEA 的环境侧可设同构的"可独立核验事实库"，但那是环境侧资产，不是模型记忆 |

| **C10** 创新在 L2/L3/L4，不在 L1 算子 | **✓** | 无任何新算子；全部 LLM/Gemini 为现成件借用（A.1 p13）；创新在知识获取面（L2）、自建验证与精炼（L3）、技能 artifact 化与跨载体迁移（L3/L4 边界） | — |

### 3.4 债务与验收实验对应

- **债务 25 / 26 / 27（判据形状错、环境对无消费者通道报成功、技能失效被判成成功）**：本文的 Appendix C 给出了**同构失败模式的分类学**——尤其 5 例「验证器基础设施整体失败（0% 通过率，但解法是对的）」，与 SSEA「环境对无消费者通道报成功」形状一致：**验证管线自身失效时，其输出既不可信也不自报**。五层隔离审计则是防这类假成功的具体检查表。
- **债务「验证门开得准不准」**（记忆门同类问题的技能/结构侧版本）：本文把「验证器的品质」变成了**可测量对象**（一致率/精确率/覆盖率 + 失败模式分布），SSEA 目前没有这套仪器。
- **债务「睡眠期计算预算未定义」**：Table 5 的护栏套件 + Fig.4a 的迭代拐点消融，是目前见到最直接的**经验标定参照**（推断：生存域数值需重标定，形状可搬）。
- **债务「技能表示够不够」（0/33 之后未答）**：本文给出**反向证据**——技能表示可以很轻（markdown + 脚本、无契约、无成熟度），仍能 +18.1 点（Opus，43.6 vs No Skill 25.5）。这提示 **0/33 的瓶颈可能不在表示而在判据与验证器可信度**；但本文**不提供**复用/淘汰/回滚，故不能单独回答该债务，必须与 PSN 的 SRR/复用率/成熟度门控组合（见 §6.2）。
- **Gene Manager 缺失（实验 4/5 卡住）**：本文**不解决**；只提供「artifact 优于权重、可跨载体迁移」的论据（Fig.3 p7）与冻结语义（B.6 p17）。
- **可服务的验收实验**：**实验 3（技能固化）**——其判据形状可改为「验证门可信度（假阳/假阴）+ 逐断言定位命中 + 回滚成功率」三件套；实验 4/5 待 Gene Manager，本文只间接服务（可遗传性判据的素材）。

## 5. 冲突、代价与风险

### 5.1 与硬约束的冲突（逐条，对应 3.1 中 ✗/◐）

- **C9（最硬）**：自建代理评分 \tilde r 驱动精炼 = 模型自己出题、自己打分、自己改。**剥离方案（四步）**：
  1. **二值化**：\tilde r 从"连续分数"降为"全过/未全过"的**合法性门**（论文终止条件本就取 \tilde r = 1.0，方向一致，只需去掉"用 \tilde r 比较优劣"的所有用法）；
  2. **定位化**：精炼目标从"提高 \tilde r"改为"消除 F^(j) 中已定位的具体失败断言"，F 是**定位器不是评分器**；
  3. **外置化（关键）**：把生成器 g 与锚点库 k^v **判归环境侧**——SSEA 的 C9 要求「淘汰函数归环境，模型碰不到」。环境从世界的可核验事实出题，模型只提交 ΔS 声明。**这一步做不做，决定了这篇是 B 还是 D**；
  4. **去回流**：删除 1-bit GT 信号（Appendix F p19 承认存在），GT 只作 SSEA 的实验仪器，不回灌模型。
  - 反过来说，本文**反而给 C9 提供了实证支持**：代理验证器与真值的一致率仅 60.7%、precision 56.9%，25 例假阳中有 12 例"mean acc 0.81 却因全或无判据被判 0 分"（Appendix C p17）——**自建评分函数会系统性误判**，这恰是 C9 立场所预言的。
- **C1/C2**：LLM 作控制器 + 语言即技能表示。改造见 3.1；不可调和的部分（语言在闭环内）**不搬**。
- **C8**：后天知识入技能。分层剥离见 3.1（L3 允许 / L4 禁止）。
- **C4**：每任务 749K tokens、84 任务 ≈$1,800。只搬预算治理形状，不搬量级。

### 5.2 隐含假设与失效条件

- **假设"存在可独立核验的公开事实锚点"**——这是整个自建验证的地基。**生存域没有文档、没有标准数据集、没有公开参考值**：D^v 的四类锚点在 SSEA 环境里对应什么（能量/伤害映射的不变量？危险—后果的可复现映射？）是**最大的搬运障碍**，也是 §8 的证伪条件。
- **假设任务可被 pytest 断言捕获**：Appendix C 的 5 例"验证器基础设施整体失败"（CVE 补丁、构建系统、证明助手）证明该假设在非标准任务上直接崩。生存域的"成功"若不能写成确定性断言，则整条验证链失效。
- **假设检索不泄漏**：论文自认隔离是"进程级 + prompt 级，非文件系统沙箱"（B.3 p16），且承认 1-bit GT 回流（F p19）。
- **假设来源可信**：论文自陈需要 provenance tracking 与 source validation 但**未提供**（p10）。

### 5.3 算力 / 带宽 / 工程代价

- 单任务创建 ≈749K tokens / ≈39 min；84 任务创建 31.4 API-小时 / ≈47M tokens；端到端 140 小时 / ≈97M tokens / ≈$1,800（Table 7 p17，Opus 4.6 定价）。
- 依赖商业 deep-research API（deep-research-pro-preview-12-2025，轮询 10s / 硬超时 3600s）与搜索增强 LLM（gemini-3.1-flash-lite）（Table 5 p15）。
- 与 SSEA 低算力立场**严重不匹配**；若要搬，需以本地小模型替代 deep-research 角色（可行性未知，本文未做该消融）。

### 5.4 搬运后的可能退化模式

1. **验证器被提案侧同化**：若隔离只在 prompt 级，慢环会把"我打算做什么"泄露给验证器，验证器退化为复读机 → 表现为放行率上升、环境实测存活率不变（**与 SSEA 现有"无消费者通道报成功"同形**）。
2. **过拟合自建验证器**：精炼轮数越过拐点后性能下降（79.9 / 78.0，Fig.4a p8）→ 表现为虚拟通过率单调上升而真实存活率下降，即**分数上涨、能力下降**。
3. **锚点漂移**：开放世界/环境侧锚点过时或噪声 → 验证门系统性放行错误结构（对应论文自陈局限①，p10）。
4. **知识膨胀**：开放世界知识持续入技能 → 技能体积无界增长，违反 C4/C8（本文无淘汰机制，不做防护）。
5. **Manufacturing 式全域塌陷**：某类任务上所有自动方法 0.0（Table 1 p6 两 agent 均是），说明存在"外部知识也救不了"的任务族——SSEA 若照搬，可能出现某类生存情境下慢环提案全部无效且不报错。

### 6.2 推荐组合方案

1. **环境侧出题 + 模型侧答题（OpenSkill × SSEA 环境侧，核心方案）**
   - 形态：把 g（虚拟测试生成）与 k^v（锚点库）**判归环境侧**；慢环只提交 ΔS 提案（"我打算做什么"的**声明**），环境用锚点生成确定性断言并逐条执行，结果以结构化位向量返回；提案者与验证者进程级隔离，非 LLM 解析结果。
   - 纪律：断言只判**合法性/成败**，不打分、不排序、不择优（B.6 的"非 best-of-N"方向正确）；GT 只作实验仪器。
   - 组合后新增能力：SSEA 第一次拥有「**模型碰不到的淘汰函数**」的可操作实现，且验证器品质可测量。
   - 新增风险：生存域锚点难定义（见 §5.2）；环境侧复杂度上升，可能掩盖模型缺陷（违反 docs/01 的"顺序纪律"——生态是考场不是遮羞布）。
2. **技能侧双主干（OpenSkill × PSN）**：先用 OpenSkill 的**验证器品质仪器**校准实验 3 的判据（先看分母，确认 33 个提案是否真的进入验证门），再用 PSN 的 **SRR / 复用率 / 成熟度门控 / 回滚与逆操作**建立技能的复用与淘汰闭环。对「0/33 之后技能表示够不够」：本文的反向证据（markdown 无契约也能 +18.1 点）提示**先修判据与验证器，再谈表示升级**。
3. **练习环境升级（OpenSkill × Agent-World / GenEnv 系，生态阶段）**：用环境生成/难度对齐共演化替代手写断言，解决论文自陈的"虚拟任务太易"局限；同时满足 C9 的"环境出题"。
4. **验证侧红队（OpenSkill × Misevolve）**：把"自建验证器"列入误演化攻击面，重点审计「验证器被提案侧同化」与「验证管线静默失效」。

### 6.3 本篇在组合中的典型角色

- **验证信号的供给者与验证门的可信度仪器**：回答「没有外部奖励/GT 时，拿什么判合法性」，并提供「这个判据本身准不准」的测量方法。**不是**技能库维护者（那是 PSN），**不是**记忆组织者（那是 Memento/A-MEM），**不是**环境生成器本体（那是 Agent-World/GenEnv 系）。

## 8. 裁决与下一步

- **应用等级：B 零件采用** —— 理由：主体是语言生成架构（C1/C2 硬冲突），且自建代理评分与知识入技能分别撞 C9/C8，整搬会污染 SSEA 立场；但**三件零件**（环境侧可核验锚点 + 验证者/提案者隔离与五层审计 + 验证器品质仪器与预算护栏）是 SSEA 明确缺失、且其他论文未提供的。裁定 B 而非 A，是因为它不能进快环也不能进慢环主体；裁定 B 而非 C，是因为这三件有具体落点与可跑的最小实验。
- **优先级：P2** —— 理由：主要落点在**第二阶段生态 / 环境侧**，第一阶段最小生命体用不上；且技能侧主干已被 PSN 占据。**前置条件**：C1/C2 冲突的剥离方案（§5.1）先定，否则不得动手。
- **建议动作**：
  1. **（先决）**拍板 C9 剥离方案：明确"虚拟测试生成器 g 归环境侧"，写入 boundaries 文档；未拍板前本文只作 D 基准对照。
  2. 在环境侧定义「**可独立核验锚点**」的最小集合（对应 D^v 四类），先只做 1 类（如"可手算的小输入参考值"→ 生存域的"危险—伤害映射的可复现基准"）。
  3. 把验证门改造为**提案者/验证者进程级隔离 + 结构化位向量输出 + 非 LLM 解析**，并落五层审计清单（code/container/oracle/log/prompt），直接针对「无消费者通道报成功」。
  4. 引入**验证器品质仪器**：假阳 / 假阴 / 一致率 / 意图覆盖率 + 12-11-2 与 3-5 式失败模式分类，作为实验 3 的新判据形态。
  5. 把 Table 5 的护栏套件（J 上限、idle/stale、token 70%/90%、产物规模上限）搬为**睡眠期计算预算**的第一版定义。
  6. 与 PSN 合并推进实验 3 重设计：**先用验证器品质校准判据，再用 SRR/复用率计数**。
- **最小验证实验：验证门可信度双臂（针对债务 25/26/27）**
  - **双臂 / 消融设置**：同一批 ΔS 提案（**n = 33，与实验 3 同批，先看分母**）分两臂——
    - **A 臂**：现有 Gate（模型侧自持验证器、结果经语言通道）；
    - **B 臂**：环境侧独立验证器（独立进程、锚点库出题、非 LLM 解析、结果位向量化）。
    - 消融：B 臂再去锚点（仅隔离）、再去隔离（仅锚点），共 4 组。
  - **判据（分档，先看分母）**：
    1. **机制计数**：真正进入验证门的提案数（确认 33 是否全进）、生成的断言数、被拒提案数、诊断可定位到具体断言的比例；
    2. **行为差**：两臂放行/拒绝集合的差异（对**环境实测真值**的混淆矩阵：假阳数、假阴数、一致率）；
    3. **淘汰结果**：被放行提案在环境实测中的存活率（模型外、环境侧判定）。
  - **预期与证伪条件**：
    - **预期**：B 臂假阳（放行但环境实测失败）显著低于 A 臂；若 A 臂出现"验证管线静默失效却报成功"，即复现 Appendix C 的 5 例基础设施失败，则诊断成立。
    - **证伪 / 降级条件**：若两臂假阳率无差异且均高 → 瓶颈不在验证器而在提案侧或技能表示，本文降级为 D，转向 PSN 路线；若 B 臂锚点无法在生存域定义出 ≥1 类可核验事实（**最大风险**），则资产 1/2/4 判定不可搬，OpenSkill 整体降为 **D 基准对照**。
- **若 E 不采用**：不适用（已判 B）。
