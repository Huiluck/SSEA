> **一句话判断**：SSEA 试图用「生存控制架构」替换「语言生成架构」，在不缩减智力的前提下
> 压低算力与内存带宽；其工程底座（协议、双环、注入面、记忆、技能、验证门、经验编译器、

## 一、结论速览

### 这个项目真正解决了什么

SSEA 针对的是当前主流智能架构（以 LLM/Transformer 为代表）的一个根本不满：**智力被
锁死在「越来越大的权重 + 越来越长的上下文」这条路径上**，算力与内存带宽成本随能力
线性甚至超线性膨胀。项目主张换一个组织原则——**让模型为「生存」而不是为「生成下一个
token」而存在**：感知 → 决策 → 行动 → 反馈 → 学习 → 遗传，自然语言降级为观察员接口，
不进入控制闭环。

到当前节点，项目**解决的是「这套架构能否被干净地构造出来」**：协议自洽、双环解耦、
结构可注入、记忆可读写、技能可编译、自我修改有门、失败天然回滚。它**尚未解决「这套
架构是否真的更省、更聪明、更能活」**——后者需要对照实验，而第一组对照实验把问题
引向了测量判据本身。

### 最重要的三个判断

1. **真正的新意（核心贡献）**：不是发明新算子（GRU/Mamba/SSM 属可替换的 L1 借用层），
   而是在 **L2 信息流 / L3 学习 / L4 演化** 三层上的一组结构主张——**权重/记忆/技能
   三分离**、**快慢双环经唯一「结构注入面」耦合**、**自我修改四权分立且失败天然回滚**、
   **能力经基因包跨代而知识不跨代**。
2. **最强证据**：工程侧是 910 passed / 1 skipped 且在 15 个随机顺序 seed 下一致；
   闭环侧记忆系统真实运转（40 帧写入 40 条、命中 39 次），慢环已能在睡眠期自主产出
   提案、过四级验证门、提交并切换版本，且能把记忆门开启率从均值 0.375 自修正到 1.000。
3. **关键边界**：上述全部是「机制通了」的证据，**不是「架构有效」的证据**。带对照组的
   实验 2/3 读出的是「尺子坏了」——实验 2 尺太粗（分辨率低于效应），实验 3 尺量错了
   东西（编译判据与重放判据互不蕴含）；在修判据之前，任何「记忆有用 / 技能有用」的
   结论都不成立，也不能反过来判它们无用。

### 是否值得继续推进

值得，但**下一步的重心是「修判据、取有效证据」，不是「补剩余组件」**。项目最有价值的
资产已经不只是代码，而是一套自我纠偏的方法论：区分机制与能力、先看分母、量不出差先
怀疑尺子。按此推进，最小、最高杠杆的动作是修「债务 26」并给实验 2 换一把有分辨率的
判据；RuleCompiler / HeritableFilter / Gene Manager 等组件应让位于取证。

## 二、项目全景

### 研究背景与问题

主流路径把「智能」等价于「在更大语料上训练更大的语言模型」，导致三件事被权重绑架：
**记忆**（全部压进参数，回忆是模糊的模式补全而非精准检索）、**学习**（任何改动都近似
一次全量重训）、**遗传**（没有「把能力传给后代」的一等公民结构）。SSEA 认为这不是
「把 Transformer 调小」能解决的，而是**架构组织原则**问题。

项目要同时满足四条可检验性质：**低算力低带宽**、**精准回忆历史（记忆外置）**、
**可自主修改代码与参数**、**可保存/恢复/变异/继承（生命周期）**。

### 核心贡献（区分「声称」与「可确认」）

- **可确认的贡献**：一套以十条裁判标准（C1–C10）为推理依据的架构设计，及其可运行、
  被测试守住的实现骨架；双环之间唯一的「结构注入面」及其四条结构性质；自我修改的
  四权分立；基因先验与知识语料的分离原则。
- **仍是主张、待证据的部分**：该架构「更省算力/带宽」「记忆提升生存」「技能降低能耗」
  「遗传传递能力」——这些正是七条验收实验要回答、目前尚无有效读数的命题。

## 三、研究故事与论证链

```text
问题：智力被「大权重 + 长上下文」绑架，算力/带宽成本随能力膨胀
 → 现有方案不足：「更小的 Transformer」仍在语言生成范式内，
    记忆/学习/遗传三件事都没有独立的结构位置
 → 核心洞察：把组织原则从「生成语言」换成「维持生存」；
    生存只给「淘汰」不给「评分」，语言只作观察不作控制
 → 架构回应：三分离（权重/记忆/技能）+ 快慢双环 + 唯一结构注入面 +
    四权分立的自我修改 + 基因包生命周期
 → 关键证据：910 测试守机制；闭环连续跑；慢环能自主提提案、过门、改阈值
 → 结论与边界：机制「能构造」已证；架构「有效」未证——
    第一组对照数字暴露判据坏了两处（实验 2 太粗 / 实验 3 量错）
```

这条链最有力量的部分，是项目**用 C8/C9 两条元约束把模糊设计问题变成可推导的结构
问题**：「能不能接人类知识库」「本能该以什么形态给」「验证门该不该打分」都能回溯到
裁判标准；最明显的跳步则出现在末端——**「补完前置就会出有效数字」的预期被实验
证伪**，断点从「机制」移到了「判据」。

## 四、架构与机制

### 核心思想（直觉）

把一个智能体想象成**生命体**而非**会说话的程序**：

- 它用**身体**实时感知与行动（快环，毫秒级、低带宽、不做长推理）；
- 它在**睡眠/离线**时整理经验、修改自身结构（慢环，可验证、可回滚）；
- 它把**可遗传的先验**（本能）放进基因包，把**后天知识**留在个体记忆里、不跨代；
- 世界只决定它「活不活得下去」（淘汰），不告诉它「做得好不好」（无评分）。

### 工作机制：双环

```
快环 FSL（实时控制；不输出自然语言、不做长文本推理、不频繁改权重）
  o_t ──► PerceptionEncoder ──► ┐
                                  ├─► StateCore(GRU) ──► ActionDecoder ──► Action
  MemorySystem.retrieve(p_t) ────┘                         │
  MetabolicMonitor.drive(...) ───────────────────────────┘ ▼
                                                     SkillRunner ──► Environment
                                                          │
                                              o_{t+1}, f_t（含 prediction_error）

慢环 SEL（离线、可验证、可回滚）
  Trace + Feedback + Memory
      ──► ExperienceCompiler ──► 提案 ──► VerificationGate ──► StructureStore
                                                │ pass           │ 原子切换版本号
                                                │ reject         ▼
                                                │      FastLoopContext（不可变快照）
                                                └► 版本号不切换 ─► 快环沿用旧版
```

**关键不变量：慢环不调用快环**。慢环只**发布结构新版本**，快环只**读取当前版本**。

- **快环**：14 个协议定义结构化观测/动作；动作是**混合控制空间**——连续（移动速度/
  方向/时长）+ 离散（操作码）+ 参数化（力/目标/技能参数）+ 技能调用四类并存。
- **慢环**：经验编译器吃轨迹产出 ΔS（技能）/Δθ（阈值等结构参数）提案；验证门四级
  （**格式 → 沙盒 → 回归 → 小范围环境实测**）；通过则 Store 原子升版，拒绝则版本不动。

### 结构注入面：四条性质（双环唯一接口）

| 性质 | 含义 | 由什么结构事实保证 |
|---|---|---|
| 快环零改动 | 快环只读快照、不知慢环存在；换版本=换句柄 | 快照与 Store 脱钩 |
| 失败天然回滚 | 门不通过则版本不切换 | **不存在「回滚」操作，因为从未应用**；Store 无 rollback/undo API |
| 可遗传 | 快照内容即基因包直接来源 | 注入面是遗传面的子集 |
| 可审计 | 每次升版留 `(proposal_id, from_v, to_v, gate_result, timestamp)` | append-only 审计日志 |

### 四权分立：自我修改的四个不同问题

| 权 | 归谁 | 刻意不做 |
|---|---|---|
| 提什么（ΔS/Δθ） | ExperienceCompiler / LocalPlasticity | 不提交、不评估好坏、不发明切分规则 |
| 在不在边界内 | PlasticityController.allowed_scope（白名单） | 07 §6.7 不可更新清单**先于**白名单匹配 |
| 能不能安全应用 | VerificationGate | **不打分（C9）**、不碰权重、不执行代码、不做回滚 |
| 应用不应用 | StructureStore.commit | 拒绝时记审计、**不抛异常、不改版本号** |

### 关键设计选择（每个都回答「为什么存在」）

- **三分离 C3**：权重可微但当前不训练；记忆外置可精准检索；技能可编译/淘汰/继承。
  三者生命周期与可遗传性不同，混在一起就无法单独修改或遗传。
- **C8 给先验不给知识**：决定了「趋近资源」「抓握」等被实现为**可遗传的本能 adapter
  （加法偏置）**，而非手调解码器权重（不可遗传）；也决定不接人类知识库。
- **C9 只淘汰不评分**：验证门只判合法性，一个让存活翻倍、一个让它减半的提案，只要
  合法一视同仁；淘汰函数在模型之外，模型物理上碰不到，故「不可修改淘汰函数」是
  结构事实而非权限设定。
- **`context_fingerprint` 证据窗口**：让可塑性只统计「当前结构版本」产出的帧，症状
  消失即沉默——这是「修正规则不能每次都提」的棘轮。
- **本能推 logit 不推概率、加法不替换**：避开 sigmoid 饱和把强先验压成无效；保留
  `loco_dir` 等学习作用点；本能为 0 时逐位等于改动前表达式（天然对照臂）。

## 五、关键证据与实验结果

### 主要结论—证据对应

| 主要结论 | 决定性证据 | 判断 | 可信边界 |
|---|---|---|---|
| 架构能被干净构造、机制按设计工作 | 910 测试 + 15 seed 顺序一致；协议 JSON 全往返；协议层 0 处依赖 torch | 充分支持（工程层面） | 仅证明工程质量，不证明架构有效 |
| 非语言闭环可运行（实验 1） | 最长干净连段 68 帧；合法率 1.0000；异常率 0；控制边界 0 次语言越界 | 条件性支持 | 无「用语言」对照实现，无法排除「压根做不到」 |
| 记忆通路通电且扰动传到行为（实验 2） | 458 落库/844 检索/475 命中；动作在 5/8 seed 不同；隐状态第 0 帧分叉 | 机制成立，**增益未测出** | 粗签名 7/8 相同是「尺太粗」；回避率 0.9814 已饱和 |
| 技能可固化但不可重放（实验 3） | 固化 2 条；主环 33 次调用全失败；能耗变化 +0.00055 | 存在真缺陷，**定性为判据形状错** | 不能归因于「技能表示丢信息」；见债务 26 |
| 慢环能自主提提案并改自身阈值 | 门开启率 0.375→1.000；阈值 0.5→0.4；正常 seed 保持沉默 | 充分支持（机制层面） | 在「病理监控器」下测得；默认世界当时 0 睡眠 |
| 自我修改可控、失败安全（实验 6/7） | 通过率/回滚率/未破坏率均 1.0000；睡眠 8/8、13 睡对 13 次调用 | 机制成立 | 4 个 1.0000 分母是注入样本（6/5 条）；自然驳回为 0 |

### 最有说服力的一组数字：阈值自修正

8 seed × 25 帧、强制睡眠一次：记忆门开启率均值 **0.375 → 1.000**；5/8 seed 恰好提案
一步（`memory_gate_threshold` 0.5→0.4），3/8 seed 因本就 1.000 而**沉默**。项目特别
强调：**「会沉默」比「能提升」更重要**——每次都提的规则不配叫修正。

三条保留：① 该数字在病理监控器下测得，默认世界当时 0 睡眠（机制被证明、可达性没有）；
② 全局阈值是钝器，只能全开、做不到「惊奇帧开、平淡帧关」；③ 初始版本没有棘轮，靠
`context_fingerprint` 才收敛。

### 反直觉结果与失效条件（本项目最该读的部分）

**1. 实验 2：尺太粗——「整数指标相同」≠「行为相同」。**
记忆确实在转，也确实改变了行为：两臂 `m_t` 不同（84/147 帧非零，范数均值 0.18），
隐状态从第 0 帧分叉（最大逐元素差 ~1.4），解码动作在 **5/8 seed** 上不同（变化 seed
内 56–99% 的帧，中位幅度 3.5e-4~1.8e-3；全体合池 49.5%）。但脚本原判据只比 **5 个
整数**的粗签名（帧数/RUN 帧/可编译段/ENERGY_GAINED/危险接触帧），它在 7/8 seed 上
相同——**~1e-3 的效应投不过整数阈值**。读数是「通路通电、增益小于分辨率」，不是
「机制空转」。

**2. 实验 3：尺量错了东西——编译判据与重放判据互不蕴含。**

- 编译是**回溯性**判据：窗口内 `energy_change` 的**积分 > 0**，从不看绝对水平；
- 重放闸 1 是**前瞻性**判据：某帧**绝对能量 ≥ 一个冻结数**，从不看窗口总量；
- 那个冻结数 `precondition["min_energy"]` 取的是窗口首帧**动作后**能量——**技能自己
  刚制造的峰值**（seed0=0.99 / seed5=0.9366）。于是技能被要求「复现自己的峰值」，
  最好也只是零余量；实测 2/2 条技能出生后闸 1 可过的 RUN 帧**只剩出生那一帧**。
- 编译判据还**系统性偏好最不可重放的窗口**：「首帧一次性增益 + 后续小额流失」最容易
  满足积分>0，而它的峰值恰好最高。

闸序 1→2→3 使第二条成因（重放首帧是已被消费的目标）在主环**从未轮到**、只在沙箱
现形：主环 33 次中止全为 `precondition_failed`；沙箱另有 8 次（4 precondition +
4 environment_rejected）。**合池 37/4 不代表主环构成。**

**3. 饱和指标：危险回避率两臂均 0.9814。**
默认世界危险源极少进视野：8 seed 仅 336 个暴露帧、6 次接触，一次接触就能让一个
seed 的率跳几个百分点。**算对了但量不出东西**——它比「算错」更难发现，因为数字
本身完全正常。脚本据此不拿该率下结论，并把分母一并打出。

**4. 反向信号：实验 6 通过率 1.0000、自然驳回 0。**
18（复跑为 13）条自然提案全部四级通过，说明现行提案保守到不触发后三级；沙盒/回归/
环境实测三级的**拒绝能力只有测试覆盖、没有实验覆盖**。通过率 100% 与拒绝率 0% 是
同一件事的两面，后者才值得警惕。

## 六、可信边界、局限与复现风险

### 证据最扎实的部分

协议自洽与序列化保真、约束强制（生成端 + 环境端 + `writable=False` 三处防御）、
注入面四性质、记忆/技能机制、慢环一步闭环、阈值自修正与「会沉默」——这些都有
**能变红的测试**（含变异测试）守着，且 15 seed 顺序一致，可较有信心地接受为
「机制成立」。

### 会改变结论的关键问题（按影响排序）

1. **判据问题（最高优先）**：实验 2 缺一把分辨率足够的尺；实验 3 的 `precondition`
   把「观测描述」当成了「准入判据」（债务 26）。不修，就无法判定记忆/技能是否有效，
   且容易把「判据问题」误修成「模型/表示问题」。
2. **参数侧 Δθ 整体缺席**：权重增量递不进验证门第四级，硬塞会让「经过验证门」变成
   假话；因此没有任何参数学习发生，门控也没有「惊奇帧开、平淡帧关」的选择性。
3. **生命周期全空**：保存/恢复/变异/继承一件未做，实验 4/5 与 §18 第 8/9/10 项全压
   在未实现的 Gene Manager 上；`DeathHook` 默认 None，死亡快照未接。

### 局限性（分三类）

**作者明确承认的局限**

- 第一阶段不建生态系统，只建最小生命体；默认世界一度 0 睡眠、一度无可学成功
  （二者均已通过小改动修复，但留下「机制可达性需单独验证」的教训）。
- 参数侧学习、跨代记忆累积等被刻意推迟；其中**跨代记忆累积是永久设计（防膨胀），
  不是延期**。

**基于文档证据的推断（本报告分析，非原文断言）**

- 项目当前的主要风险已从「实现缺口」转为「取证缺口」：继续补组件会增加测试数，却
  不增加任何有效性证据，可能制造「越来越完整」的错觉。
- 多条「假守卫 / 假契约」（测试名说消费者、测的是名字；访问器声明不存在的消费者）
  说明：**覆盖率数字与守卫名称本身不可信，必须用变异测试反查能否变红**。

**当前无法确认**

- 修完债务 26 后技能能否重放成功（文档预期：闸 1 的红会换成闸 3 的红，而非直接
  转正）——需实测。
- `action_divergence` 第三档判据的跨 seed 稳定性——尚未量。
- 实验 1/6/7 的部分记录数字随工作树变动不复现（债务 25），其测量方法部分未留档，
  因此这些「机制数字」应被视为工作树快照，而非不变量。

### 复现与落地风险

- 环境：Python + `.venv`（`pytest-randomly` 已装）；测试 `.venv/Scripts/python.exe -m
  pytest tests/ -q` → 910 passed / 1 skipped；实验 `-m experiments.run_all`。
- **最高频陷阱**：凡依赖随机门控的结论必须固定 seed——未训练的记忆门约一半概率
  完全不激活；不要从 16 槽环形缓冲 `event_log/event_notes` 取累计量（会静默偏向零），
  用 `event_counts()`、逐帧 `Feedback` 增量或 append-only 审计日志。
- 本报告只做文档精读与整合，**未运行测试或实验、不构成复现或同行评审**。

## 七、可复用洞察与研究行动

### 值得复用

- **三分离 + 双环 + 唯一注入面**的组织方式：把「实时控制」与「离线自我修改」彻底
  解耦，使安全属性由结构事实而非调用方自觉保证。
- **四权分立**与「失败天然回滚（不应用即无需回滚）」：一种比 try/except + 补偿式
  回滚更简洁、更可审计的安全自修改范式。
- **C8/C9 元约束作为设计推导工具**：把「本能 vs 知识」「淘汰 vs 评分」变成可判定的
  结构边界。
- **方法论**：机制≠能力；先看分母；量不出差先怀疑尺子；用变异测试验证守卫能否变红；
  工具失效时先怀疑被测对象再怀疑工具。

### 不应直接照搬

- 具体世界参数（代谢率、资源增益、感知半径）与实验阈值是为当前最小世界调的，换
  任务需重定；本能以「整份替换的 bytes」播种，不提供可微参数增量，不适合需要连续
  梯度适配的场景。
- 「不设评分函数」是架构立场而非通用结论；在非生存型任务中照搬可能失去必要的
  密集学习信号。

### 下一步研究问题（从机制与失效边界推导，非泛泛扩展）

1. 把 `min_energy` 改为取首帧**动作前**能量并修掉假守卫夹具后，技能重放是否如预期
   从「闸 1 红」转为「闸 3 红」？这决定「技能表示够不够」能否首次成为可测问题。
2. 用常驻 `action_divergence` 判据量实验 2 的跨 seed 稳定性：效应是否稳定可复现，
   还是只在特定 seed 出现（双峰）？
3. 在不引入评分函数（C9）的前提下，能否构造一个危险源/资源密度更高、让「危险
   回避率」不再饱和的世界配置，使对照实验具备分辨力？

### 建议行动顺序

1. **先取证**：修债务 26 + 给实验 2 换高分辨率判据，跑出第一组真正可读的对照数字。
2. **再补关键路径组件**：HeritableFilter（工作量小）与 Gene Manager save/load，
   解锁实验 4；随后 RuleCompiler（注意「从 trace 提规则」是唯一带设计不确定性的
   组件）与 mutate，解锁实验 5。
3. **最后接线与扩展**：`DeathHook` 死亡快照、本能与操纵链的进一步验证，再考虑 v0.4
   的观察员（自然语言）接口与生态系统。
