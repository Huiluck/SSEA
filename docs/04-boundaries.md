## 1. 本文要回答的问题

Milestone 0 的验收标准只有一句话，但它是一个**可被推翻**的命题：

> 明确 SSEA 是新架构，而不是现有模型应用。

推翻它最有效的方式是这样一个提问：

> 如果把 GRU 换成别的、把 RAG 换成别的、把技能库换成别的，SSEA 还剩下什么？

如果答案是"什么都不剩"，那 SSEA 就是集成工作，不是架构工作。本文用四步回答：

1. 给出创新层级定位——说清在哪一层新（第 2 节）
2. 给出六项架构主张，每项附**消融检验**（第 3 节）
3. 汇总消融表——每行说明"去掉这一层会退化成哪个已有系统"（第 4 节）
4. 明确列出我们**不**声称什么（第 5 节）—— 声明的边界越窄，声明越可信

---

## 2. 创新层级定位

"新架构"必须先说清在哪一层新。SSEA 采用四层划分：

| 层次 | 含义 | 传统 LLM | SSEA v0.3.1 | 是否创新点 |
|---|---|---|---|---|
| **L1 算子层** | 基础网络模块 | Attention / MLP | GRU / 小型 Mamba / SSM | **否** —— 借用，可替换 |
| **L2 信息流层** | 模块如何连接 | 文本 → Transformer → token | 感知 → 状态 → 记忆 → 动作 → 反馈；双环 + 结构注入面 | **是** |
| **L3 学习层** | 如何更新自身 | 喂数据 + 全量反向传播 | 记忆写入、技能固化、规则生成、局部可塑性、技能代码段 | **是** |
| **L4 演化层** | 如何保存继承变异 | 训练后固定 | 基因包、本能内化规则、变异继承、可审计 | **是** |

**SSEA 的立场**：创新在 L2 / L3 / L4。第一阶段使用 L1 已有算子，是为了降低工程风险——先用成熟引擎验证新车架的传动是否成立。

但这不等于"套壳"。区别在于**可检验性**：L2/L3/L4 的每一项都可以做消融，消融后会退化为一个**具名的已有系统**。见第 4 节。集成工作没有这个性质——把 Voyager 的技能库换成另一套技能库，系统性质不变；而把 SSEA 的结构注入面拿掉，系统就变成了另一种东西。

---

## 3. 六项架构主张

以下六项即任务书第 4 节的原创性声明，此处为每项补上最近似工作、架构级差异与消融检验。

---

### 主张一：从语言建模架构转向生存控制架构

**主张**：模型的主任务不是预测下一个 token，而是

```
感知 → 决策 → 行动 → 反馈 → 学习 → 遗传
```

**最近似工作**：World Models（Ha & Schmidhuber）、Dreamer 系列、MuZero。它们同样是 observation → action 的闭环。

**架构级差异**：

| | Dreamer / MuZero | SSEA |
|---|---|---|
| 优化目标 | 最大化累积回报 | **无回报函数**。主任务是维持生存 + 降低惊奇度 |
| 经验去向 | 回放缓冲区，训练后丢弃 | 长期记忆，可检索、可遗传 |
| 模型终点 | 训练完成的策略 | 可保存 / 变异 / 继承的生命体 |

差异不在"有没有环境闭环"（这个早有），而在**闭环的出口连到了遗传机制**，且闭环内没有**外部**评分函数（对应裁判标准 C9，2026-09-28 修订，见 [03](03-architecture-spec.md) §8.1）。

**消融检验**：拿掉双环与结构注入面 → 退化为 Dreamer 式 model-based RL agent。

---

### 主张二：权重、记忆、技能三分离

**主张**：不把全部知识压入权重，而是

| 能力类型 | 存储位置 | 更新方式 |
|---|---|---|
| 基础控制能力 | 小型核心网络 | 少量局部更新或冻结 |
| 历史事件经验 | 外部记忆系统 | 写入、检索、合并、遗忘 |
| 可执行行为 | 技能库 / 代码库 | 生成、验证、复用、变异 |

**最近似工作**：RAG / kNN-LM（外部记忆）、Voyager skill library（外部技能）。

**架构级差异**：RAG 与 Voyager 是**语言模型的增强模块**——模型主体仍是语言模型，外部记忆只是补丁。SSEA 的三类存储各有独立的更新机制与遗传路径，且注入面与遗传面**共用同一份结构定义**（08 §2.1）：`FastLoopContext` 的内容就是 `GenePackage` 三个字段的直接来源。这意味着"学什么"和"传什么"不是两套机制。

**消融检验**：拿掉三分离 → 退化为 LLM + RAG 记忆。

---

### 主张三：动作空间不是词表，而是控制空间

**主张**：动作不是从词表采样一个 token，而是多通道结构化控制对象（连续 + 离散 + 参数化 + 技能 + 潜空间通信）。

**最近似工作**：机器人连续控制、LLM function calling、Voyager programmatic actions。

**架构级差异**：混合动作空间本身不是新东西。SSEA 的新意在两条**硬约束**：

1. **动作必须可执行** —— 协议中不允许存在无消费者的通道。这是删除 `latent_action` 的原因（08 §2.4）。
2. **技能是可逐帧执行的压缩先验，不是提示模板** —— Skill Runner 把 `action_sequence` 按帧展开（08 §2.3）。Voyager 的技能是可执行代码，但由 LLM 在提示层调用；SSEA 的技能由模型内的 Runner 执行，**查表比每步重新推理更省算力**。

第 2 条是"低算力"目标真正的落地机制，也解释了为什么技能库增长不会导致算力爆炸——技能是查表，不是搜索。

**消融检验**：拿掉 Skill Runner → 技能退化为提示模板，退化为 Voyager 的 prompt-based skill。

---

### 主张四：学习不依赖全量权重训练

**主张**：学习 = 结构注入，不是梯度更新：

```
慢环产出提案 → Verification Gate → 版本化 Structure Store → 原子切换 → 快环读取新快照
```

**最近似工作**：STaR / Quiet-STaR（自举推理）、LoRA / adapter（局部更新）。

**架构级差异**：STaR 与 LoRA 回答的是"如何更省地训练语言模型"，前提是存在损失函数。SSEA 把学习重新定义为**结构注入**：学习信号是预测误差与生存后果（不是损失），学习产物是五类结构提案（不是参数增量），应用方式是版本号切换（不是权重覆写）。

**消融检验**：拿掉版本化快照注入 → 自我修改必须依赖外部事务与沙盒，即 Darwin Gödel Machine 路线（见主张六）。

---

### 主张五：模型具有生命周期

**主张**：模型支持

```
出生 → 运行 → 学习 → 保存 → 死亡快照 → 基因提取 → 变异 → 继承
```

**最近似工作**：Weight Inheritance、NEAT / HyperNEAT、Evolutionary Model Merging。

**架构级差异**：这些都是**训练技术**——在训练管线里传递权重。SSEA 把保存 / 恢复 / 变异 / 继承做成模型的一等接口，并定义了**本能内化规则**（08 §3.4）：

> 某技能 `success_count ≥ K` 且被 Skill Runner 累计执行帧数 ≥ F → 由经验编译器提议固化为 instinct adapter，标记 `origin: consolidated_from:<skill_id>`，进入基因包可遗传。

这一条落地了 doc 01 的原始目标"内化成类似本能传递到下一代"。它此前在 v0.3.1 里只有字段、没有规则，等于目标被静默搁置。

**消融检验**：拿掉基因包与内化规则 → 退化为一次性 agent，无生命周期。

---

### 主张六：自我修改必须经过验证，且验证是架构内部必经路径

**主张**：所有自我修改必须经过

```
提案 → 格式检查 → 沙盒运行 → 回归测试 → 小范围环境测试 → 通过则应用 → 失败则回滚
```

**最近似工作**：Darwin Gödel Machine、AI Scientist、DeepSeek DSec。

**架构级差异**：这些工作把验证放在**模型外部**——沙盒 + 回归测试 + 人工把关，模型与验证器是两个系统。SSEA 把验证门做成模型内部的必经路径，且失败回滚的机制不同：

> **Gate 不通过则版本号不切换，快照继续用旧版。不存在"回滚"这个操作，因为从未应用。**

安全性来自架构形态（版本隔离），不来自外部事务。这对应任务书 4.6 的原文："这是架构的一部分，而不是外部安全措施。"

**消融检验**：同主张四。去掉版本化注入，验证门就退化成一个外部沙盒工具。

---

## 4. 消融检验汇总表

这是本文最核心的一张表。它把"SSEA 是新架构"这个命题变成**可伪证的**：每一行都说明，抽掉该层后系统退化为哪个具名已有工作。

| 若移除这一层 | 退化为 | 是否即某个已有系统 |
|---|---|---|
| 双环 + 结构注入面 | Dreamer 式 model-based RL agent | 是 |
| 权重 / 记忆 / 技能三分离 | LLM + RAG 记忆 | 是 |
| Skill Runner | Voyager 式 prompt-based skill | 是 |
| 版本化快照注入 | Darwin Gödel Machine 式外部沙盒路线 | 是 |
| 基因包 + 本能内化规则 | 一次性 agent，无生命周期 | 是 |
| 惊奇估计器（替代**外部**评分信号） | 必须引入**外部**奖励函数，违背 C9 | 是 |
| 睡眠期一等公民状态 | 固定 checkpoint 式经验回放 | 是 |

**读法**：没有任何一行退化为"通用智能体框架"。每一行都落到一个具体的、已发表的系统上。这正是架构主张与集成工作的分界——集成工作的消融结果是"换了个零件"，架构工作的消融结果是"变成了别的东西"。

## 5. 我们不声称什么

声明的边界越窄，声明越可信。以下各项 SSEA **明确不主张**：

| 不声称 | 原因 |
|---|---|
| 发明了新的神经网络算子 | State Core 用 GRU / Mamba / SSM，是 L1 借用，可替换 |
| 在智力基准上超过主流 LLM | "智力"需重新定义（doc 03 第九节：生存智力 / 工具智力 / 社会智力 / 记忆智力…）。第一阶段无此类基准 |
| 第一阶段实现了开放式演化 | 无种群、无淘汰函数、无多模型竞争。第一阶段只是最小生命体 |
| 解决了对齐与安全 | 只有分层权限 + 验证门 + 核心系统只读。这是工程缓解，不是对齐方案 |
| 潜空间通信是新技术 | 第一阶段只预留 `CommunicationSignal.signal` 接口，不实现语言演化 |
| 精准回忆已被验证 | 这是第一阶段要**检验**的命题（验收实验 2），不是已成立的结论 |
| 低算力主张已被验证 | 同理，Skill Runner 的查表机制是**设计意图**，需实验 3 的「能量消耗变化」指标证实 |
| **具备跨域的抽象关系推理能力**（2026-09-28 新增，第八项） | 这是 A1 唯一**未关闭**的子问题，学界无共识：Penn, Holyoak & Povinelli 2008 主张只有人类能处理关系抽象（RMTS），而 3 个月**前语言**婴儿与部分 baboon 显示了初步关系学习能力。`ExperienceCompiler` 做的正是关系抽象（从多段 trace 提炼共性），若反方成立，它会在「跨情境提炼同一条规则」上遇到天花板——**而这个天花板不会被任何测试抓到**，因为它不是 bug 是能力边界。处置为**不声称**，并给 `RuleCompiler`（尚未实现）留专门检验：能否从**不同情境**的 trace 提炼出**同一条**规则。见 [02](02-nonverbal-cognition.md) §5.6 |

最后两行尤其重要：本文是**设计声明**，不是**结果声明**。六项主张的正确性由第一阶段六个验收实验判定，不由本文判定。

> ⚠️ **第八项（跨域关系抽象）性质不同**：前七项是「尚未验证」，第八项是「**学界尚无共识、SSEA 无法靠自己解决**」，所以它的处置是**永久不声称**，而不是「等实验来判」。见 [02](02-nonverbal-cognition.md) §5.6、§7.1。

## 7. 结论

SSEA v0.3.1 的第一阶段不是：

```
拿一个现有大脑，放入环境中生存。
```

而是：

```
设计一种新的生存式模型架构。
该架构以非语言感知-行动闭环为核心，
以权重、记忆、技能三分离为基础，
以局部学习、技能固化、自我修改和基因遗传为演化机制。
```

本文使这一定位可被检验：**创新在 L2 / L3 / L4，六项主张各可消融，消融后退化为具名的已有系统，且我们明确列出了八项不声称的事。**

第一阶段要证明的是：

> 一个模型可以不以自然语言为中心，
> 不把全部知识压入权重，
> 不依赖全量数据投喂，
> 而通过感知、行动、记忆、技能、验证和遗传形成可持续演化的生命体架构。

## 1. 为什么需要判定规则，而不只是一张表

一张静态边界表挡不住范围扩散——新想法每天都会出现，每次都重新讨论"这算模型还是算生态"，成本高且结论不稳定。

所以本文先给**三条可执行的判定测试**（第 2 节），再给边界表（第 3 节），最后给争议裁决流程（第 4 节）。表是测试的输出，不是替代品。

---

## 2. 三条判定测试

对新出现的任一要素，依次问三个问题，**先命中者定类**：

| 顺序 | 测试 | 问法 | 命中则归类 |
|---|---|---|---|
| 1 | **算力 / 行为测试** | 它是否消耗模型的算力或带宽？是否改变模型自身行为？是否可被遗传？ | **模型架构** |
| 2 | **格式测试** | 它是否只是数据格式——模型与环境都不拥有其语义，只约定结构？ | **接口** |
| 3 | **筛选测试** | 它是否筛选模型？模型能否修改它？它是否不随单个模型死亡而消失？ | **生态系统** |

**平局裁决**：若某要素同时通过测试 1 与测试 3，**判为生态系统**，并在模型侧设一个只读镜像。

已应用的先例：

- **代谢** —— 环境真实扣减能量/损伤（测试 3），模型侧只有 `Metabolic Monitor` 镜像（测试 1）。判为生态，模型侧做镜像。
- **淘汰函数** —— 环境拥有死亡判定（测试 3），模型侧无判定权。判为生态，**模型侧连镜像都不做**（08 §3.6）。

这条平局裁决有一个重要后果：安全约束"模型不可修改淘汰函数"因此**结构性成立**——淘汰函数在模型之外，模型物理上碰不到它，不需要靠权限系统阻止。

## 3. 边界定义表

列含义：

- **模型架构** —— 模型内部的算法与数据结构，消耗算力，可被遗传
- **接口** —— 模型与环境之间的数据格式约定
- **生态系统** —— 外部世界规则，筛选模型，模型不可修改

| 要素 | 模型架构 | 接口 | 生态系统 | 第一阶段是否实现 |
|---|---|---|---|---|
| **身体** | 身体状态表征（energy / damage / fatigue / position / orientation 的编码） | `BodyState`、`ActionConstraints` | 物理规则（碰撞、地形） | **接口级** |
| **感知** | 感知编码器（ObjectVector / EventVector → perception_vector） | `Observation` | 世界如何生成对象 | **是**（编码器） |
| **动作** | `ActionSpace` 定义、Action Decoder、Skill Runner | `Action` 对象 | 动作的物理后果 | **是** |
| **状态核心** | GRU / Mamba / SSM，输出 hidden_state 与 intent_vector | 无（纯内部状态流） | 环境反馈如何反作用于状态 | **是** |
| **记忆** | Memory System（写入 / 检索 / 合并 / 遗忘）+ HeritableFilter | `MemoryItem` | 历史事件的来源 | **是** |
| **技能** | Skill Library + Skill Runner | `Skill` 协议、`Action.skill` 通道 | 无（技能纯模型侧） | **是** |
| **学习 / 可塑性** | Experience Compiler、Plasticity Controller | `SelfModificationProposal` | 演化选择（种群级筛选） | **是**（提案机制）；环境侧选择不做 |
| **自我修改** | 提案生成、允许范围、Verification Gate | `SelfModificationProposal` | 无（验证门属模型架构，不属生态） | **是**（P1） |
| **繁衍 / 遗传** | Gene Manager（save / load / mutate / inherit） | `GenePackage` | 繁衍规则（何时可繁殖、如何交配） | **接口级**（保存/恢复/变异可运行；无种群繁衍规则） |
| **同族语言 / 通信** | 通信向量编解码 | `CommunicationSignal`（预留） | 语言演化、社会结构 | **只预留接口** |
| **代谢** | Metabolic Monitor（预算镜像、睡眠判定） | 经 `BodyState` 与 `internal_drive_vector` 体现 | 环境真实扣减能量与损伤 | **是**（模型侧镜像） |
| **惊奇 / 预测误差** | SurpriseEstimator（一阶持久化预测，代谢监控器子组件） | `Feedback.prediction_error` | 无 | **是**（最小版） |
| **睡眠期** | 睡眠判定、SEL 触发（一等公民状态） | 无独立接口 | 睡眠期间不施加伤害、不消耗（需环境配合） | **是** |
| **双环 / 结构注入** | Structure Store、FastLoopContext、Verification Gate | 无（纯模型内部数据组件） | 无 | **是** |
| **淘汰函数 / 死亡** | **无**。模型侧不拥有死亡判定 | `Feedback.survived` | **淘汰函数归环境** | **环境桩级**（energy ≤ 0 或 damage ≥ max）；无种群级淘汰 |
| **自然语言 / 观察员接口** | **无**。控制闭环内不含语言模块 | 观察员日志（v0.4+） | 人类观察员 | **不做**。仅调试输出可用自然语言，但不进闭环 |
| **算力 / 内存预算** | 动作预算约束（`energy_budget`） | 无 | 硬件限制作为物理法则 | **接口级**（能量即预算代理）；真实硬件计量不做 |

| 19 | 模型合并（Model Merging） | 需要多模型共存 | v0.4+ | 风险 1 |
| 20 | 硬件级算力 / 带宽计量 | 第一阶段用 `energy_budget` 作预算代理 | v0.5+ | 过度工程 |

| **22** | **递归组合生成 / 无限生成能力** | **2026-09-28 裁决完毕（见 [03](03-architecture-spec.md) §9）**。技能是**扁平的**：`action_sequence` 内**不得**携带 `skill` 通道，且须**协议级强制**（不是文档约定）。NSL 研究显示递归可在无传授下由群体涌现，**但涌现出来的递归仍然是一种符号系统**（Senghas et al. 2004）；home signers 有组合性而**缺乏稳定语法**。技能库的表达力因此有**硬上限**：固定长度的原子动作序列。⚠️ **组合能力不因此消失，它换了位置**——由 §8.3 的睡眠期**前瞻预演**在离线状态试组合，产出**已展开的扁平序列**再固化；递归风险为零，因为它从不发生在闭环里 | **永不**（能力剖面差异，非延期）；替代机制见 §8.3 | 技能库表达力上限此前从未被讨论；且实测发现「允许嵌套」的现状是**静默空转**而非「有递归能力」——见 [03](03-architecture-spec.md) §9.1–9.3 |
| **23** | **二阶自我解释（模型生成「我为什么这样决定」的叙述）** | **2026-09-28 新增（裁决一）**。「我在想什么」这类二阶表征似乎需要语言作为操作对象；Donald 本人承认 **theoretic culture（外部符号存储）才是显式反思的真正起点**。⚠️ **本项与 C2 完全一致，不是新增的损失**——观察员接口的存在本来就承认「解释由外部生成」。SSEA 的慢环能做**一阶自我修正**（检测症状 → 提修正，有 ACC 冲突监控这一 A 级非语言先例），**不能做二阶自我解释** | **永不**；解释归**观察员接口**（v0.4+），按边界表应归类为**接口**而非**模型** | 被误认为「模型不会反思」；实际是一阶可行、二阶不做 |

## 2. 易误解项

以下事项**看起来**应该做，实际不在第一阶段范围内。列在此处是因为它们最容易被"顺手加上"。

| 易误解 | 实际情况 |
|---|---|
| "模型应该能说话解释自己为什么这么做" | **不做**。自然语言只作调试输出，不进控制闭环。事后解释接口留到 v0.4 观察员系统 |
| "应该给模型一个奖励信号让它学得快" | **不做**（指**外部**奖励）。学习信号是 `prediction_error` + 生存后果（能量 / 损伤 / 存活），不是外部奖励函数。⚠️ 2026-09-28 起 C9 表述为「不设**外部**评分函数」——**内在驱动是合法的第三层信号**（它早已落地并直接改变行为），但其**定义**不可被模型修改、不可被提案触碰、不进入淘汰判定。三层区分见 [03](03-architecture-spec.md) §8.1 |
| "变异率应该可以让模型自己调" | `mutation_rate` 位于 `behavior_policy`，理论上可经 `UPDATE_THRESHOLD` 提案修改，但**必须过验证门**，且默认不允许模型调高自身变异率（会绕过筛选） |
| "技能库应该预置几个初始技能让模型有起点" | **部分不做**。C8 允许给基因先验（接口、预测目标、生存约束），但预置人类定义的具体技能等于喂知识。允许的最小先验不含具体技能 |
| "记忆应该越多越好，别忘了任何事" | **不做**。有容量上限 + 重要度衰减 + 定期合并（任务书风险 4 缓解措施） |
| "环境应该主动给模型任务目标" | **不做**。环境只提供资源、危险与反馈，不设任务。目标是模型侧由生存压力涌现的 |
| "应该先做一个能聊天的 demo 演示进展" | **不做**。这会立刻把项目性质变成语言模型应用，与 Milestone 0 的验收标准冲突 |

## 3. 执行机制

清单本身没有约束力，约束力来自流程：

```
任何新需求出现
      ↓
1. 查本清单 ──命中──► 拒绝，或走第 4 步显式修订
      ↓ 未命中
2. 查《边界定义表》第 2 节三条测试，归类
      ↓
3. 归类为「模型架构」或「接口」且任务书未覆盖
      ↓
   先修订任务书对应章节 + 本清单，再进入实现
      ↓
4. 若坚持要突破清单
      ↓
   必须同时给出：修订后的任务书章节、对 Milestone 0 验收标准的影响、
   以及对《架构原创性说明》第 4 节消融表的影响
```

第 4 步是故意的门槛：突破清单不是不可以，但必须重新过一遍"这是不是还是 SSEA"的检验。**范围扩散几乎总是以"这个很小"的形式发生的**，把成本前置到文档修订，比前置到代码返工便宜。
