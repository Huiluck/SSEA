## 1. 一页结论

**状态**：Milestone 0 / 1 / 2 / 3 已完成，Milestone 4 进行中（增量 1 验证门、
增量 2 经验编译器、增量 3 可塑性已落地），Milestone 5 未开始。代码与测试全部就绪，
**但架构有效性尚无一个实验数字**。

07 §18 的十二条第一阶段完成标准里：

```
已满足      5 项   （1–5）
部分满足    3 项   （6、7、11）
未开始      4 项   （8、9、10、12）
```

**一句话判断**：基础设施是扎实的——协议、双环、注入面、记忆、技能、验证门、
经验编译器、可塑性八块都有测试守着，910 项测试通过，闭环能连续跑，
**慢环现在已经能自己产出提案并提交，并能按可观测症状调整自己的行为阈值**。
但「SSEA 是一个有效的生存控制架构」这句话**目前仍然没有证据支持**——
§12 的七个验收实验跑了五条，而**带对照组的那两条（实验 2 / 3）量出来的
是「机制在转、扰动也传到了行为，但增益跨不过整数判据的分辨率」**（§4.2）。
缺的已经不是对照数字了，对照数字有了，它暴露的是**判据本身太粗**。

**下一步**：实验 2 / 3 已经把「记忆/技能没接上」这个解释**排除掉了**，
剩下的问题是「接上了，为什么扰动传不到行为」。这是当前最高优先级，
优先于 Milestone 4 剩余三个组件（RuleCompiler、HeritableFilter、Gene Manager）。
执行顺序见 [13-milestone4-plan.md](13-milestone4-plan.md) §3 与 §6.6。

### 3.2 已实现能力及其边界

按项目自身的坐标轴说清每条能力「能做什么」与「不能做什么」。

**三分离（权重 / 记忆 / 技能）**

| 层 | 能做到 | 不能做到 |
|---|---|---|
| 权重 | `StateCore`（GRU）+ `ActionDecoder` 各头均为标准 `nn.Module`，内部可微；`TestTrainability` 守住「学习作用点存在」 | **没有任何参数学习发生**。增量 3 的 Δθ 只动**结构侧**阈值（`thresholds` / `retrieval`），torch 参数自初始化后不再变；参数侧整个推迟，见 `plasticity.DEFERRED_SCOPES` |
| 记忆 | 写入 / 向量检索 / 重要度排序 / 容量限制 / 记忆合并 / 可继承判定六项齐全；策略来自不可变快照 | 记忆**不被任何机制读取后用于决策**——`m_t` 进了 State Core，但没有证据表明它改变了输出 |
| 技能 | 从成功轨迹编译 / 提案过门 / 淘汰 / 继承；端到端可被快环真实调用 | 模型**不会自己决定何时编译技能**——睡眠期钩子虽已接上，但默认随机初始化的策略产生不了可编译的成功段 |

**双环与结构注入面**

能做到：慢环只发布结构新版本，快环只读不可变快照；四条性质（快环零改动 /
失败天然回滚 / 可遗传 / 可审计）由结构事实保证而非调用方自觉，各有测试。
`StructureStore` 上**没有** rollback / revert / undo / restore 方法——被驳回的
提案从未被应用，所以没有东西需要回滚。

**提案可以过门了**（增量 1）：`VerificationGate.check(proposal, snapshot)`
返回 `GateResult`，`StructureStore.commit(proposal, result, timestamp)` 内部
分流——通过则版本号按类别递增，拒绝则记一条 `applied=False` 的审计项，
**不抛异常、不改版本号**。慢环因此可以写成一条直线，不需要 try/except
包住拒绝路径。

**提案有生产者了**（增量 2）：`ExperienceCompiler.compile(trace)` 吃一条轨迹，
吐 `ADD_SKILL` 提案；`run_slow_loop(trace, store, gate)` 把「编译 → 过门 →
提交」接成一步，`make_slow_loop_hook(store, gate)` 直接可传给
`FastLoop(slow_loop=...)`。于是 07 §18 第 7 项缺的那半条——**触发器**——补上了。

编译器刻意只做一件事：**提什么**。它不提交（那是 Store 的事）、不评估提案好坏
（与 Gate 同一条 C9 纪律）、不自己发明切分规则（复用 `skill_library.compile_skills`）。

**Δθ 也有生产者了**（增量 3）：`LocalPlasticity.observe(trace)` 给出纯读的症状
诊断（三种帧类别可区分：门没开 / 门开了但决定不记 / 记了），`propose(trace, structure)`
按症状提提案。`PlasticityController` 持有 `allowed_scope`——**白名单**，
未登记边界的键不可改，且 07 §6.7 的不可更新清单**先于**白名单匹配。

两条规则都能沉默：症状都不成立时一条提案都没有。`TestNotTautological` 用四种
独立的方式证它会沉默（无 RUN 帧 / 路径正常 / 已在边界 / 证据不足）。

不能做到：慢环**只有一步**。`DeathHook` 仍默认 `None`（死亡快照未接），
ΔR / ΔM 两类提案还没有生产者。这是 Milestone 4 与 5 之间的刻意留白。

**生命周期**

能做到：`GenePackage` 协议定义了基因包字段（含 08 新增的 `heritable_memory`），
可序列化；`MemoryItem.is_heritable()` 判据已实现并有测试。

不能做到：保存 / 恢复 / 变异 / 继承四件事一件都没做。

**约束强制执行**

能做到：两个执行点共用 `ActionConstraints.violations()` 同一份规则。第一执行点
（Action Decoder）在生成阶段就不越界；第二执行点（Environment）兜住漏网的，
记 `ACTION_FAILED` 事件而不崩溃。记忆侧有第三处防御：`writable=False`。

不能做到：无。这一项是完整闭环的。

| 7 | 版本切换审计记录完整率 | **1.0000**（18 次升版 18 条审计） |

**实验 2 / 3 是七实验里唯一带对照组的，它们给出了第一组对照数字——
而这一组数字说的是「机制在转、扰动也传到了行为，但增益跨不过判据的分辨率」。**

实验 2：**记忆确实在运转，也确实改变了行为**——落库 458 条、检索 844 次、
命中 475 次；两臂的 `m_t` 并不相同（探针实测 84/147 帧非零，范数均值 0.18），
`StateCore` 隐状态**从第 0 帧就分叉**（最大逐元素差 ~1.4），
解码出的动作在 **5/8 个 seed 上不同**——逐 seed 帧占比 63.2% / 56.2% /
87.9% / 98.5% / 64.0%（seed 0 / 1 / 5 / 6 / 7），中位幅度 3.5e-4 ~ 1.8e-3；
另外 3 个 seed（2 / 3 / 4）两臂**逐帧全同**，因为那里的记忆门一次都没开。
这组数字**由常驻判据量出**（`experiments/_harness.action_divergence`，
2026-09-28 落地），不是临时探针。

但脚本原先的判据只比**粗粒度签名**——(帧数, RUN 帧, 可编译段,
`ENERGY_GAINED`, 危险接触帧) 这 **5 个整数**——而这 5 个数在 7/8 个 seed 上
完全相同，差的只有 seed 7（164→165 帧）。**「整数指标相同」不等于「行为相同」**：
整数是阈值化之后的投影，~1e-3 的扰动投不过去。所以这条实验真正的读数是
**通路通电、但增益小于指标的分辨率**，而不是「机制空转」。

> **一条措辞债（2026-09-28 自查发现）**：本节与 README / 14 / experiments/README
> 此前把这 5 个整数的相同写成了「**两臂逐位相同**」。代码里 `coarse_signature`
> 的 docstring 一直写的是「粗粒度行为」——**是正文名不副实，不是代码说谎**。
> 「逐位相同」这个词属于**本能消融**那组对照（`adapters` 为空时 `direction`
> 真的逐位不变，有测试钉住），不能挪用到记忆两臂上。
>
> **当时的逐帧数字来自仓库外的临时探针，现已落成常驻判据**
> （`experiments/_harness.action_divergence`，2026-09-28），
> 并收紧了口径：探针说「63–84% 的帧不同」，那是**有改变的 5 个 seed 内部**
> 的比例；**全体 8 个 seed 合池是 49.5%**，而更该看的判据是
> **「有几个 seed 动了」= 5/8**。合池中位数是 **0**——因为没动的那 3 个
> seed 贡献了大量精确的 0，把中位数拉平了。**这是双峰分布，不是"平均有点差"。**

实验 3：慢环确实固化出了技能（0 → 2），但**调用成功率是 0/33**——
调用它的每 33 帧全部报 `SKILL_FAILURE`。更值得记的是这 2 条技能
编译自一段 **41 帧的连续成功**：**编译它的那一段成功，重放它时一次都没成功。**
「生成的技能数」与「技能有没有用」是两个数。

**而且这一条不是判据太粗，是真缺陷**（2026-09-28 独立复核，41 次 abort
全部发生在 `cursor=0`，成因 `precondition_failed` 37 / `environment_rejected` 4）：

1. `precondition["min_energy"]` 取的是**窗口首帧**的能量，而那段窗口是
   「抓取成功之后」——能量正贴近上限（实测 `0.99`）。技能一旦要重放，
   能量只可能比它低，于是**每一帧都被前置条件挡在门外**；
2. 即便放行，`action_sequence[0]` 就是那次 `grasp`，而**那个目标资源
   在窗口创建时已被消费**——重放第一帧就会 `ACTION_FAILED`。

所以技能固化这条通路的问题是**编译判据与重放判据不是同一把尺**：
编译看「回顾式窗口净收益 > 0」，重放看「前瞻式逐帧硬判 + 前置状态快照」。
这与实验 2 的问题不同类，不能一起归到「尺子太粗」里（见 §6 债务 24）。

还有一条**方法上的**读数，比上面两条更该记：`危险回避率` 两臂都是 0.9814，
差值为零。**这不是「记忆对危险回避没影响」，是这个指标在默认世界里饱和了**——
危险源极少进视野，8 个 seed 合计只有 336 个暴露帧、6 次接触，
一次接触就能让一个 seed 的率跳好几个百分点。**一个饱和的率不能当证据，
哪怕它很好看。** 脚本因此把分母一并打出来（`experiments/README.md` 设计选择三）。

**这五组数字证明的与不证明的，必须分开读。**

它们证明的是**机制通了**：控制边界上确实没有正文流过（实验 1）；
修改路径确实四权分立、每一权都能独立拦下（实验 6）；睡眠这个入口确实
通往慢环，而且进得去、里面有东西（实验 7）；记忆与技能这两条通路
**确实通电**（实验 2/3 的写入数、检索数、生成数都不是 0）。

它们**不**证明 SSEA 比其他架构更省算力、更聪明。实验 2/3 有了对照组，
但对照组量出来的结论是**扰动跨不过整数判据的分辨率**，不是「有了它更好」。
§4.3 那条区分在这里仍然成立——它只是从「零个有效性数字」
变成了「有对照组数字，而现有判据粗到量不出它」。

**一个反向信号要单独指出**：实验 6 的验证通过率是 1.0000，而自然驳回
是 **0**。这不是「Gate 很准」——是**Gate 的四级里后三级从来没有拒绝过
任何一条自然提案**。18 条提案全部四级通过，说明现行 ΔS / Δθ 产生的
提案保守到不触发后三级；后三级的拒绝能力目前**只有测试覆盖，没有实验
覆盖**（注入样本也只打到了格式级，见 `experiments/README.md`）。
通过率 100% 与拒绝率 0% 是同一件事的两面，后者才是要注意的那面。

> 实验 6 与 7 各有两列指标在自然运行下**分母是 0**（驳回率、核心系统被
> 破坏率）。0/0 最容易被写成 100% 然后当成「机制有效」的证据，所以
> `experiments/_injection.py` 主动注入必然走失败路径的提案造分母。
> 上表那两个 1.0000 的分母是 6 与 5 条注入样本，不是 0。

### 4.3 一个必须说清的区分

**910 项测试通过，证明的是工程质量，不是架构有效性。**

它证明的是：协议自洽、序列化保真、约束不被违反、注入面四条性质成立、
记忆与技能的机制按设计工作。它**不**证明：这个架构比别的架构更省算力、
记忆真的提升了生存率、技能固化真的降低了能量消耗、基因继承真的传递了能力。

后者需要 §12 的实验数字。§4.2 现在有了五个实验的数字，其中实验 2/3 是
**第一组带对照的数字**。但对照数字本身不是答案——对照数字说「扰动传得到行为，
但跨不过判据的分辨率」，所以上一条区分不因为跑了五个实验就失效。它现在的形态是：

> 五组实验数字，其中一组带对照；而**那组对照的判据粗到量不出差**。

这比「零个有效性数字」更有信息量，也更难堪：它先排除了「机制没接上」，
又排除了「接上了但扰动传不到行为」，把问题逼到**判据本身**上。
**量不出差的时候，先怀疑尺子**——这是本项目第 8 类坑
（`15-glossary.md` §二「缺陷的四种来路」的第四种：工具失效反向撞出来的）。

**同一事实的另一面**：固定 `torch.manual_seed(0)` 时上述运行写入 40 条记忆；
换成 seed 1 或 2，同样 40 帧的统计是：

```
stats : MemoryStats(frames=40, retrievals=40, hits=0, misses=40,
                    writes=0, merged=0, ...)
```

**零写入**。原因是记忆通道门控由随机初始化的权重决定，而没有任何机制训练它。
这不是 bug——训练门控正是 Milestone 4 的 Plasticity Controller（08 公式里的
`LocalPlasticity`）的职责——但它意味着一件要紧的事：**当前这版系统「开箱即用」
时，记忆通路有约一半概率完全不激活**。任何关于记忆的实验，若不先固定 seed 或
先训练门控，结论都是抽奖。

#### 增量 3 之后：解药有了，但默认配置下吃不到

增量 3（Plasticity Controller + LocalPlasticity）给出了解药：慢环在睡眠期观察
「值得记的帧上门从没开过」这个症状，据此下调 `memory_gate_threshold`，提案经四级
Gate 后提交。实测（8 seed × 25 帧，强制睡眠一次）均值 **0.375 → 1.000**，
6/8 seed 恰好提案一步，2/8 因本就是 1.000 而沉默——**沉默是对的**，
每次都提的规则不配叫修正。

但有三条必须说清的保留，否则这个数字会被读错：

1. **它需要一次睡眠，而默认世界不给睡眠——原因是算术互斥，不是搜索失败。**
   实测默认 `MetabolicMonitor` 8 个 seed：全部在 **60 余帧**（65–70）死亡，
   `sleeps=0`，`proposals=0`。也就是说 0.375 → 1.000 这个数字是在
   **病理监控器**下测得的（把睡眠阈值压到 0），默认配置下这条通路一次都没被走过。
   机制被证明了，可达性没有。

   进一步逐层实测后，可达性缺失的性质被定死了：**三条睡眠判据在默认世界参数下
   几乎处处互斥**——不含移动时两者恰好都在第 30 帧附近擦肩（`fatigue` 刚够而
   `energy` 刚破），一旦有移动（实际运行总有）能量侧提前到第 20–25 帧，
   交集就彻底空掉。实测 536 帧的全体扫描中**没有任何一帧同时满足三条**。具体地——

   | 判据 | 默认参数下的算术 | 最早可能满足于 |
   |---|---|---|
   | `fatigue ≥ 0.6` | `fatigue_rate=0.02`，需累积 30 帧 | 第 30 帧 |
   | `energy ≥ 0.7` | `base_drain=0.01`，纯基础消耗在第 30 帧就已跌破 | 若含移动，第 20–25 帧即破 |
   | `threat ≤ 0.05` | 由 `safe` 条件给出 | 视世界而定 |

   实测（`seed 0/1/2`，`t=49`）：`fatigue = 1.000` 而 `energy = 0.25`——
   疲劳判据终于等到的时刻，能量判据早已失效几十帧。三者的阻塞占比为
   42.6% / 31.3% / 26.0%——**没有一个是压倒性的**，这正是「看起来只差一点」
   的错觉来源：三个条件各自都不苛刻，凑在一起才是空集。

   所以 §12 实验 2 的前置不是「决定睡眠由谁触发」这样一个开放设计问题，
   而是**一处判据的语义错误**：`energy ≥ 0.7` 是**防御性整理**的判据
   （「能量充裕到闲着也是闲着，不如整理一下」），而 `fatigue ≥ 0.6` 是
   **生理必要性**的判据（「撑不住了，必须睡」）——把两者用 `and` 串起来，
   得到的是空集。

   能量条件错在**两处**，各自独立成立，所以它不是「阈值调坏了」而是
   「不该在这儿」：

   - **合取取到空集**：两条反向曲线只在第 30 帧附近擦肩，一有移动就错开。
   - **能量作入口会自我复制**（更根本）：`Environment.rest()` 不扣基础代谢、
     反而每帧 `+0.01` 能量，于是「能量充裕」是睡眠自己生产的前提，构成正反馈。
     把能量单独当条件实测是**双峰退化**：4/8 seed 锁进「睡-醒-睡」循环，
     **65%–72% 的寿命在睡眠中度过**、26–28 次唤醒，却只产出 0–1 条提案
     ——RUN 帧被切成 1 帧碎片，慢环无事可做，**模型学会了不行动**；
     另外 4/8 seed 从不睡眠，67–70 帧死。**拿「余粮」当门槛，筛出来的是不行动。**

   修法是一处布尔结构（去掉 `energy` 合取项，保留 `safe ∧ fatigue ≥ 0.6`）。
   疲劳判据没有这个问题，因为它是自限的：睡眠期每帧恢复 0.15，醒来归零，
   要再攒约 30 帧，天然有不应期。实测修正后 **8/8 seed 可达**
   （2026-09-28 复跑；记录原为 7/8，见 §6 债务 25），
   睡眠只占寿命 6%–12%，**13** 段睡眠对 **13** 次慢环调用、13 条提案 13 条应用。
   ~~唯一未睡的 seed 0 是安全条件在正确拒绝~~ —— 2026-09-28 复跑时 seed 0 也睡了；
   「哪个 seed 不睡」是随工作树变动的读数，不是判据的性质。

   **这是当前最优先的一件事**：它的代价是几行代码，收益是解锁实验 7，
   并让实验 2 / 3 的睡眠前置不再悬空。完整推导见
   [14](14-overview-and-roadmap.md) §6.3.1 与 [13](13-milestone4-plan.md) §6.6。

2. **它是一个钝器，不是一把选择性的闸门。** 门控值由随机权重决定，
   240 个采样里 min 0.463 / 中位 0.487 / max 0.530——几乎是个常数。
   阈值 0.5 正好落在分布中间，所以约一半 seed 打不开。
   全局阈值这个杠杆只能把门**全开**，做不到「惊奇帧开、平淡帧关」。
   **选择性需要参数侧 Δθ，而参数侧被 07 §16 整体推迟了**
   （权重增量递不进 Gate 第四级，硬塞进 `UPDATE_ADAPTER`
   会让「经过验证门」这句话变成假话）。所以现状是：
   **「门控不开」修好了，「门开得准不准」是下一步的事。**

3. **没有棘轮。** 修正前这条规则会一路把阈值推到下界 0.15
   （第二轮睡眠的触发证据全部来自第一轮之前）。增量 3 用
   `context_fingerprint` 切了证据窗口，只统计当前结构版本产出的帧，
   于是症状消失后规则自动沉默——`TestConvergesOnce` 守的就是这个不动点。

**5. 目标选择无语义——它是债务 6b 的成因之一（2026-09-27 已修，保留原始记录）**
`manip_target` 对候选按索引顺序打分，候选不带可学特征。Milestone 3 之前做注意力
没有输入依据；现在记忆系统落地了，这个留待项有了前提。

**同日实测把它从「留待项」升格为债务 6b 的成因之一**，而且比原先描述的更硬：
`ActionDecoder._add_manipulation` 里是

```python
scores = self.manip_target(h).expand(len(candidates.object_ids))
target_idx = int(torch.argmax(scores))
```

`expand` 出来的张量**所有分量数值相等**，`argmax` 因此恒返回 0。也就是说
`manip_target` 这个头**结构上不可能影响选择**——永远取候选表第 0 个，
即距离最近的那个可见物体，与它的种类无关。这不是「打分不准」，是**打分被丢弃**。
再加上候选表按距离排序（`fast_loop._candidates`），当前行为精确地是
「抓最近的东西」。修它之前，任何「模型学会了选择目标」的说法都不成立。

**同日已修**（2026-09-27）：等值张量改为**逐候选打分**
（`feature_matrix @ self.manip_target(h)`），`DecodeCandidates` 从此携带每个候选
自己的 `(resource_value, threat_level, distance)`。上面那段代码是**修复前的样子，
刻意留着**——它是这笔债务唯一的原始证据，删掉之后「为什么需要逐候选打分」
就只剩一句结论了。候选不带特征时各候选得分相同、行为退回「取第一个」，
那是**退化情形**，不是另一条实现路径。

**6b. 默认世界上没有可学的成功——已解除（2026-09-27）**
增量 2 的端到端测试（`TestSleepActuallyCompiles`）靠一个手写策略才跑通，
原因是三件事叠在一起：默认 Action Decoder 随机初始化，从不 emit grasp；
而这个世界里**唯一的正能量来源就是 grasp 资源**（`resource_gain`，
且能量上限 1.0 而 agent 开局就满）。于是默认配置下慢环跑一万帧也编译不出
任何东西。

这不是编译器的缺陷——是世界还没给出可学的成功。但它是一条要紧的债务：
**在默认策略能产出可编译的成功段之前，「模型自己学会了」这句话没有证据。**

同日逐层实测把「默认策略不 emit grasp」**拆成了三层**，逐层解决后仍然不够：

| 层 | 现象 | 实测 |
|---|---|---|
| a 操纵门 | 与记忆门同一病理：随机初始化的门控值 ≈ 0.5，而阈值恰好 0.5 | 约一半 seed 门是关的 |
| b 动作选择 | `manip_op` 走随机 argmax | 560 帧里 **0 帧**选中 `grasp` |
| c 目标选择 | `manip_target(h).expand(n)` 分值全等，argmax 恒为 0（债务 5） | 恒选最近可见物体，无论种类 |

**三层全部手动打开后，8 个 seed 一共只成功 3 次 grasp，平均寿命 67 → 72 帧**
——依然不够。原因是编译需要 `min_frames=3` 的**连续正能量帧**，
而 3 次零散的抓取凑不出这样一段。

所以真约束不在操纵链上，而在**趋近能力**：位移是恒定的 ~0.245，
**方向不可控**。agent 靠近不了资源，grasp 再准也没用。

~~解药可能是 Plasticity Controller（增量 3），也可能是换一个非随机初始化的
默认解码器。~~ 增量 3 落地后确认：**不是这条债务的解药**。
`LocalPlasticity` 只动结构侧阈值（`memory_gate_threshold` /
`min_similarity`），而默认策略不 emit grasp 与阈值无关——
阈值决定「记不记」，不决定「抓不抓」。

**解药的形态（按 C8 推导，不是照业界的默认做法）**：把「趋近资源」做成
`instinct_adapters` 的**第一个消费者**。理由是分工——「趋近」是**本能**，
不是**知识**：本能可继承（合 C7），知识不可（C8 明令「给基因先验，不给知识语料」）。
给它一个可学参数头（`instinct_adapters` 已在 `DEFERRED_SCOPES` 中登记）
既是本能，又天然是「遗传来的初始倾向 + 可被 Δθ 局部修正」，两头都占。
反过来说，**手调一个更好的默认解码器是错的**——那是权重，不可继承，
也不受 C8 保护。

> 只有淘汰函数）**。世界只该给出**能量**这一种信号，其余都是生存本身的后果。

**15. `adapters` 里的权重可以是 `inf` / `nan`——一份先验因此能顶掉约束（已修，2026-09-27）**

操纵链的 `op` 选择按约束把越界的操作**屏蔽成 `-inf`**，再 `argmax`。
一份含 `inf` 的先验偏置加进去之后是 `-inf + inf = nan`，而 **`nan` 在比较里
胜过 `-inf`**——实测确认 `torch.argmax(tensor([nan, -inf])) == 0`。
于是 `argmax` 落在一个**本该被屏蔽的 op** 上：**先验顶掉了约束**。

这与本项目的立场直接冲突：「行为不该改边界」。先验是行为，约束是边界。

修法在 `instinct.decode_instinct`：含 `inf` / `nan` 的权重按"读不懂"拒绝
（fail-closed 返回 `None`，不抛——解码在快环每帧路径上）。门调的是同一个
解码器，所以这份 blob 也进不了结构。`_add_manipulation` 里"先推偏置、
后屏蔽"的顺序是**第二道防线**，注释里明说它**不是唯一那道**。

**这一条的重要性不在缺陷本身，在它是怎么被找到的**：变异测试把屏蔽挪到偏置
之前，测试**全绿**——因为偏置有限时两种顺序**本来等价**（`-inf + 有限数 = -inf`）。
查"为什么这个变异活下来了"才挖出真洞。**读代码读不出来。** 回归钉子在
`test_instinct.py::TestDecodeIsFailClosedAndNeverRaises::test_non_finite_weights_are_not_decodable`
（3 例）与 `test_verification_gate.py::TestSandboxStage::test_non_finite_weight_blob_is_rejected`
（2 例），均已实测可红。

**16. 门偏置的加注位置原先测不出来——测试的缺陷，不是实现的缺陷（已修，2026-09-27）**

把操纵门偏置从 sigmoid **之前**挪到**之后**（一个真实的语义变更，
见 `action_decoder.py` 模块 docstring：推 logit 而不是概率），
**68 项测试全绿**。

原因不是守卫漏了，是**测的量级选错了**：原两条门测试用的偏置是 ±5.0，
而两种语义在 ±5.0 上**都能跨过 0.5 阈值**——它们测的是"能推开 / 能关掉"，
不是"加在哪"。分界点是 `sigmoid(x) ≥ 0.5 ⟺ x ≥ 0`，所以 logit 偏置的阈值是
`-logit`，概率偏置的阈值是 `0.5 - sigmoid(logit)`，**只有落在这两者之间的
偏置才能把两种语义分开**。补的测试钉 `logit = +0.6`、`bias = -0.3`：
logit 语义下开、概率语义下关。补完再跑同一个变异 → 红。

教训：**「能翻转」不等于「在正确的地方翻转」**。用大得离谱的值做边界测试，
会恰好绕开边界——而它看起来测得很扎实（"强偏置都推不动，说明加错地方了"）。

**18. `FastLoopContext` 的四个访问器零调用方——实现侧债务（已修，2026-09-28）**

`get_threshold` / `get_adapter` / `get_retrieval_policy` / `version_of`。
**前两个的 docstring 一直写着并不存在的消费者**：「Action Decoder 的决策阈值来源」
「本能（instinct）的读取入口」——而那两个消费者读的都是**整个 mapping**

类别活着不等于名字对应的接口活着，这是 14 §6.3.6「名字是标签，作用点是内容」
低一级的重演。`version_of` 则是被 `fingerprint()` 取代了。

三处假声明已**订正为真话**并指向 `tests/test_consumer_surface.py` 的

**已处置（2026-09-28）：四个全部删除。** 逐条理由（14 §6.4 线 D 第 14 项有同一张表）：

| 访问器 | 接上要付什么代价 | 删的理由 |
|---|---|---|
| `get_threshold` | **改语义**：解码器缺键时回落到 `cfg.gate_threshold`（`action_decoder.py:369`），而 `get_threshold` 的默认值恰是 `0.0`——用它预填会把回落打死 | **默认值是那个假的契约**：两个真消费者各自算各自的回落，**没有一个是 0.0**（解码器→config，`plasticity._current_value`→`DEFAULT_BOUNDS[target]` 的中点，且它专门写了理由说明 0.0 是错的）。`default` 取什么值都对不上任何真消费者 |

| `version_of` | **没有接法**：被 `fingerprint()` 严格支配，而它提供的类别名校验在 `structure_store.py:129` / `plasticity.py:218` 已有一份 | 同左。删它**不丢任何独有覆盖**，各自的测试都还在 |

`ACCESSOR_LEDGER` 因此**首次为空**——表留着，它有双向断言守着。

**没有一条是「改一行让它绿」**——若为过守卫而造一个调用方，守卫从此对该名字

**19. `serialization._encode` 里 `typing.Mapping` 那句判断从未生效（已修，2026-09-28）**

`origin in (dict, typing.Mapping)` ——**这句对 `Mapping` 永远为假**：
`typing.get_origin(Mapping[str, Any])` 返回 `collections.abc.Mapping`，
而它与 `typing.Mapping` 既不 `is` 也不 `==`（实测）。后果是两层：

1. 该分支对**每个**带 `Mapping` 标注的字段从未生效，实际生效的是下面
   「无类型容器」那条 `isinstance(value, dict)`；
2. 那条路拿 `Any` 当值的 hint，于是**标注里的值类型被静默丢弃**——
   `Mapping[str, Skill]` 是按 `Mapping[str, Any]` 编码的（roundtrip 仍能过，
   因为走的是带标记形式，只是多一层标记）。

**它是被撞出来的，不是读出来的**：给快照字段包 `MappingProxyType` 之后，
`isinstance(mappingproxy, dict)` 为假，`_encode` 直接
`TypeError: 协议层无法序列化类型 mappingproxy`，撞坏了 07 §11
「所有接口可序列化为 JSON」。**修的是两处**：判断改比 `collections.abc.Mapping`，
无类型回退从 `dict` 放宽到 `Mapping`。

**这条的形状与债务 16 / 17 同族**：一句看起来在管某件事的判断，
其实从来没管过——而它一直绿，因为另一条更宽的路顺手接住了。
**「被别的分支顺手接住」是这类缺陷藏身的标准方式。**

**20. `FastLoop.__init__` 用一个假值判空——传进来的检索器被静默换掉（已修，2026-09-28）**

```python
self.memory = memory_retriever or MemorySystem(MemoryConfig(...), context)
```

`MemorySystem` 定义了 `__len__`（返回库内条数），而 Python 里**定义了
`__len__` 的实例在长度为 0 时是假值**。于是**刚构造出来的记忆系统是假值**，
`or` 会把调用方传进来的那个换成一个新建的实例——**调用方的引用从此指向
一个不在环里的对象**。

今天两个实例配置相同、行为一致，所以**这个替换不报错也测不出**：
跑起来一切正常，只是你传的那个从来没被用过。它的代价要等第一个
**有状态的**子类出现（记录器、预载了记忆的系统）才显现，
而那时的症状是「我明明传了，它却说没有」。

**它是被一个失效的探针反向撞出来的。** 为量实验 2 写了一个
`Recording(MemorySystem)` 子类记录每次 `retrieve()`，结果它**一个调用都收不到**
（0/0 帧）。第一反应是探针写错了——查下去才发现探针根本没被用上。
**工具不工作时，先怀疑被测对象，再怀疑工具。**

修法是判 `is not None`。回归测试
（`test_a_passed_memory_system_is_not_silently_replaced`）**断言的是身份而不是行为**：

```python
assert not passed, "前提：刚构造的 MemorySystem 是假值（__len__ == 0）"
assert loop.memory is passed
```

**为什么必须断身份**：这个缺陷能活到今天，正是因为「行为恰好相同」。
任何以行为为判据的测试都抓不到它——而身份断言在修复前会红（变异实测）。

**这是本项目的第四类缺陷来路**：前三是读代码、变异测试、撞（改一处别的
东西时暴露）。这一条是**工具失效**。包内还有第二个同形状的位置
（`SkillLibrary.__len__`，`skill_library.py:143`），已核对：没有
`x or SkillLibrary(...)` 这样的写法，暂不受影响。

**21. 措辞债：`coarse_signature` 被四份文档读成了「两臂逐位相同」（已修，2026-09-28）**

`experiments/exp2_memory_recall.py` 的 `coarse_signature` 返回 5 个整数
（帧数 / RUN 帧 / 可编译段 / `ENERGY_GAINED` / 危险接触帧），
它的 docstring 写的是「粗粒度行为」——**代码没说谎**。

**复现增量 3 的阈值自修正**（§4.1 那行 0.375 → 1.000 的来源）：

```python
import torch, statistics
from SSEA.environment import Environment
from SSEA.fast_loop import FastLoop, FastLoopConfig, STATE_RUN
from SSEA.metabolic_monitor import MetabolicMonitor
from SSEA.experience_compiler import make_slow_loop_hook
from SSEA.plasticity import LocalPlasticity
from SSEA.sse_protocols.structure_store import StructureStore
from SSEA.verification_gate import GateConfig, VerificationGate
from tests.conftest import make_context

def once_at(n):
    """只在第 n 次询问时同意睡眠一次——真实监控器不会每帧都同意。"""
    inner = MetabolicMonitor(sleep_threat_threshold=1.1,
                             sleep_fatigue_threshold=0.0)
    fired, asked = [False], [0]
    class OnceAt:
        def drive_vector(self, body): return inner.drive_vector(body)
        def observe(self, obs): return inner.observe(obs)
        def wants_sleep(self, body, obs):
            asked[0] += 1
            if fired[0]: return False
            if asked[0] >= n and inner.wants_sleep(body, obs):
                fired[0] = True; return True
            return False
        def reset(self): inner.reset()
    return OnceAt()

def measure(seed, frames=25):
    torch.manual_seed(seed)
    store = StructureStore()
    hook = make_slow_loop_hook(store, VerificationGate(GateConfig(env_frames=8)),
                               plasticity=LocalPlasticity())
    loop = FastLoop(Environment(seed=seed), make_context(),
                    metabolic_monitor=once_at(frames),
                    config=FastLoopConfig(max_frames=4*frames, min_sleep_frames=3),
                    slow_loop=hook)
    loop.run(frames)
    pre = [r for r in loop.trace() if r.state == STATE_RUN]
    before = sum(1 for r in pre if r.decoded_action.memory is not None) / len(pre)
    while loop.alive and loop.state != STATE_RUN: loop.step()
    loop.run(frames)
    run = [r for r in loop.trace() if r.state == STATE_RUN]
    post = [r for r in run if r.context_fingerprint == run[-1].context_fingerprint]
    after = sum(1 for r in post if r.decoded_action.memory is not None) / len(post)
    return before, after, len(store.audit_log()), \
           store.snapshot().thresholds.get("memory_gate_threshold")

res = [measure(s) for s in range(8)]     # 0.375 → 1.000，5/8 提案，0.5 → 0.4
```

> 这里的 `once_at` 是**病理监控器**：它把睡眠同意条件压到只在第 25 帧成立一次。
> 换成默认 `MetabolicMonitor()` 重跑同一个 `measure`，8 个 seed 全部 `sleeps=0`、
> `proposals=0`、agent 在 60 余帧（65–70）死亡——**这条通路默认走不到**。
> 原因是判据算术互斥（债务 9），不是设计缺口：改成 `safe ∧ fatigue ≥ 0.6`
> 后 **8/8** seed 可达（2026-09-28 复跑；记录原为 7/8，见 §6 债务 25）。见 §4.3 保留 1 与
> [14](14-overview-and-roadmap.md) §6.3.1。
