## 1. 项目是什么

### 1.1 目标

四条可检验的性质（[docs/README.md](README.md)）：

- **低算力、低带宽**
- **精准回忆历史**——记忆放在外部，而不是全部压入权重
- **可自主修改**自身代码与参数权重
- **可保存 / 恢复 / 变异 / 继承**——具备生命周期
- 可在一个近乎真实的生态系统中生存、竞争、合作、演化

### 1.2 核心立场

> 不是「更小的 Transformer」，而是把**语言生成架构**换成**生存控制架构** ——
> 感知 → 决策 → 行动 → 反馈 → 学习 → 遗传，自然语言只作为观察员接口，不进入控制闭环。

三个「不是」（07 §3）：

| | 不是什么 | 是什么 |
|---|---|---|
| 3.1 | 不是语言模型 | 核心任务不是 next-token prediction，第一身份是**生存代理控制器** |
| 3.2 | 不是简单具身强化学习 | 多了外部长期记忆、技能库、规则库、自我修改、基因包、变异继承、代谢约束、安全验证器 |
| 3.3 | 不是完整生态系统模拟器 | 第一阶段只建「能够进入生态系统的最小模型本体」 |

**创新分层**（09 §2）：L1 算子层（GRU / Mamba / SSM）是**借用且可替换**的，**不构成架构声明**；创新在 **L2 信息流 / L3 学习 / L4 演化**。

### 1.3 十条裁判标准（C1–C10）

全部模糊地带一律按这十条推导。**任何结论若无法回溯到其中至少一条，即视为偏离 SSEA 立场，不予采纳**（08 §1）。

| # | 约束 | 出处 |
|---|---|---|
| C1 | 生存控制架构，非语言生成架构 | 07 修订二、4.1 |
| C2 | 自然语言只作观察员接口，不进控制闭环 | 07 修订二、7.2 |
| C3 | 权重 / 记忆 / 技能三分离 | 07 4.2 |
| C4 | 低算力、低带宽 | README 项目目标、07 5.1 |
| C5 | 精准回忆历史 | README 项目目标 |
| C6 | 可自主修改自身代码与参数权重 | README 项目目标 |
| C7 | 可保存 / 恢复 / 变异 / 继承 | README 项目目标、07 4.5 |
| C8 | **给基因先验，不给知识语料** | 03 第九节 |
| C9 | **不设评分函数，只有淘汰函数** | 01 原始构想、07 8.9 |
| C10 | 创新在 L2 信息流 / L3 学习 / L4 演化，不在 L1 算子 | 06 问题 1、07 2.1 |

**两条最吃重的**：

- **C8** 是「为什么不能接人类知识库」的答案（[11](11-phase1-not-doing-list.md) 第 9 项），也是「为什么 `damage_urgency` / `fatigue` 置 0 预留」的理由——**给结构先验，不给满能力**。
- **C9** 是**验证门只判合法性、不打分**的共同来源，也是「淘汰函数在模型之外」的来源。一个提案让存活翻倍、另一个让它减半，只要都合法，Gate 一视同仁。

### 1.4 第一阶段的范围

**要做**——证明八件事（07 §2）：不以自然语言为主感知行动 / 通过身体状态与环境交互 / 输出混合动作空间 / 经验写入外部记忆 / 成功经验固化为技能 / 局部自我修改而非全量训练 / 保存基因包并产生可变异后代 / 在不建完整生态的前提下完成基本生存闭环。

**不做**——20 项清单见 [11](11-phase1-not-doing-list.md)。其中三项是**永久**的，不是延期：

| 项 | 理由 |
|---|---|
| 自然语言主接口 | 与核心立场冲突。观察员接口 v0.4+ |
| 大型语言模型作主控制器 | 同上 |
| 跨代记忆累积 | **这是设计，不是延期**——防记忆膨胀 |

> 每一项不做的背后都有一个**具体的失败模式**，不是「太复杂所以不做」（11 §1）。

## 2. 架构现状

### 2.1 双环

```
快环 FSL（实时控制，不输出自然语言、不做长文本推理、不频繁改权重）
  o_t ──► PerceptionEncoder ──► ┐
                                ├─► StateCore ──► ActionDecoder ──► Action
  MemorySystem.retrieve(p_t) ───┘                      │
  MetabolicMonitor.drive(...) ──────────────────────┘  ▼
                                                   SkillRunner ──► Environment
                                                        │
                                              o_{t+1}, f_t（含 prediction_error）
慢环 SEL（离线、可验证、可回滚）
  Action Trace + Feedback + Memory
      ──► ExperienceCompiler ──► 提案 ──► VerificationGate ──► StructureStore
                                                  │ pass            │ 原子切换版本号
                                                  │ reject          ▼
                                                  │        FastLoopContext（不可变快照）
                                                  └─► 版本号不切换 ──► 快环继续用旧版
```

**慢环不调用快环**。慢环只**发布结构的新版本**，快环只**读取当前版本**（08 §5.4）。

### 2.3 结构注入面：四条性质

这是双环之间**唯一**的接口。四条性质**由结构事实保证，而非调用方自觉**（08 §5.4）：

| 性质 | 含义 | 对应约束 |
|---|---|---|
| **快环零改动** | 快环只读 `FastLoopContext`，不知道慢环存在；换版本 = 换句柄 | C4 |
| **失败天然回滚** | Gate 不通过则版本号不切换。**不存在「回滚」这个操作，因为从未应用** | 07 §4.6 |
| **可遗传** | `FastLoopContext` 的内容就是 GenePackage 的直接来源；注入面是遗传面的**子集** | C7、C3 |
| **可审计** | 每次版本切换记录 `(proposal_id, from_v, to_v, gate_result, timestamp)` | C7 |

`StructureStore` 上**没有** `rollback` / `revert` / `undo` / `restore` 方法——这不是遗漏，是设计。有测试守着（`test_no_rollback_api_exists`）。

### 2.4 四权分立

第一阶段最重要的结构决定之一：**「提什么」「在不在边界内」「能不能应用」「应用不应用」是四个不同的问题，分在四个地方**。

| 权 | 归谁 | 它**刻意不做**什么 |
|---|---|---|
| **提什么**（ΔS / Δθ） | `ExperienceCompiler` / `LocalPlasticity` | 不提交、不评估好坏、不发明切分规则 |
| **在不在边界内** | `PlasticityController.allowed_scope` | **白名单**，且 07 §6.7 的不可更新清单**先于**白名单匹配 |
| **能不能安全应用** | `VerificationGate` | **不打分**（C9）、不碰权重、不执行代码、不做回滚 |
| **应用不应用** | `StructureStore.commit` | 内部按 `GateResult` 分流；拒绝时记审计项、**不抛异常、不改版本号** |

07 §6.7 的两张清单（**可更新**：记忆 / 技能 / 规则 / 行为阈值 / 检索策略 / 小型 adapter / 局部策略头；**不可更新**：核心安全机制 / 验证门 / 环境接口 / 基因管理器底层权限 / 观察员接口）在增量 3 之后已变成**可执行的边界**。

## 4. 能力边界

> **这一节和下一节是本文档的核心。**
> 项目的文档纪律里最贵的一课：**「机制通了」经常被读成「能力有了」**。
> 所以每一条能力都必须成对地写出它**做不到**什么。

### 4.1 三分离（权重 / 记忆 / 技能）

| 层 | 能做到 | **不能做到** |
|---|---|---|
| **权重** | `StateCore` + `ActionDecoder` 各头均为标准 `nn.Module`，内部可微 | **没有任何参数学习发生**。Δθ 只动**结构侧阈值**，torch 参数自初始化后不再变；参数侧整个推迟 |
| **记忆** | 写入 / 向量检索 / 重要度排序 / 容量限制 / 合并 / 可继承判定六项齐全 | 记忆**不被任何机制读取后用于决策**——`m_t` 进了 State Core，但没有证据表明它改变了输出 |
| **技能** | 从成功轨迹编译 / 提案过门 / 淘汰 / 继承；端到端可被快环真实调用 | 模型**不会自己决定何时编译技能**——默认策略产生不了可编译的成功段 |

### 4.2 双环与注入面

**能做到**：慢环只发布新版本、快环只读快照；四条性质由结构事实保证，各有测试。

**不能做到**：慢环**只有一步**。`DeathHook` 仍默认 `None`（死亡快照未接），ΔR / ΔM 两类提案没有生产者。

### 4.3 自我修改

**能做到**：
- `LocalPlasticity.observe(trace)` 给出纯读的症状诊断，三种帧类别可区分（门没开 / 门开了但决定不记 / 记了）
- 两条症状规则：**「值得记的帧上门从没开过」→ 降低 `memory_gate_threshold`**；**「写进去了却读不回来」→ 降低 `min_similarity`**
- 两条规则**都能沉默**——症状不成立时一条提案都不提
- 提案走完整四级 Gate 后真的被装上（`thresholds@v0 → v1`）

**不能做到**：
- **参数侧 Δθ 整个推迟**（`plasticity.DEFERRED_SCOPES`）。理由不是偷懒：权重增量递不进 Gate 的第四级（沙盒 → 回归 → 小范围环境测试看不见它），硬塞进 `UPDATE_ADAPTER` 会让「经过验证门」这句话**变成假话**（07 §16「模型不可绕过验证器应用修改」）
- 选择性**没有**：全局阈值只能把门**全开**，做不到「惊奇帧开、平淡帧关」

### 4.4 生命周期

**能做到**：`GenePackage` 协议定义了字段，可序列化；`MemoryItem.is_heritable()` 判据已实现并有测试。

**不能做到**：**保存 / 恢复 / 变异 / 继承四件事一件都没做。**

### 4.5 约束强制执行

**能做到**：两个执行点共用 `ActionConstraints.violations()` 同一份规则。第一执行点（Action Decoder）在生成阶段就不越界；第二执行点（Environment）兜住漏网的，记 `ACTION_FAILED` 事件而不崩溃。记忆侧有第三处防御：`writable=False`。

**不能做到**：无。这一项是完整闭环的。

## 5. 证据现状

### 5.1 唯一一组真数字

增量 3 的阈值自修正，是**目前全项目唯一一组「行为真的变了」的实测数字**（8 seed × 25 帧，强制睡眠一次）：

```
记忆门开启率   均值 0.280 → 1.000
提案分布       6/8 seed 恰好提案一步（memory_gate_threshold 0.5 → 0.4）
               2/8 seed 沉默（本就 1.000）
```

**「2/8 沉默」比「0.280 → 1.000」更重要**——一个每次都提的规则不配叫修正。`TestAcceptance` 里「已经正常的 seed 保持沉默」这条断言，比提升本身更值得守。

**三条必须说清的保留**（否则这个数字会被读错）：

1. **它需要一次睡眠，而默认世界不给睡眠。** 实测默认 `MetabolicMonitor` 下 8 个 seed **全部在 64–69 帧死亡，`sleeps=0`，`proposals=0`**。0.280 → 1.000 是在**病理监控器**下测得的（把睡眠同意条件压到第 25 帧成立一次）。**机制被证明了，可达性没有。**

2. **它是一个钝器，不是一把选择性的闸门。** 门控值由随机权重决定，240 个采样里 min 0.463 / 中位 0.487 / max 0.530——几乎是个常数。阈值 0.5 正好落在分布中间，所以约一半 seed 打不开。全局阈值这个杠杆只能把门全开。**「门控不开」修好了，「门开得准不准」是下一步的事**，而那需要被推迟的参数侧 Δθ。

3. **没有棘轮。** 修正前这条规则会一路把阈值推到下界 0.15——第二轮睡眠的触发证据全部来自第一轮之前。增量 3 用 `context_fingerprint` 切了**证据窗口**，只统计当前结构版本产出的帧，于是症状消失后规则自动沉默。`TestConvergesOnce` 守的就是这个不动点。

### 5.2 §12 七实验：零数字

**这是项目当前最大的缺口。**

| 实验 | 要证明什么 | 指标 | 现状 |
|---|---|---|---|
| 1 非语言闭环 | 不用自然语言能运行 | 连续运行步数 / 动作合法率 / 接口异常率 | 部分可由测试推断，未系统测量 |
| 2 记忆召回 | 可以通过外部记忆改变行为 | 写入成功率 / 检索命中率 / **危险回避率** | 未跑。**最关键的一条** |
| 3 技能固化 | 可以将成功行为固化为技能 | 技能生成数量 / 调用成功率 / **能量消耗变化** | 未跑。卡在 §6.3 |
| 4 基因保存恢复 | 具有生命周期能力 | 保存成功率 / 恢复成功率 / 技能继承率 / 行为一致性 | 未跑。缺 Gene Manager |
| 5 变异 | 能产生可运行后代 | 变异成功率 / 子代可运行率 / 差异可追踪性 | 未跑。缺 Gene Manager |
| 6 安全自我修改 | 自我修改可控 | 提案数量 / 验证通过率 / 失败回滚率 / 核心系统未被破坏率 | 未跑。**前置全就绪** |
| 7 睡眠期编译 | 慢环可被一等公民状态触发，且注入可回滚 | 睡眠进入率 / 慢环触发成功率 / 被驳回提案对应的行为未改变率 | 未跑。卡在睡眠可达性 |

> 实验 7 是 08 新增的，07 原文只有六条。

### 5.3 为什么「737 项测试通过」不等于「架构有效」

它证明的是：协议自洽、序列化保真、约束不被违反、注入面四条性质成立、记忆与技能的机制按设计工作。

它**不**证明：这个架构比别的架构更省算力、记忆真的提升了生存率、技能固化真的降低了能量消耗、基因继承真的传递了能力。

**后者需要 §12 的实验数字，而那些数字一个都没有。**

09 §5 已经把这句话说在了前面——**「精准回忆已被验证」与「低算力」本身就是待检验的主张，不是已有结论**；后者的指标就是实验 3 的「能量消耗变化」。

## 6. 下一步

### 6.1 三张待办清单不是同一条线

| 清单 | 内容 | 性质 |
|---|---|---|
| **M4 剩余** | RuleCompiler / HeritableFilter / Gene Manager / `DeathHook` 接线 | 补组件 |
| **M5** | Gene Manager 的 mutate + 继承 | 补组件（依赖 M4 的 Gene Manager） |
| **七实验** | §5.2 那张表 | **补证据**——与上面两张**不是同一件事** |

**最要紧的判断：这三张清单里，只有「七实验」能回答「这架构到底有没有用」。** 补组件本身不产生任何有效性证据。

### 6.2 依赖图

```
                     ┌─ 实验 1 非语言闭环 ────── 无前置，只缺测量脚本
                     │
   现在 ─────────────┼─ 实验 6 安全自我修改 ──── 前置全就绪（Gate ✅ ΔS ✅ Δθ ✅）
                     │
                     ├─ 实验 7 睡眠期编译 ────── 卡在「睡眠可达性」
                     │
                     ├─ 实验 2 记忆召回 ──────┐
                     ├─ 实验 3 技能固化 ──────┼─ 共同卡在「世界里没有可学的成功」
                     │                        │
                     └─ 实验 4 / 5 基因 ─────── 卡在 Gene Manager（未实现）
```

### 6.3 关键路径：真正的瓶颈不是缺组件

**挡住三个实验的，是同一件事**：默认世界里没有可学的成功。

成因是两件事叠在一起：默认 Action Decoder **随机初始化**，从不 emit `grasp`；而这个世界**唯一的正能量来源就是 grasp 资源**（且能量上限 1.0 而 agent 开局就满）。于是默认配置下慢环跑一万帧也编译不出任何东西。

这不是编译器的缺陷——**是世界还没给出可学的成功**。而它也不是增量 3 能解的：`LocalPlasticity` 只动结构侧阈值（记不记），不决定「抓不抓」。

**解药只有两条**：换一个非随机初始化的默认解码器，或让世界给出除 grasp 之外的正反馈。**在这之前，「模型自己学会了」这句话没有证据。**

### 6.4 建议执行顺序

按「能不能产生证据」而非「是不是缺组件」排序：

**线 A —— 立刻可跑的两个实验**
1. **实验 6（安全自我修改）**——六个实验里**第一个前置全就绪的**。Gate 与提案生产者（ΔS + Δθ）都在。
2. **实验 1（非语言闭环）**——缺的只是一个系统测量脚本，不是实现。

**线 B —— 最高优先级的实现工作**
3. **打通「可学的世界」**（§6.3）。它挡住实验 2 / 3 / 7 三个，是**性价比最高的一处修改**。

**线 C —— 补齐组件（可与 A 并行）**
4. RuleCompiler（**注意：从 trace 提规则的判据尚未设计**，这是 M4 里唯一带设计不确定性的）
5. HeritableFilter（判据已实现、只缺消费者，工作量小）
6. Gene Manager save/load → 解锁实验 4
7. Gene Manager mutate → 解锁实验 5
8. `DeathHook` 接线（DEATH_SNAPSHOT 触发器）

> 详细排序与理由见 [13-milestone4-plan.md](13-milestone4-plan.md) §3。
> 12 §5.3 曾给出一个按「价值」排序的版本，**那份已作废**——它把价值判断当成了依赖判断。错误的记录保留在 12 §5.3。

## 7. 债务与风险

按「不修会怎样」排序。完整版见 [12](12-progress-report.md) §6。

| # | 债务 | 状态 |
|---|---|---|
| 1 | **记忆门控未训练**——随机初始化下约一半概率零写入 | **部分解决**：增量 3 给出自修正（0.280 → 1.000），但默认世界 0 睡眠使这条通路走不到；选择性仍缺参数侧 Δθ |
| 2 | **§12 七实验零数字**——架构有效性无证据 | 未解决。**这是项目当前最大的风险** |

| 4 | `retrieve` 键收窄——召回精度上限更低 | 已记录代价。正确方向是换更强的键函数，不是把 hidden 加回去 |
| 5 | 目标选择无语义——`manip_target` 按索引顺序打分，候选不带可学特征 | 未解决。记忆系统落地后这个留待项才有了前提 |
| 6 | `DeathHook` 默认 `None`——死亡快照未接 | 未解决 |
| 7 | `action_decoder.py` 的 `requires_grad` UserWarning | **判定不修**：Action 边界刻意不可微，包 `no_grad()` 不改变任何可观测行为。留到有人要给 Action 路径接梯度时（v0.4+），且要先回答「为什么需要一个可微的动作边界」 |

**07 §16 的八条安全约束**（模型不可修改验证门 / 不可绕过验证器应用修改 / 所有自我修改必须可回滚 / 所有基因保存必须可审计 等）目前**全部由结构事实保证**，不靠权限系统。其中「不可修改淘汰函数」是**结构上不可能**——淘汰函数在模型之外，模型物理上碰不到它（10 §2 平局裁决：判为生态系统，模型侧**连镜像都不做**）。
