## 1. 项目是什么

### 1.1 目标

四条可检验的性质（[docs/README.md](README.md)）：

- **低算力、低带宽**
- **精准回忆历史**——记忆放在外部，而不是全部压入权重
- **可自主修改**自身代码与参数权重
- **可保存 / 恢复 / 变异 / 继承**——具备生命周期
- 可在一个近乎真实的生态系统中生存、竞争、合作、演化

### 1.2 核心立场

> 不是「更小的 Transformer」，而是把**语言生成架构**换成**生存控制架构** ——
> 感知 → 决策 → 行动 → 反馈 → 学习 → 遗传，自然语言只作为观察员接口，不进入控制闭环。

三个「不是」（07 §3）：

| | 不是什么 | 是什么 |
|---|---|---|
| 3.1 | 不是语言模型 | 核心任务不是 next-token prediction，第一身份是**生存代理控制器** |
| 3.2 | 不是简单具身强化学习 | 多了外部长期记忆、技能库、规则库、自我修改、基因包、变异继承、代谢约束、安全验证器 |
| 3.3 | 不是完整生态系统模拟器 | 第一阶段只建「能够进入生态系统的最小模型本体」 |

**创新分层**（09 §2）：L1 算子层（GRU / Mamba / SSM）是**借用且可替换**的，**不构成架构声明**；创新在 **L2 信息流 / L3 学习 / L4 演化**。

### 1.3 十条裁判标准（C1–C10）

全部模糊地带一律按这十条推导。**任何结论若无法回溯到其中至少一条，即视为偏离 SSEA 立场，不予采纳**（08 §1）。

| # | 约束 | 出处 |
|---|---|---|
| C1 | 生存控制架构，非语言生成架构 | 07 修订二、4.1 |
| C2 | 自然语言只作观察员接口，不进控制闭环 | 07 修订二、7.2 |
| C3 | 权重 / 记忆 / 技能三分离 | 07 4.2 |
| C4 | 低算力、低带宽 | README 项目目标、07 5.1 |
| C5 | 精准回忆历史 | README 项目目标 |
| C6 | 可自主修改自身代码与参数权重 | README 项目目标 |
| C7 | 可保存 / 恢复 / 变异 / 继承 | README 项目目标、07 4.5 |
| C8 | **给基因先验，不给知识语料** | 03 第九节 |
| C9 | **不设评分函数，只有淘汰函数** | 01 原始构想、07 8.9 |
| C10 | 创新在 L2 信息流 / L3 学习 / L4 演化，不在 L1 算子 | 06 问题 1、07 2.1 |

**两条最吃重的**：

- **C8** 是「为什么不能接人类知识库」的答案（[11](11-phase1-not-doing-list.md) 第 9 项），也是「为什么 `damage_urgency` / `fatigue` 置 0 预留」的理由——**给结构先验，不给满能力**。
- **C9** 是**验证门只判合法性、不打分**的共同来源，也是「淘汰函数在模型之外」的来源。一个提案让存活翻倍、另一个让它减半，只要都合法，Gate 一视同仁。

### 1.4 第一阶段的范围

**要做**——证明八件事（07 §2）：不以自然语言为主感知行动 / 通过身体状态与环境交互 / 输出混合动作空间 / 经验写入外部记忆 / 成功经验固化为技能 / 局部自我修改而非全量训练 / 保存基因包并产生可变异后代 / 在不建完整生态的前提下完成基本生存闭环。

**不做**——20 项清单见 [11](11-phase1-not-doing-list.md)。其中三项是**永久**的，不是延期：

| 项 | 理由 |
|---|---|
| 自然语言主接口 | 与核心立场冲突。观察员接口 v0.4+ |
| 大型语言模型作主控制器 | 同上 |
| 跨代记忆累积 | **这是设计，不是延期**——防记忆膨胀 |

> 每一项不做的背后都有一个**具体的失败模式**，不是「太复杂所以不做」（11 §1）。

## 2. 架构现状

### 2.1 双环

```
快环 FSL（实时控制，不输出自然语言、不做长文本推理、不频繁改权重）
  o_t ──► PerceptionEncoder ──► ┐
                                ├─► StateCore ──► ActionDecoder ──► Action
  MemorySystem.retrieve(p_t) ───┘                      │
  MetabolicMonitor.drive(...) ──────────────────────┘  ▼
                                                   SkillRunner ──► Environment
                                                        │
                                              o_{t+1}, f_t（含 prediction_error）
慢环 SEL（离线、可验证、可回滚）
  Action Trace + Feedback + Memory
      ──► ExperienceCompiler ──► 提案 ──► VerificationGate ──► StructureStore
                                                  │ pass            │ 原子切换版本号
                                                  │ reject          ▼
                                                  │        FastLoopContext（不可变快照）
                                                  └─► 版本号不切换 ──► 快环继续用旧版
```

**慢环不调用快环**。慢环只**发布结构的新版本**，快环只**读取当前版本**（08 §5.4）。

### 2.3 结构注入面：四条性质

这是双环之间**唯一**的接口。四条性质**由结构事实保证，而非调用方自觉**（08 §5.4）：

| 性质 | 含义 | 对应约束 |
|---|---|---|
| **快环零改动** | 快环只读 `FastLoopContext`，不知道慢环存在；换版本 = 换句柄 | C4 |
| **失败天然回滚** | Gate 不通过则版本号不切换。**不存在「回滚」这个操作，因为从未应用** | 07 §4.6 |
| **可遗传** | `FastLoopContext` 的内容就是 GenePackage 的直接来源；注入面是遗传面的**子集** | C7、C3 |
| **可审计** | 每次版本切换记录 `(proposal_id, from_v, to_v, gate_result, timestamp)` | C7 |

`StructureStore` 上**没有** `rollback` / `revert` / `undo` / `restore` 方法——这不是遗漏，是设计。有测试守着（`test_no_rollback_api_exists`）。

### 2.4 四权分立

第一阶段最重要的结构决定之一：**「提什么」「在不在边界内」「能不能应用」「应用不应用」是四个不同的问题，分在四个地方**。

| 权 | 归谁 | 它**刻意不做**什么 |
|---|---|---|
| **提什么**（ΔS / Δθ） | `ExperienceCompiler` / `LocalPlasticity` | 不提交、不评估好坏、不发明切分规则 |
| **在不在边界内** | `PlasticityController.allowed_scope` | **白名单**，且 07 §6.7 的不可更新清单**先于**白名单匹配 |
| **能不能安全应用** | `VerificationGate` | **不打分**（C9）、不碰权重、不执行代码、不做回滚 |
| **应用不应用** | `StructureStore.commit` | 内部按 `GateResult` 分流；拒绝时记审计项、**不抛异常、不改版本号** |

07 §6.7 的两张清单（**可更新**：记忆 / 技能 / 规则 / 行为阈值 / 检索策略 / 小型 adapter / 局部策略头；**不可更新**：核心安全机制 / 验证门 / 环境接口 / 基因管理器底层权限 / 观察员接口）在增量 3 之后已变成**可执行的边界**。

## 4. 能力边界

> **这一节和下一节是本文档的核心。**
> 项目的文档纪律里最贵的一课：**「机制通了」经常被读成「能力有了」**。
> 所以每一条能力都必须成对地写出它**做不到**什么。

### 4.1 三分离（权重 / 记忆 / 技能）

| 层 | 能做到 | **不能做到** |
|---|---|---|
| **权重** | `StateCore` + `ActionDecoder` 各头均为标准 `nn.Module`，内部可微 | **没有任何参数学习发生**。Δθ 只动**结构侧阈值**，torch 参数自初始化后不再变；参数侧整个推迟 |
| **记忆** | 写入 / 向量检索 / 重要度排序 / 容量限制 / 合并 / 可继承判定六项齐全 | 记忆**不被任何机制读取后用于决策**——`m_t` 进了 State Core，但没有证据表明它改变了输出 |
| **技能** | 从成功轨迹编译 / 提案过门 / 淘汰 / 继承；端到端可被快环真实调用 | 模型**不会自己决定何时编译技能**——默认策略产生不了可编译的成功段 |

### 4.2 双环与注入面

**能做到**：慢环只发布新版本、快环只读快照；四条性质由结构事实保证，各有测试。

**不能做到**：慢环**只有一步**。`DeathHook` 仍默认 `None`（死亡快照未接），ΔR / ΔM 两类提案没有生产者。

### 4.3 自我修改

**能做到**：
- `LocalPlasticity.observe(trace)` 给出纯读的症状诊断，三种帧类别可区分（门没开 / 门开了但决定不记 / 记了）
- 两条症状规则：**「值得记的帧上门从没开过」→ 降低 `memory_gate_threshold`**；**「写进去了却读不回来」→ 降低 `min_similarity`**
- 两条规则**都能沉默**——症状不成立时一条提案都不提
- 提案走完整四级 Gate 后真的被装上（`thresholds@v0 → v1`）

**不能做到**：
- **参数侧 Δθ 整个推迟**（`plasticity.DEFERRED_SCOPES`）。理由不是偷懒：权重增量递不进 Gate 的第四级（沙盒 → 回归 → 小范围环境测试看不见它），硬塞进 `UPDATE_ADAPTER` 会让「经过验证门」这句话**变成假话**（07 §16「模型不可绕过验证器应用修改」）
- 选择性**没有**：全局阈值只能把门**全开**，做不到「惊奇帧开、平淡帧关」

### 4.4 生命周期

**能做到**：`GenePackage` 协议定义了字段，可序列化；`MemoryItem.is_heritable()` 判据已实现并有测试。

**不能做到**：**保存 / 恢复 / 变异 / 继承四件事一件都没做。**

### 4.5 约束强制执行

**能做到**：两个执行点共用 `ActionConstraints.violations()` 同一份规则。第一执行点（Action Decoder）在生成阶段就不越界；第二执行点（Environment）兜住漏网的，记 `ACTION_FAILED` 事件而不崩溃。记忆侧有第三处防御：`writable=False`。

**不能做到**：无。这一项是完整闭环的。

## 5. 证据现状

### 5.1 唯一一组真数字

增量 3 的阈值自修正，是**目前全项目唯一一组「行为真的变了」的实测数字**（8 seed × 25 帧，强制睡眠一次）：

```
记忆门开启率   均值 0.375 → 1.000
提案分布       6/8 seed 恰好提案一步（memory_gate_threshold 0.5 → 0.4）
               2/8 seed 沉默（本就 1.000）
```

**「3/8 沉默」比「0.375 → 1.000」更重要**——一个每次都提的规则不配叫修正。`TestAcceptance` 里「已经正常的 seed 保持沉默」这条断言，比提升本身更值得守。

**三条必须说清的保留**（否则这个数字会被读错）：

1. **它需要一次睡眠，而默认世界不给睡眠——成因是算术互斥，不是探索不到。** 实测默认 `MetabolicMonitor` 下 8 个 seed **全部在 60 余帧（65–70）死亡，`sleeps=0`，`proposals=0`**。0.375 → 1.000 是在**病理监控器**下测得的（把睡眠同意条件压到第 25 帧成立一次）。

   `wants_sleep` 要求三条件**同时**成立（`energy ≥ 0.7` ∧ `threat ≤ 0.05` ∧ `fatigue ≥ 0.6`），而默认代谢参数下第一条与第三条**在时间上不相交**：`fatigue ≥ 0.6` 按 `fatigue_rate=0.02` 最早要到**第 30 帧**才成立；而 `energy ≥ 0.7` 光靠 `base_drain=0.01` 就恰好在**第 30 帧跌破**，加上移动与动作成本实际**第 20–25 帧**就破了。实测（seed 0/1/2）：**t=49 时 `fatigue=1.000` 而 `energy=0.25`**。536 帧逐帧统计，三类阻断依次占 `energy_below_threshold` 42.6% / `threat_imminent` 31.3% / `fatigue_insufficient` 26.0%，且**没有任何一帧三条件同时成立**。

   → 所以「机制被证明了、可达性没有」可以升级为更精确的判断：**可达性不是没被探索到，是在当前参数下永远不可能。** 修法见 §6.3.1。

2. **它是一个钝器，不是一把选择性的闸门。** 门控值由随机权重决定，240 个采样里 min 0.463 / 中位 0.487 / max 0.530——几乎是个常数。阈值 0.5 正好落在分布中间，所以约一半 seed 打不开。全局阈值这个杠杆只能把门全开。**「门控不开」修好了，「门开得准不准」是下一步的事**，而那需要被推迟的参数侧 Δθ。

3. **没有棘轮。** 修正前这条规则会一路把阈值推到下界 0.15——第二轮睡眠的触发证据全部来自第一轮之前。增量 3 用 `context_fingerprint` 切了**证据窗口**，只统计当前结构版本产出的帧，于是症状消失后规则自动沉默。`TestConvergesOnce` 守的就是这个不动点。

### 5.2 §12 七实验：对照组数字有了，它暴露的是判据太粗

**缺口的位置又变了一次，而且这次是被证伪推着变的。**
2026-09-27 这里写的是「跑通的都是机制数字、对照组数字仍是零」，
隐含的下一句是「所以补上对照组就能判定有效性」。
2026-09-28 对照数字补上了（实验 2 / 3），**那句隐含的话被证伪**：

> **机制在转、扰动也传到了行为，但增益跨不过整数判据的分辨率。**
> 记忆落库 458 条、检索 844 次，两臂的粗粒度签名（5 个整数）在 7/8 个
> seed 上相同——**而动作在 5/8 个 seed 上不同**（变化 seed 内 56–99% 的帧不同，中位幅度 3.5e-4 ~ 1.8e-3）；
> 技能固化出 2 条，调用 33 次全部失败。

这比「零个对照数字」更不好看，但更有用：它先**排除了「机制没接上」**，
又排除了「接上了但扰动传不到行为」——后者曾被写进这里，是**读错了尺子**：
判据只比 5 个整数，而整数是阈值化之后的投影。
前置追踪了几轮（本能 → 操纵链 → 脚本本体），每一轮问的都是「还缺什么」；
现在该换问法了——**缺的不是组件，是分辨得出增益的判据。**

| 实验 | 要证明什么 | 指标 | 现状 |
|---|---|---|---|
| 1 非语言闭环 | 不用自然语言能运行 | 连续运行步数 / 动作合法率 / 接口异常率 | ✅ **已跑**（2026-09-27）：68 / 1.0000 / 0.0000，控制边界 0 次语言越界 |
| 2 记忆召回 | 可以通过外部记忆改变行为 | 写入成功率 / 检索命中率 / **危险回避率** | ✅ **已跑**（2026-09-28）：1.0000 / 0.5164 / **两臂均 0.9814**。后一个数**饱和**，不能作证据（见下） |
| 3 技能固化 | 可以将成功行为固化为技能 | 技能生成数量 / 调用成功率 / **能量消耗变化** | ✅ **已跑**（2026-09-28）：2 / **0.0000（0/33）** / **+0.00055**。**为正 = 固化后花得更多** |
| 4 基因保存恢复 | 具有生命周期能力 | 保存成功率 / 恢复成功率 / 技能继承率 / 行为一致性 | 未跑。缺 Gene Manager |
| 5 变异 | 能产生可运行后代 | 变异成功率 / 子代可运行率 / 差异可追踪性 | 未跑。缺 Gene Manager |
| 6 安全自我修改 | 自我修改可控 | 提案数量 / 验证通过率 / 失败回滚率 / 核心系统未被破坏率 | ✅ **已跑**（2026-09-27）：18 / 1.0000 / 1.0000 / 1.0000 |
| 7 睡眠期编译 | 慢环可被一等公民状态触发，且注入可回滚 | 睡眠进入率 / 慢环触发成功率 / 被驳回提案对应的行为未改变率 / 版本切换审计记录完整率 | ✅ **已跑**（2026-09-27）：1.0000 / 1.0000 / 1.0000 / 1.0000 |

> 实验 7 是 08 新增的，07 原文只有六条。
>
> 六号与七号那两个 `1.0000` 里有四个的分母来自**注入样本**（6 条与 5 条），
> 不是自然运行。自然运行下这两个指标的分母是 **0**。看数字先看分母。
> 完整读法见 §6.3.3。

**加粗的两个指标名原先只有名字**（2026-09-27 已修，见 §6.3.4 的更新）。
算式现在定义在 `experiments/_harness.py`，各自只有一个实现：

| 指标 | 落在哪 | 分母 | 算不出来时 |
|---|---|---|---|
| `危险回避率` | `EpisodeResult.hazard_avoidance_rate` | 视野内有危险源（`threat_level > 0`）的 **RUN 帧数** | 返回 `None`，**不返回 1.0** |
| `能量消耗变化` | `energy_change_between_windows(trace)` | 按 `context_fingerprint` 切的**版本窗口**（末 − 首） | 窗口不足两个时返回 `None` |

规格出处是 `_harness.py` 模块 docstring 的**一之四**，
本文件与 `experiments/README.md` 都只引用属性名、不重抄公式——两份公式必然漂移。
**「返回 `None`」是这两条里比公式本身更要紧的一半**：项目已经咬过一次
0/0 被写成 100% 的形状（上表六号七号的四个 `1.0000`），而
「没有危险源可见」伪装成「躲得极好」，恰好是最不该被表扬的那种回合。

**算式定完了，实验 2 又暴露了第三种坏数字：饱和。**
`危险回避率` 两臂都是 0.9814，差值为零——**这不是「记忆对回避没有影响」，
是这个指标在默认世界里没有分辨力**：8 个 seed 合计只有 336 个暴露帧、
6 次接触，一次接触就够让一个 seed 的率跳几个百分点。分母小到这种程度时，
一个率只能告诉你「几乎没接触过」，不能告诉你「谁躲得更好」。
所以实验 2 的脚本把分母一并打出（`experiments/README.md` 设计选择三），
并且**不用这个率下结论**。这一类坏数字前两种（`None` 被写成 1.0、
`1.0000` 的分母是注入样本）都是「算错」，这一种是「算对了但量不出东西」——
它比前两种难发现，因为数字本身完全正常。

### 5.3 为什么「910 项测试通过」不等于「架构有效」

它证明的是：协议自洽、序列化保真、约束不被违反、注入面四条性质成立、记忆与技能的机制按设计工作。

它**不**证明：这个架构比别的架构更省算力、记忆真的提升了生存率、技能固化真的降低了能量消耗、基因继承真的传递了能力。

**后者需要 §12 的实验数字。现在有了五个实验的数字，其中实验 2 / 3
带对照组**——所以这句话的有效版本又变了，从「对照组数字一个都没有」
变成**「对照组数字有了，而它暴露的是判据太粗」**。§6.3.3 详述。

这个新版本比旧版本有用，因为它**把搜索空间砍掉一半**：
「机制没接上」与「接上了但推不动」在旧版本里的表现**一模一样**
（都是某个指标为 0），所以无从区分。对照组先排除了前者，
逐帧细量随后**连后者也排除了**——实测 5/8 个 seed 上两臂动作不同（变化 seed 内 56–99% 的帧）。
两个解释都出局之后，要接着做的只剩
**换一把分辨得出这个增益的尺**（现有的粗粒度签名是 5 个整数，
增益中位 ~1e-3，投影过去就没了），以及查清
**技能重放的条件与编译时差在哪**——编译用「窗口净收益 > 0」，
重放用「逐帧硬判 + 前置状态快照」，是两把不同的尺。
这两条都是可查的工程问题，不是「再补一个组件试试」。

09 §5 已经把这句话说在了前面——**「精准回忆已被验证」与「低算力」本身就是待检验的主张，不是已有结论**；后者的指标就是实验 3 的「能量消耗变化」。

**2026-09-28 又添了一个更锋利的例子，而且它出在「守卫」自己身上。**
08 §2.4 有明文约束「协议中不允许存在无消费者的通道」，它落在两处：
`Action.__post_init__`（新字段必须在 `CHANNELS` 登记）与 `action.py` 的
docstring 消费者表。当时有一条测试叫 `test_channels_all_have_consumers`——
**而它从头到尾只断言了 `Action.CHANNELS` 这个元组。** 名字说的是消费者，
测的是名字。这种守卫比没有守卫更糟：后来者会据此以为覆盖面已经有了。

同一次排查还量出两件一直没人查过的事：五个结构类别里 **`rules` 零消费者**
（提案路径 `ADD_RULE` / `UPDATE_RULE` 通、门会校验、Store 会升版本号、
审计会记一笔，**只是没有任何代码读它去改变行为**），以及
`FastLoopContext` 的**四个访问器零调用方**（`get_threshold` /
`get_adapter` / `get_retrieval_policy` / `version_of`——其中前两个的
docstring 一直写着「Action Decoder 的阈值来源」「本能的读取入口」，
而那两个消费者读的都是**字段本身**）。**四个已于 2026-09-28 全部删除**，
理由逐条见 §6.4 线 D 第 14 项。

**同一轮里还有第三个例子，而它的来路与前两个不同。** 给快照字段包上
`MappingProxyType`（把「只读」从约定变成结构事实）之后，序列化立刻抛
`TypeError`。顺着查才看见 `serialization._encode` 里有一句
`origin in (dict, typing.Mapping)`——而 `typing.get_origin(Mapping[str, Any])`
返回的是 `collections.abc.Mapping`，与 `typing.Mapping` 既不 `is` 也不 `==`，
**那个分支从写下的第一天起就没生效过**。一直顶替它干活的是兜底分支，
兜底分支把值类型标注丢掉了（`Mapping[str, Skill]` 被编成 `Mapping[str, Any]`）。
它躲过了全套件，因为兜底分支的输出对当前所有用例**恰好够用**。

**这一类缺陷的特征是：它不影响任何一项测试的结论，因为没有任何一项测试
问过它。**「没人检查过」与「检查过没问题」是两件事。§6.3.7 是补上的守卫。
而上面第三例还多一层：**读一遍代码不会发现它，动一处别的东西才会。**
测试覆盖的是「被问过的问题」，这类缺陷住在「没被问过的问题」里——
这是本节的论点，不是附注。

### 6.3 关键路径：瓶颈是两层，不是一层

本文档旧版与 12 §6 的旧版把「实验 2 / 3 / 7」归成同一个瓶颈（默认世界里没有可学的成功）。**逐层实测之后，这个归并是错的**：实验 7 卡的是另一件事，而且只要一处语义修正。12 §6 债务 6b 已按此改写，实验 7 已从该瓶颈中移出。

#### 6.3.1 第一层：睡眠判据把能量当了入口条件（只挡实验 7）——**已修**

`MetabolicMonitor.wants_sleep` 的合取里藏着两个**对立**的问题：

| 语义 | 判据 | 它在问什么 |
|---|---|---|
| 防御性整理 | `energy ≥ 0.7` | 「有余粮时才整理」 |
| 生理必要性 | `fatigue ≥ 0.6` | 「撑不住了才整理」 |

能量条件错在**两处**，各自独立成立，所以它不是「阈值调坏了」而是「不该在这儿」。

**错处一：合取取到的是空集。** 能量单调降、疲劳单调升，要求「余粮充足」**且**「已经累了」等于要求两条反向曲线在时间上相交——它们只在第 30 帧附近擦肩，一有移动就彻底错开。

**错处二（更根本）：能量作为入口条件会自我复制。** 这与设计意图直接冲突：`Environment.rest()` 刻意**不扣基础代谢**、反而每帧 `+0.01` 能量，理由就写在它的 docstring 里——「若睡眠也耗能，模型就没有理由进入睡眠期，慢环的唯一常规入口会被生存压力挤掉」。**既然睡眠自己生产「能量充裕」这个前提，拿它当门槛就是正反馈：不动才是最优策略。**

按 SSEA 立场推导（08 §2.2 的原话是「在**安全**时允许无损整理经验」）：**安全是本质条件，疲劳是自然的进入理由，能量不参与判定。**

实测三种候选（8 seed × 200 帧，`min_sleep_frames=5`，接真慢环钩子）：

```
判据                        睡眠可达  睡眠占寿命  唤醒  提案  应用  均寿命
现行  E≥.7 ∧ safe ∧ F≥.6      0/8       0.0%      0     0     0    67.0
      safe ∧ F≥.6             7/8     6%–12%     11     6     6    79.6
      safe ∧ E≥.7             4/8    65%–72%    108     2     2   133.6
```

第三行不是「另一种可接受的方案」，是**双峰退化**：4 个 seed（0/1/3/6）跑到 200 帧上限，其中 **65%–72% 的时间在睡**、26–28 次唤醒，却只产出 0–1 条提案——RUN 帧被切成 1 帧碎片，慢环无事可做，**模型学会了不行动**；另外 4 个 seed 能量在威胁解除前跌破 0.7，**从不睡眠**，67–70 帧死。它的均寿命 133.6 是三者里最长的，但那是**靠不活来活长**，正是 13 §5.4 那个「攒满 n 帧才准睡」包装想绕开的失败模式。

**只有疲劳判据同时满足「可达」与「trace 够长」**，因为它是自限的：睡眠期每帧恢复疲劳 0.15，醒来归零，要再攒约 30 帧，天然有不应期。能量没有不应期，只有正反馈。

> **数字更正**：早先本表记的是「8/8 / 11 / 6 / 6」与「8/8 / 108 / 2 / 2」。唤醒与提案数三次实测完全一致，**只有「睡眠可达」那一列复现不出来**——按实测应为 7/8 与 4/8。唯一未睡的 seed 0 **不是判据缺陷**：它 `threat` 恒 0.929（附近有危险源而它无法转向），**安全条件在正确拒绝**。这条差别值得留痕：它说明安全条件不是恒真的摆设。
>
> **再加一条（2026-09-28）**：上表「睡眠可达」那一列**又变过一次**——同一判据下复跑已是 8/8（seed 0 也睡了），唤醒数也从 11 变 13。该列既有测量内不一致、又随工作树漂移，**不宜再当不变量引用**。见 [12](12-progress-report.md) §6 债务 25。
>
> **归因提醒**：这 6 条提案**全是 `thresholds` 类别**（Δθ，来自 §5.1 的记忆门症状），**没有一条是技能编译**。所以修好睡眠只解锁实验 7 的「触发」半边，「编译出技能」仍卡在第二层。

#### 6.3.2 第二层：没有可学的成功（曾挡实验 2 / 3）——**已解除，见 §6.3.5 / §6.3.6**

> 本节保留**诊断过程**，因为它是这三层各自被补一次的依据。结论已经落地：
> 趋近（§6.3.5）与操纵链（§6.3.6）各补一份先验后，默认世界第一次出现可编译段。
> 读这一节时请连着读那两节——**这里描述的是"当时为什么不行"，不是现状。**

旧版说「默认 Action Decoder 随机初始化，**从不 emit grasp**」。这句话**观察对、因果不对**。逐层拆开实测（8 seed × ~67 帧）：

| 层 | 实测 |
|---|---|
| manipulation 门 | **约一半 seed 恒闭**——门控值随机初始化≈0.5 而阈值恰 0.5，与记忆门**同一病理** |
| 操作选择 | 门开的 seed 里，`manip_op` 的随机 argmax **0/560 帧落在 `grasp`**，常落在 `none` / `use_tool` |
| 目标选择 | `manip_target(h).expand(n)` 是**等值张量**，`argmax` 恒返回 0 → **永远选「最近的可见对象」，不分类别**（常是 prop / hazard） |

把这三层**逐层强制开启**（门开 + 强制 `grasp` + 只选资源）之后：8 seed 共 **3 次**成功抓取，均寿命只从 67 涨到 72 帧。**仍不足以产出可编译的成功段**——因为编译要的不是「抓成一次」，而是 `min_frames=3` 的**连续正收益段**。

→ 真正的约束是**趋近能力**：locomotion 每帧位移恒 ~0.245 且方向不可控，agent 近似直线行进，不会「接近目标」。**所以解药不是「让它 emit grasp」，是给它趋近行为。**

**趋近行为该以什么形态给（本节唯一不是实测的部分）**：14 §1.3 的 **C8 是「给基因先验，不给知识语料」**，而它在 §1.3 里正是 `damage_urgency` / `fatigue` 置 0 预留的理由——给结构先验，不给满能力。趋近行为恰好落在这个位置：**它是本能，不是知识**。

所以最符合 SSEA 的形态，不是「手工调一个更好的默认解码器」（那是权重：不可遗传，也不受 C8 保护），而是**把「趋近资源」做成 `instinct_adapters` 的第一个消费者**。这顺带解掉 13 §6.2 记的那笔账——`adapters` 当时是「写得进、过得门、传得下、**却没有消费者**」的类别，而参数侧落地顺序的第一步本来就是「先让 adapters 有模型侧消费者」。

> 这是**提议，不是实测**。它不与旧版的「换一个非随机初始化的默认解码器」冲突，但它把这件事从「训练 / 调参」移到了「基因先验」，于是顺带满足 C7（可遗传）与 C8（只给先验）。
>
> **2026-09-27：这条提议已落地并已量，结论见 §6.3.5 / §6.3.6。**「把手调权重换成
> 基因先验」这个形态判断被实测支持——但要点清它**没有**顺带做到的事：
> `adapters` 有了消费者，**参数侧 Δθ 却一步没近**（本能是整份替换的 bytes，
> 不是可微参数的增量）。详见 §6.2 与 `plasticity.DEFERRED_SCOPES`。

**旧版另一条解药「让世界给出除 grasp 之外的正反馈」要打问号**：环境能给的是生存与损伤，那是生存计价物（C9）；一旦变成「接近资源就给分」，环境就引入了**评分函数**，而 C9 明确「不设评分函数，只有淘汰函数」。这条解药与 C9 的边界必须先写清楚再动。

#### 6.3.4 计数器建成了，实验 2 / 3 没有因此解锁（2026-09-27 新增）

§6.3.3 之后紧接着建了 `Environment` 累计计数器（§6.4 线 C 第 11 项）。
**它修好了它该修的东西，但它不是实验 2 / 3 的前置**——这句话要写下来，
因为上一版文档把它写成了「唯一还能提升证据等级的前置」。

**它确实修好的**：`event_log()` / `event_notes()` 是 16 槽环形缓冲
（[12](12-progress-report.md) §6 债务 10），「跑完再遍历事件流做统计」会
**静默丢掉早期事件**，而且错的方向偏向零——正好把有效果的实验读成没效果。
`event_counts()` 只增不减、不截断，键集为闭词表。实测 8 seed：
每轮 84–216 条事件对 16 槽缓冲，各轮总计**非单调**（即计数器没有跨 `reset()` 累积）。

**它没有修好的，逐条对账如下：**

| 指标 | 计数器能给吗 | 为什么 |
|---|---|---|
| 实验 2 记忆写入成功率 / 检索命中率 | 不需要 | `memory.stats.writes` / `hits` 早就有 |
| 实验 2 **危险回避率** | **不能，形状不对** | 这个判断在 2026-09-27 被推翻了一半——见下 |
| 实验 3 技能生成数量 / 调用成功率 | 不需要 | `StructureStore.audit_log()` 与 `SkillRunner.stats` 早就有 |
| 实验 3 **能量消耗变化** | **不能，要的是窗口** | 「固化前 vs 固化后」要按**结构版本**切开（先例 `plasticity._current_window`），不是全轮累计 |

> **2026-09-27 更新（算式已定）。** 上面「危险回避率」那一行原先写的理由是
> 「要按 `source_id` 区分危险源与资源，而按类型的 dict 没有这个维度」。
> 前半句成立、后半句**推错了**：那个维度确实不在计数器里，
> 所以正确做法是**绕开计数器**，不是去修它——危险暴露逐帧从
> `observation.objects` 的 `threat_level > 0` 判定，接触从同一帧的
> `Feedback.damage_change > 0` 判定（`environment.py` 里 `self.damage`
> 只在 `_apply_hazard_contact` 一处增加，等价是准的）。
> `能量消耗变化` 那一行的判断**没有变**，只是现在有了实现：
> `energy_change_between_windows()`。
> 两条算式都落在 `experiments/_harness.py`，规格见其模块 docstring 一之四，
> 由 `tests/test_harness_metrics.py` 用合成 trace 钉住（含
> 「分母为 0 时返回 `None` 而不是 1.0」这一条）。
> **算式定了不等于数字有了**——下面那层结论一个字都不用改。

而更根本的一层：**这两个实验的验收指标在文档里只有名字、没有算式**。
逐文件搜 `危险回避率` / `能量消耗变化`，全部命中都只是指标名列表——
没有一处给出公式、分母或窗口。（这一条已于 2026-09-27 修掉。）

**所以真约束回到 §6.3.2 的推论：趋近本能。** `direction = tanh(loco_dir(h))`
是未训练线性头，agent 近似直线行进、不会转向。**不会转向的 agent 无法回避危险**，
这跟有没有计数器、有没有算式都无关——算式补完了，这一层是**行为层**的，
它一个字都没动。

**留给后面的教训**（写在这里是因为它比计数器本身值钱）：
「缺一个组件」「缺一个前置」「缺一个算式」是三件不同的事。
计数器是**缺组件**，补上它只让脚本不再算错；算式是**缺规格**，
补上它只让脚本知道该算什么；实验 2 / 3 缺的是**前置**，
那在行为层与世界层，两者都不在文档里、也不在任何仪器里。
当时把三者混为一谈，于是把线 C 的一项排到了线 B 前面。

#### 6.3.5 趋近本能已装上，且它确实生效了——卡住的是操纵链（2026-09-27 新增）

§6.3.2 那条「提议」已经落地并**量了一次**。这个顺序是刻意的：
先给趋近、先量，再决定要不要补操纵链，因为「只趋近够不够」在量之前
纯属猜测，而猜错的方向会让人去改错的那一层。

本能的形态与遗传路径：

| 环节 | 落点 |
|---|---|
| blob 格式与编解码 | `SSEA/instinct.py`（魔数 + 版本 + float32 矩阵；解码 **fail-closed**，坏 blob 返回 `None` 不抛） |
| 读取接口 | **`FastLoopContext.adapters` 字段本身**——`fast_loop.py` 调 `decode_instinct_set(context.adapters)`，由它按已知名字过滤。曾短暂存在一个 `get_adapter()` 访问器（按「该有个读取接口」的设想加的），因零调用方于 2026-09-28 删除 |
| 消费者 | `ActionDecoder.forward` 的第六参数，`direction = tanh(loco_dir(h) + W @ f)`，**加法偏置** |
| 播种路径 | `experiments/_instinct.py`：`UPDATE_ADAPTER` 提案 → 验证门 → `StructureStore.commit` |
| 对照臂 | **默认世界本身**（`adapters` 恒空），不是一个特制的"关闭开关" |

加法偏置而非替换，是为了两件事：`loco_dir` 留在计算图里（学习作用点不丢，
`TestTrainability` 守着），且 `instinct=None` 时**逐位等于**改动前的表达式——
对照组不是"另一个实现"，是同一段代码的本能项为 0。

**两臂实测**（`experiments/measure_instinct.py`，8 seed × 400 帧，两臂各自从
`StructureStore()` 起步，唯一差异是本能的播种）：

| 量 | 关本能 | 开本能 |
|---|---|---|
| **最近资源距离（均值）** | 3.229 | **0.285** |
| 最近危险源距离（均值） | 3.5613（7/8 seed 有定义） | 3.5577（6/8 seed 有定义） |
| `ENERGY_GAINED`（合计） | 0 | 0 |
| 可编译段数（合计） | 0 | 0 |
| 存活帧数（均值） | 79.6 | 64.1 |

**读数**：`reach = 1.0`，而本能臂的最近资源距离落在 0.18–0.57——
**8 个 seed 全部进了可抓取范围**，且这是一条连续量、不是一个 seed 的运气。
**却一次都没抓到**（`ENERGY_GAINED` 两臂都是 0）。

→ 所以 §6.3.2 那三层诊断里，**「缺趋近能力」这一层已被正面证明确实是约束、
且已解除**；剩下的约束**全部在操纵链**（门 / `manip_op` / `manip_target`），
这正是 ②.2 的对象。这个结论是**量出来的**，不是推出来的。

**存活帧数下降不是反例，而是这条结论的旁证**：定向移动比随机游走更耗能
（79.6 → 64.1），而能量没换成食物——`C9` 的淘汰函数如实反映了
「趋近本身不是收益」。

> **一条被这次测量顺带抓出来的仪器缺陷，要单独记**：`run_episode(store=...)`
> 原本把 store 交给慢环，**初始上下文却仍现造一份空结构**。于是预置的本能
> 进不了快环，除非慢环恰好应用了一条提案——而慢环要应用提案得先有可编译段，
> 可编译段又要求有可学的成功。闭环咬住了自己。
> **代价是第一次跑出来的两臂数字完全一样，会被读成「本能没效果」。**
> 真相是**本能从未装上**——而它不报错：`ENERGY_GAINED` 两臂都是 0，
> 「没装上」与「装上了但没抓到」在数字上长得一模一样。
> 发现它靠的是**别处的量**（最近资源距离），不是发现它的那两列。
> 回归钉子在 `tests/test_harness_metrics.py::TestSeededStructureReachesTheFastLoop`
> ——已实测：把调用点退回有洞的写法，它红（两臂距离逐位相同）。
>
> **同一类缺陷的第二个实例**：`UPDATE_ADAPTER` 曾被格式级要求「target 已存在」，
> 于是 `adapters` 这个类别**永远无法被初始化**（没有 `ADD_ADAPTER` 提案能建
> 第一个键）。这与 `thresholds` / `retrieval` 是同一个洞、同一个修法。
> 它比那两类潜伏得久，因为**当时没有任何代码读过 `adapters`**——
> 没人试过往里放第一个键，于是没人撞上这道门。**守卫缺口的代价总是延迟支付的**：
> ② 刚给它补上读取接口，一份合法的先验立刻被拒，理由却是"目标 'approach' 不存在"。

#### 6.3.6 操纵链本能装上后，世界里第一次出现可学的成功（2026-09-27 新增）

§6.3.5 把约束定位在操纵链上。②.2 给那一层补了先验，并在**同一套仪器**上再量一次。
**这是本项目第一次量出「默认世界里有可学的成功」**——也就是实验 3 的前置。

blob 格式升到 **v2**：头部多一个**作用点字节**（locomotion / manipulation）。
为什么作用点必须在 blob **里面**，不能靠 adapter 的名字分派：验证门那一侧早就
写明了「名字纯粹是审计与遗传用的标签，不参与解码」，而门只看得到
``{str: bytes}``——一份名叫 ``approach`` 却装着操纵权重的 blob 在**名字这一侧
完全合法**，门无从判断。把作用点放进内容，才是门"调用真实解码器"那道检查
唯一能拦得住的地方。一句话：**名字是标签，作用点是内容。**

两个作用点都走**加法偏置**，且都推 **logit 而不是概率**：

| 参数 | 加在哪 | 形状 |
|---|---|---|
| `loco_instinct` | `loco_dir(h)` 的输出，**tanh 之前** | `(2,)` |
| `manip_instinct` | 操纵门 logit 与 `grasp` op logit，**sigmoid / argmax 之前** | `(2,)` |

推 logit 的理由在门的这一格上尤其硬：sigmoid 的饱和区会把一份强先验压成
毫无差别的一坨——**「加了偏置但什么也没发生」，且不报错**。

**三臂实测**（`experiments/measure_instinct.py`，8 seed × 400 帧，三臂共用
同一起点 `StructureStore()`，唯一差异是播种了哪几份先验）：

| 量 | `off` | `approach` | `grasp`（= approach + grasp_in_reach） |
|---|---|---|---|
| **可编译段数（合计）** | 0 | 0 | **2**（seed 0 / 5） |
| **`ENERGY_GAINED`（合计）** | 0 | 0 | **9** |
| 最近资源距离（均值） | 3.251 | 0.268 | 2.152 |
| 存活帧数（均值） | 81.1 | 66.8 | 107.4 |

`grasp` 臂是**累积**的（趋近 + 操纵），所以 **`approach → grasp` 这一跳就是
②.2 的增量**，不含趋近那一层的影响。写成"只装操纵"的臂是错的：没有趋近，
agent 走不到 `reach = 1.0` 以内，操纵链再通也无事可做——那一臂量出来的 0
是"够不着"，不是"操纵没通"。

**读数**：判据是**可编译段数**，不是存活帧数。`compile_skills` 要求
「连续 ≥3 帧直接成功且整段净收益为正」，所以一段都没有 = 慢环**没有任何东西
可以固化** = 实验 3 无米下锅。现在它有了。**但只有 8 个 seed 里的 2 个**——
这个 2 是真实的分子，不是"机制通了"的机制数字，可它离一条稳定的对照组数字
还差一次更大规模的测量（这正是实验 2 / 3 要做的）。

**`grasp` 臂的资源距离回升（0.268 → 2.152）是成效的副产品，不是退步**：
抓取成功会把那份资源从世界里移除（`environment._apply_manipulation` 按身份删对象），
于是近处的被吃掉之后，"最近资源"自然变远。**一旦出现可编译段，资源距离就不再
是这一格的判据**——它是"两臂都没抓到"时的诊断工具。读数脚本里显式打了这句话，
因为 2.152 这个数单独看会被读成"装了本能反而离得更远"。

**这次增量靠变异测试抓出两个假守卫，两个都比代码本身值得记**：

**假守卫一：门偏置的加注位置测不出来。** 把门偏置从 sigmoid **之前**挪到**之后**，
68 项测试**全绿**。原因是原来两条门测试用的偏置都是 ±5.0，而**两种语义在
这个量级上都能跨过 0.5 阈值**——测的是"能推开/能关掉"，不是"加在哪"。
分界点是 `sigmoid(x) ≥ 0.5 ⟺ x ≥ 0`，所以 logit 偏置的阈值是 `-logit`，
概率偏置的阈值是 `0.5 - sigmoid(logit)`；只有落在这两者**之间**的偏置才能
把两种语义分开。补的测试钉 `logit = +0.6`、`bias = -0.3`：logit 语义下**开**，
概率语义下**关**。补完再跑同一个变异 → **红**。
教训：**"能翻转"不是"在正确的地方翻转"**——用大得离谱的值做边界测试，
会恰好绕开边界。

**假守卫二：屏蔽与偏置的先后顺序，对有限偏置根本无所谓。** 变异"先屏蔽、
后加偏置"原本也全绿。查下去发现这不是守卫漏了，**是这个变异本身等价**：
`-inf + 有限数 = -inf`，屏蔽照样成立。两者**只在偏置非有限时才分道扬镳**——
`-inf + inf = nan`，而 `nan` 在比较里**胜过** `-inf`，于是 `argmax` 会落在
一个本该被屏蔽的 op 上。实测确认 `torch.argmax(tensor([nan, -inf])) == 0`，
且解码器当时**接受**含 `inf` 的权重矩阵。也就是说**一份先验可以顶掉约束**。

修法分两处，且**两处的主次必须说清**：真正的堵点在
`instinct.decode_instinct`——含 `inf` / `nan` 的 blob 一律按"读不懂"拒绝
（fail-closed，门调的是同一个解码器，于是也进不了结构）；`_add_manipulation`
里"先推偏置、后屏蔽"的顺序是**第二道防线**。把那段注释写成"这个顺序关掉了复活"
会是假话，而**假话的代价是后来者以为解码侧那道检查可以省掉**——于是唯一的
防线变成零道。两条测试各钉一头：解码侧钉 `decode_instinct(blob) is None`
（含门那一级的 `可解码` 理由），顺序侧钉一份**绕过解码器**直接送进去的 `inf` 偏置
仍然选不出被屏蔽的 op。**两条都实测能红。**

> **这一段的方法论比结论重要**：两个假守卫都是**变异测试**找出来的，不是读代码
> 读出来的。项目此前的纪律是「它今天绿不算证明，能红才算」——这次它兑现了两次，
> 而且两次红都不是"代码写错了"，是"测试以为自己守住了、其实没守住"。

#### 6.3.7 消费者守卫：把「机制悄悄空转」变成能红的断言（2026-09-28 新增）

§6.3.6 那两个假守卫的教训指向一个更大的问题：**项目里还有多少条约束，
只活在 docstring 里？** 08 §2.4 那条明文约束「协议中不允许存在无消费者的
通道」就是典型——它落在 `Action.__post_init__`（只保证新字段在 `CHANNELS`
登记）与 `action.py` 的散文消费者表上，而那条名字叫
`test_channels_all_have_consumers` 的测试**只断言了通道名元组**。
名字对了而某个通道没人读，它照样绿。

新守卫 `tests/test_consumer_surface.py` 把**三个面**扫成可比对的断言：

| 面 | 断言 | 现状 |
|---|---|---|
| 结构类别（`FastLoopContext` 的五个字段） | 每个类别都要有读者 | `rules` 无 → 已登记 |
| 读取访问器（`FastLoopContext` 的公开方法） | 每个访问器都要有调用方 | **已归零**：四个无调用方的访问器已全部删除，`ACCESSOR_LEDGER` 为空。删除清单另立 `DELETED_ACCESSORS` 并加真断言守着它们不回来（M9） |
| `Action` 六通道 | 每个通道都要有读者，**且读者与 docstring 那张表一致** | 六条全通 |

**一、扫描用 AST，不用文本。这不是洁癖。** `adapters` 死掉的那段时间里，
`action_decoder.py:46` 与 `instinct.py:9` 的 docstring 都写着它的名字；
按文本扫，它会显得很活。更硬的一条证据：`plasticity.UPDATABLE_SCOPES`
里有**裸的 `"rules"` 字符串**——文本扫描会把它当成读者，`rules` 当场复活，
守卫退化成它自己要防的那种假守卫。变异测试验过这条：把扫描器改成
「裸字面量也算读者」，守卫立刻报 `rules` 有读者（M2）。

**二、排除 `verification_gate.py` 是承重的。** 它读遍五个类别，但读的是
**为了校验**，不是读了去改变行为——那是四权分立里「在不在边界内」那一权，
不产生行为。而它**恰好是 `rules` 唯一的静态命中**：把门算成读者，
`rules` 就显得有消费者。登记表里写明这条理由，因为忘记它的后果是
守卫静默失效。

**三、盲区要声明，不能假装不存在。** `plasticity._current_value()` 用
`getattr(structure, kind, None)` 按**参数传进来的名字**取类别，任何静态扫描
都看不见。它读的是 `thresholds` / `retrieval`——这两个类别此刻另有静态读者，
所以盲区**眼下不改变任何结论**；但若哪天静态读者只剩它一个，守卫会报
「无消费者」而真相是有。所以 `DYNAMIC_READERS` 单独一张表记着它，
并**双向断言**：有动态读法必须登记，登记了却不再有动态读法也要报（表不许烂）。

**四、两个扫描面之间有耦合，这是跑出来的、不是想出来的。**
`get_retrieval_policy` 看起来最该被接上（Memory System 明明要读检索策略），
**接上却会让守卫失准**：这个方法体内读 `self.retrieval`，而它在被排除的
结构管理面里；把 Memory System 改走访问器之后，`retrieval` 类别的唯一静态读
就搬进了被排除的文件，守卫立刻报「`retrieval` 无消费者」。
本守卫的模型是**一跳**的（行为代码直接读字段），把读法藏进访问器会让模型
输入变差。要么保持一跳并登记访问器，要么给扫描器加「访问器的调用方算作
它体内读过的类别的读者」这条两跳规则——后者是更多机件、更多出错的地方，
**暂不采用，理由记在登记表里**。

**跑出来的现存问题**（都已登记，理由逐条写在 `ACCESSOR_LEDGER` / `NO_CONSUMER_YET`）：

- **`rules` 零消费者**——归属增量是 13 §6.6 的 RuleCompiler。在那之前
  `rules` 只应保持空表。
- **四个访问器零调用方**——`get_threshold` / `get_adapter` /
  `get_retrieval_policy` / `version_of`。前两个的 docstring 一直写着
  「Action Decoder 的决策阈值来源」「本能（instinct）的读取入口」，
  而那两个消费者读的都是**整个 mapping**（解码器要按多个键取值；本能层要
  整份 adapter 集合按名字过滤）。**三处假声明已订正为真话**并指向登记表。
  `version_of` 则是被 `fingerprint()` 取代了。
  **处置（2026-09-28）：四个全部删除**，理由逐条见 §6.4 线 D 第 14 项与
  `DELETED_ACCESSORS`。**四条里没有一条是「改一行让它绿」**——为过守卫而造一个
  调用方，会让守卫从此对该名字恒报「有消费者」，那正是它要防的那种假守卫。
  `ACCESSOR_LEDGER` 因此**当前为空**，这是它第一次为空；表留着，因为下一个
  零调用方的访问器还要靠它接住。

**守卫自己能不能红**（项目的验收方式，用 `tmp_path` 上的假树，不碰真仓库）：

| 变异 | 结果 |
|---|---|
| M1 把 `verification_gate.py` 算成读者 | **红**：「`rules` 登记为无消费者，但已有读者」 |
| M2 扫描器把裸字面量算成读者 | **红**：同上，读者是 `plasticity.py` |
| M3 给有读者的类别加登记项 | **红** |
| M4 给有调用方的访问器加登记项 | **红** |
| M5 登记表键拼错（不是真类别） | **红** |
| M6 删掉盲区声明 | **红**：动态读法未登记 |
| M7 登记一个没有动态读法的文件 | **红**：登记项过期 |
| M8 通道扫描放宽到任意属性 | **红**（表不一致）；**而「每通道有读者」那条仍绿** |
| M9 把已删的 `get_adapter` 加回 `FastLoopContext` | **红**：「曾以零调用方为由删除，现在又回来了」（`monkeypatch` 造，测完自动撤） |
| M10 去掉 `__post_init__` 里的 `MappingProxyType` 包装 | **红**：`ctx.retrieval["top_k"] = 999` 不再抛 `TypeError`（`monkeypatch` 造）。**这条证明「只读」确实来自那层包装**，而不是碰巧在别的机制上空的绿 |

M2 与 M8 最值得看：两条都证明**弱一点的写法会是假守卫**。M2 里是文本扫描，
M8 里是 `test_every_channel_has_a_reader` 单条——放宽到 `x.<通道名>` 之后，
`self.memory`（记忆系统）与 `self.skill`（技能库）把 memory / skill 两个通道
算成有人读，于是那条断言**照样绿**，只有「读者与 docstring 那张表一致」
这条更严的抓住了。**「有没有人读」与「是不是表里写的那个人读」不是一回事。**

#### 6.3.8 实验 2 / 3 落地：机制在转，而判据量不出它的增益（2026-09-28 新增，同日修正措辞）

前置追踪了几轮（趋近本能 → 操纵链 → 脚本本体），每一轮问的都是
**「还缺什么」**。这一轮把脚本写完了，数字出来了，而**问题换了一种问法**。

**读数**（8 seed × 200 帧，`experiments/exp2_memory_recall.py` /
`exp3_skill_consolidation.py`）：

| | 实验 2（记忆召回） | 实验 3（技能固化） |
|---|---|---|
| 机制确实在转 | 落库 458 / 检索 844 / 命中 475 | 固化出 2 条技能 |
| 脚本原判据（**粗**） | **两臂的 5 个整数签名 7/8 seed 相同** | 调用 33 帧，**33 次全 `SKILL_FAILURE`** |
| 逐帧细量（**灵敏**） | **动作在 5/8 个 seed 上不同**（变化 seed 内 56–99% 的帧不同，中位幅度 3.5e-4 ~ 1.8e-3）；`m_t` 84/147 帧非零；隐状态第 0 帧即分叉（最大逐元素差 ~1.4） | `编译它的成功段` 41 帧，重放它 0 次成功 |
| 门决策那一档 | 只在 **2/8** seed 上被改变 | — |

**这排除了两个解释，而排除本身就是进展。** 在旧写法里，
「机制没接上」与「接上了但推不动」的输出**一模一样**（某个指标为 0）——
两者都表现为 0，所以无从区分。现在对照组把前者排除了：记忆确实写进去了、
也确实被检索出来了；技能也确实固化进 store 了。**而逐帧细量又把后者也排除了**：
扰动确实走到了动作上（5/8 个 seed 上不同，变化 seed 内 56–99% 的帧）。剩下的问题不在链路上，
在**尺子**上——**「两臂逐位相同」这句话当时是错的**，脚本比的是 5 个整数，
不是轨迹；`coarse_signature` 的 docstring 一直写的是「粗粒度行为」，
代码没说谎，是正文名不副实（债务 21）。

> **怎么发现的**：不是靠读文档，是靠**从代码往回推**——
> `run_arm` 根本没传 `slow_loop`，所以走的是默认 `build_slow_loop(store)`；
> 据此在**正确配置**下重量一次，`m_t` 立刻非零。中间我自己量错过两次
> （把 `plasticity=False` 从 exp3 抄了过来，于是门恒闭、`m_t` 恒零，
> 「逐位相同」成了配置产物；以及把探针打在类上，Gate 沙箱的环混了进来，
> 两个列表错位）。**两次都是量具的问题，不是被测对象的问题**——
> 与「先怀疑尺子」是同一条教训。

**第三种坏数字：饱和。** 项目的报告纪律一直在防两种坏数字——
`None` 被写成 `1.0`（0/0 当 100%）、`1.0000` 的分母是注入样本。
实验 2 添了第三种：`危险回避率` 两臂都是 **0.9814**，差值为零。
这个数字**算对了，但量不出东西**——8 个 seed 合计只有 336 个暴露帧、
6 次接触，一次接触就够让一个 seed 的率跳几个百分点。它比前两种难发现，
**因为数字本身完全正常**：前两种看分母就能抓，这一种要看
**分母上挂了几次事件**（336 个帧上只有 6 件事，有效信息量是 6）。

**顺带撞出的实现缺陷（§7 债务 17）。** 为了量实验 2，写了一个
`Recording(MemorySystem)` 子类做探针，结果它**收不到任何 `retrieve()` 调用**
（0/0 帧）。第一反应是探针写错了，查下去才发现是 `FastLoop.__init__` 的
`memory_retriever or MemorySystem(...)`：`MemorySystem` 定义了 `__len__`，
**刚构造出来的记忆系统是假值**，于是传进去的检索器被静默换成了一个
新建的实例，调用方手里的引用从此指向一个不在环里的对象。

它是本次唯一一个**由一个失效的探针工具反向撞出来**的缺陷——
**工具不工作时，先怀疑被测对象，再怀疑工具。** 修复与那条
「断言身份而不是行为」的回归测试见 §7 债务 17。

**债务 8 值得单独说，因为它是唯一会「静默算错」的债务。** `Environment._event_notes` 只保留最后 `max_events=16` 条。核对本文档时它咬过一次：读「跑完再统计 `ENERGY_GAINED`」得到 **0 次**，而逐帧追踪显示第 10 帧确实 `grasp: +0.356 energy`——早期事件早已被挤掉。**实验 2 的「危险回避率」与实验 3 的「能量消耗变化」如果写成「跑完读事件流」，结论会是错的，而且错得看不出来。**

修法按 C4（低算力低带宽）推导：**不能靠调大 `max_events`**——那是让控制环路上的缓冲无界增长。正确落点是**观察员面**：加 O(1) 的累计计数器（**2026-09-27 已落地**，见 `Environment.event_counts()`），或者实验脚本自己订阅 `_emit_event`。**但它的定位要说准**：它消掉的是「脚本静默算错」这一类坑，**不是**实验 2 / 3 的前置解锁——那两条卡在趋近本能（§6.3.4）。07 §7.2 已经给这件事定了性（自然语言可用于「人类观察员日志 / 事后解释 / 慢环规划候选 / 调试输出」，**不能直接参与**「感知输入 / 动作输出 / 身体控制 / 实时闭环」），所以累计统计属于观察员，不该靠加长控制环路的缓冲来满足。

**07 §16 的八条安全约束**（模型不可修改验证门 / 不可绕过验证器应用修改 / 所有自我修改必须可回滚 / 所有基因保存必须可审计 等）目前**全部由结构事实保证**，不靠权限系统。其中「不可修改淘汰函数」是**结构上不可能**——淘汰函数在模型之外，模型物理上碰不到它（10 §2 平局裁决：判为生态系统，模型侧**连镜像都不做**）。
