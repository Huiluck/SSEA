## 1. 项目是什么

### 1.1 目标

四条可检验的性质（[docs/README.md](README.md)）：

- **低算力、低带宽**
- **精准回忆历史**——记忆放在外部，而不是全部压入权重
- **可自主修改**自身代码与参数权重
- **可保存 / 恢复 / 变异 / 继承**——具备生命周期
- 可在一个近乎真实的生态系统中生存、竞争、合作、演化

### 1.2 核心立场

> 不是「更小的 Transformer」，而是把**语言生成架构**换成**生存控制架构** ——
> 感知 → 决策 → 行动 → 反馈 → 学习 → 遗传，自然语言只作为观察员接口，不进入控制闭环。

三个「不是」（07 §3）：

| | 不是什么 | 是什么 |
|---|---|---|
| 3.1 | 不是语言模型 | 核心任务不是 next-token prediction，第一身份是**生存代理控制器** |
| 3.2 | 不是简单具身强化学习 | 多了外部长期记忆、技能库、规则库、自我修改、基因包、变异继承、代谢约束、安全验证器 |
| 3.3 | 不是完整生态系统模拟器 | 第一阶段只建「能够进入生态系统的最小模型本体」 |

**创新分层**（09 §2）：L1 算子层（GRU / Mamba / SSM）是**借用且可替换**的，**不构成架构声明**；创新在 **L2 信息流 / L3 学习 / L4 演化**。

### 1.3 十条裁判标准（C1–C10）

全部模糊地带一律按这十条推导。**任何结论若无法回溯到其中至少一条，即视为偏离 SSEA 立场，不予采纳**（08 §1）。

| # | 约束 | 出处 |
|---|---|---|
| C1 | 生存控制架构，非语言生成架构 | 07 修订二、4.1 |
| C2 | 自然语言只作观察员接口，不进控制闭环 | 07 修订二、7.2 |
| C3 | 权重 / 记忆 / 技能三分离 | 07 4.2 |
| C4 | 低算力、低带宽 | README 项目目标、07 5.1 |
| C5 | 精准回忆历史 | README 项目目标 |
| C6 | 可自主修改自身代码与参数权重 | README 项目目标 |
| C7 | 可保存 / 恢复 / 变异 / 继承 | README 项目目标、07 4.5 |
| C8 | **给基因先验，不给知识语料** | 03 第九节 |
| C9 | **不设评分函数，只有淘汰函数** | 01 原始构想、07 8.9 |
| C10 | 创新在 L2 信息流 / L3 学习 / L4 演化，不在 L1 算子 | 06 问题 1、07 2.1 |

**两条最吃重的**：

- **C8** 是「为什么不能接人类知识库」的答案（[11](11-phase1-not-doing-list.md) 第 9 项），也是「为什么 `damage_urgency` / `fatigue` 置 0 预留」的理由——**给结构先验，不给满能力**。
- **C9** 是**验证门只判合法性、不打分**的共同来源，也是「淘汰函数在模型之外」的来源。一个提案让存活翻倍、另一个让它减半，只要都合法，Gate 一视同仁。

### 1.4 第一阶段的范围

**要做**——证明八件事（07 §2）：不以自然语言为主感知行动 / 通过身体状态与环境交互 / 输出混合动作空间 / 经验写入外部记忆 / 成功经验固化为技能 / 局部自我修改而非全量训练 / 保存基因包并产生可变异后代 / 在不建完整生态的前提下完成基本生存闭环。

**不做**——20 项清单见 [11](11-phase1-not-doing-list.md)。其中三项是**永久**的，不是延期：

| 项 | 理由 |
|---|---|
| 自然语言主接口 | 与核心立场冲突。观察员接口 v0.4+ |
| 大型语言模型作主控制器 | 同上 |
| 跨代记忆累积 | **这是设计，不是延期**——防记忆膨胀 |

> 每一项不做的背后都有一个**具体的失败模式**，不是「太复杂所以不做」（11 §1）。

## 2. 架构现状

### 2.1 双环

```
快环 FSL（实时控制，不输出自然语言、不做长文本推理、不频繁改权重）
  o_t ──► PerceptionEncoder ──► ┐
                                ├─► StateCore ──► ActionDecoder ──► Action
  MemorySystem.retrieve(p_t) ───┘                      │
  MetabolicMonitor.drive(...) ──────────────────────┘  ▼
                                                   SkillRunner ──► Environment
                                                        │
                                              o_{t+1}, f_t（含 prediction_error）
慢环 SEL（离线、可验证、可回滚）
  Action Trace + Feedback + Memory
      ──► ExperienceCompiler ──► 提案 ──► VerificationGate ──► StructureStore
                                                  │ pass            │ 原子切换版本号
                                                  │ reject          ▼
                                                  │        FastLoopContext（不可变快照）
                                                  └─► 版本号不切换 ──► 快环继续用旧版
```

**慢环不调用快环**。慢环只**发布结构的新版本**，快环只**读取当前版本**（08 §5.4）。

### 2.3 结构注入面：四条性质

这是双环之间**唯一**的接口。四条性质**由结构事实保证，而非调用方自觉**（08 §5.4）：

| 性质 | 含义 | 对应约束 |
|---|---|---|
| **快环零改动** | 快环只读 `FastLoopContext`，不知道慢环存在；换版本 = 换句柄 | C4 |
| **失败天然回滚** | Gate 不通过则版本号不切换。**不存在「回滚」这个操作，因为从未应用** | 07 §4.6 |
| **可遗传** | `FastLoopContext` 的内容就是 GenePackage 的直接来源；注入面是遗传面的**子集** | C7、C3 |
| **可审计** | 每次版本切换记录 `(proposal_id, from_v, to_v, gate_result, timestamp)` | C7 |

`StructureStore` 上**没有** `rollback` / `revert` / `undo` / `restore` 方法——这不是遗漏，是设计。有测试守着（`test_no_rollback_api_exists`）。

### 2.4 四权分立

第一阶段最重要的结构决定之一：**「提什么」「在不在边界内」「能不能应用」「应用不应用」是四个不同的问题，分在四个地方**。

| 权 | 归谁 | 它**刻意不做**什么 |
|---|---|---|
| **提什么**（ΔS / Δθ） | `ExperienceCompiler` / `LocalPlasticity` | 不提交、不评估好坏、不发明切分规则 |
| **在不在边界内** | `PlasticityController.allowed_scope` | **白名单**，且 07 §6.7 的不可更新清单**先于**白名单匹配 |
| **能不能安全应用** | `VerificationGate` | **不打分**（C9）、不碰权重、不执行代码、不做回滚 |
| **应用不应用** | `StructureStore.commit` | 内部按 `GateResult` 分流；拒绝时记审计项、**不抛异常、不改版本号** |

07 §6.7 的两张清单（**可更新**：记忆 / 技能 / 规则 / 行为阈值 / 检索策略 / 小型 adapter / 局部策略头；**不可更新**：核心安全机制 / 验证门 / 环境接口 / 基因管理器底层权限 / 观察员接口）在增量 3 之后已变成**可执行的边界**。

## 4. 能力边界

> **这一节和下一节是本文档的核心。**
> 项目的文档纪律里最贵的一课：**「机制通了」经常被读成「能力有了」**。
> 所以每一条能力都必须成对地写出它**做不到**什么。

### 4.1 三分离（权重 / 记忆 / 技能）

| 层 | 能做到 | **不能做到** |
|---|---|---|
| **权重** | `StateCore` + `ActionDecoder` 各头均为标准 `nn.Module`，内部可微 | **没有任何参数学习发生**。Δθ 只动**结构侧阈值**，torch 参数自初始化后不再变；参数侧整个推迟 |
| **记忆** | 写入 / 向量检索 / 重要度排序 / 容量限制 / 合并 / 可继承判定六项齐全 | 记忆**不被任何机制读取后用于决策**——`m_t` 进了 State Core，但没有证据表明它改变了输出 |
| **技能** | 从成功轨迹编译 / 提案过门 / 淘汰 / 继承；端到端可被快环真实调用 | 模型**不会自己决定何时编译技能**——默认策略产生不了可编译的成功段 |

### 4.2 双环与注入面

**能做到**：慢环只发布新版本、快环只读快照；四条性质由结构事实保证，各有测试。

**不能做到**：慢环**只有一步**。`DeathHook` 仍默认 `None`（死亡快照未接），ΔR / ΔM 两类提案没有生产者。

### 4.3 自我修改

**能做到**：
- `LocalPlasticity.observe(trace)` 给出纯读的症状诊断，三种帧类别可区分（门没开 / 门开了但决定不记 / 记了）
- 两条症状规则：**「值得记的帧上门从没开过」→ 降低 `memory_gate_threshold`**；**「写进去了却读不回来」→ 降低 `min_similarity`**
- 两条规则**都能沉默**——症状不成立时一条提案都不提
- 提案走完整四级 Gate 后真的被装上（`thresholds@v0 → v1`）

**不能做到**：
- **参数侧 Δθ 整个推迟**（`plasticity.DEFERRED_SCOPES`）。理由不是偷懒：权重增量递不进 Gate 的第四级（沙盒 → 回归 → 小范围环境测试看不见它），硬塞进 `UPDATE_ADAPTER` 会让「经过验证门」这句话**变成假话**（07 §16「模型不可绕过验证器应用修改」）
- 选择性**没有**：全局阈值只能把门**全开**，做不到「惊奇帧开、平淡帧关」

### 4.4 生命周期

**能做到**：`GenePackage` 协议定义了字段，可序列化；`MemoryItem.is_heritable()` 判据已实现并有测试。

**不能做到**：**保存 / 恢复 / 变异 / 继承四件事一件都没做。**

### 4.5 约束强制执行

**能做到**：两个执行点共用 `ActionConstraints.violations()` 同一份规则。第一执行点（Action Decoder）在生成阶段就不越界；第二执行点（Environment）兜住漏网的，记 `ACTION_FAILED` 事件而不崩溃。记忆侧有第三处防御：`writable=False`。

**不能做到**：无。这一项是完整闭环的。

## 5. 证据现状

### 5.1 唯一一组真数字

增量 3 的阈值自修正，是**目前全项目唯一一组「行为真的变了」的实测数字**（8 seed × 25 帧，强制睡眠一次）：

```
记忆门开启率   均值 0.280 → 1.000
提案分布       6/8 seed 恰好提案一步（memory_gate_threshold 0.5 → 0.4）
               2/8 seed 沉默（本就 1.000）
```

**「2/8 沉默」比「0.280 → 1.000」更重要**——一个每次都提的规则不配叫修正。`TestAcceptance` 里「已经正常的 seed 保持沉默」这条断言，比提升本身更值得守。

**三条必须说清的保留**（否则这个数字会被读错）：

1. **它需要一次睡眠，而默认世界不给睡眠——成因是算术互斥，不是探索不到。** 实测默认 `MetabolicMonitor` 下 8 个 seed **全部在 60 余帧（65–70）死亡，`sleeps=0`，`proposals=0`**。0.280 → 1.000 是在**病理监控器**下测得的（把睡眠同意条件压到第 25 帧成立一次）。

   `wants_sleep` 要求三条件**同时**成立（`energy ≥ 0.7` ∧ `threat ≤ 0.05` ∧ `fatigue ≥ 0.6`），而默认代谢参数下第一条与第三条**在时间上不相交**：`fatigue ≥ 0.6` 按 `fatigue_rate=0.02` 最早要到**第 30 帧**才成立；而 `energy ≥ 0.7` 光靠 `base_drain=0.01` 就恰好在**第 30 帧跌破**，加上移动与动作成本实际**第 20–25 帧**就破了。实测（seed 0/1/2）：**t=49 时 `fatigue=1.000` 而 `energy=0.25`**。536 帧逐帧统计，三类阻断依次占 `energy_below_threshold` 42.6% / `threat_imminent` 31.3% / `fatigue_insufficient` 26.0%，且**没有任何一帧三条件同时成立**。

   → 所以「机制被证明了、可达性没有」可以升级为更精确的判断：**可达性不是没被探索到，是在当前参数下永远不可能。** 修法见 §6.3.1。

2. **它是一个钝器，不是一把选择性的闸门。** 门控值由随机权重决定，240 个采样里 min 0.463 / 中位 0.487 / max 0.530——几乎是个常数。阈值 0.5 正好落在分布中间，所以约一半 seed 打不开。全局阈值这个杠杆只能把门全开。**「门控不开」修好了，「门开得准不准」是下一步的事**，而那需要被推迟的参数侧 Δθ。

3. **没有棘轮。** 修正前这条规则会一路把阈值推到下界 0.15——第二轮睡眠的触发证据全部来自第一轮之前。增量 3 用 `context_fingerprint` 切了**证据窗口**，只统计当前结构版本产出的帧，于是症状消失后规则自动沉默。`TestConvergesOnce` 守的就是这个不动点。

### 5.3 为什么「751 项测试通过」不等于「架构有效」

它证明的是：协议自洽、序列化保真、约束不被违反、注入面四条性质成立、记忆与技能的机制按设计工作。

它**不**证明：这个架构比别的架构更省算力、记忆真的提升了生存率、技能固化真的降低了能量消耗、基因继承真的传递了能力。

**后者需要 §12 的实验数字。现在有了三个实验的十二个数字，但它们全是
「这条路径能走通」，没有一条是对照组数字**——所以这句话的有效版本是
**「对照组数字一个都没有」**，而不是「数字一个都没有」。区别要紧：
前者说的是证据等级不够，后者说的是工程还没做完。§6.3.3 详述。

09 §5 已经把这句话说在了前面——**「精准回忆已被验证」与「低算力」本身就是待检验的主张，不是已有结论**；后者的指标就是实验 3 的「能量消耗变化」。

### 6.3 关键路径：瓶颈是两层，不是一层

本文档旧版与 12 §6 的旧版把「实验 2 / 3 / 7」归成同一个瓶颈（默认世界里没有可学的成功）。**逐层实测之后，这个归并是错的**：实验 7 卡的是另一件事，而且只要一处语义修正。12 §6 债务 6b 已按此改写，实验 7 已从该瓶颈中移出。

#### 6.3.1 第一层：睡眠判据把能量当了入口条件（只挡实验 7）——**已修**

`MetabolicMonitor.wants_sleep` 的合取里藏着两个**对立**的问题：

| 语义 | 判据 | 它在问什么 |
|---|---|---|
| 防御性整理 | `energy ≥ 0.7` | 「有余粮时才整理」 |
| 生理必要性 | `fatigue ≥ 0.6` | 「撑不住了才整理」 |

能量条件错在**两处**，各自独立成立，所以它不是「阈值调坏了」而是「不该在这儿」。

**错处一：合取取到的是空集。** 能量单调降、疲劳单调升，要求「余粮充足」**且**「已经累了」等于要求两条反向曲线在时间上相交——它们只在第 30 帧附近擦肩，一有移动就彻底错开。

**错处二（更根本）：能量作为入口条件会自我复制。** 这与设计意图直接冲突：`Environment.rest()` 刻意**不扣基础代谢**、反而每帧 `+0.01` 能量，理由就写在它的 docstring 里——「若睡眠也耗能，模型就没有理由进入睡眠期，慢环的唯一常规入口会被生存压力挤掉」。**既然睡眠自己生产「能量充裕」这个前提，拿它当门槛就是正反馈：不动才是最优策略。**

按 SSEA 立场推导（08 §2.2 的原话是「在**安全**时允许无损整理经验」）：**安全是本质条件，疲劳是自然的进入理由，能量不参与判定。**

实测三种候选（8 seed × 200 帧，`min_sleep_frames=5`，接真慢环钩子）：

```
判据                        睡眠可达  睡眠占寿命  唤醒  提案  应用  均寿命
现行  E≥.7 ∧ safe ∧ F≥.6      0/8       0.0%      0     0     0    67.0
      safe ∧ F≥.6             7/8     6%–12%     11     6     6    79.6
      safe ∧ E≥.7             4/8    65%–72%    108     2     2   133.6
```

第三行不是「另一种可接受的方案」，是**双峰退化**：4 个 seed（0/1/3/6）跑到 200 帧上限，其中 **65%–72% 的时间在睡**、26–28 次唤醒，却只产出 0–1 条提案——RUN 帧被切成 1 帧碎片，慢环无事可做，**模型学会了不行动**；另外 4 个 seed 能量在威胁解除前跌破 0.7，**从不睡眠**，67–70 帧死。它的均寿命 133.6 是三者里最长的，但那是**靠不活来活长**，正是 13 §5.4 那个「攒满 n 帧才准睡」包装想绕开的失败模式。

**只有疲劳判据同时满足「可达」与「trace 够长」**，因为它是自限的：睡眠期每帧恢复疲劳 0.15，醒来归零，要再攒约 30 帧，天然有不应期。能量没有不应期，只有正反馈。

> **数字更正**：早先本表记的是「8/8 / 11 / 6 / 6」与「8/8 / 108 / 2 / 2」。唤醒与提案数三次实测完全一致，**只有「睡眠可达」那一列复现不出来**——按实测应为 7/8 与 4/8。唯一未睡的 seed 0 **不是判据缺陷**：它 `threat` 恒 0.929（附近有危险源而它无法转向），**安全条件在正确拒绝**。这条差别值得留痕：它说明安全条件不是恒真的摆设。
>
> **归因提醒**：这 6 条提案**全是 `thresholds` 类别**（Δθ，来自 §5.1 的记忆门症状），**没有一条是技能编译**。所以修好睡眠只解锁实验 7 的「触发」半边，「编译出技能」仍卡在第二层。

#### 6.3.2 第二层：没有可学的成功（挡实验 2 / 3）

旧版说「默认 Action Decoder 随机初始化，**从不 emit grasp**」。这句话**观察对、因果不对**。逐层拆开实测（8 seed × ~67 帧）：

| 层 | 实测 |
|---|---|
| manipulation 门 | **约一半 seed 恒闭**——门控值随机初始化≈0.5 而阈值恰 0.5，与记忆门**同一病理** |
| 操作选择 | 门开的 seed 里，`manip_op` 的随机 argmax **0/560 帧落在 `grasp`**，常落在 `none` / `use_tool` |
| 目标选择 | `manip_target(h).expand(n)` 是**等值张量**，`argmax` 恒返回 0 → **永远选「最近的可见对象」，不分类别**（常是 prop / hazard） |

把这三层**逐层强制开启**（门开 + 强制 `grasp` + 只选资源）之后：8 seed 共 **3 次**成功抓取，均寿命只从 67 涨到 72 帧。**仍不足以产出可编译的成功段**——因为编译要的不是「抓成一次」，而是 `min_frames=3` 的**连续正收益段**。

→ 真正的约束是**趋近能力**：locomotion 每帧位移恒 ~0.245 且方向不可控，agent 近似直线行进，不会「接近目标」。**所以解药不是「让它 emit grasp」，是给它趋近行为。**

**趋近行为该以什么形态给（本节唯一不是实测的部分）**：14 §1.3 的 **C8 是「给基因先验，不给知识语料」**，而它在 §1.3 里正是 `damage_urgency` / `fatigue` 置 0 预留的理由——给结构先验，不给满能力。趋近行为恰好落在这个位置：**它是本能，不是知识**。

所以最符合 SSEA 的形态，不是「手工调一个更好的默认解码器」（那是权重：不可遗传，也不受 C8 保护），而是**把「趋近资源」做成 `instinct_adapters` 的第一个消费者**。这顺带解掉 13 §6.2 记的那笔账——`adapters` 至今是「写得进、过得门、传得下、**却没有消费者**」的类别，而参数侧落地顺序的第一步本来就是「先让 adapters 有模型侧消费者」。

> 这是**提议，不是实测**。它不与旧版的「换一个非随机初始化的默认解码器」冲突，但它把这件事从「训练 / 调参」移到了「基因先验」，于是顺带满足 C7（可遗传）与 C8（只给先验）。

**旧版另一条解药「让世界给出除 grasp 之外的正反馈」要打问号**：环境能给的是生存与损伤，那是生存计价物（C9）；一旦变成「接近资源就给分」，环境就引入了**评分函数**，而 C9 明确「不设评分函数，只有淘汰函数」。这条解药与 C9 的边界必须先写清楚再动。

三个实验的测量脚本已落地（`experiments/`），实测十二个数字见 12 §4.2。
**结论一句话：机制通了，有效性一个都没证明。**

格式级。**通过率 100% 与拒绝率 0% 是同一件事的两面，后者才是要注意的那面。**

#### 6.3.4 计数器建成了，实验 2 / 3 没有因此解锁（2026-09-27 新增）

§6.3.3 之后紧接着建了 `Environment` 累计计数器（§6.4 线 C 第 11 项）。
**它修好了它该修的东西，但它不是实验 2 / 3 的前置**——这句话要写下来，
因为上一版文档把它写成了「唯一还能提升证据等级的前置」。

**它确实修好的**：`event_log()` / `event_notes()` 是 16 槽环形缓冲
（[12](12-progress-report.md) §6 债务 10），「跑完再遍历事件流做统计」会
**静默丢掉早期事件**，而且错的方向偏向零——正好把有效果的实验读成没效果。
`event_counts()` 只增不减、不截断，键集为闭词表。实测 8 seed：
每轮 84–216 条事件对 16 槽缓冲，各轮总计**非单调**（即计数器没有跨 `reset()` 累积）。

**它没有修好的，逐条对账如下：**

| 指标 | 计数器能给吗 | 为什么 |
|---|---|---|
| 实验 2 记忆写入成功率 / 检索命中率 | 不需要 | `memory.stats.writes` / `hits` 早就有 |
| 实验 2 **危险回避率** | **不能，形状不对** | 要按 `source_id` 区分危险源与资源，而按类型的 dict 没有这个维度——`OBJECT_FOUND` 对两者一视同仁 |
| 实验 3 技能生成数量 / 调用成功率 | 不需要 | `StructureStore.audit_log()` 与 `SkillRunner.stats` 早就有 |
| 实验 3 **能量消耗变化** | **不能，要的是窗口** | 「固化前 vs 固化后」要按**结构版本**切开（先例 `plasticity._current_window`），不是全轮累计 |

而更根本的一层：**这两个实验的验收指标在文档里只有名字、没有算式**。
逐文件搜 `危险回避率` / `能量消耗变化`，全部命中都只是指标名列表——
没有一处给出公式、分母或窗口。

**所以真约束回到 §6.3.2 的推论：趋近本能。** `direction = tanh(loco_dir(h))`
是未训练线性头，agent 近似直线行进、不会转向。**不会转向的 agent 无法回避危险**，
这跟有没有计数器、有没有记忆都无关。

**留给后面的教训**（写在这里是因为它比计数器本身值钱）：
「缺一个组件」与「缺一个前置」是两件事。计数器是**缺组件**，
补上它只让脚本不再算错；实验 2 / 3 缺的是**前置**，那在别处。
当时把两者混为一谈，于是把线 C 的一项排到了线 B 前面。

**债务 8 值得单独说，因为它是唯一会「静默算错」的债务。** `Environment._event_notes` 只保留最后 `max_events=16` 条。核对本文档时它咬过一次：读「跑完再统计 `ENERGY_GAINED`」得到 **0 次**，而逐帧追踪显示第 10 帧确实 `grasp: +0.356 energy`——早期事件早已被挤掉。**实验 2 的「危险回避率」与实验 3 的「能量消耗变化」如果写成「跑完读事件流」，结论会是错的，而且错得看不出来。**

修法按 C4（低算力低带宽）推导：**不能靠调大 `max_events`**——那是让控制环路上的缓冲无界增长。正确落点是**观察员面**：加 O(1) 的累计计数器（**2026-09-27 已落地**，见 `Environment.event_counts()`），或者实验脚本自己订阅 `_emit_event`。**但它的定位要说准**：它消掉的是「脚本静默算错」这一类坑，**不是**实验 2 / 3 的前置解锁——那两条卡在趋近本能（§6.3.4）。07 §7.2 已经给这件事定了性（自然语言可用于「人类观察员日志 / 事后解释 / 慢环规划候选 / 调试输出」，**不能直接参与**「感知输入 / 动作输出 / 身体控制 / 实时闭环」），所以累计统计属于观察员，不该靠加长控制环路的缓冲来满足。

**07 §16 的八条安全约束**（模型不可修改验证门 / 不可绕过验证器应用修改 / 所有自我修改必须可回滚 / 所有基因保存必须可审计 等）目前**全部由结构事实保证**，不靠权限系统。其中「不可修改淘汰函数」是**结构上不可能**——淘汰函数在模型之外，模型物理上碰不到它（10 §2 平局裁决：判为生态系统，模型侧**连镜像都不做**）。
